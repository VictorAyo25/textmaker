AnswerQuestion Two

(a) A relation is in BCNF if it is in 3NF and every determinant is a candidate key.

(b) Candidate keys: (student, course) determines teacher, so it is a key; and since teacher → course, (student, teacher) determines course and therefore everything, so it too is a key. Highest normal form: the dependency teacher → course has a non-key determinant, but course is a prime attribute (part of the key (student, course)), so the relation is in 3NF. It is not in BCNF, because teacher is a determinant that is not a candidate key. BCNF decomposition:

R1(teacher, course)     PK teacher
R2(student, teacher)    PK (student, teacher)   FK teacher -> R1

This is the classic case where BCNF costs a dependency: (student, course) → teacher is no longer enforced by one relation. That trade-off is itself an exam point.

AnswerQuestion Three
(i)   SELECT s.sName, c.cTitle
      FROM   Student s JOIN Enrol e ON s.sID = e.sID
                       JOIN Course c ON e.cID = c.cID;
(ii)  SELECT cID, COUNT(*) FROM Enrol GROUP BY cID;
(iii) SELECT * FROM Student WHERE sID IN
        (SELECT sID FROM Enrol WHERE score > (SELECT AVG(score) FROM Enrol));
(iv)  SELECT * FROM Course WHERE cID NOT IN (SELECT cID FROM Enrol);
(v)   SELECT cID, MAX(score) FROM Enrol GROUP BY cID;

AnswerQuestion Six

(a) A foreign key refers from one relation to the candidate (primary) key of another; the candidate key is the target, the foreign key the pointer. Referential integrity: every foreign-key value must match an existing primary key or be wholly null.

(b) Each one-to-many puts the "one" side's key into the "many" side:

CUSTOMER(custID, name, address)          PK custID
ROUTE(routeID, description)              PK routeID
COURIER(courierID, name, routeID)        PK courierID   FK routeID -> ROUTE
PARCEL(parcelID, weight, custID, courierID)
   PK parcelID   FK custID -> CUSTOMER, FK courierID -> COURIER
