AnswerQuestion One (compulsory)

(a) Generalization: bottom-up, defining a supertype from shared subtypes. Specialization: top-down, defining subtypes of a supertype. Subtype discriminator: a supertype attribute whose value says which subtype a row belongs to. Completeness constraint: whether every supertype instance must belong to a subtype (total) or need not (partial).

(b) Determinants: matricNo → sName (partial, on part of the key); courseCode → cTitle (partial); the full key (matricNo, courseCode) → grade (full dependency). Both single-attribute dependencies are partial, so the relation is not in 2NF.

(c)

(i)   SELECT * FROM Sales WHERE amount > 5000 ORDER BY amount DESC;
(ii)  SELECT region, SUM(amount) FROM Sales GROUP BY region;
(iii) SELECT staffID, AVG(amount) FROM Sales GROUP BY staffID;
(iv)  SELECT * FROM Sales WHERE item = 'Laptop';

AnswerQuestion Six

(a) Relation: a table. Degree: number of attributes (columns). Cardinality: number of tuples (rows).

(b) Key (empNo, projNo). empNo → eName, deptNo and projNo → pName are partial; deptNo → deptName is transitive. 2NF lifts the partials; 3NF lifts the transitive:

Emp(empNo, eName, deptNo)            PK empNo   FK deptNo -> Dept
Dept(deptNo, deptName)               PK deptNo
Proj(projNo, pName)                  PK projNo
WorksOn(empNo, projNo, hours)        PK (empNo, projNo)
   FK empNo -> Emp, FK projNo -> Proj
