Components of Computer Architecture - 5
Von Neumann Architecture: Shared memory for data and instructions
This processor configuration consists of a control unit, an arithmetic logic unit, a register set, and a memory region containing program instructions and data. 
The key feature distinguishing the von Neumann architecture from the Harvard architecture is the use of a single area of memory for program instructions and the data acted upon by those Instructions.
40

--- slide 41 ---
Components of Computer Architecture - 5
It is conceptually straightforward for programmers, and relatively easier for circuit designers, to locate all of the code and data a program requires in a single memory region.  Figure 1 shows the elements of Von Neumann architecture.
41

--- slide 42 ---
Components of Computer Architecture - 5
Harvard Architecture: Separate memory for data and instructions
A strict Harvard architecture uses one address space and memory bus for program instructions and a separate address space and memory bus for data. 
This configuration has the immediate benefit of enabling simultaneous access to instructions and data, thereby implementing a form of parallelism.  
This enhancement comes at the expense of essentially duplicating the number of address lines, data lines, and control signals that must be implemented by the processor to access both of the memory regions.

INTRODUCTION
Memory hierarchy is a structured arrangement of different storage types in a computer system, designed to optimize performance and cost.
Memory trade-offs are a sad part of reality 
Faster access time, greater cost per bit;  faster, the expensive 
Greater capacity:  slower in terms of access
Smaller cost per bit;  slower in terms of access
Slower access time  - larger capacity
4

--- slide 5 ---
INTRODUCTION
Design constraints on memory can be summed up by three questions:
How much space?
If memory exists, applications will likely be developed to use it.
How fast – access time?
Best performance achieved when memory keeps up with the processor;
i.e. as the processor execute instructions, memory should minimize pausing / waiting for instructions or operands.
How expensive?
Cost of memory must be reasonable in relationship to other components;
5

--- slide 6 ---
THE WAY OUT
The way out of this dilemma: 
Don’t rely on a single memory; 
Instead employ a memory hierarchy; 
Supplement: 
smaller, more expensive, faster memories with larger, cheaper, slower memories;

--- slide 7 ---
THE WAY OUT
As one goes down the hierarchy: 
Decreasing cost per bit; 
Increasing capacity; 
Increasing access time; 
Decreasing frequency of access of memory by processor – very key to the performance of the CPU

Cache Memory Principles
When the processor attempts to read a word of memory:
Check is made to determine if the word is in the cache;
If so (Cache Hit): word is delivered to the processor.
If the word is not in cache (Cache Miss):
Block of main memory that contains the word is read into the cache;
Cache delivers the Word to the processor.
Because of the locality of reference principle (time and space):
When a block of data is fetched into the cache...
It is likely that there will be future references to that same memory location

--- slide 40 ---
Direct Mapping Function
The simplest technique, known as direct mapping, maps each block of main memory into only one possible cache line. 
The mapping is expressed as
i = j modulo m
where
i = cache line number
j = main memory block number
m = number of lines in the cache
40

--- slide 41 ---
Direct Mapping Function
41

--- slide 42 ---
Direct Mapping Function
42

--- slide 43 ---
To determine whether a block is in the cache:
Use the line field of the memory address to index the cache line;
Compare the tag from the memory address with the line tag;
If both match, then Cache Hit:
Use the line field of the memory address to index the cache line;
Retrieve the corresponding word from the cache line;
If both do not match, then Cache Miss:
Use the line field of the memory address to index the cache line;
Update the cache line (word + tag);
43

--- slide 44 ---
Direct Mapping Function
• Advantage: simple and inexpensive to implement;
• Disadvantage: there is a fixed cache location for any given block;
• if a program happens to reference words repeatedly from two different blocks that map into the same line;
• then the blocks will be continually swapped in the cache;
• hit ratio will be low (a.k.a. thrashing).

Set associative mapping
This form of mapping is an enhanced form of direct mapping where the drawbacks of direct mapping are removed. 
Set associative addresses the problem of possible thrashing in the direct mapping method. 
It does this by saying that instead of having exactly one line that a block can map to in the cache, we will group a few lines together creating a set. 
Then a block in memory can map to any one of the lines of a specific set. Set-associative mapping allows that each word that is present in the cache can have two or more words in the main memory for the same index address. 
Set associative cache mapping combines the best of direct and associative cache mapping techniques.

Underflow
Overflow  is a situation in which the exponent is too large to be represented in the Exponent field while Underflow is a situation in which the number is too small to be represented in the Exponent field.
Arithmetic underflow can occur when the true result of a floating point operation is smaller in magnitude (that is, closer to zero) than the smallest value representable as a normal floating point number in the target datatype. 
Underflow can in part be regarded as negative overflow of the exponent of the floating point value. For example, if the exponent part can represent values from −127 to 127, then a result with a value less than −127 may cause underflow.

Introduction
Instruction Set Architecture (ISA) is one of the most fundamental concepts in Computer Architecture and Organization. 
It defines the interface between hardware and software, acting as a bridge that allows software programs to communicate with the processor.
In simple terms, ISA specifies:
What operations a processor can perform (instruction set)
How instructions are represented (instruction format)
How data is accessed and manipulated (addressing modes)

Types of Instructions - Load/Store Instructions
One of the universal characteristics of instruction execution is that the source does not get changed, only the destination. 
Thus, in a load operation the processor copies data into a register, and in a store operation the processor copies data from a register into a memory location. 
Examples of load/store instructions in the MC68009 processor are LDA, STA, LDB, STB, LDD, STD, and so forth.
14

--- slide 15 ---
Types of Instructions - Load/Store Instructions
Examples of load/store instructions in the MC68000 processor are
MOVE (for either direction of data movement), 
MOVEM (for moving the content of several registers into or out of memory with a single instruction), and 
EXG (for exchanging register contents). 
These instructions and others like them must include information identifying the source and destination.

Arithmetic/logic operations provide the primary data-processing capabilities of the computer. 
The minimum arithmetic operations required are those of addition and subtraction.  5 – 3  = 5 + (-3)     101 + 011
All processors, implement the basic logic operations of AND, OR, and exclusive-OR on a bit-by-bit basis between two operands.

--- slide 19 ---
Test/branch operations provide the decision-making capabilities in computer programs. 
The test is often performed on the result of some prior arithmetic/logic operation. 
It determines whether the result was zero or non-zero, positive or negative, or some other binary choice involving bits in the condition code register. 
During the execution of a test/branch instruction, the processor examines the appropriate condition code bits to determine the result of the test.

Types of Instructions - Test/Branch Instructions

Examples of test/branch instructions are BCC (branch if carry is cleared), BEQ (branch if equal to 0), BMI (branch if minus), and BRA (branch always).

The program in assembly language that evaluates 
	X = (A + B) * (C + D)

--- slide 34 ---
Three Address - Instruction FormatX = (A + B) * (C + D)   X =A +B + C
ADD R1, A, B  R1 ← M[A] + M[B]   ADD R1,A,B
ADD R2, C, D  R2 ← M[C] + M[D]  ADD X, R1,C
MUL  X, R1, R2  M[X] ← R1 * R2 
It is assumed that the computer has two processor registers, R1 and R2. The symbol M[A] denotes the operand at memory address symbolized by A.
The advantage of the three-address format is that it results in short programs when evaluating arithmetic expressions.
The disadvantage is that the binary-coded instructions require too many bits to specify three addresses.

--- slide 35 ---
Two Address - Instruction Format
Two-address instructions are the most common in commercial computers. Here again each address field can specify either a processor register or a memory word. The program to evaluate X = (A + B) * (C + D) is as follows:
MOV R1, A   R1 ← M[A]
ADD R1, B   R1 ← R1 + M[B]
MOV R2, C   R2 ← M[C]
ADD R2, D   R2 ← R2 + M[D]
MOL R1, R2  R1 ← R1 * R2
MOV X, R1   M[X] ← R1

Indirect Addressing  Mode

An addressing technique in which the address field of the instruction contains the address of another memory location that stores the effective address of the operand.

|Opcode|Address|
Interpretation

Indirect Addressing  Mode
52
How It Works (Step-by-Step)
CPU fetches the instruction 
Reads the address field (say A) 
Goes to memory location A 
Retrieves the effective address (EA) stored there 
Accesses operand using EA
Example 1
LOAD R1, (200)
Explanation
Instruction contains 200 
Memory[200] contains 500 
Memory[500] contains actual data 
Final operation:R1 = Memory[500]

Relative Addressing  Mode
54
Relative Addressing Mode is defined as:
An addressing technique in which the effective address (EA) is obtained by adding a displacement (offset) to the current value of the Program Counter (PC).
Formula:
Effective Address (EA) = PC + Offset
