INTRODUCTION
Memory hierarchy is a structured arrangement of different storage types in a computer system, designed to optimize performance and cost.
Memory trade-offs are a sad part of reality
Faster access time, greater cost per bit;  faster, the expensive
Greater capacity:  slower in terms of access
Smaller cost per bit;  slower in terms of access
Slower access time  - larger capacity

============================================================
SLIDE 5
INTRODUCTION
Design constraints on memory can be summed up by three questions:
How much space?
If memory exists, applications will likely be developed to use it.
How fast – access time?
Best performance achieved when memory keeps up with the processor;
i.e. as the processor execute instructions, memory should minimize pausing / waiting for instructions or operands.
How expensive?
Cost of memory must be reasonable in relationship to other components;

Cache Memory Principles
When the processor attempts to read a word of memory:
Check is made to determine if the word is in the cache;
  If so (Cache Hit): word is delivered to the processor.
  If the word is not in cache (Cache Miss):
    Block of main memory that contains the word is read into the cache;
    Cache delivers the Word to the processor.
Because of the locality of reference principle (time and space):
  When a block of data is fetched into the cache...
  It is likely that there will be future references to that same memory location

What is the difference?
Virtual cache stores data using logical addresses.
Processor accesses the cache directly, without going through the MMU.
Advantage:
  Faster access speed;
  Cache can respond without the need for an MMU address translation;
Disadvantage:
  Same virtual address in two different applications refers to two different
  physical addresses;
  Therefore cache must be flushed with each application context switch...
  ...or extra bits must be added to each cache line
to identify which virtual address space this address refers to

Cache Size
Cache size should be:
Small enough so that overall:
  Average cost per bit is close to that of main memory alone;
• Large enough so that the overall
  Average access time is close to that of the cache alone;
The larger the cache, the more complex the addressing logic:
  Result: large caches tend to be slightly slower than small ones
Available chip and board area also limits cache size.

SLIDE 40
Direct Mapping Function
The simplest technique, known as direct mapping, maps each block of main memory into only one possible cache line.
The mapping is expressed as
i = j modulo m
where
i = cache line number
j = main memory block number
m = number of lines in the cache

SLIDE 43
To determine whether a block is in the cache:
Use the line field of the memory address to index the cache line;
Compare the tag from the memory address with the line tag;
  If both match, then Cache Hit:
    Use the line field of the memory address to index the cache line;
    Retrieve the corresponding word from the cache line;
If both do not match, then Cache Miss:
  Use the line field of the memory address to index the cache line;
  Update the cache line (word + tag);

============================================================
SLIDE 44
Direct Mapping Function
• Advantage: simple and inexpensive to implement;
• Disadvantage: there is a fixed cache location for any given block;
  • if a program happens to reference words repeatedly from two different blocks that map into the same line;
  • then the blocks will be continually swapped in the cache;
  • hit ratio will be low (a.k.a. thrashing).

SLIDE 50
Associative Mapping
Associative mapping overcomes the disadvantage of direct mapping by permitting each main memory block to be loaded into any line of the cache (Figure 4.8b).
In this case, the cache control logic interprets a memory address simply as a Tag and a Word field.
The Tag field uniquely identifies a block of main memory. To determine whether a block is in the cache, the cache control logic must simultaneously examine every line’s tag for a match.

SLIDE 61
Set associative mapping
This form of mapping is an enhanced form of direct mapping where the drawbacks of direct mapping are removed.
Set associative addresses the problem of possible thrashing in the direct mapping method.
It does this by saying that instead of having exactly one line that a block can map to in the cache, we will group a few lines together creating a set.
Then a block in memory can map to any one of the lines of a specific set. Set-associative mapping allows that each word that is present in the cache can have two or more words in the main memory for the same index address.
Set associative cache mapping combines the best of direct and associative cache mapping techniques.
