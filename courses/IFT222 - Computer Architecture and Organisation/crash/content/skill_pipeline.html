Pipelining means overlapping instructions so several are in progress at once. Picture a laundry: you do not wait for one load to wash, dry and fold before starting the next, because the moment the first load moves to the dryer the second goes into the washer. A processor overlaps its instructions the same way. What everyday process is pipelining most like?

a laundry (or any assembly line). To overlap them, we split each instruction into stages, called k stages. A common five are IF (instruction fetch), ID (instruction decode), EX (execute), MEM (memory access) and WB (write back). Each stage is its own hardware, so five instructions can each sit in a different stage at the same moment. Name the five stages in order.

IF, ID, EX, MEM, WB. Without a pipeline, instruction 2 cannot start until instruction 1 has passed through every stage. With a pipeline, the instant an instruction leaves a stage the next one enters it, so once the pipe is full one instruction finishes every clock cycle. Once the pipe is full, how many instructions complete per clock cycle?

one every cycle. That steady one-per-cycle output is the whole payoff. Now, how long is one clock cycle? Every stage must finish inside it, so the cycle is set by the slowest stage plus a small latch delay between stages, never the average and never the sum. If the stages take 60, 50, 90, 80 ns with a 10 ns latch, what is the cycle time?

100 ns. (The slowest stage is 90 ns, plus the 10 ns latch, giving 100 ns.) Read on.

Now the time for n instructions. The first takes k cycles to fill the pipe; after that one more finishes every cycle, so n instructions take (k + n − 1) cycles, which you then multiply by the cycle time. With k = 4 stages and n = 500 tasks, how many cycles is that?

503 cycles. (4 + 500 − 1 = 503, and at 100 ns each that is 50 300 ns.) Read on.

Without the pipeline each instruction needs its full one-instruction time, the sum of the stage times, here 60 + 50 + 90 + 80 = 280 ns. The speedup is that one-instruction time divided by the cycle time, and it can never exceed k, the number of stages. Divide 280 ns by the 100 ns cycle to get the speedup.

2.8. (280 / 100 = 2.8, below the ceiling of k = 4 stages.) For a whole batch you compare totals instead: 500 × 280 = 140 000 ns without a pipeline, against 50 300 ns with one. The reference card and the two worked examples below sit exactly these; do them with the answers covered.

Must doThe pipeline sums
  • Cycle time = slowest stage + latch delay.
  • Pipelined time for n tasks = (k + n − 1) × cycle time. (It takes k cycles to fill with the first task, then one more cycle for each of the other n − 1.)
  • Non-pipelined time for n tasks = n × (time for one instruction). One instruction takes the sum of all the stage times, or the given per-instruction time.
  • Speedup = non-pipelined time / pipelined time. Its ceiling is k.

Memory hook: "k + n − 1", and the clock runs at the slowest stage, never the average.

Worked examplethe method, vertically

A pipeline has 4 phases of 60, 50, 90, 80 ns, with a 10 ns latch delay. Find the cycle time, the one-task time, the speedup, and the times for 500 tasks. The exam sets exactly this; sit it verbatim in the final mock.

Given 4 phases 60, 50, 90, 80 ns · latch 10 ns · 500 tasks
Formula cycle = slowest + latch · pipe(n) = (k + n − 1) × cycle · seq(n) = n × Σphases · speedup = Σphases / cycle
Cycle    = max(60,50,90,80) + 10 = 90 + 10 = 100 ns
One task = 60 + 50 + 90 + 80 = 280 ns
Speedup  = 280 / 100 = 2.8
Pipe 500 = (4 + 500 - 1) x 100 = 503 x 100 = 50 300 ns
Seq 500  = 500 x 280 = 140 000 ns
Cycle 100 ns; one task 280 ns; speedup 2.8; 500 tasks pipelined 50 300 ns against sequential 140 000 ns.
Worked examplethe revision deck's new one

A non-pipelined processor takes 60 ns per instruction. Redesigned as a 6-stage pipeline with a 12 ns cycle time, running 50 instructions. Find both times and the speedup. (This is the one question on the revision deck that is not on any past paper, so learn it fresh.)

Given non-pipelined 60 ns/instruction · k = 6 stages · cycle 12 ns · n = 50
Formula non-pipe = n × time/instruction · pipe = (k + n − 1) × cycle · speedup = non-pipe / pipe
Without pipelining = 50 x 60 = 3000 ns
With pipelining    = (6 + 50 - 1) x 12
                   = 55 x 12
                   = 660 ns      (fill 6x12=72, then 49x12=588)
Speedup            = 3000 / 660 = 4.55
Without pipelining 3000 ns; with pipelining 660 ns; speedup 4.55.

Now redo it: n × per-instruction time without, (k + n − 1) × cycle with, then divide.

Overlapping is not free: sometimes two instructions in the pipe clash, and a clash is called a hazard. There are three kinds, and you must be able to name them. The first is the structural hazard, where two instructions need the same piece of hardware in the same cycle (one memory wanted for a fetch and a data access at once). How do you remove a structural hazard?

duplicate the resource (for example, separate instruction and data memories, so each instruction has its own). The second kind is the data hazard: an instruction needs a result that an earlier instruction has not written yet. We name its three types by the order in which two instructions touch the same register. Read on.

RAW (read after write) is the true dependency: the second instruction reads a register the first has not written yet. It is eased by forwarding, which feeds the result straight from where it is produced to where it is needed, before the write-back stage. Which of the three data hazards is the real dependency?

RAW. The other two, WAR (write after read) and WAW (write after write), are only naming clashes over the same register, not true data flow. Read on.

When forwarding cannot deliver the value in time, the pipeline must stall: it inserts a bubble, an idle cycle, until the value is ready. What is the idle cycle a stall inserts called?

a bubble. The third kind is the control hazard: a branch changes which instruction runs next, but the pipe has already fetched the ones right after the branch. It is eased by branch prediction and speculative execution, whose whole purpose is to reduce control-hazard stalls. Read on.

Now classify one pair. The first instruction writes R3, and the second instruction reads R3. The shared register is R3, and the order is write then read. Which data hazard is that?

RAW (write then read is exactly read-after-write). That is every hazard idea in place. The box just below shows how to draw the pipeline timing diagram the paper sometimes asks for; after it, sit the two "your turn" boxes with the answers covered.

TeachHow to draw the timing (cycle) diagram

The paper sometimes says "draw the pipeline timing diagram" or "draw the cycle diagram". It is always the same grid, and you draw it the same way every time:

  • Cycles across the top (1, 2, 3, ...), one instruction per row down the side.
  • In each cell write the stage that instruction is in that cycle: IF, ID, EX, (MEM), WB. Some papers add an operand fetch (OF) stage between ID and EX; use whatever stages the question names.
  • Each instruction begins its IF one cycle after the instruction above it.
  • A multi-cycle execute (say a 3-cycle multiply or a 6-cycle divide) writes EX in that many cells in a row, and everything behind it slides right.
  • A stall (waiting for a hazard to clear, or for a busy stage) is a gap you mark with a bubble, written --.

The total number of cycles is simply the column where the last instruction reaches WB. That is your answer to "how many cycles".

How to remember it: "cycles across, instructions down, stages in the boxes, count to the last WB." A long EX pushes; a stall is a --. (You will draw exactly this for Question Two and Question Three in the final mock.)

Your turnclassify the hazards

Find the one register on both lines and read its order. (i) R3 ← R1 op R2, then R5 ← R3 op R4. (ii) R3 ← R1 op R2, then R1 ← R4 op R5. (iii) R3 ← R1 op R2, then R3 ← R6 op R7.

Answer

(i) R3 is written then read, so RAW. (ii) R1 is read then written, so WAR. (iii) R3 is written then written, so WAW. Only RAW is a real data dependency; the other two are naming clashes.

Your turnMCQ, pipelining

(1) The main objective of branch prediction and speculative execution is to? (2) A read-after-write clash is eased by which technique?

Answer

(1) reduce pipeline stalls caused by control hazards (keep the pipe full across branches). (2) forwarding (feed the result straight to where it is needed).

Trap

The clock runs at the slowest stage plus latch, not the average or the sum. For n tasks the count is k + n − 1, so 500 tasks in a 4-stage pipe is 503 cycles, not 504. Classify data hazards by the shared register and the order it is written and read, never by the instruction name.

Lock it in

"Clock = the slowest stage + latch. For n tasks it is (k + n − 1) cycles."

Speedup tops out at k stages. Name a data hazard by the register order: RAW (read after write, the real one, eased by forwarding), WAR, WAW. A long execute pushes everything behind it; a stall is a bubble.
