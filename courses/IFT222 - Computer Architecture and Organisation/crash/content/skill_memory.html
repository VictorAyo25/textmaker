Memory and Cache

The memory hierarchy carries the largest single block of objective questions, and cache mapping is the most examined calculation on the whole course. It looks fiddly, so we do it as a programme: many tiny steps, and you check each one before moving on. By the end the cache split will be the same four moves every time.

Memory is arranged in levels, fastest to slowest: registers, then cache, then main memory, then secondary storage (disk or SSD). Of those four, which is the fastest?

registers. Picture it as your workspace: the few things in your hands (registers), the book open on your desk (cache), the shelf beside you (main memory), and the library across campus (disk). You keep what you use most closest, because reaching further costs time. As you climb toward registers, does memory get cheaper or dearer per bit?

dearer. Climbing up, memory gets faster, smaller, and more expensive per bit. The reason there are levels at all is a trade-off: you cannot have fast, big and cheap at once. So which level has the highest cost per bit?

registers. Now the two kinds of RAM. SRAM (static RAM) is built from flip-flops: fast, needs no refresh, but costly and low density. Given it is fast but costly, which level is SRAM used for?

cache. DRAM (dynamic RAM) is built from capacitors: dense and cheap, but slower and it needs periodic refresh, so it is used for main memory. (ROM and Flash are non-volatile; RAM, cache and DRAM are volatile, lost on power off.) Which kind of RAM has to be refreshed?

DRAM. Two facts the MCQs love: the MAR (memory address register) holds the address being accessed; and access time is how long one access takes, while cycle time is the minimum gap between the starts of two accesses. A device with 60 ns access and 90 ns cycle can start a new access how often?

every 90 ns (the cycle time, not the access time). Now, why does a small nearby cache help at all? Because programs are predictable, a habit called locality of reference. It comes in two kinds. Read on.

Temporal locality: a location used now is likely used again soon (think of a loop counter, read over and over). Reusing the same location again soon is which locality?

temporal. Spatial locality: once a location is used, nearby ones are likely used next (stepping through an array). That is exactly why the cache copies a whole block at a time, not one lonely byte. Read on.

Two limits to know by name. The memory wall is the widening gap between fast CPUs and slow memory, which is why a processor can still wait on data despite a big cache. Virtual memory lets a program use an address space larger than the physical RAM, with a memory management unit (MMU) translating the addresses. Read on.

Now the cache sum itself, gently. Picture the cache as a wall of numbered hooks (the lines), each big enough to hold one block, a short run of consecutive bytes copied from memory together. Far more blocks exist in memory than there are hooks, so many blocks compete for the same hook. Read on.

When the CPU names an address, that address answers three questions, and that is exactly why it splits into three fields. The first, from the low bits, is the offset. Which one thing does the offset pick out: which byte in the block, which hook, or which block?

which byte inside the block. The middle bits are the index (or set): which hook the block hangs on. The high bits are the tag: which of the many blocks sharing that hook is actually here, stored beside the block and compared on every access. A tag that matches means what?

a hit (no match is a miss). Now the sizes, in order. Address bits = log2(main memory size). Offset = log2(block size). A 16-byte block needs how many offset bits?

4 (log216 = 4). Number of lines = cache size / block size. Index bits (direct mapped) = log2(lines). A direct-mapped cache with 64 lines needs how many index bits?

6 (log264 = 6). For a k-way set associative cache, sets = lines / k and set bits = log2(sets); fully associative has no index at all (any block on any hook). Whatever is left over is the tag: tag bits = address bits − index (or set) − offset. The tag directory = lines × tag bits. Read on.

Last, the average memory access time (AMAT), with hit ratio h, cache time Tc and memory time Tm. Hierarchical (cache first): AMAT = Tc + (1 − h) × Tm. Simultaneous (both at once): AMAT = h × Tc + (1 − h) × Tm. Read on.

Done. That is the whole method: address bits from the memory, offset from the block, lines from cache over block, tag is whatever is left, then the tag directory and AMAT. Now watch it on real numbers in the three worked examples below, then drill the six extra caches with a card over each row.

Worked examplethe cache slides' standard case

Main memory 64 KB, cache 1 KB, block 16 B, direct mapped. Find the address split and the tag-directory size.

Address = log2(64 KB) = log2(2¹⁶)     = 16 bits
Offset  = log2(16)                     = 4 bits
Lines   = cache/block = 1024/16 = 64
Index   = log2(64)                     = 6 bits
Tag     = 16 - 6 - 4                   = 6 bits
Tag dir = lines x tag = 64 x 6 = 384 bits = 48 bytes
Offset 4, index 6, tag 6; tag directory 384 bits (48 bytes).

Now redo it: address from the memory size, offset from the block, lines from cache over block, and the tag is whatever is left. This works for any numbers.

Your turnMCQ, memory

(1) Order fastest to slowest: registers, cache, main memory, secondary. (2) SRAM versus DRAM in one line? (3) Reusing the same location soon is which locality? (4) A program using more address space than physical RAM uses what? (5) Which memory has the highest cost per bit?

Answer

(1) registers, cache, main memory, secondary. (2) SRAM = flip-flops, fast, no refresh; DRAM = capacitors, dense, needs refresh. (3) temporal (nearby locations would be spatial). (4) virtual memory. (5) registers.

Trap

Keep the units straight: offset comes from the block size, lines from cache over block. For set associative, divide lines by the ways to get sets before taking the log, and the bits you save on the index move into the tag. Temporal locality is "same place, later"; spatial is "nearby places".
