The Machine

Memory and Cache

The memory hierarchy carries the largest single block of objective questions, and cache mapping is the most examined calculation on the whole course. It looks fiddly, but once you see what the cache is actually doing it is the same four steps every time. Two teach boxes of facts, then one method for the cache sums.

TeachThe hierarchy, and the memory types

Memory is arranged in levels. From fastest to slowest: registers → cache → main memory → secondary storage (disk, SSD). Think of it like your workspace: the few things in your hands (registers), the book open on your desk (cache), the shelf beside you (main memory), and the library across campus (disk). You keep what you use most closest, because reaching further costs time. Going up, memory gets faster, smaller, and more expensive per bit; registers are the fastest and the highest cost per bit. The reason there are levels at all is a trade-off: you cannot have fast, big and cheap at once.

  • SRAM (static RAM) uses flip-flops: fast, no refresh, but costly and low density, so it is used for cache.
  • DRAM (dynamic RAM) uses capacitors: dense and cheap but slower and needs periodic refresh, so it is used for main memory.
  • ROM is non-volatile and holds firmware permanently. Flash is also non-volatile. RAM, cache and DRAM are all volatile (lost on power off).

Two more facts the MCQs love: the memory address register (MAR) holds the address currently being accessed; and access time is how long one access takes, while cycle time is the minimum gap between the starts of two accesses, so a device with 60 ns access and 90 ns cycle can start a new access only every 90 ns.

TeachLocality, the memory wall, virtual memory

Why does keeping a small nearby cache help at all? Because programs are predictable in two ways, together called locality of reference:

  • Temporal locality: a location used now is likely used again soon (reusing the same instruction or variable, for example a loop counter).
  • Spatial locality: once a location is used, nearby locations are likely used next (stepping through an array). This is why the cache copies a whole block at a time, not one byte.

Even so, cache cannot fix everything: the growing gap between fast CPUs and slow memory is the memory wall, and it is why a processor can still wait on data despite a big cache. Virtual memory lets a program use an address space larger than the physical RAM, with a memory management unit (MMU) translating addresses.

Must doCache: the address split, in five steps

Picture the cache as a wall of numbered hooks (the lines), each big enough to hold one block, a short run of consecutive bytes copied from memory together. Far more blocks exist in memory than there are hooks, so many blocks compete for the same hook. When the CPU names an address, the address itself answers three questions, and that is exactly why it splits into three fields:

  • Offset (the low bits): which byte inside the block?
  • Index or set (the middle bits): which hook does this block hang on?
  • Tag (the high bits): which of the many blocks that share this hook is actually hanging here? The tag is stored beside the block and compared on every access; a match is a hit, no match is a miss.

So the sizes fall out in this order:

  • Address bits = log2(main memory size).
  • Offset = log2(block size). It picks the byte inside a block.
  • Number of lines = cache size / block size.
  • Index bits (direct) = log2(lines). For a k-way set associative cache, sets = lines / k and set bits = log2(sets). Fully associative has no index at all (any block may hang on any hook).
  • Tag bits = address bits − index (or set) bits − offset bits. The tag directory is lines × tag bits.

And the average memory access time (AMAT), with hit ratio h, cache time Tc, memory time Tm:

Hierarchical (cache first): AMAT = Tc + (1 − h) × Tm.   Simultaneous (both at once): AMAT = h × Tc + (1 − h) × Tm.
Worked examplethe cache slides' standard case

Main memory 64 KB, cache 1 KB, block 16 B, direct mapped. Find the address split and the tag-directory size.

Address = log2(64 KB) = log2(2¹⁶)     = 16 bits
Offset  = log2(16)                     = 4 bits
Lines   = cache/block = 1024/16 = 64
Index   = log2(64)                     = 6 bits
Tag     = 16 - 6 - 4                   = 6 bits
Tag dir = lines x tag = 64 x 6 = 384 bits = 48 bytes
Offset 4, index 6, tag 6; tag directory 384 bits (48 bytes).

Now redo it: address from the memory size, offset from the block, lines from cache over block, and the tag is whatever is left. This works for any numbers.

Worked exampleaverage access time

Hit rate 80%, cache time 5 ns, memory time 100 ns. Find the AMAT both ways.

Simultaneous = h.Tc + (1-h).Tm = 0.8x5 + 0.2x100 = 4 + 20 = 24 ns
Hierarchical =   Tc + (1-h).Tm =    5 + 0.2x100 = 5 + 20 = 25 ns
Simultaneous 24 ns, hierarchical 25 ns. Hierarchical pays the cache time on every access, so it is a touch slower here.

Your turnMCQ, memory

(1) Order fastest to slowest: registers, cache, main memory, secondary. (2) SRAM versus DRAM in one line? (3) Reusing the same location soon is which locality? (4) A program using more address space than physical RAM uses what? (5) Which memory has the highest cost per bit?

Answer

(1) registers, cache, main memory, secondary. (2) SRAM = flip-flops, fast, no refresh; DRAM = capacitors, dense, needs refresh. (3) temporal (nearby locations would be spatial). (4) virtual memory. (5) registers.

Trap

Keep the units straight: offset comes from the block size, lines from cache over block. For set associative, divide lines by the ways to get sets before taking the log, and the bits you save on the index move into the tag. Temporal locality is "same place, later"; spatial is "nearby places".
