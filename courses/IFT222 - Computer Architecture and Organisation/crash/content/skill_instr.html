Instruction Sets and Formats

What a machine instruction is, the kinds there are, and the four "address" formats the paper asks you to write a program in. Plus the counting question the objective test likes.

Cover the page just below the first line with a card or your hand. Read a frame, do the small task, then slide the card down to the next line to check your answer. One step at a time, and do not skip.

A machine instruction is one small command for the CPU. It always names an operation to carry out, for example ADD. The part that says which operation is called the opcode. Name the part of an instruction that says which operation to do.

the opcode. Sitting beside the opcode are zero or more operands: the things the operation works on. In ADD A, B the opcode is ADD, and A and B are the operands. (Each operand also carries an addressing mode saying where it is; that is the next section.) In ADD A, B, what are A and B called?

the operands. Opcode and operands are just bit fields packed side by side. The fixed layout of those fields is the instruction format. What word means the layout of the bit fields in an instruction?

the format (the instruction format). And the whole collection of instructions one CPU understands is called its instruction set. That is the vocabulary. Now the kinds of instructions. Read on.

There are four main types. First, data transfer: LOAD, STORE, MOVE. These move data between registers and memory, and a LOAD in particular reads from memory into the CPU. Does LOAD read from memory, or write to it?

reads from memory. Second, arithmetic and logic: ADD, SUB, AND, OR. This is the ALU's work. Third, input/output: talk to devices. Which unit does the ADD and AND work?

the ALU. Fourth, and the one the exam cares about, control transfer: JUMP, BRANCH, CALL. Normally instructions run one after another in order; these change that order. Which type changes the order instructions run in?

control transfer. Now the four address formats. This is only a count: how many operand addresses each instruction names. We go from most to fewest. Read on.

Three-address names both sources and the destination in one instruction, e.g. ADD X, A, B meaning X = A + B. Because each instruction does so much, you need the fewest of them. How many addresses does ADD X, A, B name?

three. Two-address drops the separate destination; the destination doubles as one source, e.g. ADD A, B means A = A + B. After ADD A, B, where has the result gone?

into A. One-address works through a single register called the accumulator: LOAD a value in, do the operation, then STORE the result out. Only one address is named each time. Read on.

Zero-address names no address at all. It is a stack machine: you PUSH operands onto the stack, and ADD simply pops the top two and pushes their sum. Which of the four formats is the stack machine?

zero-address. Now the trade-off across all four. Fewer addresses means each instruction is shorter, but you need more of them. Which format gives the shortest program (fewest instructions)?

three-address. And the other end: zero-address gives the longest program (most instructions), though each one is tiny. You will write one expression in all four formats in the worked example below. Read on.

Now the counting question the objective test likes. To size a program in bytes, count each instruction and add up, using: bytes per instruction = opcode bytes + (number of addresses × bytes per address). Read on.

A single instruction's total length is just its fields added together. Take an 8-bit opcode, a 6-bit register field and an 18-bit address field. Add them; what is the total length in bits?

32 bits. (8 + 6 + 18 = 32.) When every instruction is the same size it is called fixed-length; these decode faster and are used by RISC. Variable-length instructions are used by CISC. Which style, fixed or variable, is faster to decode?

fixed-length. Last one: to fit more opcodes into the same instruction length, you give the opcode more bits (and the operands fewer). That is every idea here. Now watch one expression written in all four formats in the worked example below, then sit the recall with the answer covered.

A single instruction's total length is its fields added: an 8-bit opcode + a 6-bit register field + an 18-bit address field = 32 bits. Fixed-length (all one size) decodes faster and is used by RISC; variable-length by CISC. More opcodes in the same length means giving the opcode more bits.

Worked examplewrite X = (A + B) × (C + D)

The same expression in each format. Watch the instruction count climb as the number of addresses drops.

Three-address (shortest, 3 instructions):

ADD  T, A, B      ; T = A + B
ADD  X, C, D      ; X = C + D
MUL  X, T, X      ; X = T * X

Two-address (destination is also a source):

MOV  T, A
ADD  T, B         ; T = A + B
MOV  X, C
ADD  X, D         ; X = C + D
MUL  X, T         ; X = X * T

One-address (one accumulator, AC):

LOAD  A
ADD   B           ; AC = A + B
STORE T
LOAD  C
ADD   D           ; AC = C + D
MUL   T           ; AC = AC * T
STORE X

Zero-address (stack, most instructions but each is tiny):

PUSH A   PUSH B   ADD      ; A + B on the stack
PUSH C   PUSH D   ADD      ; C + D on the stack
MUL                       ; (A+B) * (C+D)
POP  X

The bigger version, X = ((A×B) + C/D) / (F×G + J×K), is Question 4b on the 2025/2026 paper and is in your final mock at the back.

Your turnMCQ, instructions

(1) Which format is used by stack machines? (2) Which instruction category changes the program's execution sequence? (3) An instruction has an 8-bit opcode, a 6-bit register field and an 18-bit address field: total length? (4) Which is NOT defined by the ISA: addressing modes, instruction formats, internal ALU implementation, or visible registers?

Answer

(1) zero-address (operands on the stack top). (2) control transfer (branch/jump/call). (3) 8 + 6 + 18 = 32 bits. (4) internal ALU implementation (that is organization, not the programmer-visible ISA).

Trap

"Zero-address" goes with the stack and operands on top of the stack; do not mix it up with three-address (the shortest program). And the ISA defines what the programmer sees (formats, modes, registers), never how the ALU is wired inside.
