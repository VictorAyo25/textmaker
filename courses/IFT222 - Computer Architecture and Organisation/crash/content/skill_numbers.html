Number Systems and Conversions

Everything a computer holds is binary. This skill is turning numbers between binary, decimal and hexadecimal without thinking, plus the special decimal codes, and it is easy marks. We build it as a programme: many tiny steps worked through one at a time, and you check each one before the next. Go slowly and it will soon feel automatic.

Work it frame by framecover, work, then slide down to check

Cover the page just below the first line with a card or your hand. Read a frame, do the small task, then slide the card down to the next line to check your answer. One step at a time, and do not skip.

A base just means how many symbols you count with before you start a new column. Decimal is base 10: the ten symbols 0 to 9. A computer wire is only ever on or off. So how many symbols does binary have?

2, just 0 and 1 (on or off), which is base 2. Binary is correct but gets very long, so we bundle it up as hexadecimal, base 16, whose symbols run 0 to 9 and then A, B, C, D, E, F. A is the first letter-symbol; what decimal value does the hex digit A stand for?

10. Then B = 11, C = 12, D = 13, E = 14, F = 15. Next, place value: reading a number from right to left, the columns are worth base0 = 1, then base1, then base2, and so on. In hex, what is the place value of the third column from the right?

162 = 256. So the hex columns are 1, 16, 256, 4096. Three size words before we convert: one binary digit is a bit, four bits are a nibble, and eight bits are a byte. How many bits are in a byte?

8 (and four bits are a nibble). Now the first conversion. To turn any base into decimal, multiply each digit by its place value and add the results. Take the hex number 2F: its columns are 16 and 1, and F = 15. Work out 2×16 + 15.

47, so hex 2F = 47. That is every base-to-decimal question. The reverse, decimal to any base, divides repeatedly by the base, jots each remainder, and reads the remainders bottom to top. For 13 to binary: 13÷2 = 6 r 1, 6÷2 = 3 r 0, 3÷2 = 1 r 1, 1÷2 = 0 r 1. Read the four remainders from the bottom up.

1101. Let us prove it rather than trust it. The binary columns are 8, 4, 2, 1, and 1101 has 1-bits in the 8, 4 and 1 columns. Add 8 + 4 + 1; do you land back on 13?

yes, 8 + 4 + 1 = 13. The conversion checks out. Now binary to hex. Because 16 = 24, one hex digit is exactly four bits, so group the bits into fours from the right and turn each four into one hex digit. Take 1101 0110: the right group 0110 = 4+2 = 6. What hex digit is the left group 1101?

D (that is 8+4+1 = 13). So 1101 0110 = D6, and going the other way you simply expand each hex digit back into its four bits. Read on.

A few powers of two must be instant. 210 = 1024, which we call "1 K"; then 220 = 1 M and 230 = 1 G. How many bytes is 210, and what one-letter name do we give it?

1024 bytes, called 1 K. Every memory and cache question leans on these. Now the special decimal codes, where each decimal digit is kept on its own. First is BCD. Read on.

BCD (binary coded decimal), the 8421 code, writes each decimal digit as its own 4 bits. So 59 becomes 5 = 0101 and 9 = 1001, written 0101 1001. It is a weighted code (the bit positions are worth 8, 4, 2, 1). Write the single digit 7 in BCD.

0111 (4+2+1 = 7). BCD is just the digit in plain 4-bit binary. The next code, Excess-3, takes the digit, adds 3, then writes the result in 4 bits. So 9 becomes 9+3 = 12 = 1100. Write the digit 6 in Excess-3.

1001 (6+3 = 9 = 1001); to decode you subtract 3. Excess-3 is non-weighted (its bits carry no fixed weight) and self-complementing. Read on.

Last, the character codes, which store text and not numbers. ASCII encodes English letters, digits and symbols in 7 or 8 bits; Unicode was introduced to cover the characters of all the world's languages. Which of the two would you need for Chinese or Arabic letters?

Unicode (it covers every language). That is every fact in this skill. Now watch the moves used together in the two worked examples below, then sit the recalls with the answers covered.

Must doThe three conversions, and powers of two
  • Any base to decimal: multiply each digit by its place value and add. In hex the places are 1, 16, 256, 4096.
  • Decimal to any base: divide repeatedly by the base, write down each remainder, then read the remainders bottom to top.
  • Binary to hex: group the bits into fours from the right, turn each group of four into one hex digit. Hex to binary is the reverse: each hex digit becomes four bits. This works because 16 = 24, so one hex digit is exactly four bits.

Worked examplehex to decimal

Convert the hex number 7D3A to decimal.

place:   4096   256    16     1
digit:      7    13(D)   3    10(A)
         ----   ----   ---   ---
   7 x 4096  = 28 672
  13 x  256  =  3 328
   3 x   16  =     48
  10 x    1  =     10
             --------
               32 058
7D3A = 28 672 + 3328 + 48 + 10 = 32 058

Now redo it: the only hard part is remembering 4096, 256, 16, 1. Write those four first, then multiply.

Worked examplebinary to hex

Convert binary 11010110 to hex.

  1. Group in fours from the right: 1101  0110.
  2. Each group of four to one hex digit: 1101 = 8+4+1 = 13 = D; 0110 = 4+2 = 6.
  3. Write them in order: D6.
11010110 = 1101 0110 = D6 (check: both equal 214)

Now redo it: go backwards too. 2A7F to binary is 2=0010, A=1010, 7=0111, F=1111, giving 0010101001111111.

Your turnconvert three

(1) Write decimal 255 in hex. (2) How many hex digits does a 20-bit binary number need? (3) A hex value shifted right by one bit is the same as which operation?

Answer

(1) 255 = 15×16 + 15 = FF. (2) 20 ÷ 4 = 5 hex digits (one hex digit per four bits). (3) shifting right one bit is dividing by 2 (left one bit is times 2).

Your turnMCQ, the codes

(1) The Excess-3 code for decimal 9 is? (2) The Excess-3 code 0110 is which decimal digit? (3) The 8421 BCD of decimal 59 is?

Answer

(1) 9 + 3 = 12 = 1100. (2) 0110 = 6, minus 3 = 3. (3) 5 = 0101, 9 = 1001, so 01011001. Remember: BCD is the digit itself in 4 bits; Excess-3 is the digit plus 3.

Trap

Group binary into fours from the right, never the left, and pad the leftmost group with leading zeros if it is short. And do not confuse the codes: BCD is weighted (8421) and is just the digit in binary; Excess-3 is non-weighted and is the digit plus 3. "BCD" stands for binary coded decimal, nothing else.
