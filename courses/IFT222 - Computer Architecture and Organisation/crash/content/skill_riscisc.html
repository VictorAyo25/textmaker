RISC, CISC and the Rest

Two design philosophies, plus the loose theory ideas the objective test dips into. Mostly describing and comparing, so we do it as a short programme: one small contrast at a time, then check. Get the contrasts clean and these are fast, reliable marks.

An instruction set can be designed with two opposite philosophies. The first is CISC (complex instruction set computer): many, powerful, variable-length instructions, some doing a lot of work each (even direct memory-to-memory operations). Does CISC have few or many instructions?

many. Because each instruction does so much, CISC programs are short, but the hardware is complex, instructions take several cycles, and it is harder to pipeline. Its instructions can resemble high-level language constructs, which eases the compiler. It suited the old days of slow, expensive memory. Read on.

The opposite is RISC (reduced instruction set computer): few, simple, fixed-length instructions, each ideally one cycle. Are RISC instructions fixed-length or variable-length?

fixed-length. RISC touches memory only through load and store (a load-store design), keeps many registers, and uses hardwired control. Programs are longer, but the hardware is simple, fast, and pipelines cleanly. It minimises chip area and power and leans on the compiler. So which philosophy pipelines more easily, RISC or CISC?

RISC (simple fixed-length instructions flow through the pipeline cleanly). One quick sort for the exam: variable-length instruction formats go with RISC or CISC?

CISC (RISC is fixed-length). The card just below lays the two side by side. Examples to recognise: RISC is ARM, MIPS, SPARC, PowerPC; CISC is Intel x86, VAX, the Motorola 68000. Read on to the loose ideas the MCQs also test.

SIMD (single instruction, multiple data): one instruction acts on many data items at once, to speed up data-parallel work like graphics and matrices. Why does SIMD exist?

to accelerate data-parallel computations. Domain-specific architecture: a processor tailored to one job (say the matrix work in AI) can be far more efficient than a general-purpose one for that job. Read on.

Abstraction: layering the design, with the ISA as the key layer, lets the hardware and software teams work independently while staying compatible. Read on.

Backward compatibility: keeping a stable ISA while the organization underneath evolves is what lets twenty-year-old software still run on new chips. What one thing gives backward compatibility across processor generations?

a stable ISA (with the organization evolving underneath). Last one, a wording the test likes: architecture versus engineering. Computer architecture is the conceptual, operational design; computer engineering is the broader design, build and integration of the hardware. Read on.

Your turnMCQ, RISC/CISC and friends

(1) Variable-length instructions go with RISC or CISC? (2) A chip that minimises area and power and leans on the compiler follows which philosophy? (3) Why does SIMD exist? (4) What gives backward compatibility across processor generations?

Answer

(1) CISC (RISC is fixed-length). (2) RISC. (3) to accelerate data-parallel computations. (4) a stable ISA while the organization evolves underneath.
