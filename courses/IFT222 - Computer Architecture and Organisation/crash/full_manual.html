How to pass this in a weekend

You have not read this course and the exam is on Tuesday. That is fine. This book is built for exactly that. It ignores everything the exam will not ask and teaches you, from zero, the dozen skills that answer every question. Do what it says and you will walk in ready.

TeachThe one idea behind this book

Computer Architecture looks huge but the exam is small. It reuses about a dozen ideas, over and over, with the numbers changed. So this book does not try to cover the syllabus. It works backwards from the exam: it takes the real questions as the target, then teaches every skill you need to reach them, starting from nothing. Each skill is taught so you understand why it works, not just what to write, which is the only way to stay safe when the examiner changes the numbers on you.

Must doThe habit that passes the exam

Reading feels like studying and teaches you almost nothing. What puts a skill into your hands is doing it with the answer covered. So all through this book you will meet two things, and you must actually use them:

  • A Your turn box: a question with new numbers and the answer hidden under a dashed line. Cover it, work it on paper, then check. This is where the learning happens.
  • After a worked example, Now redo it: close the book and reproduce the whole solution on blank paper. If you can do that, you own the skill.

The rule: never move on from a skill until you can do its Your-turn box cold, from memory, with different numbers. That single habit is the difference between a pass and a blank page.

Foundations and Data

The Big Picture

Before any sums, the shape of the whole thing. Half the objective questions live right here: what a computer is made of, and the one distinction the examiner asks in a dozen disguises, architecture versus organization.

TeachWhat a computer is

A computer runs a program by repeating three steps forever: fetch an instruction from memory, decode it (work out what it means), and execute it. This is the fetch, decode, execute cycle. The big idea, called the stored-program or Von Neumann concept, is that the program and the data live together in the same memory, both just binary numbers. That is what makes a computer general: change the numbers in memory and it does a different job.

TeachThe parts inside

The CPU (central processing unit, the processor) has two working parts and a handful of tiny fast stores called registers:

  • The control unit (CU) is the conductor: it fetches each instruction and sends out the control signals that make everything else act at the right moment.
  • The arithmetic and logic unit (ALU) does the actual work: add, subtract, AND, OR, compare.
  • Registers hold what the CPU is using right now. Learn four by name: the program counter (PC) holds the address of the next instruction; the instruction register (IR) holds the instruction being executed; the memory address register (MAR) holds the address the CPU is about to read or write; the memory data register (MDR) holds the data going to or coming from memory.

Everything talks over three buses (shared wires): the address bus carries which location is wanted, the data bus carries the value itself, and the control bus carries the signals that say read or write and when.

TeachThe one distinction they love: architecture vs organization

This is the most asked idea on the objective test. Learn it once, cleanly.

  • Computer architecture is what the machine does, as the programmer sees it. It answers "what does the computer do?" It is the instruction set architecture (ISA): the instructions available, the data types, the addressing modes, the registers a program can name, the instruction formats. If a programmer can see it or use it, it is architecture.
  • Computer organization is how the machine is built to do it. It answers "how does it do it?" It is the hidden hardware: the control signals, the buses, the memory technology used, the cache, how many execution units there are. The programmer never sees it directly; it decides how fast and how efficiently the job gets done.

The clean test: can a program see it or name it? Then it is architecture. Is it an implementation choice hidden inside? Then it is organization. Two chips with the same ISA run the same programs (binary compatible) but can differ wildly in speed, because their organization differs. The deeper hardware realisation of an ISA is also called the microarchitecture: same ISA, different microarchitecture, different performance. (There are two whole ISA styles, the reduced instruction set computer and the complex instruction set computer, RISC and CISC; they are compared in Part C.)

Must doSort it: architecture or organization

Memorise these two lists. Most arch-vs-org MCQs are just "which side is this?"

Memory hook: architecture is the blueprint (the design); organization is the construction (how it is actually built). Same blueprint, two builders, two costs and two speeds.

TeachVon Neumann vs Harvard, and how to draw each

Two ways to wire memory to the CPU. The distinction the examiner wants is whether instructions and data share one memory or sit in two separate ones:

  • Von Neumann: one memory and one bus for both instructions and data. Simple and cheap, but the shared path is a bottleneck (you cannot fetch an instruction and read data at the very same moment).
  • Harvard: separate memories and buses for instructions and data. More hardware (the address, data and control lines are duplicated), but it can fetch an instruction and read data at the same time, a form of parallelism, and that is its whole advantage.

How to draw each (the paper asks for a diagram, so practise it): draw the CPU as one box. For Von Neumann, join it by a single line, the shared bus, to one Memory box holding instructions and data together. For Harvard, draw two memory boxes, an instruction memory and a data memory, and join each to the CPU by its own bus.

How to remember it: Von Neumann = one box, one bus. Harvard = two boxes, two buses; picture the two upright strokes of the letter H as the two separate memories.

Your turnsort five things

Label each as architecture (A) or organization (O): (1) the list of addressing modes, (2) the size of the cache, (3) the number of general registers a program can use, (4) the technology the main memory is built from, (5) the control signals the control unit sends.

Answer

1 A (programmer names them), 2 O (hidden size choice), 3 A (programmer-visible), 4 O (implementation), 5 O (hidden). If you can explain why for each, you have this topic.

Your turnMCQ, arch vs org

A bank upgrades its servers to processors with larger caches and faster RAM while keeping the same x86 instruction set. What has primarily changed?   (a) Architecture only   (b) Organization only   (c) Both   (d) Neither

Answer

(b) Organization only. Same instruction set means the architecture is unchanged; larger caches and faster RAM are organization. This exact shape, "same ISA, faster hardware", appears again and again: the answer is always organization.

Your turnMCQ, same ISA

A developer runs the same compiled application on two processors from different manufacturers. This is possible because both implement the same:   (a) Instruction Set Architecture   (b) Microarchitecture   (c) Control unit design   (d) Cache hierarchy

Answer

(a) Instruction Set Architecture. The same binary program runs on both because they share an ISA. Their microarchitecture, control unit and cache may all differ; that is organization, and it only changes speed, not what runs.

Your turnMCQ, Harvard

A processor fetches an instruction while simultaneously reading data from memory. Which architecture makes this possible?   (a) Stack   (b) CISC   (c) Von Neumann   (d) Harvard

Answer

(d) Harvard. Separate instruction and data memories and buses let both happen at once. Von Neumann shares one path, so it cannot.

Trap

When an MCQ says "same instruction set" or "same ISA" but the hardware changed, the change is organization, never architecture. And "which is visible to the programmer?" almost always points to the instruction formats / addressing modes / registers (architecture), not to caches, buses or memory technology (organization).

Foundations and Data

Number Systems and Conversions

Everything a computer holds is binary. This skill is turning numbers between binary, decimal and hexadecimal without thinking, plus the special decimal codes. It is easy marks and a big share of the objective questions.

TeachBases, and place value

A base is just how many symbols you count with before starting a new column. Decimal is base 10 (symbols 0 to 9). Computers use binary, base 2 (0 and 1), because a wire is either on or off. Binary gets long, so we write it in hexadecimal, base 16 (0 to 9 then A to F, where A = 10 up to F = 15). One binary digit is a bit; four bits are a nibble; eight bits are a byte.

In every base, a digit's value is the digit times the place value, and the places are powers of the base: reading right to left they are base0 = 1, then base, then base2, and so on. That one rule reads every base.

Must doThe three conversions, and powers of two
  • Any base to decimal: multiply each digit by its place value and add. In hex the places are 1, 16, 256, 4096.
  • Decimal to any base: divide repeatedly by the base, write down each remainder, then read the remainders bottom to top.
  • Binary to hex: group the bits into fours from the right, turn each group of four into one hex digit. Hex to binary is the reverse: each hex digit becomes four bits. This works because 16 = 24, so one hex digit is exactly four bits.
n012345678910
2n12481632641282565121024

Memory hook: know these powers of two cold; 210 = 1024 = "1 K", then 220 = 1 M, 230 = 1 G. Every cache and memory question needs them.

Your turnconvert three

(1) Write decimal 255 in hex. (2) How many hex digits does a 20-bit binary number need? (3) A hex value shifted right by one bit is the same as which operation?

Answer

(1) 255 = 15×16 + 15 = FF. (2) 20 ÷ 4 = 5 hex digits (one hex digit per four bits). (3) shifting right one bit is dividing by 2 (left one bit is times 2).

TeachDecimal codes: BCD, Excess-3, and characters

Sometimes we keep decimal digits as separate 4-bit codes rather than one binary number. The exam asks about three:

  • BCD (binary coded decimal), the 8421 code: write each decimal digit on its own as 4 bits. So 59 is 5 = 0101 and 9 = 1001, giving 0101 1001. It is a weighted code (the bits are worth 8, 4, 2, 1).
  • Excess-3: take the digit, add 3, then write that in 4 bits. So 9 becomes 9 + 3 = 12 = 1100. To read it back, subtract 3. It is non-weighted (the bits carry no fixed weights) and self-complementing: flipping all four bits gives the Excess-3 of the digit's 9's complement, which makes decimal subtraction easy.
  • Character codes: ASCII encodes English letters, digits and symbols in 7 or 8 bits; Unicode was introduced to cover the characters of all the world's languages. These are how text, not numbers, is stored.
Your turnMCQ, the codes

(1) The Excess-3 code for decimal 9 is? (2) The Excess-3 code 0110 is which decimal digit? (3) The 8421 BCD of decimal 59 is?

Answer

(1) 9 + 3 = 12 = 1100. (2) 0110 = 6, minus 3 = 3. (3) 5 = 0101, 9 = 1001, so 01011001. Remember: BCD is the digit itself in 4 bits; Excess-3 is the digit plus 3.

Trap

Group binary into fours from the right, never the left, and pad the leftmost group with leading zeros if it is short. And do not confuse the codes: BCD is weighted (8421) and is just the digit in binary; Excess-3 is non-weighted and is the digit plus 3. "BCD" stands for binary coded decimal, nothing else.

Signed Numbers

How a computer stores negative numbers. Three schemes, one of which (two's complement) is what real machines use. This is the single most asked numeric topic, on the paper and in the objective test, so learn the moves until they are automatic.

TeachUnsigned first

With n bits and no sign, you can store 0 to 2n − 1. So 8 bits hold 0 to 255, and 10 bits hold 0 to 1023. All patterns are positive; the biggest is all ones.

TeachThree ways to store a sign

The top (leftmost) bit becomes a sign bit: 0 means positive, 1 means negative. The three schemes differ only in how they build a negative:

  • Sign-magnitude: sign bit, then the plain magnitude. So −42 in 8 bits is 1 (negative) then 0101010 (42) = 1010 1010. Simple to read, but arithmetic hardware is slow and messy, and there are two zeros (+0 = 0000 0000 and −0 = 1000 0000).
  • One's complement: to make a number negative, invert every bit of the positive. Adding needs an end-around carry (any carry out of the top is added back into the bottom), and it too has two zeros (+0 = all zeros, −0 = all ones).
  • Two's complement: to make a number negative, invert every bit and add 1. This is what real computers use, because it has one zero and the same adder does subtraction, so the hardware is simpler and faster.
Must doThe two's-complement moves
  • Make a negative: write the positive in n bits, invert all bits, add 1.
  • Read a pattern whose top bit is 1 (so it is negative): invert all bits and add 1 to get the magnitude, then put a minus sign on it. (Example: 1000 0000 in 8 bits inverts to 0111 1111, plus 1 is 1000 0000 = 128, so the value is −128.)
  • Range in n bits: −2n−1 to 2n−1 − 1. For 16 bits that is −32 768 to 32 767.
  • Add two's-complement numbers: just add the bit patterns and throw away any carry off the top. No end-around carry.

Memory hook: one's complement is "flip"; two's complement is "flip and add one". That extra "add one" is what buys the single zero and the simple hardware.

Your turnread three patterns

In 8 bits: (1) what decimal is 1000 0000 in two's complement? (2) what is the two's complement of 0010 1100? (3) what decimal is 1010 1010 in sign-magnitude?

Answer

(1) top bit 1 so negative; invert 0111 1111 + 1 = 1000 0000 = 128, so −128. (2) invert 0010 1100 to 1101 0011, add 1 = 1101 0100. (3) sign bit 1 (negative), magnitude 010 1010 = 42, so −42.

Your turnMCQ, quick facts

(1) How many representations of zero in sign-magnitude? (2) Which scheme needs an end-around carry? (3) The one's-complement pattern 1110 0011 is which decimal? (4) Why is two's complement used?

Answer

(1) two (+0 and −0). (2) one's complement. (3) top bit 1 so negative; invert 1110 0011 to 0001 1100 = 28, so −28. (4) simpler and faster hardware (one zero, and add/subtract share one circuit).

Trap

Reading a negative two's-complement pattern, do not just read the magnitude bits; you must invert and add 1 first. Overflow is when the true result is too big or too small for the range, not division by zero. And the end-around carry belongs to one's complement only; two's complement just discards the top carry.

Floating Point, IEEE 754

How a computer stores numbers with a fractional part and a huge range, like 64.2 or −1240.56. The exam asks it both ways: a decimal to its 32-bit pattern, and a hex pattern back to decimal. One method each, and it is the same three fields every time.

TeachWhy, and the three fields

Floating point exists to hold very large and very small values in a few bits: its strength is range, not exact decimals. A number is stored as three fields, left to right: sign (s), then exponent (E), then mantissa M (also called the fraction).

  • Single precision: 32 bits = 1 sign + 8 exponent + 23 mantissa. It covers roughly 10±38.
  • Double precision: 64 bits = 1 sign + 11 exponent + 52 mantissa. It covers roughly 10±308.

The value is ± 1.M × 2exponent. The leading 1 is always there for a normalised number, so it is not stored (the "hidden 1"). The exponent is stored with a bias added so it can be negative without a sign of its own: bias is 127 for single, 1023 for double.

Must doEncode and decode
  • Decimal to IEEE (single): (1) sign bit from the sign. (2) Convert the magnitude to binary. (3) Normalise to 1.something × 2e by moving the point. (4) Exponent field = e + 127, in 8 bits. (5) Mantissa = the "something" after the point, padded with zeros to 23 bits. (6) Put the 32 bits together and group in fours for hex.
  • IEEE (hex) to decimal: (1) write the 32 bits, split as 1 / 8 / 23. (2) Sign bit gives the sign. (3) Real exponent e = exponent field − 127. (4) Value = ± 1.M in binary × 2e.

Memory hook: "sign, exponent, mantissa", and the exponent is always stored plus the bias, read minus the bias.

Worked examplethe method, vertically

Convert C1400000 (single precision) to decimal. This is the X the exam sets in Question 4a; you will sit it verbatim in the final mock.

Given C1400000h, single precision
Formula value = (−1)sign × 1.M × 2(exp field − 127)
C1400000 = 1 10000010 100 0000...
  sign 1  ->  negative
  exp field 1000 0010 = 130,  e = 130 - 127 = 3
  mantissa 1.100... = 1 + 1/2 = 1.5

Now redo it: exponent field minus 127, then read 1.M as a binary fraction (first bit a half, next a quarter).

Encode +6.0 in single precision. (Hint: 6 in binary is 110; normalise it.)

Your turnMCQ, the facts

(1) How many exponent bits in single precision? (2) The bias in double precision? (3) How many bits is double precision? (4) A floating-point number is stored as which order of fields?

Answer

(1) 8. (2) 1023. (3) 64. (4) sign, then exponent, then mantissa (the exam phrases the answer as "sign, mantissa, exponent", meaning those three parts with the sign first; the true field order on the chip is sign, exponent, mantissa).

Trap

Do not forget the bias: the exponent you compute is e + 127 going in, and field − 127 coming out. And the leading 1 is hidden, so when you read the mantissa put a "1." in front of it. Single precision has range about 10±38; double about 10±308.

Image and Memory Sizing

A small, reliable question: how much memory a picture needs. One formula, a couple of unit facts, and the marks are yours.

TeachBitmap vs vector, and the size formula

A bitmap (raster) image is a grid of pixels; each pixel stores its colour in some bits. A vector image stores shapes as maths (lines, curves), so it scales to any size without losing quality. Photographs are bitmaps (continuous tone); a logo you must blow up to billboard size should be vector.

Colour depth: monochrome (black or white) is 1 bit per pixel; greyscale is often 8 bits; full colour is 24 bits. The memory a bitmap needs is:

bits = width in pixels × height in pixels × bits per pixel;   then bytes = bits ÷ 8

If the size is given in inches at some dpi (dots per inch), first get pixels: pixels across = inches × dpi, same down.

Worked examplethe method, vertically

An image is 17.12 inches by 9.45 inches at 250 dpi, 1 bit per pixel. Find its memory in megabytes. The exam sets exactly this; sit it verbatim in the final mock.

Given 17.12 in × 9.45 in · 250 dpi · 1 bit per pixel
Formula pixels = inches × dpi (both ways) · bytes = pixels × bits / 8 · MB = bytes / 1024 / 1024
pixels across = 17.12 x 250 = 4280
pixels down   =  9.45 x 250 = 2362.5
total pixels  = 4280 x 2362.5 = 10 111 500
bytes = 10 111 500 / 8 = 1 263 937.5
MB    = 1 263 937.5 / 1024 / 1024 = 1.21 MB
10 111 500 pixels × 1 bit = 1 263 937.5 bytes ≈ 1.21 MB. Say which megabyte you used (1024 twice gives 1.21; a million gives about 1.26).

Now redo it: pixels first, times the bits per pixel, divide by 8, then by 1024 twice.

Your turnMCQ, images

(1) How many bits per pixel for a monochrome bitmap? (2) A logo must be enlarged to billboard size without losing quality: bitmap or vector? (3) Photographs are best represented as?

Answer

(1) 1 bit (two states). (2) vector (scales with no quality loss). (3) bitmap (a photo is a grid of continuous-tone pixels).

The Machine

Instruction Sets and Formats

What a machine instruction is, the kinds there are, and the four "address" formats the paper asks you to write a program in. Plus the counting question the objective test likes.

TeachParts and types of an instruction

An instruction has an opcode (which operation to do) and zero or more operands (what to do it to), with an addressing mode saying where each operand is. The instruction format is just the layout of these bit fields. The whole collection of instructions a processor understands is its instruction set. The main types:

  • Data transfer (LOAD, STORE, MOVE): move data between registers and memory. LOAD reads from memory.
  • Arithmetic and logic (ADD, SUB, AND, OR): the ALU's work, mostly on registers.
  • Control transfer (JUMP, BRANCH, CALL): change the order instructions run in, usually after a compare.
  • Input/output: talk to devices.
TeachThe four address formats

How many operand addresses each instruction names:

  • Three-address: names both sources and the destination, e.g. ADD X, A, B (X = A + B). Fewest instructions for an expression.
  • Two-address: the destination is also a source, e.g. ADD A, B (A = A + B).
  • One-address: works through a single register, the accumulator: LOAD a value in, operate, STORE it out.
  • Zero-address: a stack machine. Operands sit on top of the stack, so operations name no address at all: PUSH values, then ADD takes the top two. Most instructions here, but each is tiny.

The trade-off: fewer addresses means shorter instructions but more of them. Three-address gives the shortest program; zero-address the longest.

Worked examplewrite X = (A + B) × (C + D)

The same expression in each format. Watch the instruction count climb as the number of addresses drops.

Three-address (shortest, 3 instructions):

ADD  T, A, B      ; T = A + B
ADD  X, C, D      ; X = C + D
MUL  X, T, X      ; X = T * X

Two-address (destination is also a source):

MOV  T, A
ADD  T, B         ; T = A + B
MOV  X, C
ADD  X, D         ; X = C + D
MUL  X, T         ; X = X * T

One-address (one accumulator, AC):

LOAD  A
ADD   B           ; AC = A + B
STORE T
LOAD  C
ADD   D           ; AC = C + D
MUL   T           ; AC = AC * T
STORE X

Zero-address (stack, most instructions but each is tiny):

PUSH A   PUSH B   ADD      ; A + B on the stack
PUSH C   PUSH D   ADD      ; C + D on the stack
MUL                       ; (A+B) * (C+D)
POP  X

The bigger version, X = ((A×B) + C/D) / (F×G + J×K), is Question 4b on the 2025/2026 paper and is in your final mock at the back.

TeachCounting bytes, and fixed vs variable length

To size a program, count each instruction's bytes and add up:

bytes per instruction = opcode bytes + (number of addresses × bytes per address)

An instruction's total length is just its fields added: an 8-bit opcode, a 6-bit register field and an 18-bit address field make an 8 + 6 + 18 = 32-bit instruction. Fixed-length instructions (all the same size) are faster to decode and are used by RISC (reduced instruction set computers); variable-length instructions are used by CISC (complex instruction set computers). To fit more opcodes in the same length, give the opcode more bits and the operands fewer. (Both philosophies are covered in Part C.)

Your turnMCQ, instructions

(1) Which format is used by stack machines? (2) Which instruction category changes the program's execution sequence? (3) An instruction has an 8-bit opcode, a 6-bit register field and an 18-bit address field: total length? (4) Which is NOT defined by the ISA: addressing modes, instruction formats, internal ALU implementation, or visible registers?

Answer

(1) zero-address (operands on the stack top). (2) control transfer (branch/jump/call). (3) 8 + 6 + 18 = 32 bits. (4) internal ALU implementation (that is organization, not the programmer-visible ISA).

Trap

"Zero-address" goes with the stack and operands on top of the stack; do not mix it up with three-address (the shortest program). And the ISA defines what the programmer sees (formats, modes, registers), never how the ALU is wired inside.

CPU Performance

How fast a processor runs is a calculation, not a mystery. Two formulas do almost everything: the CPU-time equation and Amdahl's law. This is the most heavily weighted numeric topic on the recent paper.

Must doThe performance formulas

A program's time is how many instructions it runs, times the average cycles each takes, times how long a cycle lasts:

  • CPU time = IC × CPI × T, where IC is the instruction count, CPI is the average cycles per instruction, and T is the clock cycle time. Since T = 1 / clock rate, this is also CPU time = (IC × CPI) / clock rate.
  • Average CPI = Σ (fraction of each type × its cycles), a weighted average. The fractions add to 1.
  • MIPS = clock rate / (CPI × 106), millions of instructions per second.
  • Improvement = (old − new) / old, always measured against the old time.

So performance is not set by clock speed alone: it also depends on the instruction count and the CPI (and behind CPI, the cache, branch prediction and instruction-level parallelism). That is why "judge a processor by clock frequency only" is wrong.

Worked examplethe method, vertically

One million instructions, by addressing mode: Register 40% at 1 cycle, Immediate 20% at 1, Direct 15% at 2, Indirect 10% at 4, Indexed 10% at 3, Relative 5% at 2. Find the average CPI and total cycles; then optimise indirect to 2 cycles and give the improvement. The exam sets exactly this; sit it verbatim in the final mock.

Given IC = 1 000 000 · the share and cycle cost of each mode
Formula CPI = Σ(fraction × cycles) · total = IC × CPI · improvement = (old − new) / old
Avg CPI = 0.40x1 + 0.20x1 + 0.15x2 + 0.10x4 + 0.10x3 + 0.05x2
        = 0.40 + 0.20 + 0.30 + 0.40 + 0.30 + 0.10

Now redo it: weighted average, then recompute with the one changed cost.

Must doAmdahl's law

Amdahl's law: if you speed up only part of a task, the part you did not touch limits the gain. Let f be the fraction of the time spent in the part you improve, and let that part become s times faster. Then the overall speedup is

S = 1 / ( (1 − f) + f / s )

As s grows without limit, the speedup can never beat 1 / (1 − f), because the untouched fraction (1 − f) still takes its full time. Memory hook: the slow part you left alone sets the ceiling, no matter how fast you make the rest.

Worked examplethe method, vertically

A cache is 10 times faster than main memory, and the CPU finds what it needs in cache 85% of the time. Find the overall speedup. The exam sets exactly this; sit it verbatim in the final mock.

Given f = 0.85 (cache hits) · s = 10
Formula S = 1 / ((1 − f) + f/s)
S = 1 / ((1 - 0.85) + 0.85/10)
  = 1 / (0.15 + 0.085)
  = 1 / 0.235
  = 4.26
S = 4.26, far below 10, because the 15% of slow accesses dominate. That is exactly Amdahl's point.

Now redo it: the "10 times faster" is s, not the answer; only the 85% gets divided by s, the other 15% stays at full cost.

Pipelining and Hazards

Overlapping instructions so several are in progress at once, like a laundry that washes one load while drying the last. It speeds the processor up, and the paper asks you to compute that speedup and to name the hazards that get in the way.

TeachThe idea, and the stages

Split each instruction into k stages. A common five are IF (instruction fetch), ID (instruction decode), EX (execute), MEM (memory access) and WB (write back). Without a pipeline one instruction finishes before the next starts. With a pipeline, as soon as an instruction leaves a stage the next enters it, so once the pipe is full one instruction finishes every clock cycle. The clock cycle is set by the slowest stage (plus a tiny latch delay between stages).

Must doThe pipeline sums
  • Cycle time = slowest stage + latch delay.
  • Pipelined time for n tasks = (k + n − 1) × cycle time. (It takes k cycles to fill with the first task, then one more cycle for each of the other n − 1.)
  • Non-pipelined time for n tasks = n × (time for one instruction). One instruction takes the sum of all the stage times, or the given per-instruction time.
  • Speedup = non-pipelined time / pipelined time. Its ceiling is k.

Memory hook: "k + n − 1", and the clock runs at the slowest stage, never the average.

Worked examplethe method, vertically

A pipeline has 4 phases of 60, 50, 90, 80 ns, with a 10 ns latch delay. Find the cycle time, the one-task time, the speedup, and the times for 500 tasks. The exam sets exactly this; sit it verbatim in the final mock.

Given 4 phases 60, 50, 90, 80 ns · latch 10 ns · 500 tasks
Formula cycle = slowest + latch · pipe(n) = (k + n − 1) × cycle · seq(n) = n × Σphases · speedup = Σphases / cycle
Cycle    = max(60,50,90,80) + 10 = 90 + 10 = 100 ns
One task = 60 + 50 + 90 + 80 = 280 ns
Speedup  = 280 / 100 = 2.8
Pipe 500 = (4 + 500 - 1) x 100 = 503 x 100 = 50 300 ns
Seq 500  = 500 x 280 = 140 000 ns
Cycle 100 ns; one task 280 ns; speedup 2.8; 500 tasks pipelined 50 300 ns against sequential 140 000 ns.

TeachThe three hazards

Overlapping can clash. Three kinds of hazard, and you must name them:

  • Structural hazard: two instructions need the same hardware at once (one memory for a fetch and a data access). Fixed by duplicating the resource.
  • Data hazard: an instruction needs a result the one before it has not written yet. The three types, by the order two instructions touch the same register: RAW (read after write, the true dependency, eased by forwarding), WAR (write after read), and WAW (write after write). When forwarding cannot help, the pipeline stalls (a bubble).
  • Control hazard: a branch changes what runs next, but the pipeline already fetched the following instructions. Eased by branch prediction and speculative execution, which exist precisely to reduce control-hazard stalls.
TeachHow to draw the timing (cycle) diagram

The paper sometimes says "draw the pipeline timing diagram" or "draw the cycle diagram". It is always the same grid, and you draw it the same way every time:

  • Cycles across the top (1, 2, 3, ...), one instruction per row down the side.
  • In each cell write the stage that instruction is in that cycle: IF, ID, EX, (MEM), WB. Some papers add an operand fetch (OF) stage between ID and EX; use whatever stages the question names.
  • Each instruction begins its IF one cycle after the instruction above it.
  • A multi-cycle execute (say a 3-cycle multiply or a 6-cycle divide) writes EX in that many cells in a row, and everything behind it slides right.
  • A stall (waiting for a hazard to clear, or for a busy stage) is a gap you mark with a bubble, written --.

The total number of cycles is simply the column where the last instruction reaches WB. That is your answer to "how many cycles".

How to remember it: "cycles across, instructions down, stages in the boxes, count to the last WB." A long EX pushes; a stall is a --. (You will draw exactly this for Question Two and Question Three in the final mock.)

Memory and Cache

The memory hierarchy carries the largest single block of objective questions, and cache mapping is the most examined calculation on the whole course. Two teach boxes of facts, then one method for the cache sums.

TeachThe hierarchy, and the memory types

Memory is arranged in levels. From fastest to slowest: registers → cache → main memory → secondary storage (disk, SSD). Going up, memory gets faster, smaller, and more expensive per bit; registers are the fastest and the highest cost per bit. The reason there are levels at all is a trade-off: you cannot have fast, big and cheap at once.

  • SRAM (static RAM) uses flip-flops: fast, no refresh, but costly and low density, so it is used for cache.
  • DRAM (dynamic RAM) uses capacitors: dense and cheap but slower and needs periodic refresh, so it is used for main memory.
  • ROM is non-volatile and holds firmware permanently. Flash is also non-volatile. RAM, cache and DRAM are all volatile (lost on power off).

Two more facts the MCQs love: the memory address register (MAR) holds the address currently being accessed; and access time is how long one access takes, while cycle time is the minimum gap between the starts of two accesses, so a device with 60 ns access and 90 ns cycle can start a new access only every 90 ns.

TeachLocality, the memory wall, virtual memory

Cache works because of locality of reference:

  • Temporal locality: a location used now is likely used again soon (reusing the same instruction or variable).
  • Spatial locality: once a location is used, nearby locations are likely used next (stepping through an array).

Even so, cache cannot fix everything: the growing gap between fast CPUs and slow memory is the memory wall, and it is why a processor can still wait on data despite a big cache. Virtual memory lets a program use an address space larger than the physical RAM, with a memory management unit (MMU) translating addresses.

Must doCache: the address split, in five steps

Cache is divided into lines the size of a memory block. An address splits into tag, then index (or set), then offset. Work them in this order:

  • Address bits = log2(main memory size).
  • Offset = log2(block size). It picks the byte inside a block.
  • Number of lines = cache size / block size.
  • Index bits (direct) = log2(lines). For a k-way set associative cache, sets = lines / k and set bits = log2(sets). Fully associative has no index at all.
  • Tag bits = address bits − index (or set) bits − offset bits. The tag directory is lines × tag bits.

And the average memory access time (AMAT), with hit ratio h, cache time Tc, memory time Tm:

Hierarchical (cache first): AMAT = Tc + (1 − h) × Tm.   Simultaneous (both at once): AMAT = h × Tc + (1 − h) × Tm.

RISC, CISC and the Rest

Two design philosophies, plus the loose theory ideas the objective test dips into. Mostly describing and comparing, which means fast, reliable marks if you know the contrasts cleanly.

TeachRISC versus CISC

CISC (complex instruction set computer) has many, powerful, variable-length instructions, some doing a lot of work each (including direct memory-to-memory operations). Programs are short but the hardware is complex, instructions take several cycles, and it is harder to pipeline. Its instructions can resemble high-level language constructs, which eases the compiler. It suited the old days of slow, expensive memory.

RISC (reduced instruction set computer) has few, simple, fixed-length instructions, each ideally one cycle, with memory touched only by load and store (a load-store design), many registers, and hardwired control. Programs are longer but the hardware is simple, fast, and pipelines cleanly. It minimises chip area and power and leans on the compiler.

RISCCISC
Few, simple, fixed-length instructionsMany, complex, variable-length
Mostly one cycle each; pipelines wellSeveral cycles; harder to pipeline
Load-store; many registersMemory-to-memory; fewer registers
Complexity handled by the compilerComplexity handled by the hardware

Examples. RISC: ARM, MIPS, SPARC, PowerPC. CISC: Intel x86, VAX, the Motorola 68000.

TeachA few loose ideas the MCQs use
  • SIMD (single instruction, multiple data): one instruction acts on many data items at once, to accelerate data-parallel work (graphics, matrices).
  • Domain-specific architecture: a processor tailored to one job (for example AI matrix work) can be far more efficient than a general one for that job.
  • Abstraction: layering the design (the ISA is the key layer) lets hardware and software teams work independently while staying compatible.
  • Backward compatibility: keeping a stable ISA while the organization underneath evolves is what lets old software still run on new chips.
  • Architecture versus engineering: computer architecture is the conceptual, operational design; computer engineering is the broader design, build and integration of the hardware.

(1) CISC (RISC is fixed-length). (2) RISC. (3) to accelerate data-parallel computations. (4) a stable ISA while the organization evolves underneath.

In the hall25/26 Q1(a)

i) Differentiate computer architecture from computer organization.

Computer architecture is defined as the functional design and logical structure of the computer system as the programmer sees it: the instruction set, the data types, the addressing modes and the register organization. It answers the question "What does the computer do?" and serves as the blueprint for the system.

Computer organization is defined as the operational units and their interconnections that realize (carry out) that architecture: the control signals, the buses, the memory technology used and the cache. It answers the question "How does the computer do it?" A useful likeness: architecture is the building's design, organization is the actual construction of the building.

ii) Compare Von Neumann and Harvard architecture, with a diagram for each.

Von Neumann architecture is defined as a design that uses a single (shared) area of memory, reached over one bus, for both the program instructions and the data those instructions act on. It is simple to build, but the shared path is a bottleneck (an instruction fetch and a data access cannot happen at the same instant).

Harvard architecture is defined as a design that uses separate memories and separate buses for instructions and data, which lets it fetch an instruction and read data at the same time (a form of parallelism), at the cost of duplicating the address, data and control lines.

In the hall25/26 Q5(c)

i) Locality of reference is defined as the tendency of a program to keep accessing the same small set of memory locations over a short period, a consequence of loops and subroutines; it is why a small fast cache can satisfy most accesses.
