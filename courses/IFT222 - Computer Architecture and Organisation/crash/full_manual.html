How to pass this in a weekend

You have not read this course and the exam is on Tuesday. That is fine. This book is built for exactly that. It ignores everything the exam will not ask and teaches you, from zero, the dozen skills that answer every question. Do what it says and you will walk in ready.

TeachThe one idea behind this book

Computer Architecture looks huge but the exam is small. It reuses about a dozen ideas, over and over, with the numbers changed. So this book does not try to cover the syllabus. It works backwards from the exam: it takes the real questions as the target, then teaches every skill you need to reach them, starting from nothing. Each skill is taught so you understand why it works, not just what to write, which is the only way to stay safe when the examiner changes the numbers on you.

Must doThe habit that passes the exam

Reading feels like studying and teaches you almost nothing. What puts a skill into your hands is doing it with the answer covered. So all through this book you will meet two things, and you must actually use them:

  • A Your turn box: a question with new numbers and the answer hidden under a dashed line. Cover it, work it on paper, then check. This is where the learning happens.
  • After a worked example, Now redo it: close the book and reproduce the whole solution on blank paper. If you can do that, you own the skill.

The rule: never move on from a skill until you can do its Your-turn box cold, from memory, with different numbers. That single habit is the difference between a pass and a blank page.

Foundations and Data

The Big Picture

Before any sums, the shape of the whole thing. Half the objective questions live right here: what a computer is made of, and the one distinction the examiner asks in a dozen disguises, architecture versus organization.

Cover the page just below the first line with a card or your hand. Read a frame, do the small task, then slide the card down to the next line to check your answer. One step at a time, and do not skip.

A computer runs a program by repeating three steps forever: it fetches an instruction from memory, decodes it (works out what it means), then executes it, and loops back to do it all again. That never-ending loop is the fetch, decode, execute cycle. Name the three steps, in order.

fetch, decode, execute. Where do those instructions live? In memory, written as plain binary numbers, sitting right beside the data they work on. This one idea, the program and the data together in the same memory, is the stored-program (or Von Neumann) concept. Are the program and the data kept in the same memory, or in two separate ones?

the same memory. That is exactly what makes a computer general: change the numbers in memory and the same machine does a different job. Now look inside the processor, the CPU. Its first working part is the control unit (CU), the conductor: it fetches each instruction and sends out the control signals that make everything act at the right moment. Does the CU itself do the adding and subtracting, yes or no?

no. The adding, subtracting, AND, OR and comparing is the job of the second part, the arithmetic and logic unit (ALU). So keep the two apart: the CU directs, the ALU calculates. Which unit actually works out 7 + 5?

the ALU. The CPU also keeps a few tiny, very fast stores called registers, each holding something it needs right now. The first is the program counter (PC): it holds the address of the next instruction to fetch. What does the PC hold?

the address of the next instruction. Once an instruction has been fetched, it is held in the instruction register (IR) while it is decoded and run. Which register holds the instruction currently being executed?

the IR. Two more registers, both for talking to memory. The memory address register (MAR) holds the address the CPU is about to read from or write to. Does the MAR hold an address, or a value?

an address. Its partner, the memory data register (MDR), holds the data itself going to or coming from memory. So the MAR says which location, and the MDR carries the value there. From memory, name all four registers you have now met.

PC, IR, MAR, MDR. How do these parts reach each other and memory? Over three shared sets of wires called buses. The address bus carries which location is wanted. Which register's contents would travel out on the address bus?

the MAR (the address it is holding). The data bus carries the value itself, and the control bus carries the signals that say read or write, and when. Which of the three buses carries the value itself?

the data bus. Now the idea the examiner asks in a dozen disguises: architecture versus organization. Computer architecture is what the machine does, as the programmer sees it; it answers "what does the computer do?" Does architecture describe what the programmer can see, or the hidden hardware?

what the programmer can see. Concretely, architecture is the instruction set architecture (ISA): the instructions available, the data types, the addressing modes, the registers a program can name, the instruction formats. Rule of thumb: if a program can see it or name it, it is architecture. So is the list of addressing modes architecture?

yes (a program chooses among them, so architecture). Its opposite is computer organization: how the machine is built to do it. It is the hidden hardware, the control signals, the buses, the memory technology, the cache, how many execution units there are; the programmer never sees it, and it decides how fast the job gets done. Architecture answers "what"; organization answers which one-word question?

"how". Here is the clean test: can a program see it or name it? Then architecture. Is it an implementation choice hidden inside? Then organization. Try it on a hard one, the size of the cache. Is cache size architecture or organization?

organization (a hidden build choice; no program names the cache size). Because the ISA is all a program sees, two chips with the same ISA run the same programs (they are binary compatible), yet can differ wildly in speed because their organization differs; that deeper hardware realisation is the microarchitecture. If two chips share an ISA, will one compiled program run on both?

yes. One hook to lock it in for the test: architecture is the blueprint (the design); organization is the construction (how it is actually built). Same blueprint, two builders, two speeds. (There are two whole ISA styles you will meet in Part C: the reduced instruction set computer, RISC, and the complex instruction set computer, CISC.) Two ways to wire memory to the CPU, and the examiner wants the difference. The first you have already met, Von Neumann: one memory and one bus shared by both instructions and data. It is simple and cheap. In a Von Neumann machine, how many memories hold the instructions and the data?

one (shared). That single shared path has a price: the CPU cannot fetch an instruction and read data at the very same moment, they must take turns on the one bus. That traffic jam is the well-known bottleneck. What do we call the slowdown caused by sharing one path?

the bottleneck. The rival design is Harvard: separate memories and separate buses, one set for instructions and another for data. It costs more hardware, since the address, data and control lines are duplicated. How many separate memories does a Harvard machine use?

two. That extra hardware buys one thing: Harvard can fetch an instruction and read data at the same time, a form of parallelism, and that is its whole advantage. Which design, Von Neumann or Harvard, can fetch an instruction and read data at once?

Harvard. So hold the trade in your head: Von Neumann is one memory, cheap but with a shared bottleneck; Harvard is two memories, more hardware but faster because both happen together. Your turnMCQ, arch vs org

A bank upgrades its servers to processors with larger caches and faster RAM while keeping the same x86 instruction set. What has primarily changed?   (a) Architecture only   (b) Organization only   (c) Both   (d) Neither

Answer

(b) Organization only. Same instruction set means the architecture is unchanged; larger caches and faster RAM are organization. This exact shape, "same ISA, faster hardware", appears again and again: the answer is always organization.

Your turnMCQ, same ISA

A developer runs the same compiled application on two processors from different manufacturers. This is possible because both implement the same:   (a) Instruction Set Architecture   (b) Microarchitecture   (c) Control unit design   (d) Cache hierarchy

Answer

(a) Instruction Set Architecture. The same binary program runs on both because they share an ISA. Their microarchitecture, control unit and cache may all differ; that is organization, and it only changes speed, not what runs.

Your turnMCQ, Harvard

A processor fetches an instruction while simultaneously reading data from memory. Which architecture makes this possible?   (a) Stack   (b) CISC   (c) Von Neumann   (d) Harvard

Answer

(d) Harvard. Separate instruction and data memories and buses let both happen at once. Von Neumann shares one path, so it cannot.

Trap

When an MCQ says "same instruction set" or "same ISA" but the hardware changed, the change is organization, never architecture. And "which is visible to the programmer?" almost always points to the instruction formats / addressing modes / registers (architecture), not to caches, buses or memory technology (organization).

"Architecture is the blueprint, what the machine does; organization is the construction, how it does it."

If a program can see or name it, it is architecture (the ISA); if it is a hidden build choice, it is organization. Same ISA runs the same programs. Von Neumann shares one memory; Harvard splits instructions and data so it fetches both at once.

Number Systems and Conversions

Everything a computer holds is binary. This skill is turning numbers between binary, decimal and hexadecimal without thinking, plus the special decimal codes, and it is easy marks. We build it as a programme: many tiny steps worked through one at a time, and you check each one before the next. Go slowly and it will soon feel automatic.

Work it frame by framecover, work, then slide down to check

Cover the page just below the first line with a card or your hand. Read a frame, do the small task, then slide the card down to the next line to check your answer. One step at a time, and do not skip.

A base just means how many symbols you count with before you start a new column. Decimal is base 10: the ten symbols 0 to 9. A computer wire is only ever on or off. So how many symbols does binary have?

2, just 0 and 1 (on or off), which is base 2. Binary is correct but gets very long, so we bundle it up as hexadecimal, base 16, whose symbols run 0 to 9 and then A, B, C, D, E, F. A is the first letter-symbol; what decimal value does the hex digit A stand for?

10. Then B = 11, C = 12, D = 13, E = 14, F = 15. Next, place value: reading a number from right to left, the columns are worth base0 = 1, then base1, then base2, and so on. In hex, what is the place value of the third column from the right?

162 = 256. So the hex columns are 1, 16, 256, 4096. Three size words before we convert: one binary digit is a bit, four bits are a nibble, and eight bits are a byte. How many bits are in a byte?

8 (and four bits are a nibble). Now the first conversion. To turn any base into decimal, multiply each digit by its place value and add the results. Take the hex number 2F: its columns are 16 and 1, and F = 15. Work out 2×16 + 15.

47, so hex 2F = 47. That is every base-to-decimal question. The reverse, decimal to any base, divides repeatedly by the base, jots each remainder, and reads the remainders bottom to top. For 13 to binary: 13÷2 = 6 r 1, 6÷2 = 3 r 0, 3÷2 = 1 r 1, 1÷2 = 0 r 1. Read the four remainders from the bottom up.

1101. Let us prove it rather than trust it. The binary columns are 8, 4, 2, 1, and 1101 has 1-bits in the 8, 4 and 1 columns. Add 8 + 4 + 1; do you land back on 13?

yes, 8 + 4 + 1 = 13. The conversion checks out. Now binary to hex. Because 16 = 24, one hex digit is exactly four bits, so group the bits into fours from the right and turn each four into one hex digit. Take 1101 0110: the right group 0110 = 4+2 = 6. What hex digit is the left group 1101?

D (that is 8+4+1 = 13). So 1101 0110 = D6, and going the other way you simply expand each hex digit back into its four bits. Read on.

A few powers of two must be instant. 210 = 1024, which we call "1 K"; then 220 = 1 M and 230 = 1 G. How many bytes is 210, and what one-letter name do we give it?

1024 bytes, called 1 K. Every memory and cache question leans on these. Now the special decimal codes, where each decimal digit is kept on its own. First is BCD. Read on.

BCD (binary coded decimal), the 8421 code, writes each decimal digit as its own 4 bits. So 59 becomes 5 = 0101 and 9 = 1001, written 0101 1001. It is a weighted code (the bit positions are worth 8, 4, 2, 1). Write the single digit 7 in BCD.

0111 (4+2+1 = 7). BCD is just the digit in plain 4-bit binary. The next code, Excess-3, takes the digit, adds 3, then writes the result in 4 bits. So 9 becomes 9+3 = 12 = 1100. Write the digit 6 in Excess-3.

1001 (6+3 = 9 = 1001); to decode you subtract 3. Excess-3 is non-weighted (its bits carry no fixed weight) and self-complementing. Read on.

Last, the character codes, which store text and not numbers. ASCII encodes English letters, digits and symbols in 7 or 8 bits; Unicode was introduced to cover the characters of all the world's languages. Which of the two would you need for Chinese or Arabic letters?

Unicode (it covers every language). That is every fact in this skill. Now watch the moves used together in the two worked examples below, then sit the recalls with the answers covered.

Signed Numbers

This is the most asked numeric topic, and the one most people find confusing. So we do it as a programme: many tiny steps, and you check each one before moving on. Go slowly. By the last frame the moves will feel obvious.

Start with 8 bits and no sign yet. The patterns run 0000 0000, 0000 0001, all the way up to 1111 1111. That top one, 1111 1111, is 28 − 1. Write its value in decimal, then slide down.

255. Every one of the 256 patterns is a positive number; there is no minus sign anywhere yet. To make room for negatives we sacrifice the top (leftmost) bit and let it carry the sign: a top bit of 0 means positive. So a top bit of 1 must mean what?

negative. So just by glancing at 1010 1010 (top bit 1) you know it is a negative number. The only question left in the whole topic is which pattern to use for a given negative. The scheme real computers use is called two's complement, and the next few frames build it slowly. Read on.

Picture the 8 bits as a car odometer. It counts up 0000 0000, 0000 0001, and on to 1111 1111, then rolls back round to 0000 0000. Now turn it one step backwards from 0000 0000. What pattern do you land on?

1111 1111. One step below zero. So it is natural to call 1111 1111 the value −1. Step back once more, to 1111 1110, and that is −2. Negatives are just the patterns you meet counting down from the top. Counting back once more, what pattern is −3?

1111 1101. Counting all the way down would be slow, so here is the shortcut to build any negative: write the positive, flip every bit, then add 1. Try it on −1. Start with +1 = 0000 0001. Flip every bit and write the result.

1111 1110. Now the second half of the shortcut. Add 1 to 1111 1110. What do you get?

1111 1111. That is the same pattern the odometer gave for −1, so the shortcut is trustworthy. Say it like a chant: "flip every bit, add one." Now your turn, all by yourself: make −5 in 8 bits. Start with +5 = 0000 0101. Flip, then add 1.

1111 1011. (0000 0101 flips to 1111 1010, and adding 1 gives 1111 1011.) That pattern is −5. Notice you only ever do three things: positive, flip, add one. Read on.

Now the other direction: reading a negative pattern back into a number. The trick is the very same one. Take 1111 1011 (top bit 1, so it is negative). Flip it and add 1 to find its size. Flip 1111 1011, add 1, and say what size you get.

0000 0101 = 5, so the value is −5. (Flip 1111 1011 to 0000 0100, add 1 to get 0000 0101.) Writing a negative and reading one use the same move, which is why it is worth learning well. Read on.

Why did the world settle on this scheme? Two reasons. It has only one zero (just 0000 0000), and the ordinary adder does subtraction for free, because a − b is the same as a + (−b). Here is the proof. Add −5 (1111 1011) to +5 (0000 0101), and drop any carry that falls off the top. What 8-bit pattern is left?

0000 0000. (1111 1011 + 0000 0101 = 1 0000 0000; throw away the carry and you have 0000 0000, which is zero.) A number plus its negative gives zero, which is exactly what a negative should do. The scheme really works. Read on.

Last piece: the range. Half the patterns are negative and half positive, but zero uses up one positive slot, so there is always one more negative than positive: −2n−1 to 2n−1 − 1. In 16 bits that is −32 768 to 32 767. So in 8 bits the range is −128 to what?

127. (−27 to 27 − 1 is −128 to 127.) That is two's complement, start to finish. Read on.

Two older schemes you only need to recognise for the objective test. Sign-magnitude: a sign bit then the plain size, so −42 is 1 then 010 1010 = 1010 1010; its drawback is two zeros (+0 and −0). One's complement: negate by flipping every bit only (no add 1); it needs an end-around carry when adding and also has two zeros. Two's complement beat both by adding that 1. How many zeros does sign-magnitude have?

two (+0 and −0). That is every idea in this topic. Now watch all the moves used together in the worked example below, then sit it yourself with the answer covered.

Your turnMCQ, quick facts

Trap

Reading a negative two's-complement pattern, do not just read the magnitude bits off; you must flip and add 1 first. Overflow means the true result is too big or too small for the range, not division by zero. And the end-around carry belongs to one's complement only; two's complement simply discards the top carry.

Lock it in

"Flip and add one, to write a negative and to read one. Add the patterns, throw away the top carry."

Floating Point, IEEE 754

One 32-bit pattern has to hold both a tiny number like 0.0000001 and a huge one like 6 billion, and plain whole-number binary cannot stretch that far. The fix is a trick you already know from science class, but people find it fiddly, so we do it as a programme: many tiny steps, and you check each one before moving on. Go slowly. By the last frame the three fields will feel obvious, and both exam directions fall out of a single line.

Work it frame by framecover, work, then slide down to check

Cover the page just below the first line with a card or your hand. Read a frame, do the small task, then slide the card down to the next line to check your answer. One step at a time, and do not skip.

Here is the whole problem in one line. You have one box, exactly 32 bits wide, and it must be able to write both a tiny number like 0.0000001 and a giant one like 6,000,000,000. Plain whole-number binary, the kind you have used so far, cannot reach both ends. Can plain whole-number binary write both of those in 32 bits? Yes or no?

No. It runs out of room. But you already beat this same problem in decimal, in science class: to write 6,020,000 compactly you put it as 6.02 × 106. Hidden in that little form are three separate pieces of information. Name the three pieces.

a sign (it is positive, +), a fraction (6.02), and an exponent (6). That is all scientific notation is. Floating point does exactly this, but in base 2: a sign, a fraction, and a power of 2 instead of 10. Nothing more is going on. Read on.

So a floating-point number is stored as those same three pieces, now called three fields, written left to right: the sign (s), then the exponent (E), then the mantissa M (which is just the fraction, also called the significand). Which of the three fields sits on the far left?

the sign. Now their sizes. Single precision is 32 bits, split as 1 sign bit, then 8 exponent bits. That leaves how many bits for the mantissa, to reach 32?

23. (1 + 8 + 23 = 32.) You only need to recognise the bigger size: double precision is 64 bits, split 1 + 11 + 52. Everything from here uses single precision. Read on.

One preparation step, called normalising. In decimal you insist on exactly one non-zero digit before the point (6.02, never 60.2 or 0.602). In binary you do the same: slide the point until the number reads 1.something × 2e. Since the only non-zero binary digit there can be is 1, what single thing does a normalised binary number always start with?

"1." (a one, then the point). Always. And here is the first trick that helps: because it is always "1.", actually storing that 1 would waste a bit on something you already know for certain. So it is left out and just assumed. This is the famous hidden 1. When you READ a stored pattern back, what must you put in front of the mantissa?

a "1.". Put the hidden 1 back before you read. And going the other way, when you write a number you drop that leading 1 and keep only what follows the point. It costs nothing and buys you one extra bit of precision for free. Read on.

Now the second trick, the one that trips up most beginners: the bias. The exponent can be negative (for a tiny number like 2−3) or positive (for a big one). Rather than give the exponent its own sign bit, we add a fixed number, the bias, so the stored exponent is always a positive count. The bias is 127 for single (1023 for double). It is like storing temperatures as "degrees above −127", so a minus sign is never needed. Read on.

So the stored exponent field is the true exponent plus 127. To undo that and get the true exponent back, you simply subtract the bias again. Suppose a pattern has an exponent field of 130. What is its true exponent?

3. (130 − 127 = 3.) That is the whole method on one line, so learn it: value = ± 1.M × 2(exponent field − 127). Both exam directions fall straight out of it. Read on.

One last reading skill: turning the mantissa into a number. After the hidden "1.", each mantissa bit is a smaller and smaller fraction: the first bit is worth 1/2, the next 1/4, the next 1/8. So a stored mantissa of 100… reads as 1.1 in binary, which is 1 + 1/2. What is 1 + 1/2 in decimal?

1.5. Now decode a whole real pattern, one field at a time. Take sign bit 1, exponent field 130, mantissa 100…. The sign bit 1 means negative, the field 130 gives e = 3 (you just did that), and the mantissa gives 1.M = 1.5. First the power: what is 23?

8. Now hang the sign and the mantissa on it: value = −1.5 × 23 = −1.5 × 8. Finish it: what number is that?

−12. You just decoded a floating-point pattern by hand. Now prove the bias to yourself: to STORE that same exponent of 3 you would go the other way and do 3 + 127. What exponent field would you store?

130. The very field you started from, so the bias undoes itself cleanly, going in and coming out. That is every idea in the topic: three fields, normalise to 1.something, hide the leading 1, and shift the exponent by the bias. the ALU. Fourth, and the one the exam cares about, control transfer: JUMP, BRANCH, CALL. Normally instructions run one after another in order; these change that order. Which type changes the order instructions run in?

CPU Performance

How fast a processor runs is a calculation, not a mystery. Two formulas do almost everything: the CPU-time equation and Amdahl's law. This is the most heavily weighted numeric topic on the recent paper.

Everything about processor speed comes from one equation. A program's running time is three numbers multiplied together: CPU time = IC × CPI × T. IC is the instruction count (how many instructions actually run), CPI is the average cycles per instruction, and T is how long one clock cycle lasts. Say what each of the three, IC, CPI and T, stands for, then slide down.

instruction count, average cycles per instruction, clock cycle time. The clock rate you see advertised (say 4 GHz) is cycles per second, so one cycle lasts T = 1 / clock rate. Put that in place of T and write CPU time using clock rate.

CPU time = (IC × CPI) / clock rate. So a faster clock shortens the time, but a smaller instruction count or a smaller CPI does too. All three matter. Read on.

Look closer at CPI. Instructions are not all equal: a register add may take 1 cycle, an indirect memory access 4. The average CPI weights each type by how often it appears, adding up (fraction of the type × its cycles) over all types. The fractions must add to 1. Read on.

Try a tiny one. A program is 70% simple instructions at 1 cycle each and 30% at 3 cycles each. Work out the average CPI: (0.70 × 1) + (0.30 × 3).

1.60. (0.70 × 1 = 0.70, and 0.30 × 3 = 0.90, giving 1.60.) Notice 0.70 and 0.30 add to 1, exactly as the fractions must. Read on.

A second speed measure is MIPS, millions of instructions per second: MIPS = clock rate / (CPI × 106). A faster clock or a lower CPI both raise it. If the clock rate is 2 × 109 and CPI is 2, find the MIPS.

1000 MIPS. (2 × 109 divided by (2 × 106) gives 1000.) Read on.

When you improve something, always measure the gain against the OLD time: improvement = (old − new) / old. Old time 200, new time 150: what fraction is the improvement?

0.25, that is 25%. ((200 − 150) / 200 = 50 / 200 = 0.25.) Divide by the old value, never the new. Read on.

So is a chip fast just because its clock is fast? No. Because time = (IC × CPI) / clock rate, the instruction count and CPI count just as much, and behind CPI sit cache behaviour, branch prediction and instruction-level parallelism. Name one reason a high-clock chip can still be slow.

a high CPI (or a large instruction count, or poor cache or branch behaviour). That is why "judge a processor by clock frequency only" is wrong. Read on.

Now the second big formula, Amdahl's law. Suppose you speed up only PART of a task. The part you did not touch still takes its full time, so it caps the gain. Let f be the fraction of the original time spent in the part you improve, and let s be how many times faster you make that part. In your own words, what does f stand for?

the fraction of the time spent in the part you speed up. That part's time shrinks from f to f / s, while the rest, (1 − f), is unchanged. If the whole job was time 1, the new time is (1 − f) + f / s, and speedup is old over new. Write the speedup S.

S = 1 / ((1 − f) + f / s). Old time 1 on top, new time (1 − f) + f / s on the bottom. Read on.

Push s as large as you like, so f / s shrinks towards 0. Then S climbs only as far as 1 / (1 − f), because the untouched (1 − f) never goes away. Memory hook: the slow part you left alone sets the ceiling. With f = 0.85, what is the best speedup possible, even with an infinite s?

about 6.67. (1 / (1 − 0.85) = 1 / 0.15 = 6.67.) Now a real, finite case: a cache 10 times faster (s = 10) that the CPU hits 85% of the time (f = 0.85). First find the new time, (1 − f) + f / s. Compute 0.15 + 0.85 / 10.

0.235. (0.15 + 0.085 = 0.235.) So S = 1 / 0.235. Finish it: what is S?

about 4.26. (1 / 0.235 = 4.26.) Far below the cache's 10 times, because the 15% of slow accesses dominate, which is exactly Amdahl's point. The reference card and the two worked examples below sit both of these formulas; do them with the answers covered.

Pipelining means overlapping instructions so several are in progress at once. Picture a laundry: you do not wait for one load to wash, dry and fold before starting the next, because the moment the first load moves to the dryer the second goes into the washer. A processor overlaps its instructions the same way. What everyday process is pipelining most like?

a laundry (or any assembly line). To overlap them, we split each instruction into stages, called k stages. A common five are IF (instruction fetch), ID (instruction decode), EX (execute), MEM (memory access) and WB (write back). Each stage is its own hardware, so five instructions can each sit in a different stage at the same moment. Name the five stages in order.

IF, ID, EX, MEM, WB. Without a pipeline, instruction 2 cannot start until instruction 1 has passed through every stage. With a pipeline, the instant an instruction leaves a stage the next one enters it, so once the pipe is full one instruction finishes every clock cycle. Once the pipe is full, how many instructions complete per clock cycle?

one every cycle. That steady one-per-cycle output is the whole payoff. Now, how long is one clock cycle? Every stage must finish inside it, so the cycle is set by the slowest stage plus a small latch delay between stages, never the average and never the sum. If the stages take 60, 50, 90, 80 ns with a 10 ns latch, what is the cycle time?

100 ns. (The slowest stage is 90 ns, plus the 10 ns latch, giving 100 ns.) Read on.

Now the time for n instructions. The first takes k cycles to fill the pipe; after that one more finishes every cycle, so n instructions take (k + n − 1) cycles, which you then multiply by the cycle time. With k = 4 stages and n = 500 tasks, how many cycles is that?

503 cycles. (4 + 500 − 1 = 503, and at 100 ns each that is 50 300 ns.) Read on.

Without the pipeline each instruction needs its full one-instruction time, the sum of the stage times, here 60 + 50 + 90 + 80 = 280 ns. The speedup is that one-instruction time divided by the cycle time, and it can never exceed k, the number of stages. Divide 280 ns by the 100 ns cycle to get the speedup.

2.8. (280 / 100 = 2.8, below the ceiling of k = 4 stages.) For a whole batch you compare totals instead: 500 × 280 = 140 000 ns without a pipeline, against 50 300 ns with one. The reference card and the two worked examples below sit exactly these; do them with the answers covered.

Must doThe pipeline sums
  • Cycle time = slowest stage + latch delay.
  • Pipelined time for n tasks = (k + n − 1) × cycle time. (It takes k cycles to fill with the first task, then one more cycle for each of the other n − 1.)
  • Non-pipelined time for n tasks = n × (time for one instruction). One instruction takes the sum of all the stage times, or the given per-instruction time.
  • Speedup = non-pipelined time / pipelined time. Its ceiling is k.

Memory hook: "k + n − 1", and the clock runs at the slowest stage, never the average.

Overlapping is not free: sometimes two instructions in the pipe clash, and a clash is called a hazard. There are three kinds, and you must be able to name them. The first is the structural hazard, where two instructions need the same piece of hardware in the same cycle (one memory wanted for a fetch and a data access at once). How do you remove a structural hazard?

duplicate the resource (for example, separate instruction and data memories, so each instruction has its own). The second kind is the data hazard: an instruction needs a result that an earlier instruction has not written yet. We name its three types by the order in which two instructions touch the same register. Read on.

RAW (read after write) is the true dependency: the second instruction reads a register the first has not written yet. It is eased by forwarding, which feeds the result straight from where it is produced to where it is needed, before the write-back stage. Which of the three data hazards is the real dependency?

RAW. The other two, WAR (write after read) and WAW (write after write), are only naming clashes over the same register, not true data flow. Read on.

When forwarding cannot deliver the value in time, the pipeline must stall: it inserts a bubble, an idle cycle, until the value is ready. What is the idle cycle a stall inserts called?

a bubble. The third kind is the control hazard: a branch changes which instruction runs next, but the pipe has already fetched the ones right after the branch. It is eased by branch prediction and speculative execution, whose whole purpose is to reduce control-hazard stalls. Read on.

Now classify one pair. The first instruction writes R3, and the second instruction reads R3. The shared register is R3, and the order is write then read. Which data hazard is that?

RAW (write then read is exactly read-after-write). That is every hazard idea in place. The box just below shows how to draw the pipeline timing diagram the paper sometimes asks for; after it, sit the two "your turn" boxes with the answers covered.

TeachHow to draw the timing (cycle) diagram

The paper sometimes says "draw the pipeline timing diagram" or "draw the cycle diagram". It is always the same grid, and you draw it the same way every time:

  • Cycles across the top (1, 2, 3, ...), one instruction per row down the side.
  • In each cell write the stage that instruction is in that cycle: IF, ID, EX, (MEM), WB. Some papers add an operand fetch (OF) stage between ID and EX; use whatever stages the question names.
  • Each instruction begins its IF one cycle after the instruction above it.
  • A multi-cycle execute (say a 3-cycle multiply or a 6-cycle divide) writes EX in that many cells in a row, and everything behind it slides right.
  • A stall (waiting for a hazard to clear, or for a busy stage) is a gap you mark with a bubble, written --.

The total number of cycles is simply the column where the last instruction reaches WB. That is your answer to "how many cycles".

How to remember it: "cycles across, instructions down, stages in the boxes, count to the last WB." A long EX pushes; a stall is a --. (You will draw exactly this for Question Two and Question Three in the final mock.)

Memory is arranged in levels, fastest to slowest: registers, then cache, then main memory, then secondary storage (disk or SSD). Of those four, which is the fastest?

registers. Picture it as your workspace: the few things in your hands (registers), the book open on your desk (cache), the shelf beside you (main memory), and the library across campus (disk). You keep what you use most closest, because reaching further costs time. As you climb toward registers, does memory get cheaper or dearer per bit?

dearer. Climbing up, memory gets faster, smaller, and more expensive per bit. The reason there are levels at all is a trade-off: you cannot have fast, big and cheap at once. So which level has the highest cost per bit?

registers. Now the two kinds of RAM. SRAM (static RAM) is built from flip-flops: fast, needs no refresh, but costly and low density. Given it is fast but costly, which level is SRAM used for?

cache. DRAM (dynamic RAM) is built from capacitors: dense and cheap, but slower and it needs periodic refresh, so it is used for main memory. (ROM and Flash are non-volatile; RAM, cache and DRAM are volatile, lost on power off.) Which kind of RAM has to be refreshed?

DRAM. Two facts the MCQs love: the MAR (memory address register) holds the address being accessed; and access time is how long one access takes, while cycle time is the minimum gap between the starts of two accesses. A device with 60 ns access and 90 ns cycle can start a new access how often?

every 90 ns (the cycle time, not the access time). Now, why does a small nearby cache help at all? Because programs are predictable, a habit called locality of reference. It comes in two kinds. Read on.

Temporal locality: a location used now is likely used again soon (think of a loop counter, read over and over). Reusing the same location again soon is which locality?

temporal. Spatial locality: once a location is used, nearby ones are likely used next (stepping through an array). That is exactly why the cache copies a whole block at a time, not one lonely byte. Read on.

Two limits to know by name. The memory wall is the widening gap between fast CPUs and slow memory, which is why a processor can still wait on data despite a big cache. Virtual memory lets a program use an address space larger than the physical RAM, with a memory management unit (MMU) translating the addresses. Read on.

Now the cache sum itself, gently. Picture the cache as a wall of numbered hooks (the lines), each big enough to hold one block, a short run of consecutive bytes copied from memory together. Far more blocks exist in memory than there are hooks, so many blocks compete for the same hook. Read on.

When the CPU names an address, that address answers three questions, and that is exactly why it splits into three fields. The first, from the low bits, is the offset. Which one thing does the offset pick out: which byte in the block, which hook, or which block?

which byte inside the block. The middle bits are the index (or set): which hook the block hangs on. The high bits are the tag: which of the many blocks sharing that hook is actually here, stored beside the block and compared on every access. A tag that matches means what?

a hit (no match is a miss). Now the sizes, in order. Address bits = log2(main memory size). Offset = log2(block size). A 16-byte block needs how many offset bits?

4 (log216 = 4). Number of lines = cache size / block size. Index bits (direct mapped) = log2(lines). A direct-mapped cache with 64 lines needs how many index bits?

6 (log264 = 6). For a k-way set associative cache, sets = lines / k and set bits = log2(sets); fully associative has no index at all (any block on any hook). Whatever is left over is the tag: tag bits = address bits − index (or set) − offset. The tag directory = lines × tag bits. Read on.

Last, the average memory access time (AMAT), with hit ratio h, cache time Tc and memory time Tm. Hierarchical (cache first): AMAT = Tc + (1 − h) × Tm. Simultaneous (both at once): AMAT = h × Tc + (1 − h) × Tm. Read on.

An instruction set can be designed with two opposite philosophies. The first is CISC (complex instruction set computer): many, powerful, variable-length instructions, some doing a lot of work each (even direct memory-to-memory operations). Does CISC have few or many instructions?

many. Because each instruction does so much, CISC programs are short, but the hardware is complex, instructions take several cycles, and it is harder to pipeline. Its instructions can resemble high-level language constructs, which eases the compiler. It suited the old days of slow, expensive memory. Read on.

The opposite is RISC (reduced instruction set computer): few, simple, fixed-length instructions, each ideally one cycle. Are RISC instructions fixed-length or variable-length?

fixed-length. RISC touches memory only through load and store (a load-store design), keeps many registers, and uses hardwired control. Programs are longer, but the hardware is simple, fast, and pipelines cleanly. It minimises chip area and power and leans on the compiler. So which philosophy pipelines more easily, RISC or CISC?

RISC (simple fixed-length instructions flow through the pipeline cleanly). One quick sort for the exam: variable-length instruction formats go with RISC or CISC?

CISC (RISC is fixed-length). The card just below lays the two side by side. Examples to recognise: RISC is ARM, MIPS, SPARC, PowerPC; CISC is Intel x86, VAX, the Motorola 68000. Read on to the loose ideas the MCQs also test.

to accelerate data-parallel computations. Domain-specific architecture: a processor tailored to one job (say the matrix work in AI) can be far more efficient than a general-purpose one for that job. Read on.

a. i) Computer Systems are designed using two closely related but distinct concepts which are Computer Architecture and Computer Organization. Differentiate between these concepts. 2mks ii) Compare Von Neumann Architecture and Harvard Architecture. Include a diagram for each. 3mks
In the hall25/26 Q1(a)

i) Differentiate computer architecture from computer organization.

Computer architecture is defined as the functional design and logical structure of the computer system as the programmer sees it: the instruction set, the data types, the addressing modes and the register organization. It answers the question "What does the computer do?" and serves as the blueprint for the system.

Computer organization is defined as the operational units and their interconnections that realize (carry out) that architecture: the control signals, the buses, the memory technology used and the cache. It answers the question "How does the computer do it?" A useful likeness: architecture is the building's design, organization is the actual construction of the building.

ii) Compare Von Neumann and Harvard architecture, with a diagram for each.

Von Neumann architecture is defined as a design that uses a single (shared) area of memory, reached over one bus, for both the program instructions and the data those instructions act on. It is simple to build, but the shared path is a bottleneck (an instruction fetch and a data access cannot happen at the same instant).

Harvard architecture is defined as a design that uses separate memories and separate buses for instructions and data, which lets it fetch an instruction and read data at the same time (a form of parallelism), at the cost of duplicating the address, data and control lines.

c. Explain the following terms 3mks i. Locality of reference ii. Temporal locality
In the hall25/26 Q5(c)

i) Locality of reference is defined as the tendency of a program to keep accessing the same small set of memory locations over a short period, a consequence of loops and subroutines; it is why a small fast cache can satisfy most accesses.

ii) Temporal (time) locality is defined as: if a memory location is accessed, it is very likely to be accessed again soon (the same instruction or variable reused). Its partner, spatial (space) locality, is defined as: if a location is accessed, the nearby addresses are very likely to be accessed next (as when stepping through an array).
