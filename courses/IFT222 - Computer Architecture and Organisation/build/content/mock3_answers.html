AnswerQuestion One

(a) Architecture versus organization (2 marks)  [M1 U1]

Architecture is the set of attributes visible to the programmer (instruction set, registers, addressing modes): what the machine does. Organization is how those are realised in hardware (control signals, buses, memory technology): how it does it. Example: the architecture says a MULTIPLY instruction exists; the organization decides whether a dedicated multiplier or repeated addition carries it out.

(b) 178 and −92 in 11 bits (6 marks)  [M1 U2]

Given values 178 and −92 · n = 11 bits · four schemes
Find each value in each scheme, plus the two's complement range
Formula sign-magnitude = sign bit + magnitude · one's complement = invert all n bits · two's complement = invert then add 1 · range = −2n−1 to +(2n−1−1)
  1. 178 = 128+32+16+2, so in 11 bits 178 = 000 1011 0010. Positive, so identical in all four schemes.
  2. For −92, first write +92 = 64+16+8+4 = 000 0101 1100.
  3. Sign-magnitude: set the sign bit, keep the magnitude: 100 0101 1100.
  4. One's complement: invert all 11 bits of +92: 111 1010 0011.
  5. Two's complement: add 1 to that: 111 1010 0100.

11-bit two's complement range = −210 to +(210−1) = −1024 to 1023. Both 178 and −92 fall well inside it, so both are representable.

(c) 92.375 in IEEE-754 single precision (5 marks)  [M1 U3]

Given value = 92.375 · IEEE-754 single precision · bias 127
Find the 32-bit pattern, in binary and hex
Formula normalise to 1.m × 2e, then E = e + 127
  1. Sign: positive, so 0.
  2. Binary: 92 = 1011100 and 0.375 = 0.011, so 92.375 = 1011100.011.
  3. Normalise: move the point 6 places left, 1.011100011 × 26, so e = 6. This one terminates, so it is exact.
  4. Exponent field: 6 + 127 = 133 = 1000 0101.
  5. Mantissa: 011100011 padded to 23 bits = 0111 0001 1000 0000 0000 000.
92.375 = 0 10000101 01110001100000000000000 = 0100 0010 1011 1000 1100 0000 0000 0000 = 42B8C000H. Converting back gives 92.375 exactly, which is the check to write down.

(d) CPI over 2 500 000 instructions (6 marks)  [M2 U2]

Given IC = 2 500 000 · A 35% at 1, B 25% at 2, C 20% at 3, D 12% at 4, E 8% at 5 · for (iii), class D falls to 2 cycles
Find average CPI, total cycles, new CPI, percentage improvement
Formula CPI = Σ(fractioni × CPIi) · cycles = IC × CPI · improvement = (old − new)/old
  1. CPI = 0.35(1) + 0.25(2) + 0.20(3) + 0.12(4) + 0.08(5) = 0.35 + 0.50 + 0.60 + 0.48 + 0.40 = 2.33.
  2. Total cycles = 2 500 000 × 2.33 = 5 825 000.
  3. Class D from 4 to 2 cycles: CPI = 2.33 − 0.12(4) + 0.12(2) = 2.33 − 0.48 + 0.24 = 2.09.
  4. Improvement = (2.33 − 2.09) / 2.33 = 0.24 / 2.33 = 10.30%.
CPI 2.33; 5 825 000 cycles; new CPI 2.09; improvement 10.30%. Note the improvement is measured against the old CPI.

(e) 24-bit address, 32-byte block, 512-line direct-mapped cache (6 marks)  [M3 U3]

Given address = 24 bits · block = 32 bytes · 512 lines · direct mapped
Find the address format and the line each address maps to
Formula offset = log2(block) · index = log2(lines) · tag = address − index − offset · the index field is the line number
  1. Offset = log232 = 5 bits. Index = log2512 = 9 bits. Tag = 24 − 9 − 5 = 10 bits.
  2. Line = (address ÷ 32) mod 512, that is shift right 5 and keep the low 9 bits.
  3. A5C3E7 = 10 863 591. Shift right 5: 339 487. mod 512 = 31.
  4. 7F0044 = 8 323 140. Shift right 5: 260 098. mod 512 = 2.
  5. C0FFEE = 12 648 430. Shift right 5: 395 263. mod 512 = 511.
Format: tag 10 / line 9 / offset 5. Lines: A5C3E7 → 31, 7F0044 → 2, C0FFEE → 511. Here the fields do not fall on hex-digit boundaries (9 index bits is not a whole number of hex digits), so convert to decimal and divide rather than reading digits off, which is the trap this part sets.

AnswerQuestion Two

(a) Pipeline timing (10 marks)  [M2 U3]

Given k = 5 stages · stage times 40, 55, 45, 60, 50 ns · latch = 5 ns · n = 800 tasks
Find cycle time, one-task non-pipelined time, ideal speedup, 800-task pipelined and sequential times, throughput
Formula cycle = slowest stage + latch · pipelined = (k + n − 1) × cycle · sequential = n × Σ(stage times) · speedup = sequential / pipelined · throughput = 1 / cycle in the steady state
  1. Cycle time = slowest stage + latch = 60 + 5 = 65 ns.
  2. Non-pipelined, one task = 40+55+45+60+50 = 250 ns.
  3. Ideal speedup = 250 / 65 = 3.85 (its ceiling is k = 5; the latch and the uneven stages cost the rest).
  4. 800 tasks pipelined = (5 + 800 − 1) × 65 = 804 × 65 = 52 260 ns.
  5. 800 tasks sequentially = 800 × 250 = 200 000 ns, so the realised speedup is 200 000 / 52 260 = 3.83.
  6. Throughput = 800 / 52 260 ns = 15.31 million tasks per second; in the steady state this is one task per cycle, 1 / 65 ns = 15.38 million per second.
Cycle 65 ns; one task 250 ns; ideal speedup 3.85; 800 tasks 52 260 ns pipelined against 200 000 ns sequential, a speedup of 3.83; throughput about 15.31 million tasks per second.

(b) The three hazards (4 marks)  [M2 U3]

Structural: two instructions need the same hardware in the same cycle (one memory serving a fetch and a data access); cured by duplicating the resource, as with separate instruction and data memories. Data: an instruction needs a result the one ahead has not produced yet (read after write); mostly cured by forwarding. Control: a branch changes what runs next after the pipeline has already fetched the following instructions; cured by resolving the branch early, predicting it, or flushing. Forwarding cannot remove the load-use data hazard: the loaded value is still being fetched from memory, so exactly one stall remains.

(c) Amdahl's law (6 marks)  [M2 U2]

Given f = 0.75 · s = 8
Find the overall speedup, and why it is not 8
Formula speedup = 1 / ((1 − f) + f/s)
  1. Untouched part: 1 − f = 0.25, still at full cost.
  2. Sped-up part: f / s = 0.75 / 8 = 0.09375.
  3. Speedup = 1 / (0.25 + 0.09375) = 1 / 0.34375 = 2.91.
Overall speedup 2.91, not 8. The 25% that was not improved still takes its original time, and it alone caps the total gain at 1/0.25 = 4 even if the other 75% were made infinitely fast. That ceiling is the whole content of Amdahl's law.
AnswerQuestion Three

(a) 8-way set-associative cache design (10 marks)  [M3 U3]

Given cache = 32 KB · block = 64 bytes · main memory = 16 MB · k = 8 ways
Find lines, sets, address format, tag directory size
Formula address bits = log2(memory) · lines = cache / block · sets = lines / k · offset = log2(block) · tag = address − set − offset · tag directory = lines × tag bits
  1. Address: 16 MB = 224, so 24-bit addresses.
  2. Lines = 32 KB / 64 B = 32768 / 64 = 512.
  3. Sets = 512 / 8 = 64.
  4. Offset = log264 = 6. Set field = log264 = 6. Tag = 24 − 6 − 6 = 12.
  5. Tag directory = 512 lines × 12 bits = 6144 bits = 768 bytes.
512 lines in 64 sets of 8. Format tag 12 / set 6 / offset 6. Tag directory 768 bytes, which is the storage overhead the cache pays on top of its 32 KB of data.

(b) AMAT both ways (6 marks)  [M3 U3]

Given h = 0.92 · Tc = 3 ns · Tm = 70 ns
Find AMAT under hierarchical and simultaneous organisation
Formula hierarchical = Tc + (1−h)×Tm · simultaneous = h×Tc + (1−h)×Tm
  1. Miss ratio = 1 − 0.92 = 0.08.
  2. Hierarchical = 3 + 0.08(70) = 3 + 5.6 = 8.6 ns.
  3. Simultaneous = 0.92(3) + 0.08(70) = 2.76 + 5.6 = 8.36 ns.
Hierarchical 8.6 ns, simultaneous 8.36 ns. The difference is only whether the cache time is paid on every access or only on hits; say which organisation you assumed and you cannot lose the mark.

(c) Locality of reference (4 marks)  [M3 U1]

Locality of reference is the tendency of a program to concentrate its memory accesses in a small, predictable set of locations during any short period. Temporal locality: a location used now is likely to be used again soon, for example a loop counter read on every iteration, which is why cache keeps recently used data. Spatial locality: locations near one just used are likely to be used soon, for example successive elements of an array, which is why cache fetches a whole block of neighbouring words rather than a single one.
AnswerQuestion Four

(a) 245 − 178 by end-around carry (6 marks)  [M1 U2]

Given 245 − 178 · n = 10 bits · one's complement
Find the difference as a pattern and in decimal
Formula a − b = a + (−b) with −b the bitwise inversion; a carry out of the top is added back into the lowest bit
  1. 245 in 10 bits: 245 = 128+64+32+16+4+1 = 00 1111 0101.
  2. 178 in 10 bits: 178 = 128+32+16+2 = 00 1011 0010.
  3. −178 in one's complement: invert every bit: 11 0100 1101.
  4. Add: 00 1111 0101 + 11 0100 1101 = 1 00 0100 0010. A 1 has carried out of the 10th bit.
  5. End-around carry: drop it and add it into the lowest bit: 00 0100 0010 + 1 = 00 0100 0011.
  6. Read back: 00 0100 0011 = 64 + 2 + 1 = 67, and 245 − 178 = 67. Correct.
245 − 178 = 00 0100 0011 = 67. The signature of one's complement is that the carry never vanishes, it comes back in at the bottom.

(b) Excess-3 (4 marks)  [M1 U2]

Given (i) 507 to encode, (ii) 0111 1001 0110 to decode · code = Excess-3, 4 bits per digit
Find the code, the decimal, and the self-complementing property
Formula encode: digit + 3 in 4 bits · decode: nibble value − 3
  1. 507: 5+3 = 8 = 1000; 0+3 = 3 = 0011; 7+3 = 10 = 1010. So 507 = 1000 0011 1010.
  2. Decode 0111 1001 0110: 0111 = 7, minus 3 = 4; 1001 = 9, minus 3 = 6; 0110 = 6, minus 3 = 3. So it reads 463.
507 → 1000 0011 1010; 0111 1001 0110 → 463. (iii) Excess-3 is self-complementing: the code of (9 − d) is the bit-by-bit complement of the code of d. For example 4 is 0111 and 5 is 1000, which are exact complements, so taking the nine's complement of a digit is just inverting its bits. That is what made the code attractive for decimal subtraction hardware.

AnswerQuestion Five

(a) C2C60000H in IEEE-754 single precision (6 marks)  [M1 U3]

Given pattern = C2C60000H · IEEE-754 single precision · bias 127
Find the decimal value
Formula value = ±1.M × 2(E − 127)
  1. Expand: C2C60000 = 1100 0010 1100 0110 0000 0000 0000 0000.
  2. Split 1 / 8 / 23: sign = 1; E = 1000 0101; M = 100 0110 0000... (rest zeros).
  3. Sign 1 means negative.
  4. E = 1000 0101 = 133, so e = 133 − 127 = 6.
  5. Restore the hidden 1: 1.1000110 × 26. Move the point 6 places right: 1100011.0.
  6. Evaluate 1100011 = 64 + 32 + 2 + 1 = 99.
C2C60000H = −99. The two marks most often dropped here are forgetting the hidden 1 and forgetting to subtract the bias. Do both, every time.

(b) 21 address lines, 4-byte words (5 marks)  [M2 U1]

Given k = 21 address lines · word = 4 bytes · word-addressable
Find address space, total memory in MB, PC width
Formula address space = 2k · capacity = 2k × bytes per location · PC width = k
  1. Address space = 221 = 2 097 152 locations (words).
  2. Each word is 4 bytes, so capacity = 2 097 152 × 4 = 8 388 608 bytes.
  3. 8 388 608 ÷ 1024 ÷ 1024 = 8 MB.
  4. The PC must hold any address, so it is 21 bits wide.
2 097 152 words, 8 MB in total, PC 21 bits. Because the machine is word-addressable, each address names a 4-byte word, so the byte capacity is four times the number of locations.

(c) Image size (4 marks)  [M1 U2]

Given 8.5 in × 11 in · 200 dpi · black and white, 1 bit per pixel
Find the memory required, in KB
Formula bits = (w×dpi) × (h×dpi) × bpp, then ÷8 for bytes and ÷1024 for KB
  1. Pixels across: 8.5 × 200 = 1700. Pixels down: 11 × 200 = 2200.
  2. Total pixels = 1700 × 2200 = 3 740 000.
  3. At 1 bit per pixel: 3 740 000 bits ÷ 8 = 467 500 bytes.
  4. 467 500 ÷ 1024 = 456.54 KB.
3 740 000 pixels = 467 500 bytes ≈ 456.54 KB. Had a colour depth been given, say 24-bit, you would multiply the pixel count by 24 before dividing by 8.

(d) RISC versus CISC (5 marks)  [M4 U1]

RISCCISC
Few, simple, fixed-length instructionsMany, complex, variable-length instructions
Mostly one cycle per instructionAn instruction may take many cycles
Load/store: only those instructions touch memoryArithmetic may act directly on memory
Many registers, hardwired control, easy to pipelineFewer registers, microcoded control, harder to pipeline
Examples: RISC, ARM and MIPS (also SPARC, RISC-V). CISC, Intel x86 and Motorola 68000 (also VAX). The compiler does more work on a RISC machine; the hardware does more on a CISC one.
Recall and check

In Question One (e) you could not read the cache line off the hex digits, though you could in the past papers. Why, and what is the general rule?

Answer

Reading fields off hex digits only works when each field is a whole number of hex digits, that is a multiple of 4 bits. There the offset was 5 bits and the index 9, neither a multiple of 4, so the fields straddle hex-digit boundaries. The general rule: convert to decimal (or to full binary) and use line = (address ÷ block size) mod number of lines. Use the hex shortcut only when the offset and index are multiples of 4 bits, as they were with a 16-word block and 256 lines.
