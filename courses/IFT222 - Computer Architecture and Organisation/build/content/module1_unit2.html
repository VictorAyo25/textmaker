Data Representation

How whole numbers, positive and negative, are stored in a fixed number of bits. This is the single most examined topic on the paper, and every mark here is a mark you can guarantee with practice.

By the end of this unit you can represent any integer in unsigned, sign-magnitude, one's complement and two's complement form; state the range of each in n bits; add and subtract in binary; recognise overflow; use end-around carry; and size an image in memory. Every past question of these types is worked in full.

Unsigned integers: the starting point

With n bits and no sign, you can store the whole numbers from 0 up to 2n minus 1. Each pattern of bits is just its plain binary value. An 8-bit byte therefore holds 0 to 255, because 28 minus 1 is 255.

Must memoriseUnsigned range

In n bits, unsigned integers run 0 to 2n − 1. That is 2n different values in total.

Memory hook: n bits give 2n patterns; one of them is zero, so the largest is one less than 2n.

TeachShifting: multiply and divide by two

Because each position is worth twice the one to its right, moving every bit one place left doubles a number (×2) and moving it one place right halves it (÷2), in binary or hex alike. To halve 3FC in hex, shift its bits right by one: 3FC = 0011 1111 1100, shifted right is 0001 1111 1110 = 1FE. Check in decimal: 3FC = 1020, and 1020 ÷ 2 = 510 = 1FE; a left shift of 1FE returns 3FC. This is why shift instructions are the fastest way a processor multiplies or divides by powers of two.

The problem: how do you store a minus sign?

A memory cell holds only 0s and 1s, with nowhere to write a "−". So we spend one of the bits, the leftmost, to carry the sign, and 0 means positive, 1 means negative. There are three ways to do it, and the exam expects all three.

TeachThe three signed schemes
  • Sign-magnitude: the leftmost bit is the sign, the remaining bits are the plain size (magnitude) of the number. Simple to read, but it has two zeros (+0 and −0) and makes arithmetic awkward.
  • One's complement: to make a number negative, invert every bit of its positive form. Also has two zeros, but subtraction becomes addition (with a twist called end-around carry, below).
  • Two's complement: invert every bit and add 1. This is the one real computers use: it has a single zero, and addition and subtraction work with no special cases.

Seeing one small number in all three side by side fixes the idea. Take −5 in 4 bits. First write +5 as 0101, then apply each rule.

Worked examplePQ 24/25 Q3b · PQ 23/24 Q4b

Complete the table of Unsigned, Sign-magnitude, One's complement and Two's complement for 204 and −139, using 12 bits.

  1. Write 204 in 12-bit binary. 204 = 128+64+8+4, so 204 = 0000 1100 1100. Being positive, 204 looks identical in all four schemes.
  2. For −139, first write +139 in 12 bits: 139 = 128+8+2+1 = 0000 1000 1011.
  3. Sign-magnitude of −139: set the sign bit to 1, keep the magnitude: 1000 1000 1011.
  4. One's complement of −139: invert every bit of 0000 1000 1011: 1111 0111 0100.
  5. Two's complement of −139: add 1 to the one's complement: 1111 0111 0100 + 1 = 1111 0111 0101.

Worked examplePQ 25/26 Q1c

A telemetry system uses a 16-bit two's complement processor. The values are Temperature = −182, Pressure = 487, Altitude = −1023. (i) Give the representable range and say whether each value fits. (ii) Represent each in binary and hexadecimal. (iii) Compute (−182) + 487.

(i) Range

16-bit two's complement: −215 to +(215−1) = −32768 to +32767. All three values (−182, 487, −1023) fall inside this range, so all are representable.

(ii) Binary and hex

Method for −182: +182 = 0000 0000 1011 0110; invert to 1111 1111 0100 1001; add 1 to get 1111 1111 0100 1010 = FF4A.

(iii) (−182) + 487

Add the 16-bit patterns of −182 (FF4A) and 487 (01E7): 1111 1111 0100 1010 + 0000 0001 1110 0111 = 1 0000 0001 0011 0001. The carry out of the 16th bit is discarded in two's complement, leaving 0000 0001 0011 0001 = 0131H = 305. Check: −182 + 487 = 305. Correct.

Now redo it: this whole question is 25/26 Q1c and is worth easy marks. The trick is that in two's complement you just add the patterns and throw away the final carry.

Adding in binary, and when it overflows

Binary addition is column addition with carries, exactly like decimal but with only 0 and 1. The danger is overflow: when the true sum needs more bits than the register has, the top bit is lost and the stored answer is wrong.

Worked examplePQ 20/21 Q5b

Add 214 + 65 in an 8-bit register. Give the result in binary and decimal, and comment on overflow.

  1. Convert: 214 = 1101 0110, 65 = 0100 0001.
  2. Add the two bytes: 1101 0110 + 0100 0001 = 1 0001 0111. The result needs 9 bits.
  3. An 8-bit register holds only the low 8 bits, 0001 0111 = 23, and sets a carry.
True sum 214 + 65 = 279. In 8 bits the register keeps 0001 0111 = 23 and raises a carry out of the top bit. This is unsigned overflow: 279 will not fit in a byte (max 255), so the stored 23 is wrong by exactly 28 = 256.

Now redo it: overflow is simply "the answer needed more bits than the box has". State the true sum, the wrapped value, and that a carry came out.

Subtracting by adding: end-around carry

Computers subtract by adding a negative. In one's complement, this needs one extra step: if a carry comes out of the top after the addition, you add it back into the lowest bit. That step is the end-around carry, and it is asked almost every year.

Worked examplePQ 23/24, 24/25, tests (recurring)

Use end-around carry in one's complement to compute 153 − 142 in a 10-bit register.

  1. 153 − 142 becomes 153 + (−142). Write 153 in 10 bits: 00 1001 1001.
  2. Write −142 in one's complement: +142 = 00 1000 1110, invert to 11 0111 0001.
  3. Add: 00 1001 1001 + 11 0111 0001 = 1 00 0000 1010. A 1 has carried out of the 10th bit.
  4. End-around carry: drop that carry and add it into the lowest bit: 00 0000 1010 + 1 = 00 0000 1011.
  5. Read the result: 00 0000 1011 = 11. Positive (leading 0), and 153 − 142 = 11. Correct.
153 − 142 = 00 0000 1011 (one's complement, 10 bits) = 11.

Now redo it: the signature of one's complement is that a carry out never vanishes, it comes back in at the bottom. If there is no carry out, there is nothing to add and the result is already negative.

TeachOverflow versus underflow

Two words the exam likes to separate. Overflow is a result too large (too far positive, or a magnitude too big) to fit the available bits. Underflow is a result too small to represent: for integers, a value more negative than the smallest storable number; for floating point (Unit 3), a value so close to zero it rounds away to nothing. Example: in 8-bit two's complement (range −128 to +127), 100 + 50 = 150 overflows; −100 − 50 = −150 underflows.

Sizing an image in memory

An image is a grid of dots (pixels). Its size in memory is simply the number of pixels times the bits used per pixel. The number of pixels is the physical size in inches times the resolution in dots per inch (dpi), in each direction.

Must memoriseImage size

bits = (width×dpi) × (height×dpi) × bits-per-pixel. Then divide by 8 for bytes, by 1024 for KB, by 1024 again for MB. Unless a colour depth is given, this course assumes a black-and-white image at 1 bit per pixel (as the lecture example does).

Worked examplePQ 23/24, 24/25, 25/26 Q4c (recurring)

Find the memory needed for an image 17.12 inches by 9.45 inches at 250 dpi. Give the answer in megabytes.

  1. Pixels across: 17.12 × 250 = 4280. Pixels down: 9.45 × 250 = 2362.5. The height gives a non-whole 2362.5; carry it as is, the arithmetic is what earns the marks.
  2. Total pixels: 4280 × 2362.5 = 10 111 500.
  3. At 1 bit per pixel that is 10 111 500 bits. Divide by 8: 1 263 937.5 bytes.
  4. Divide by 1024 twice: 1 263 937.5 ÷ 1 048 576 = 1.205 MB (about 1.21 MB).
10 111 500 pixels × 1 bit = 10 111 500 bits = 1 263 937.5 bytes ≈ 1.21 MB (dividing by 1024×1024). If the paper divides by one million instead, it is about 1.26 MB: state which you used.

Now redo it: if a colour depth were given (say 24-bit colour), you would multiply the pixel count by 24 before dividing. Always check whether the question gives bits per pixel.

Two ways to store a picture: bitmap and vector

The sizing above assumed a bitmap. There are two families of computer graphics, and the point the exam likes is why their sizes differ so much.

TeachBitmap versus vector graphics
  • Bitmap (raster) graphics store the picture as a grid of pixels, each pixel's colour held explicitly. More pixels per inch means higher resolution and a sharper image, but the size grows with the pixel count (as sized above), and enlarging a bitmap makes the individual pixels show. Photographs are bitmaps.
  • Vector graphics store the picture as objects, such as lines, curves and shapes, each described by attributes: coordinates, length and breadth, line thickness, colour and fill. The image is redrawn from the maths at any size with no loss, and the file holds a few objects rather than millions of pixels, so line art and logos are far smaller as vectors. A photograph, having no simple shapes, does not reduce to vectors.
Worked exampleSlide: bitmap size

A black-and-white bitmap is 4 inches by 6 inches at 300 dpi. How much memory does it need?

  1. Pixels across: 4 × 300 = 1200. Pixels down: 6 × 300 = 1800.
  2. Total pixels: 1200 × 1800 = 2 160 000.
  3. At 1 bit per pixel (black or white): 2 160 000 bits ÷ 8 = 270 000 bytes.
  4. In KB: 270 000 ÷ 1024 = 263.67 KB.
2 160 000 pixels × 1 bit = 2 160 000 bits = 270 000 bytes ≈ 263.67 KB. Same method as the 17.12×9.45 image, different numbers.

Coded decimal: BCD and Excess-3

Pure binary is not always convenient. When decimal digits must stay exact and be read back one digit at a time (tills, meters, calculator displays), each digit is coded on its own.

TeachBinary Coded Decimal and weighted codes

Binary Coded Decimal (BCD) stores each decimal digit in its own 4 bits, so 47 is 0100 0111, not the pure-binary 101111. It wastes space (four bits can hold 0 to 15 but only 0 to 9 are used) yet keeps decimal exact. Standard BCD is a weighted code: the four positions carry the weights 8 4 2 1, and a digit is whichever bits sum to it. Other weightings exist; the lectures name 5421 and 4221, where the same "sum the weights of the 1-bits" rule applies.

TeachExcess-3, a self-complementing code

Excess-3 (XS-3) codes a digit as its 4-bit binary plus 3, so 0 is 0011, 5 is 1000, 9 is 1100. It is non-weighted but self-complementing: the code of (9 − d) is the bit-by-bit complement of the code of d, which makes nine's-complement subtraction easy. For instance XS-3 of 6 is 1001 and XS-3 of 3 is 0110, which are exact complements.

Worked exampleSlide: Excess-3 both ways

(i) Encode 24 in Excess-3. (ii) Decode 0100 0110 from Excess-3.

  1. Encode 24: digit 2 → 2+3 = 5 = 0101; digit 4 → 4+3 = 7 = 0111. So 24 = 0101 0111.
  2. Decode 0100 0110: 0100 = 4, minus 3 = 1; 0110 = 6, minus 3 = 3. So it reads 13.
24 in Excess-3 is 0101 0111; the code 0100 0110 decodes to 13. Going in, add 3 to each digit; coming out, subtract 3 from each nibble.
TeachCharacter codes: Morse to Unicode

Text is stored by an agreed table mapping each symbol to a number. Historically there was Morse code (variable-length dots and dashes, common letters kept short) and Hollerith code (punched-card columns, the ancestor of data processing). In computers today:

  • ASCII uses 7 bits, so 128 codes (0 to 127). Codes 32 to 126 are printable, code 32 is space and code 127 is DEL; 0 to 31 are control codes. "Extended ASCII" uses the eighth bit for codes 128 to 255 (for example ISO 8859-1, Latin-1).
  • EBCDIC uses 8 bits: IBM's mainframe code, descended from punched cards.
  • Unicode uses up to 32 bits, one code for every writing system; its first 128 codes are identical to ASCII.

A few ASCII values worth carrying into the exam: 'A' = 65, 'a' = 97, '0' = 48, space = 32.

Trap

Three classic slips. (1) In two's complement subtraction you discard the final carry; in one's complement you add it back. Do not mix them up. (2) Sign-magnitude and one's complement have two zeros; two's complement has one, which is why its range reaches one more negative value. (3) When negating, invert all the bits including leading zeros, not just the ones that are set.

Recall and check

In n bits, what is the two's complement range, and why is it not symmetric about zero?

Answer

−2n−1 to +(2n−1−1). It is asymmetric because there is a single zero on the positive side of the wheel, so the negatives get one extra value. In 8 bits: −128 to +127.
