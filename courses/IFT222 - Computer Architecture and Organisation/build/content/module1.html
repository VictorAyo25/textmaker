Architecture versus Organization

Two words that sound like synonyms, mean different things, and are worth an easy few marks on every paper if you can tell them apart cleanly.

By the end of this unit you can define architecture and organization and give examples of each, draw and compare the Von Neumann and Harvard designs, explain the Von Neumann bottleneck and how to reduce it, and answer every past question of this type in full.

TeachWhat a computer is, and its parts

A computer is a programmable device that stores, retrieves and processes data, following a stored set of instructions to turn input into output. Every computer, from a phone to a server, is built from the same handful of parts:

  • CPU (processor): the control unit and ALU that carry out instructions.
  • Memory: holds the instructions and data the CPU is working on (Module Three).
  • Storage: keeps data when the power is off (disk, SSD).
  • Input/output devices: move data in and out (keyboard, screen, network).
  • The motherboard (system board) and its buses: the circuit board that holds the parts and the wires that join them.

The rest of this module looks at how those parts are organised and how the CPU steps through a program.

The one distinction everything hangs on

Think of a car. The architecture is what the driver sees and uses: the steering wheel, the pedals, the gear positions, the promise that pressing the accelerator makes the car go faster. The organization is what is under the bonnet: the size of the engine, how the fuel is delivered, how the pedal is physically connected to the engine. Two cars can drive identically for the driver (same architecture) while being built completely differently inside (different organization).

TeachThe core idea

Computer architecture is the set of attributes visible to the programmer, the things that affect how a program is written: the instruction set, the number and size of registers, the data types, the addressing modes, the way memory is addressed. It answers "what does the machine do?"

Computer organization is how those attributes are actually realised in hardware, the parts hidden from the programmer: the control signals, the buses, the memory technology used, whether an add is done by one circuit or several. It answers "how does the machine do it?"

Must memoriseMemory hook

Architecture = what the programmer sees. Organization = how it is built.

Memory hook: Architecture is Abstract (the visible promise); Organization is the Operation (the hidden wiring that keeps the promise). Same instruction set, different organization, is exactly how a cheap and an expensive processor can run the identical program.

How a computer runs a program: the instruction cycle

Before we compare designs, fix the basic rhythm in your mind, because every later idea (pipelining, cache, performance) is a refinement of it. The processor repeats three steps, over and over, billions of times a second.

TeachFetch, decode, execute

Fetch: the control unit reads the next instruction from memory into the processor. Decode: it works out what the instruction is asking for. Execute: the arithmetic and logic unit (ALU) carries it out. Then the cycle starts again on the next instruction. Everything else in this course is about doing these steps faster or feeding them with data sooner.

Two ways to wire memory to the processor

A computer must store both the program (the instructions) and the data those instructions work on. The two great design templates differ in one decision: do instructions and data share one memory and one path, or get separate ones?

TeachVon Neumann architecture

In the Von Neumann design there is one memory holding both instructions and data, reached over one shared bus. This is elegant and cheap: the same memory stores everything, and a program can even treat its own instructions as data. Almost all general-purpose computers use it.

TeachHarvard architecture

In the Harvard design, instructions and data live in separate memories reached over separate buses. The processor can fetch an instruction and read data at the same time, which is faster, but it costs more and is less flexible. It is common in signal processors and microcontrollers, and inside the CPU's own caches.

The Von Neumann bottleneck

The Von Neumann design has one famous weakness, and the exam asks about it almost every year, so it is worth full marks to you.

TeachThe bottleneck

Because instructions and data share one bus, the processor cannot fetch an instruction and read or write data at the same instant. It must take turns. The single shared path between the CPU and memory therefore limits how fast the whole machine can go, however fast the CPU itself is. That limit is the Von Neumann bottleneck: the CPU is often left waiting on the one road to memory.

TeachHow to reduce it

Three standard ways to ease the bottleneck, each worth a mark:

  • Cache memory: keep a small, fast copy of the most-used instructions and data inside or beside the CPU, so most accesses never travel the slow bus (Module Three).
  • Separate caches for instructions and data (a Harvard-style split inside the chip), so the two can be fetched at once even on a Von Neumann machine.
  • Wider or faster buses, and registers: move more bits per trip, and keep frequently used values in fast CPU registers so the bus is used less often.

Modern machines add further tricks in the same spirit: faster DDR memory, prefetching data into cache before it is asked for, and even processing-in-memory (PIM), doing simple work in the memory chip itself to save a bus trip.

Trap

Do not say Harvard is "better" and stop there. The exam wants the trade-off: Harvard is faster because of simultaneous access, but Von Neumann is simpler, cheaper and more flexible, which is why general-purpose computers use it. A bare "Harvard is faster" leaves marks on the table.

Recall and check

In one sentence each: what is the Von Neumann bottleneck, and what is the single most common cure for it?

Answer

The bottleneck is that the single shared bus lets only instructions or data move at a time, so the CPU waits on memory. The most common cure is cache memory: a small fast store that keeps most accesses off the slow bus.
