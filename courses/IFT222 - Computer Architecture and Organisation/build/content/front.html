How to use this manual

This book takes you from knowing nothing about how a computer is built to solving every past question on this course with a perfect score. Read it with a pen, not just your eyes.

Computer Architecture and Organisation looks frightening because it mixes three things at once: a little binary arithmetic, a handful of diagrams, and a set of formulas for speed and memory. In truth the whole course is about a dozen ideas, each used over and over. This manual finds those ideas, teaches each one from zero, and then makes you use it on the real exam questions straight away. Nothing is assumed. Every number is worked out in full. Every symbol is explained before it appears.

The one habit that makes this work

Reading feels like studying and teaches almost nothing. What moves a fact into your memory is pulling it back out. So all through the book you will meet a RECALL AND CHECK box: a question with the answer hidden under a dashed line. Cover the answer, say yours out loud or on paper, then look. When a worked example ends, you will see Now redo it: close the book and reproduce the solution on blank paper. If you only ever do that one thing, you will pass.

Foundations · F.1

Number Systems and Positional Notation

A number system is just a set of symbols and one rule for reading a row of them. Learn the rule once and every base behaves the same way.

What "base" means

You already use a number system fluently: the decimal system, base 10. It has ten symbols, 0 to 9. When you run out of symbols you do not invent a new one, you start a new column to the left. The genius of the system, invented long before computers, is that the position of a digit tells you its value. In 735 the 7 does not mean seven, it means seven hundred, because of where it sits.

TeachPositional notation

Reading right to left, each column is worth the base raised to a higher power: the ones column is base0, the next is base1, the next base2, and so on. The value of the whole number is each digit multiplied by its column, all added up. In base 10:

Written as a formula, a number whose digits are d in base b has

value = dn−1×bn−1 + ... + d1×b1 + d0×b0
what each symbol means b = the base (2 binary, 8 octal, 10 decimal, 16 hexadecimal) · di = the digit sitting in column i · i = the column number, counted from 0 at the rightmost digit · n = how many digits the number has

The four bases this course uses

Humans count in base 10. Computers are built from switches that are either on or off, so at heart they count in base 2, binary, with just two symbols, 0 and 1. Binary numbers get long quickly, so we also use base 16, hexadecimal and occasionally base 8, octal as a shorthand: they pack neatly into binary, as F.2 will show. A single binary digit is a bit; eight bits make a byte.

Worked exampleSlide

Read the binary number 1011B into decimal.

Given number = 1011 · source base b = 2 · target base = 10
Find its decimal value
Formula value = Σ di × bi, i counted from 0 at the right
what each symbol means b = 2, the base you are reading from · di = the bit in column i · i = 0 for the rightmost bit, so the columns are worth 1, 2, 4, 8
  1. Write each bit over its column value, right to left: columns are 23, 22, 21, 20, that is 8, 4, 2, 1. Bits: 1, 0, 1, 1.
  2. Keep only the columns with a 1 in them: 8, then 2, then 1. The 4 column has a 0, so it contributes nothing.
  3. Add them: 8 + 2 + 1 = 11.
1011B = 8 + 2 + 1 = 11 (decimal)

Now redo it: cover the working and convert 10110B. You should get 22.

Recall and check

In any base, what is the value of the rightmost column, and why is it the same for every base?

Answer

It is always 1, because the rightmost column is base0, and any base raised to the power 0 is 1. That is why the last digit is called the units digit in every system.

Foundations · F.2

Converting Between Bases

Four conversions cover everything the exam asks: any base to decimal, decimal to any base, and the quick grouping trick between binary and hex or octal.

Any base to decimal: multiply and add

This is just positional notation from F.1 applied in reverse. Multiply each digit by its column value and add. It works for any base, you only change what the columns are worth.

Worked exampleSlide

Convert the hexadecimal number A34EH to decimal.

Given number = A34E · source base b = 16 · target base = 10
Find its decimal value
Formula value = Σ di × 16i
what each symbol means b = 16 · di = the digit in column i, with the letters standing for numbers (A = 10 up to F = 15) · the columns are worth 1, 16, 256, 4096
  1. Replace each hex letter by its value: A = 10, 3 = 3, 4 = 4, E = 14.
  2. Write the column values, right to left, as powers of 16: 163 = 4096, 162 = 256, 161 = 16, 160 = 1.
  3. Multiply digit by column: 10×4096 = 40 960; 3×256 = 768; 4×16 = 64; 14×1 = 14.
  4. Add: 40 960 + 768 + 64 + 14 = 41 806.
A34EH = 40 960 + 768 + 64 + 14 = 41 806 (decimal)

Now redo it: reproduce the four column values from memory before you multiply. That is where marks are lost, not in the adding.

Decimal to any base: divide and collect remainders

Go the other way by repeatedly dividing by the base and writing down the remainder each time. The remainders, read from bottom to top, are the answer.

Worked exampleSlide

Convert decimal 13 to binary.

Given number = 13 · source base = 10 · target base b = 2
Find its binary form
Formula divide repeatedly by b, keeping each remainder; read the remainders bottom-up
what each symbol means b = 2, the base you are converting into, so it is what you divide by · each remainder is one digit of the answer · the remainders come out least significant first, which is why the column is read upwards
DivideQuotientRemainder
13 ÷ 261
6 ÷ 230
3 ÷ 211
1 ÷ 201

Read the remainders bottom to top: 1101.

13 = 1101B   (check: 8 + 4 + 1 = 13)

Now redo it: convert 22 to binary. You should get 10110, and the check is 16 + 4 + 2 = 22.

Trap

The remainders come out least significant first. If you read them top to bottom you get the number backwards. Always read the column of remainders from the bottom up, and sanity-check by converting back.

Binary to hex, and back: group in fours

Hexadecimal exists to make binary readable, and the reason is exact: one hex digit is worth exactly four bits (because 16 = 24). So to turn binary into hex you simply slice the bits into groups of four from the right and convert each group on its own. Octal is the same trick in groups of three, because 8 = 23.

Worked exampleMethod

Convert 11010110B to hexadecimal.

Given number = 11010110 · source base = 2 · target base = 16
Find its hexadecimal form
Formula group the bits in fours from the right; each group of 4 bits is one hex digit
what each symbol means grouping works because 16 = 24, so exactly four bits carry one hex digit · group from the right, and pad a short leftmost group with leading zeros
  1. Slice into groups of four bits, starting from the right: 1101 0110.
  2. Convert each group using the powers 8, 4, 2, 1: 1101 = 8+4+1 = 13 = D;   0110 = 4+2 = 6.
  3. Write the hex digits in the same order: D6.
11010110B = 1101 0110 = D6H   (check: both equal 214)

Now redo it: go backwards. Convert 2FH to binary by expanding each digit to four bits: 2 = 0010, F = 1111, giving 0010 1111.

Trap

Group from the right, not the left, and pad the leftmost group with leading zeros if it is short. Grouping 110101101011101 from the left would misalign every digit. From the right it is 110 1011 0101 1101, and the short leading group 110 pads to 0110 = 6, giving 6B5DH.

Recall and check

Why can binary group into hex in fours but not into decimal in any fixed size?

Answer

Because 16 is a whole power of 2 (16 = 24), so four bits map exactly onto one hex digit with none left over. 10 is not a power of 2, so no fixed number of bits ever lines up cleanly with one decimal digit. This is the whole reason hex and octal, not decimal, are used as binary shorthand.
