AnswerQuestion One

(a) Architecture vs organization; Von Neumann vs Harvard (see M1 U1)

Architecture is the programmer-visible design (instruction set, registers, addressing modes): what the machine does. Organization is how that is built in hardware (control signals, buses, memory technology): how it does it. Von Neumann uses one memory and one bus for instructions and data (simple, but the bus is a bottleneck); Harvard uses separate memories and buses (simultaneous access, faster, costlier). Draw both diagrams.

(b) CPI (see M2 U2)

(i) CPI = 0.45(1) + 0.25(4) + 0.15(2) + 0.15(3) = 0.45 + 1.00 + 0.30 + 0.45 = 2.20. (ii) Total cycles = 2 000 000 × 2.20 = 4 400 000. (iii) With Load at 2 cycles: CPI = 0.45 + 0.25(2) + 0.30 + 0.45 = 1.70. (iv) Improvement = (2.20 − 1.70) / 2.20 = 22.73%.

AnswerQuestion Two

(a) Pipeline timing (see M2 U3)

(i) Cycle time = slowest stage + latch = 25 + 5 = 30 ns. (ii) Non-pipeline one task = 20 + 15 + 25 + 20 + 10 = 90 ns. (iii) Pipeline for 1000 tasks = (5 + 999) × 30 = 1004 × 30 = 30 120 ns. (iv) Sequential for 1000 = 1000 × 90 = 90 000 ns. (v) Speedup = 90 000 / 30 120 = 2.99.

(b) Hazards (see M2 U3, M4 U2)

Structural (two instructions need the same hardware: duplicate it), data (a value is needed before it is written back: use forwarding, and one stall for a load-use case), control (a branch changes the next instruction: resolve early or flush). Forwarding feeds a result straight from where it is produced; a load value is not ready until the memory stage, so the very next instruction still needs one stall.

(c) Why speedup < stages

The pipeline must first fill (the first task still takes k cycles), and hazards insert stalls, so the ideal ceiling of k is never quite reached, especially for few tasks.

AnswerQuestion Three

(a) Cache configuration (see M3 U3)

(i) Blocks = cache / block = 64 KB / 32 B = 216 / 25 = 2048 blocks. (ii) Sets = 2048 / 4 = 512 sets. (iii) Address = 256 MB = 228, so 28 bits. Offset = log232 = 5, set = log2512 = 9, tag = 28 − 9 − 5 = 14 bits. Format: tag 14, set 9, offset 5.

(b) AMAT (see M3 U3)

Simultaneous = 0.9(3) + 0.1(60) = 2.7 + 6 = 8.7 ns. Hierarchical = 3 + 0.1(60) = 3 + 6 = 9.0 ns.

(c) Locality (see M3 U1)

Locality of reference is the clustering of accesses in a small region over any short time. Temporal: a location used now is likely used again soon (so cache keeps recently used data). Spatial: nearby locations are likely used soon (so cache fetches whole blocks of neighbours).

(c) RISC vs CISC (see M4 U1)

RISC: few simple fixed-length one-cycle instructions, load-store, many registers (example ARM or MIPS). CISC: many complex variable-length multi-cycle instructions, direct memory access, fewer registers (example Intel x86 or Motorola 68000).

AnswerQuestion Five

(a) Amdahl's law (see M2 U2)

Stating it (the question says "state", so a formula alone does not answer it): the gain in overall performance from improving one part of a system is limited by the fraction of the total time that part accounts for. If a fraction f of the execution time is made s times faster and the rest is unchanged, the overall speedup is S = 1 / ((1 − f) + f/s); and as s grows without bound S tends to 1 / (1 − f), which is the ceiling no improvement to that part can pass.

Applying it. With f = 0.90 and s = 8: Speedup = 1 / (0.10 + 0.90 / 8) = 1 / (0.10 + 0.1125) = 1 / 0.2125 = 4.71. Sanity check against the ceiling: 1 / (1 − 0.90) = 10, and 4.71 is below it, as it must be.

(b) DRAM vs SRAM (see M3 U2)

DRAM stores a bit as capacitor charge, needs refresh, is slower, denser and cheaper, and is used for main memory. SRAM stores a bit in a transistor latch, needs no refresh, is faster, less dense and dearer, and is used for cache. Cache needs speed; main memory needs cheap capacity.

(c) Memory access methods (see M3 U1)

Sequential (read in order, example magnetic tape), direct (jump near then search, example disk), random (any location in equal time, example RAM), associative (located by content, example a cache tag store).
