AnswerQuestion One

(a) Von Neumann (see M1 U1)

(i) The Von Neumann concept: a stored-program computer keeps instructions and data in the same memory and executes instructions sequentially. Two aspects: a single shared memory for code and data; sequential fetch-execute of a stored program. (ii) The bottleneck: the single shared bus lets only instructions or data move at a time, so the CPU waits on memory. Reduce it with cache and with separate instruction and data caches (or wider buses).

(b) 16-bit two's complement (see M1 U2)

(i) Range = −215 to +(215−1) = −32768 to 32767; 300, −200 and −5000 all fit.

(iii) 300 + (−200): add the patterns 012C + FF38 = 1 0064, discard the carry out of bit 16, leaving 0064H = 100. Check: 300 − 200 = 100.

(c) IEEE-754 (see M1 U3)

(i) 85.75 = 1010101.11 = 1.01010111 × 26. Exponent 6 + 127 = 133 = 1000 0101. Mantissa 01010111 to 23 bits. Word = 0 10000101 01010111000000000000000 = 42AB8000H. (ii) C2960000H: sign 1, exponent 1000 0101 = 133 so e = 6, mantissa 0010110, value = −1.0010110 × 26 = −1001011 = −75.0.

(d) Instruction formats and bytes (see M1 U4)

3-address (opcode 1, three addresses 2 each = 7 bytes each):

ADD T1, A, B      ADD T2, C, D      MUL T1, T1, T2      ADD Z, T1, E

4 instructions × 7 = 28 bytes. 0-address (postfix A B + C D + × E +): PUSH A, PUSH B, ADD, PUSH C, PUSH D, ADD, MUL, PUSH E, ADD, POP Z = 10 instructions = 5 pushes × 3 + 1 pop × 3 + 4 ops × 1 = 22 bytes.

AnswerQuestion Two

(a) Cache fields and block lookup (see M3 U3)

(i) Offset = log28 = 3, index = log2512 = 9, tag = 32 − 9 − 3 = 20. (ii) Block = (address with the low 3 offset bits removed) mod 512, that is (address ÷ 8) mod 512. ABCD1234H gives block 70; 5678FEDCH gives block 475.

(b) The three mapping functions (see M3 U3)

Direct: one line per block (fast and simple, but conflict misses). Fully associative: a block may go anywhere (no conflict misses, but every tag must be searched, costly). Set associative: a block maps to one set of k lines (the compromise, fewer conflicts than direct at less cost than fully associative).

(b) End-around carry (see M1 U2)

200 − 75 = 200 + (−75). 200 = 0011001000; −75 in one's complement = 1110110100. Add: 0011001000 + 1110110100 = 1 0001111100, a carry out of bit 10. End-around: drop it and add 1 to the low bit: 0001111100 + 1 = 0001111101 = 125. Check: 200 − 75 = 125.

(c) Image memory (see M1 U2)

Pixels = (8 × 200) × (10 × 200) = 1600 × 2000 = 3 200 000. At 1 bit per pixel that is 3 200 000 bits = 400 000 bytes = 400 000 / 1 048 576 = 0.381 MB (about 0.38 MB).

AnswerQuestion Four

(a) IEEE-754 reverse (see M1 U3)

43A00000H = 0100 0011 1010 0000…: sign 0, exponent 1000 0111 = 135 so e = 8, mantissa 0100000. Value = 1.0100000 × 28 = 101000000 = 320.0.

(b) Instruction categories (see M1 U4)

Data transfer (LOAD, STORE, MOVE, PUSH, POP), arithmetic and logic (ADD, SUB, MUL, AND, OR), control or test-and-branch (JUMP, BEQ, CALL, RETURN).

(c) Addressing modes (see M1 U4)

Immediate: the operand is the address field itself (a constant). Direct: the operand is M[address field]. Indirect: the field points to a location that holds the address, so the operand is M[M[address field]]. Register-indirect: a register holds the address, so the operand is M[register].

AnswerQuestion Five

(a) Pipeline timing (see M2 U3)

Cycle time = slowest stage + latch = 50 + 5 = 55 ns. Pipeline time for 200 tasks = (4 + 199) × 55 = 203 × 55 = 11 165 ns. Sequential time = 200 × (40 + 30 + 50 + 35) = 200 × 155 = 31 000 ns. Speedup = 31 000 / 11 165 = 2.78.

(b) Memory hierarchy (see M3 U1)

Registers, then cache (L1, L2, L3), then main memory (RAM), then secondary storage (disk, SSD), then tertiary (tape). Going down: bigger, slower and cheaper per byte. Going up: smaller, faster and dearer.

(c) AMAT (see M3 U3)

Hierarchical: AMAT = Tcache + (1 − h) × Tmemory = 4 + 0.15 × 70 = 4 + 10.5 = 14.5 ns.
