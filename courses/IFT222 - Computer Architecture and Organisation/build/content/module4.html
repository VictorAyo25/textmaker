Processor Architectures

Two design philosophies, the reduced instruction set (RISC) and the complex instruction set (CISC), and the ways many processors are joined to work in parallel. Mostly a describing-and-comparing module, which means fast, reliable marks if you know the contrasts cleanly.
Module Four · Unit 1

RISC versus CISC

Two philosophies of instruction-set design: keep instructions few and simple, or make them many and powerful. Naming the differences and example processors is worth easy marks every year.

By the end of this unit you can give at least four differences between RISC and CISC and name example processors of each.

TeachThe two philosophies

CISC (Complex Instruction Set Computer) provides many powerful instructions, some doing a lot of work in one instruction (including direct memory-to-memory operations). This makes programs short but the hardware complex, and instructions take varying numbers of cycles.

RISC (Reduced Instruction Set Computer) provides few, simple, fixed-length instructions, each doing a little in (ideally) one cycle, with memory touched only by dedicated load and store instructions (a load-store architecture). Programs are longer but the hardware is simple and fast, and it pipelines well.

TeachWhy CISC came first, then RISC

The order is not an accident, it follows the cost of memory. In the 1960s and 1970s memory was expensive and slow while processor hardware was relatively cheap, so the sensible trade was to make each instruction do as much as possible and keep programs short. That is the CISC idea, and it also made the compiler's job easy, since one powerful instruction could stand in for a whole sequence.

By the early 1980s two measurements changed the trade. Researchers found that most programs use only a small subset of the available instructions, and that the complex instructions took many cycles while simple ones could run in one. If the fancy instructions are rarely used and slow when they are, why pay for them? Stripping them out gives the RISC idea: a few fast instructions, and let the compiler build the rest. RISC grew out of that early-1980s work: the IBM 801, Stanford MIPS and Berkeley RISC 1 and 2 were all designed on the philosophy that came to be called RISC.

The slide's answer. Because memory was expensive, and CISC instructions could perform complex operations using fewer instructions, thereby reducing program size. In other words the whole point of CISC was to spend cheap processor complexity to save on costly memory, which is exactly the trade the paragraph above describes. A one line question like this is worth 2 marks on a describing question, so learn the sentence.
TeachThe same multiply, both ways

The clearest way to feel the difference is to watch each philosophy multiply two numbers held in memory. CISC offers one instruction that reaches into memory, multiplies and writes back. RISC forbids arithmetic on memory: you must load both operands into registers, multiply register to register, then store the result. RISC needs four instructions where CISC needs one, yet each RISC instruction is simple, fixed-length and one cycle, so it pipelines cleanly.

; CISC: one instruction, memory to memory
MUL  C, A, B        ; C ← A × B, all in one

; RISC: load, work in registers, store
LOAD  R1, A         ; bring A into a register
LOAD  R2, B         ; bring B into a register
MUL   R3, R1, R2    ; multiply, register to register
STORE C, R3         ; write the result back to memory

This is the trade in miniature: CISC hides the loads and stores inside the multiply and pays for it with a slow, many-cycle instruction; RISC exposes them and pays with a longer program of fast instructions. The compiler, not the hardware, arranges the four RISC lines, which is what "complexity pushed to the compiler" means in the table below.

TeachWhy CISC needs microcode

A CISC instruction is too complex to run directly, so inside the processor it is first translated into a string of tiny internal steps called microinstructions, and those are what actually execute. A RISC instruction is already simple enough to run directly in hardware (hardwired control), with no translation layer. That extra step is a large part of why CISC instructions take more cycles and are harder to pipeline.

TeachThe contrast in numbers

When the paper asks for "clear differences", these concrete figures turn a vague contrast into a marked one:

  • Instruction count: CISC typically has a large set, on the order of 100 to 250 instructions; RISC keeps it small and simple.
  • Addressing modes: CISC offers many, roughly 5 to 20; RISC has only a few, because nearly every instruction uses simple register addressing.
  • Instruction length: CISC instructions are variable in size; RISC are a fixed size, aligned on word boundaries, which is what makes them easy to decode and to pipeline.
  • Control: CISC uses microcode; RISC uses hardwired control.
  • Registers: RISC provides many general-purpose registers, CISC relatively few.

Key point

RISC and CISC do not disagree about what a program must do. They disagree about WHERE the complexity should live. CISC puts it in the hardware, in rich instructions and a microprogrammed control unit. RISC puts it in the compiler, building complex operations out of simple fast instructions.

Blunt version: somebody has to do the hard work. CISC makes the chip do it, RISC makes the compiler do it.

TeachAdvantages and disadvantages

The slides ask you to weigh each side, so keep two points ready for each:

  • CISC advantages: fewer instructions do a given task, which saves on the slow, expensive memory CISC was built for; and microprogramming the control unit is easier and cheaper than hardwiring it, so a rich instruction set is affordable.
  • CISC disadvantages: the complex instructions are rarely used yet the hardware still has to carry them, the many memory operations are slow, and the whole design grows more complex, and harder to pipeline, with every generation.
  • RISC advantages: often 2 to 4 times the performance of a comparable CISC at the same clock, simpler hardware that uses less chip area, a shorter design cycle, and one instruction finished per cycle, which pipelines cleanly.
  • RISC disadvantages: performance leans heavily on the compiler, so poor instruction scheduling leaves the processor stalling; and because each instruction does little, programs expand (code expansion) and need a fast memory system, usually a large on-chip cache, to keep the pipeline fed.

the lecturer's own question, and the answer the slide gives

Why is pipelining more difficult in CISC processors?
The slide's answer. Because instructions have varying lengths and execution times, making it harder to process instructions uniformly through the pipeline stages. This is the flip side of everything above: a pipeline wants every instruction to be the same shape so the stages line up, and CISC instructions are not, whereas RISC's fixed-length one-cycle instructions are. Expect this as a short 2 to 3 mark question, and answer it in exactly this shape.
Recall and check

Why does RISC pipeline more easily than CISC?

Answer

RISC instructions are fixed-length and mostly take one cycle, so the stages line up uniformly and hazards are easier to manage. CISC instructions vary in length and cycle count, which makes overlapping them much harder.

Module Four · Unit 2

Parallel Architectures and Interconnection Networks

When one processor is not enough, many are joined to work together. This unit classifies parallel machines and the networks that connect them, and completes the data-hazard picture from pipelining.

By the end of this unit you can state Flynn's taxonomy, describe common interconnection networks, and name the three types of data hazard.

TeachFlynn's taxonomy

Parallel machines are classified by how many instruction streams and data streams they run at once:

  • SISD: Single Instruction, Single Data. The classic single processor.
  • SIMD: Single Instruction, Multiple Data. One instruction acts on many data items at once (vector and graphics processors).
  • MISD: Multiple Instruction, Single Data. Rare; several operations on one data stream (some fault-tolerant designs).
  • MIMD: Multiple Instruction, Multiple Data. Many processors running different instructions on different data (multicore CPUs, clusters).
TeachInterconnection networks

The processors and memories must be wired together. Common schemes: shared bus (simple, but one at a time), crossbar (every processor to every memory, fast but costly), mesh (each node to its neighbours, scales well), and hypercube and ring topologies. The trade-off is always cost and wiring against how many transfers can happen at once.

TeachThe three data hazards

Completing the pipelining picture (Module Two), data hazards come in three types, named by the order of the clashing accesses:

  • RAW (read after write): an instruction reads a value before the earlier instruction has written it. The true dependency, and the common one.
  • WAR (write after read): an instruction writes a value before an earlier one has read it.
  • WAW (write after write): two instructions write the same location in the wrong order.
