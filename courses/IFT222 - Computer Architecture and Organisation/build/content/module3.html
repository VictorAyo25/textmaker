Computer Memory Overview

Why memory is built as a hierarchy, how memory is accessed, and the principle of locality that makes the whole scheme work.

By the end of this unit you can describe the memory hierarchy and the four access methods, and explain locality of reference, including temporal and spatial locality. The recurring exam questions of this type are answered here.

Anchor

Think of where you keep things while working. The two or three pages actually under your hand are on the desk: instantly reachable, and there is room for almost nothing. The rest of the file is in the drawer, a second away. The other files are on the shelf across the room, and the archive is in a warehouse across town. Nobody designed that as a hierarchy. It happened because fast access and large capacity cost each other, and a computer's memory is organised the same way for the same reason.

The memory hierarchy

No single memory is both fast and large and cheap. So computers use several, arranged in a hierarchy: fast, small, expensive memory near the CPU, backed by slower, larger, cheaper memory further away. Data moves up the hierarchy when it is needed and down when it is not.

Must memoriseThe hierarchy

From fastest and smallest to slowest and largest: registers, cache (L1, L2, L3), main memory (RAM), secondary storage (disk, SSD), tertiary (tape).

Memory hook: as you go down, everything grows except speed and cost per byte: bigger, slower, cheaper. As you go up: smaller, faster, dearer.

TeachAccess methods
  • Sequential: read from the start in order until you reach the item (magnetic tape). Slow, access time depends on position.
  • Direct: jump near the item, then search a small region (disk: seek the track, then read round it).
  • Random: any location takes the same time to reach, by its address (RAM).
  • Associative: located by content, not address; all locations checked at once (used inside cache to find a tag). Fastest, most expensive.
TeachCharacteristics and vocabulary of memory

Memory is described by four characteristics: its location (registers, cache, main, external), its access method (above), its performance (access time and transfer rate), and its capacity. The units of capacity, smallest first:

  • Bit, one 0 or 1. A nibble is 4 bits; a byte is 8 bits.
  • Cell, one addressable location (often a byte); an address names one cell.
  • Word, the natural unit the CPU works on (say 32 or 64 bits).
  • Block, the unit moved between levels (several words), the key idea for cache.

If a memory holds 2n words with K words per block, it has M = 2n / K blocks, and needs an n-bit address.

what each symbol means n = the number of address bits, so 2n is the total number of addressable words · K = how many words are in one block (the unit moved between levels) · M = the resulting number of blocks in main memory (this M is a block count; the M of Module One Unit 3 was the IEEE mantissa)

How many bits does a 4 MB byte-addressable memory hold, and how many address lines does it need?

Given capacity = 4 MB · addressing = byte-addressable, so one cell is 1 byte = 8 bits
Find the total number of bits, and the number of address lines
Formula bytes = MB × 1024 × 1024 · bits = bytes × 8 · address lines k = log2(number of cells)
what each symbol means MB = 1024 × 1024 bytes, not a round million · byte-addressable = each address names one byte, so cells = bytes · k = address lines, and because 4 194 304 = 222, k is just that exponent
  1. 4 MB = 4 × 1024 × 1024 = 4 194 304 bytes.
  2. Bits: 4 194 304 × 8 = 33 554 432 bits ≈ 33.5 million bits.
  3. Address lines: 4 194 304 = 222 cells, so 22 address lines.
A 4 MB memory = 4 194 304 bytes = 33 554 432 bits (≈ 33.5 Mbit), addressed by 22 lines (222 = 4 194 304).
TeachLocality of reference

Cache works because real programs do not touch memory randomly.

The principle, stated

The principle of locality of reference. Over any short interval of its execution, a program references only a small and predictable subset of its address space, rather than spreading its accesses evenly across the whole of it.

It takes two forms, and a full answer names both: temporal locality, that a location referenced now is likely to be referenced again soon; and spatial locality, that locations near one just referenced are likely to be referenced soon.

Consequence: a small fast memory holding recently used blocks will satisfy the large majority of accesses. Locality is the assumption the entire memory hierarchy rests on: without it, caching would give no benefit at all.

Taking the two forms in turn:

  • Temporal locality: a location just used is likely to be used again soon (a loop counter, a variable). So keep recently used data close.
  • Spatial locality: a location near one just used is likely to be used soon (the next array element, the next instruction). So fetch neighbours together, a whole block at a time.

These are exactly why cache stores recently used blocks (temporal) and stores data in blocks of neighbours (spatial).

Locality of reference is the tendency of a program to access a small, predictable set of memory locations during any short period. Temporal locality: a location accessed now is likely to be accessed again soon (so cache keeps recently used items). Spatial locality: locations near one just accessed are likely to be accessed soon (so cache fetches a whole block of neighbouring words at once).
Worked exampleSlide: why the hierarchy pays

A two-level store has a fast level (1000 words, access 0.01 µs) and a slow level (100 000 words, access 0.1 µs). If 95% of accesses are found in the fast level, what is the average access time?

Given fast level: 1000 words at T1 = 0.01 µs · slow level: 100 000 words at T2 = 0.1 µs · H = 0.95
Find the average access time of the pair
Formula average = H×T1 + (1 − H)×(T1 + T2)
the formula, symbol by symbol average = H×T1 + (1 − H)×(T1 + T2). Here H = the hit ratio at the fast level, 0.95 · T1 = the fast level's access time, 0.01 µs · T2 = the slow level's access time, 0.1 µs · the miss term adds both times because you look in the fast level first and only then go to the slow one · the capacities (1000 and 100 000 words) do not enter the arithmetic at all, they only explain why the hit ratio is what it is
  1. Hit (95%): the word is in the fast level, costing 0.01 µs.
  2. Miss (5%): pay the fast level, then the slow level: 0.01 + 0.1 = 0.11 µs.
  3. Average = 0.95 × 0.01 + 0.05 × 0.11 = 0.0095 + 0.0055 = 0.015 µs.
Average access time = 0.95(0.01) + 0.05(0.11) = 0.015 µs, close to the fast level's 0.01 µs and far below the slow level's 0.1 µs. That gap, bought by a high hit rate, is the whole reason for the hierarchy. The same formula scales to any two levels (see average memory access time, AMAT, in Unit 3).
Recall and check

A loop repeatedly reads the same counter and steps through an array. Which kind of locality does each show?

Answer

The repeated counter is temporal locality (same location, used again and again). Stepping through the array is spatial locality (successive nearby locations).

Key point

Memory technologies trade speed, capacity and cost against each other, and no technology wins on all three at once. The hierarchy exists so that the small fast expensive store holds what is being used now, and the large slow cheap store holds everything else, giving the average speed of the fast one at close to the price of the slow one.

Blunt version: fast, big, cheap: pick two. The hierarchy is how a machine fakes all three.
