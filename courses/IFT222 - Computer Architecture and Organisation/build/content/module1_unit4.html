Instruction Set Architecture

The instruction set is the vocabulary the processor understands, and the boundary between hardware and software. Two exam staples live here: writing an expression in the 0, 1, 2 and 3 address formats, and computing an effective address.

By the end of this unit you can list the parts of an instruction set architecture, lay out an instruction format, translate an arithmetic expression into the four address organisations and count their bytes, and compute the effective address and operand for every addressing mode.

What the ISA is, and its parts

The Instruction Set Architecture (ISA) is the complete set of instructions a processor can execute, together with everything a programmer needs to use them. It is exactly the "architecture" of Unit 1: the programmer-visible design. Its components:

TeachComponents of an ISA
  • Instruction set: the operations available (add, load, jump, and so on).
  • Registers: the small fast stores inside the CPU. General-purpose registers hold working values; special ones include the PC (program counter, address of the next instruction), IR (instruction register, the current instruction), MAR (memory address register) and MDR (memory data register).
  • Data types: the kinds of value handled (integers, floating point, characters, and Booleans, meaning true/false).
  • Addressing modes: the ways an instruction can name where its operand is.
  • Instruction format: how the bits of an instruction are laid out.
TeachInstruction format

An instruction is a row of bits split into fields: an opcode saying what to do, zero or more operand or address fields saying what to do it to, and sometimes a mode field saying how to read the address.

Worked exampleSlide: decode the bits

An instruction is just a number, so with the format you can read one back. Suppose a 16-bit machine uses opcode 4 bits, register 4 bits, address 8 bits, and its opcode table has 1010 = ADD.

Given instruction = 1010 0011 11001010 · word = 16 bits · fields = opcode 4, register 4, address 8 · opcode 1010 = ADD
Find the assembly instruction the bits stand for
Formula chop the bits into the given field widths, left to right, then translate each field
what each symbol means opcode field = which operation · register field = which register, read as a plain binary number · address field = the memory address, also plain binary · the field widths must be given or derived; they are not guessable from the bits alone
  1. Decode 1010 0011 11001010. Split 4 / 4 / 8: opcode 1010, register 0011, address 11001010.
  2. Opcode 1010 = ADD; register 0011 = R3; address 11001010 = 128+64+8+2 = 202.
  3. So the instruction reads ADD R3, [202]: add the contents of location 202 to R3.

A 32-bit three-address machine just widens the fields. With opcode 6 bits then three 5-bit register fields, the bits 000001 00001 00010 00011 split as opcode 000001, then R1, R2, R3, giving ADD R1, R2, R3.

Reading an instruction is the reverse of building one: know the field widths, chop the bits, translate each field. 1010 0011 11001010 = ADD R3, [202].

The pattern: three addresses name both sources and the destination, so each operation is one instruction. Two addresses reuse the destination as a source. One address keeps a running value in the accumulator and names only the other operand. Zero addresses take everything from a stack, so the expression is written in postfix (reverse Polish) order first.

Must memoriseThe four formats

Fewer address fields, more instructions:

  • 3-address: op dest, src1, src2. Shortest programs.
  • 2-address: op dest, src (dest is also a source).
  • 1-address: LOAD, STORE, and ops against the single accumulator.
  • 0-address: PUSH and POP a stack; operators take the top items. Write the expression in postfix first.

Memory hook: 3, 2, 1, 0 addresses map to register, register, accumulator, stack machines. Postfix of A op B is "A B op".

Key point

The number of addresses an instruction carries trades instruction WIDTH against instruction COUNT. Three addresses name everything at once, so each instruction is long and few are needed; zero addresses name nothing, so each instruction is tiny and many are needed. The total work is conserved.

Blunt version: pay in instruction width or pay in instruction count. You do not get to skip both.

Worked exampleSlide: indirect for read, add and store

Indirect mode works for writing and read-modify, not only for reading. The address field points to a location whose contents are the effective address.

Given ADD R1,(150) with R1 = 10, M[150] = 250, M[250] = 5 · STORE R3,(500) with R3 = 30, M[500] = 800 · mode = indirect
Find the value left in R1, and the location and value written by the STORE
Formula EA = M[address field]; then read M[EA] for an ADD, or write to M[EA] for a STORE
what each symbol means (150) = the brackets mark the mode as indirect, so 150 is not the operand's address, it holds it · EA = effective address · the direction of the transfer is set by the opcode: ADD reads M[EA], STORE writes it
  1. ADD R1, (150) with R1 = 10, M[150] = 250, M[250] = 5. EA = M[150] = 250; operand = M[250] = 5; so R1 = 10 + 5 = 15.
  2. STORE R3, (500) with R3 = 30, M[500] = 800. EA = M[500] = 800, so the value 30 is written there: M[800] = 30.
ADD R1,(150) leaves R1 = 15; STORE R3,(500) sets M[800] = 30. Indirect always takes the address from memory first, then reads or writes the operand at it.
TeachCategories of instructions

Instructions fall into three families, and naming them with examples is a common short question:

  • Data transfer: copy data, leaving the source unchanged; only the destination changes. LOAD copies from memory into a register, STORE copies a register back to memory. MOVE, PUSH, POP move it around too.
  • Arithmetic and logic: compute. ADD, SUB, MUL, DIV, AND, OR, NOT, shifts.
  • Control (test and branch): change what runs next. JUMP, BEQ (branch if equal), CALL, RETURN.
TeachCondition codes and conditional branches

Test-and-branch instructions decide what runs next by reading the condition code register (also called the flags or status register). An arithmetic or logic operation sets flags as a side effect: Z (the result was zero), N (negative), C (a carry out), V (signed overflow). A conditional branch then tests a flag: BEQ branches if equal (Z set), BNE if not equal, BMI if minus (N set), BCC if carry clear, and BRA branches always.

Branches are usually relative: the target is the PC plus a signed offset, so a negative offset branches backwards, which is how loops are built. For example BNE −40 with PC = 1000 gives EA = 1000 − 40 = 960, jumping back 40 locations.

Trap

Do not confuse indirect with register indirect. Plain indirect goes to memory twice (the field points to a location that holds the real address). Register indirect uses a register as the pointer, so it touches memory once. And immediate has no effective address at all: the operand is the number in the instruction.

Recall and check

In direct mode the address field is 1200 and M[1200] = 4500. What are the effective address and the operand? What changes in indirect mode?

Answer

Direct: EA = 1200, operand = M[1200] = 4500. Indirect: EA = M[1200] = 4500, and the operand is M[4500], one further memory read.
