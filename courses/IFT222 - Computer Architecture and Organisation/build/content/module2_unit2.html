Module Two · Unit 2

CPU Performance Metrics

How fast a processor runs is not a mystery, it is a calculation. This is the most heavily weighted numeric topic on the recent papers, so every formula here is worth learning to reflex.

By the end of this unit you can compute CPU execution time, average cycles per instruction from a mix, MIPS, the effect of an optimisation, and overall speedup by Amdahl's law. The favourite exam questions of this type are worked in full.

The one performance equation

A program takes time equal to how many instructions it runs, times how many clock cycles each takes on average, times how long one clock cycle lasts. That is the whole of it.

Must memoriseThe performance formulas

CPU time = IC × CPI × T, where IC is the instruction count, CPI is the average cycles per instruction, and T is the clock cycle time (seconds per cycle). Since T = 1 / clock rate:

  • CPU time = (IC × CPI) / clock rate
  • Average CPI = Σ (fraction of type i × CPI of type i)
  • MIPS = clock rate / (CPI × 106) (millions of instructions per second)
  • Speedup = time(old) / time(new); improvement = (old − new) / old
what each symbol means IC = instruction count, how many instructions the program actually executes (not how many lines of source) · CPI = average clock cycles per instruction · T = clock cycle time, the seconds one cycle takes, and T = 1 / clock rate · clock rate = cycles per second in Hz (a 2 GHz clock is 2×109 Hz) · fraction of type i = the share of the instruction mix that is of type i, so the fractions add to 1 · CPI of type i = cycles one instruction of that type costs

Memory hook: "I see PT" for IC × CPI × T. Fewer instructions, fewer cycles each, or a shorter cycle: any of the three cuts the time.

When different instructions take different numbers of cycles

The same weighted-average idea handles a pipeline where some instruction types add penalty cycles. Start from an ideal CPI of 1 (one instruction finished per cycle) and add the average extra cycles each type contributes. A pipelined processor is normally split into five stages, and the papers refer to them by initials throughout: instruction fetch (IF), instruction decode (ID), execute (EX), memory access (MEM) and write-back (WB). Module Two Unit 3 takes the five apart properly; here you need only their times.

Worked examplePQ 25/26 Q1b
Given stages = 5 (IF, ID, EX, MEM, WB) · stage times = 5, 4, 6, 5, 4 ns · register overhead = 1 ns · IC = 20 000 000 · mix: arithmetic 40%, memory 35%, branch 20%, floating point 5% · non-pipelined clock = 25 ns
Find the pipelined clock period, the actual CPI, the execution time, and the speedup over the non-pipelined machine
Formula clock = slowest stage + overhead · actual CPI = ideal CPI + Σ (fractioni × penaltyi) · time = IC × CPI × T · speedup = time(non-pipelined) / time(pipelined)
what each symbol means slowest stage = 6 ns (EX), because a pipeline can go no faster than its slowest stage · overhead = the latch time added to every cycle · ideal CPI = 1, one instruction finishing per cycle once the pipe is full · penaltyi = the extra cycles that class of instruction costs · T = the clock period just computed

Reading the penalties (state your assumptions, the wording is dense): ideal CPI 1; branch adds 2 extra cycles (EX takes 3); a memory access adds a 2-cycle penalty plus, on a 10% cache miss, 4 more (so 2 + 0.10×4 = 2.4 average); floating point adds 4 extra; arithmetic adds none.

  1. Pipelined clock = slowest stage + overhead = 6 + 1 = 7 ns. A pipeline runs at the speed of its slowest stage.
  2. Actual CPI = 1 + 0.20(2) + 0.35(2.4) + 0.05(4) + 0.40(0) = 1 + 0.40 + 0.84 + 0.20 = 2.44.
  3. Execution time = IC × CPI × T = 20 000 000 × 2.44 × 7 ns = 341.6 ms (0.3416 s).
  4. Non-pipelined time = 20 000 000 × 25 ns = 500 ms (0.5 s).
  5. Speedup = 0.5 / 0.3416 = 1.46 times.
Clock = 7 ns; CPI = 2.44; execution time = 0.3416 s; speedup ≈ 1.46 (under the stated reading of the penalties).

Now redo it: the method never changes even if you read a penalty differently: clock = slowest stage + overhead, CPI = 1 + weighted extra cycles, time = IC × CPI × T. State how you read each penalty and you keep the method marks.

Worked exampleSlide: pipelined vs non-pipelined by CPI

The lecturer's deck compares two designs of the same machine. The instruction mix is 40% ALU, 20% branch, 40% memory. Design 1 is non-pipelined with a 10 ns clock, where ALU and branch instructions take 4 cycles and memory instructions take 5. Design 2 pipelines it, so one instruction finishes per cycle, but clock skew and setup add 1 ns of overhead to the cycle. Find the speedup.

Given mix = 40% ALU, 20% branch, 40% memory · Design 1 clock = 10 ns, cycles = 4 (ALU), 4 (branch), 5 (memory) · Design 2 pipelined, 1 ns overhead
Find the speedup of Design 2 over Design 1
Formula Design 1 time = clock × average CPI · average CPI = Σ(fractioni × cyclesi) · Design 2 time = clock + overhead (one instruction per cycle) · speedup = Design 1 / Design 2
what each symbol means fractioni = each type's share of the mix as a decimal, which must total 1 · cyclesi = cycles that type costs on the non-pipelined design · average CPI = the weighted average of those cycle costs · overhead = the 1 ns of latch and clock-skew time the pipeline adds to every cycle · at steady state the pipeline finishes one instruction per cycle, so its instruction time is just the cycle
  1. Average CPI = 0.40(4) + 0.20(4) + 0.40(5) = 1.6 + 0.8 + 2.0 = 4.4.
  2. Design 1 time per instruction = clock × CPI = 10 × 4.4 = 44 ns.
  3. Design 2 time per instruction = clock + overhead = 10 + 1 = 11 ns.
  4. Speedup = 44 / 11 = 4.
Design 1 = 44 ns/instruction, Design 2 = 11 ns/instruction, speedup = 4. The pipeline turns an average of 4.4 cycles per instruction into one, at the cost of 1 ns of overhead. The pipeline mechanics themselves are in Module Two Unit 3.

Now redo it: the non-pipelined machine pays its full weighted CPI on every instruction; the pipelined one pays a single cycle plus overhead. The whole speedup is 44 over 11.

Amdahl's law: the limit on any speedup

If you speed up only part of a task, the untouched part limits the gain. Amdahl's law puts a number on it, and the exam asks it most years.

Must memoriseAmdahl's law
The law, stated

Amdahl's law. The gain in overall performance from improving one part of a system is limited by the fraction of the total time that part accounts for.

Formally: let f be the fraction of the execution time spent in the part being improved, where 0 ≤ f ≤ 1, and let that part be made s times faster while the rest of the work is unchanged. Then the overall speedup S is

S = 1 / ( (1 − f) + f / s )

In the limit, as s grows without bound, f/s tends to 0 and so S tends to 1 / (1 − f).

Consequence: however much faster the improved part becomes, the whole task can never be sped up by more than 1 / (1 − f). With f = 0.85 that ceiling is 1 / 0.15 = 6.67, so even an infinitely fast cache could not make the machine more than 6.67 times faster.

what each symbol means f = the fraction of the total work that the improvement actually speeds up, written as a decimal between 0 and 1 (85% is f = 0.85) · s = how many times faster that fraction becomes · (1 − f) = the untouched part, which still takes its original time · f / s = the sped-up part's new, shorter time

Memory hook: the part you did not speed up, (1 − f), never goes away, so it caps the total gain no matter how large s is.

Trap

Two slips. (1) Improvement percentage is measured against the old time, (old − new) / old, not against the new one. (2) In Amdahl's law, f is the fraction of work that is sped up, and you divide only that part by s; the rest, (1 − f), stays at full cost.

Recall and check

A program runs 5 million instructions at an average CPI of 2 on a 1 GHz clock. How long does it take?

CPU time = IC × CPI / clock rate = (5 000 000 × 2) / 109 = 10 000 000 / 109 = 0.01 s = 10 ms.
