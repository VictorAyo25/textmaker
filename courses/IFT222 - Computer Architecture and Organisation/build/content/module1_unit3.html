Floating Point Representation

How a computer stores numbers with a fractional part, using the IEEE-754 standard. Convert cleanly in both directions and you own a whole exam question, because one appears on every paper.

By the end of this unit you can lay out the IEEE-754 single-precision format, convert a decimal number to its 32-bit hex form, convert a hex pattern back to decimal, and compare stored floating-point values. Every past question of this type is worked in full.

Why floating point, and the idea behind it

Fixed integers cannot store 3.14 or 0.001. Floating point borrows scientific notation: write a number as a sign, a fraction between 1 and 2 (the mantissa), and a power of two (the exponent), just as 6.02 × 1023 does in base 10. The standard that fixes exactly how those three parts are packed into bits is IEEE-754.

TeachIEEE-754 single precision

Single precision uses 32 bits in three fields:

  • Sign (1 bit): 0 for positive, 1 for negative.
  • Exponent (8 bits): the power of two, stored with a bias of 127 added, so a true exponent of 10 is stored as 137. The bias lets negative exponents be stored without a second sign.
  • Mantissa (23 bits): the fraction after the leading 1. Because a normalised number always starts "1.", that 1 is not stored: it is the hidden bit, giving 24 bits of precision for free.
Must memoriseThe recipe, decimal to IEEE

Single precision is 1 sign, 8 exponent, 23 mantissa, bias 127. To convert a decimal number:

  1. Sign bit: 0 if positive, 1 if negative. Work with the size only from here.
  2. Write the number in binary (integer part and fraction part).
  3. Normalise to 1.m × 2e by moving the point.
  4. Exponent field = e + 127, in 8 bits.
  5. Mantissa = the bits of m after the point, filled to 23 bits.
what each symbol means S = the sign bit (0 positive, 1 negative) · E = the stored exponent field, the number actually written in the bits · e = the true exponent, the real power of two, so E = e + bias · M = the mantissa field, the fraction bits that follow the hidden leading 1 · bias = 127 for single precision (1023 for double)

Memory hook: S, E, M is 1, 8, 23, and the bias is 127 = 27 − 1. Store exponent plus 127; read exponent minus 127.

Represent −452.25 in IEEE-754 single precision. This one terminates, so it converts exactly.

Given value = −452.25 · format = IEEE-754 single precision · layout S=1, E=8, M=23 bits · bias = 127
Find the 32-bit stored pattern, written in hex
Formula normalise to 1.m × 2e, then E = e + bias, and the stored bits are S | E | M
what each symbol means S = sign bit · e = the true exponent found by normalising · E = the stored exponent field, e + 127 · M = the 23 bits after the hidden leading 1 · bias = 127
  1. Sign: the number is negative, so the sign bit is 1.
  2. Binary: 452 = 111000100, and 0.25 = 0.01, so 452.25 = 111000100.01.
  3. Normalise: move the point 8 places left, 111000100.01 = 1.1100010001 × 28. So the true exponent is 8.
  4. Exponent field: 8 + 127 = 135 = 1000 0111.
  5. Mantissa: the bits after the point, 1100010001, padded to 23 bits: 1100 0100 0100 0000 0000 000.
  6. Assemble sign, exponent, mantissa and group into hex: 1 1000 0111 1100 0100 0100 0000 0000 000 = 1100 0011 1110 0010 0010 0000 0000 0000.
−452.25 = 1 10000111 11000100010000000000000 = C3E22000H  (check: converting C3E22000H back gives −452.25 exactly).

Now redo it: the five steps never change. Sign, binary, normalise, exponent plus 127, mantissa to 23 bits.

Given value = −1240.56 · format = IEEE-754 single precision · bias = 127 · mantissa limited to 23 bits

Formula normalise to 1.m × 2e, then E = e + bias; the fraction .56 is converted by repeated ×2
what each symbol means e = true exponent · E = stored exponent, e + 127 · M = first 23 fraction bits after the hidden 1 · repeated ×2 = the method for a decimal fraction: multiply by 2, write down the whole part, keep the rest
  1. Sign: negative, so 1.
  2. Binary: 1240 = 100 1101 1000. The fraction 0.56 keeps going: 0.56 = 0.10001111010111… (multiply by 2 repeatedly, taking the whole part each time). So 1240.56 = 10011011000.10001111010111…

The reverse: hex pattern back to a decimal value

Going backwards, split the 32 bits into the three fields, undo the bias, restore the hidden 1, and evaluate.

Must memoriseThe recipe, IEEE to decimal
  1. Expand the hex to 32 bits and split as 1, 8, 23.
  2. Sign bit gives the sign.
  3. True exponent e = (exponent field) − 127.
  4. Value = ± 1.mantissa (in binary) × 2e.
what each symbol means e = the true exponent, recovered as (stored field E) − bias · 1.mantissa = the hidden leading 1 put back in front of the stored fraction bits · ± = the sign taken from bit S · bias = 127 single, 1023 double

Find the decimal value of C4F2E000H under IEEE-754 single precision.

Given stored pattern = C4F2E000H (32 bits) · format = IEEE-754 single precision · bias = 127
Find the decimal value it represents
Formula value = ±1.M × 2(E − 127)
what each symbol means E = the 8-bit stored exponent read straight off the pattern · M = the 23 mantissa bits · 1.M = the hidden leading 1 restored in front of them · the ± comes from bit S
  1. Expand to 32 bits: C4F2E000 = 1100 0100 1111 0010 1110 0000 0000 0000.
  2. Split: sign = 1; exponent = 1000 1001; mantissa = 111 0010 1110 0000… (rest zeros).
  3. Sign 1 means negative.
  4. Exponent: 1000 1001 = 137, so e = 137 − 127 = 10.
  5. Restore the hidden 1: 1.11100101110 × 210. Move the point 10 places right: 11110010111.0.
  6. Evaluate 11110010111 = 1024+512+256+128+16+4+2+1 = 1943.
C4F2E000H = −1.1110010111 × 210 = −111100101112 = −1943.

Now redo it: the steps that lose marks are forgetting the hidden 1 and forgetting to subtract 127. Do both, every time.

TeachDouble precision, and what IEEE-754 defines

The same layout scaled up gives double precision, used wherever single precision's roughly seven significant digits are not enough, as in banking and scientific work.

FormatTotalSignExponent (bias)MantissaApprox. range
Single32 bits18 (bias 127)23±1038
Double64 bits111 (bias 1023)52±10308

The method is identical; only the field widths and the bias change, double using bias 1023 = 210 − 1. Beyond the formats, IEEE-754 also fixes the operations every conforming machine must provide: add, subtract, multiply, divide, remainder and square root, conversion between decimal and binary, and the handling of exceptions (overflow, underflow, divide-by-zero, and invalid results such as 0÷0).

Trap

The three marks students throw away here. (1) The exponent is biased: subtract 127 when reading, add 127 when writing. (2) The leading 1 is hidden, so a mantissa of 111001… means the value 1.111001…, not 0.111001…. (3) When the decimal fraction does not terminate, keep multiplying by 2 until you have 23 mantissa bits, then stop; do not round the whole number off early.

Recall and check

An IEEE-754 single number has exponent field 1000 0001. What is its true exponent, and why?

Answer

1000 0001 = 129, and the true exponent is 129 − 127 = 2. The stored field always carries the bias of 127, so you subtract it to recover the real power of two.
