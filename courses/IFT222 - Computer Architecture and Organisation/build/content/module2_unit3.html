Pipelining

Overlapping instructions so several are in progress at once, the way a laundry overlaps washing, drying and folding. It speeds a processor up, and it comes with hazards you must handle. Both the speedup sums and the hazard diagrams are exam favourites.

By the end of this unit you can compute a pipeline's cycle time, its time for n tasks, its speedup and throughput; identify structural, data and control hazards; and draw a timing diagram showing stalls and forwarding.

The idea: overlap the stages

Split each instruction into k stages. Without a pipeline, one instruction finishes before the next begins. With a pipeline, as soon as an instruction leaves stage 1 the next enters it, so after the pipeline fills, one instruction completes every clock cycle. The clock cycle is set by the slowest stage plus the small latch delay between stages.

Must memorisePipeline formulas
  • Cycle time = slowest stage time + latch delay.
  • Time for n tasks = (k + n − 1) × cycle time, for k stages.
  • Non-pipelined time = n × (sum of all stage times).
  • Speedup = non-pipelined time / pipelined time. Its ceiling is k.
  • Throughput = n / pipelined time (tasks per second); in the steady state this is 1 / cycle time.

Memory hook: "k + n − 1" is k cycles to fill the pipe with the first task, then one more cycle for each of the remaining n − 1 tasks.

Worked examplePQ 25/26 Q5b · PQ 24/25 Q5b

A pipeline has 4 phases of duration 60, 50, 90 and 80 ns, with a 10 ns latch delay. Find (i) the cycle time, (ii) the non-pipeline time for one task, (iii) the speedup ratio, (iv) the pipeline time for 500 tasks, (v) the sequential time for 500 tasks, (vi) the throughput.

  1. Cycle time = slowest phase + latch = 90 + 10 = 100 ns.
  2. Non-pipeline time for one task = 60 + 50 + 90 + 80 = 280 ns.
  3. Speedup ratio (ideal) = 280 / 100 = 2.8.
  4. Pipeline time for 500 tasks = (k + n − 1) × cycle = (4 + 499) × 100 = 503 × 100 = 50 300 ns.
  5. Sequential time for 500 tasks = 500 × 280 = 140 000 ns.
  6. Throughput = 500 / 50 300 ns ≈ 9.94 million tasks per second (in the steady state, 1 / 100 ns = 10 million per second). Actual speedup for 500 tasks = 140 000 / 50 300 = 2.78.
Cycle 100 ns; non-pipe 280 ns; ideal speedup 2.8; pipe(500) = 50 300 ns; seq(500) = 140 000 ns; throughput ≈ 9.94 M tasks/s.

Now redo it: cycle = slowest + latch, pipe = (k + n − 1) × cycle, and everything else falls out of those two.

Worked examplePQ 20/21 Q1b

Four operations run through a 5-stage pipeline with stage times 8, 9, 11, 13 and 16 ns. Compare the non-pipelined and pipelined execution times and give the speedup.

  1. Non-pipelined: each operation passes through all stages, 8+9+11+13+16 = 57 ns each, so 4 × 57 = 228 ns.
  2. Pipelined cycle time = slowest stage = 16 ns.
  3. Pipelined time = (k + n − 1) × cycle = (5 + 4 − 1) × 16 = 8 × 16 = 128 ns.
  4. Speedup = 228 / 128 = 1.78.
Non-pipelined 228 ns, pipelined 128 ns, speedup ≈ 1.78. The speedup is below 5 because only 4 tasks run, so the fill time still dominates.

Hazards: when overlap goes wrong

Overlapping instructions can clash. There are three kinds of hazard, and the exam expects you to name them and say how each is handled.

TeachThe three hazards
  • Structural hazard: two instructions need the same hardware at once (for example one memory for both a fetch and a data access). Fixed by duplicating the resource, such as separate instruction and data caches.
  • Data hazard: an instruction needs a result the previous one has not written back yet (a read-after-write, RAW). Reduced by forwarding (feeding the result straight from where it is produced to where it is needed) and, when that is not enough, by stalling one or more cycles.
  • Control hazard: a branch changes what runs next, but the pipeline has already fetched the following instructions. Handled by resolving the branch early, predicting it, or flushing the wrongly fetched instructions.
TeachThe load-use case

The one data hazard forwarding cannot fully hide is load-use: a value loaded from memory is not ready until the memory stage, so an instruction that uses it the very next cycle must wait one cycle even with forwarding. That single unavoidable stall appears in the exam's RISC pipeline question.

Worked examplePQ 25/26 Q2b

A 5-stage RISC (reduced instruction set) pipeline (IF, ID, EX, MEM, WB) runs the code below, with forwarding available, a one-cycle stall for a load-use hazard, and a multiplier that occupies EX for three cycles. Identify the hazards, draw the timing diagram, and give the total cycles.

I1: LW   R1, 0(R2)     ; load R1 from memory
I2: ADD  R3, R1, R4    ; needs R1  -> load-use hazard with I1
I3: SUB  R5, R3, R6    ; needs R3  (forwarded from I2)
I4: SW   R5, 8(R2)     ; needs R5  (forwarded from I3)
I5: BEQ  R5, R0, LABEL ; branch, resolved in EX
I6: MUL  R7, R5, R8    ; multiply, EX takes 3 cycles

Hazards

I1 to I2 is a load-use data hazard: R1 is not ready until I1's MEM stage, so I2 stalls one cycle. I2 to I3, I3 to I4, I3 to I5 and I3 to I6 are ordinary data hazards hidden by forwarding. I6's multiply holds EX for three cycles, adding two extra cycles at the end (assuming the branch is not taken).

Multi-cycle execute, with and without forwarding

When some instructions hold the EX stage for several cycles, they stall the ones behind them, and a dependent instruction must wait for its operand. The next question asks you to schedule exactly this, both with forwarding and without.

Worked examplePQ 25/26 Q3b

A 5-stage pipeline (IF, ID, OF, EX, WB) takes 1 cycle per stage, except EX takes 1 cycle for ADD and SUB, 3 for MUL and 6 for DIV. Schedule this sequence and give the total cycles, with and without operand forwarding.

I1: MUL R2, R0, R1     I2: DIV R5, R3, R4
I3: ADD R2, R5, R2     I4: SUB R5, R2, R6

I3 needs R5 from I2 and R2 from I1; I4 needs R2 from I3.

Stated assumptions

One execution unit, in order: an instruction enters EX only when EX is free, so a long EX stalls those behind it (a stalled instruction repeats its stage below). Write-back is one cycle after EX. With forwarding, a result reaches a dependent instruction's EX the cycle after it is produced; without forwarding, the dependent must wait until the producer has written back.

Trap

Forwarding removes most data-hazard stalls but not the load-use one: a loaded value simply is not available in time for the very next instruction, so exactly one stall remains. And do not forget that a multi-cycle execute (multiply, divide) holds the EX stage and delays everything behind it.

Recall and check

A 5-stage pipeline runs 100 independent instructions with no hazards. How many cycles, and what is the speedup over the non-pipelined version?

Answer

Cycles = k + n − 1 = 5 + 100 − 1 = 104. The non-pipelined version takes 100 × 5 = 500 stage-times, so the speedup is 500 / 104 ≈ 4.8, close to the ceiling of 5.
