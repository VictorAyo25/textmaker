Cache Memory Design

A small fast memory that holds copies of the data most likely to be needed, so the CPU rarely waits on slow main memory. Splitting an address into cache fields and finding a block are the most examined calculations on the whole course.

By the end of this unit you can define hit, miss and hit ratio; compute average memory access time; break an address into tag, index and offset for direct, associative and set-associative mapping; and find which cache block an address maps to. Every recent cache question is worked here.

Why cache works, and the vocabulary

Because of locality (Unit 1), a small store of recently used blocks satisfies most accesses. When the CPU needs data, it checks cache first. A hit means it is there; a miss means it must be fetched from main memory (and the whole block around it is brought in, for spatial locality).

Must memoriseHit ratio and access time

Hit ratio h = hits / total accesses; miss ratio = 1 − h.

Average memory access time depends on how cache and memory are arranged:

  • Hierarchical (look-through): always check cache first, go to memory only on a miss. AMAT = Tcache + (1 − h) × Tmemory.
  • Simultaneous (look-aside): start cache and memory together, use whichever is right. AMAT = h × Tcache + (1 − h) × Tmemory.
what each symbol means h = the hit ratio, the fraction of accesses found in cache, a decimal from 0 to 1 (96% is h = 0.96) · 1 − h = the miss ratio · Tcache (also written Tc) = the time for one cache access · Tmemory (Tm) = the time for one main-memory access · both times in the same unit, usually nanoseconds · note this T is an access time, not the clock cycle time T of the CPU-performance formula

Memory hook: a high hit ratio pulls the average toward the fast cache time; even a small miss rate hurts, because a miss pays the full slow memory cost.

Splitting the address: tag, index, offset

Main memory is divided into blocks; cache is divided into lines the same size as a block. A memory address is split into fields that say which block, which line, and where inside the block.

TeachThe three mapping functions
  • Direct mapping: each block has exactly one line it may sit in, line = (block number) mod (number of lines). Simple and fast, but two blocks that map to the same line keep evicting each other (conflict misses).
  • Fully associative: a block may sit in any line. No conflict misses, but every line's tag must be searched, which is expensive.
  • Set associative (k-way): the compromise. Lines are grouped into sets of k; a block maps to one set, set = (block number) mod (number of sets), and may sit in any of the k lines in it.
Must memoriseField widths

Work from the block and cache sizes:

  • Offset bits = log2(bytes, or words, per block).
  • Number of lines = cache size / block size.
  • Index bits (direct) = log2(number of lines); set bits (k-way) = log2(number of sets), where sets = lines / k.
  • Tag bits = address bits − index (or set) bits − offset bits.
what each symbol means address bits = the width of a memory address, from the main-memory size (1 GB = 230, so 30 bits) · block size = bytes (or words) in one block, which equals one cache line · number of lines = how many blocks the cache can hold at once · k = the associativity, the number of ways or lines per set (here k means ways, not pipeline stages or address lines) · sets = lines / k · log2 of a power of two is just the exponent, so log21024 = 10

Memory hook: offset picks the byte in the block, index/set picks the slot, tag is everything left over to confirm the right block is there.

Must memoriseTag directory size

Each cache line stores a tag beside its data, to prove which block it currently holds. The storage spent on tags, the tag directory, is number of lines × tag bits per line. It grows as the mapping gets more associative, because dropping the index (or shrinking the set field) lengthens the tag on every line.

what each symbol means number of lines = cache size / block size, and it does not change with the mapping · tag bits per line = the tag width you worked out for that mapping · the product is in bits, so divide by 8 for bytes

Elements of cache design

Beyond mapping, a few design decisions round out the topic and appear as short questions.

TeachThe cache read operation

On every read the CPU puts out an address and the cache checks it. On a hit, the cache returns the word straight to the CPU and no traffic goes onto the system bus at all, which is why a hit is fast. On a miss, the address is driven onto the system bus, main memory returns the whole block, and it is delivered to the cache and to the CPU together (the fetch and the fill happen in parallel), so the waited-for word arrives as soon as it can.

TeachPhysical and logical (virtual) addresses

Programs use logical (virtual) addresses; the hardware stores data at physical addresses. A memory management unit (MMU) translates one to the other through a page table, which is what lets each program behave as if it owns all of memory (virtual memory). A cache can be indexed by either address:

  • A physical cache waits for the MMU to translate the address, then looks up the physical address. Simple and always correct.
  • A logical (virtual) cache looks up the virtual address directly, in parallel with translation, so it is faster. The cost: different programs reuse the same virtual addresses, so the cache must be flushed on every context switch, or tagged with an address-space identifier, to avoid handing one program another's data.
TeachChoosing the cache size

Cache size is a balance. Too small and the hit rate falls and the CPU stalls; too large and it costs more, uses scarce chip or board area, and the extra addressing logic makes each lookup slightly slower. So cache is sized large enough for a good hit rate yet small enough to stay fast and affordable, which is exactly why machines use several small-to-large levels (L1, L2, L3) rather than one big cache.

Trap

Two common errors. (1) Watch the units of the block: "16 words" with a 4-byte word is 64 bytes, so the offset counts words or bytes depending on how the address is given. (2) For set-associative, divide the lines by the associativity to get the sets before taking the log for the set bits; the extra bits move into the tag, not away.
