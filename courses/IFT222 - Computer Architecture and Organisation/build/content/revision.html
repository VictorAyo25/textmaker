Data, Instructions and Addressing

The first block of the revision deck: signed numbers, instruction formats, and addressing modes. Every question here is straight off the 2025/2026 paper, so treat this as the paper itself.

By the end you can, from memory, place any signed number in a 16-bit register in binary and hex, write an expression in all four instruction formats, and read an operand out of memory under any addressing mode.

From the slidesRevision A

the lecturer's revision deck

A spacecraft telemetry system uses a 16-bit processor to transmit environmental measurements. The following values are to be stored: Temperature = −182; Pressure = 487; Altitude = −1023. The processor uses 2's complement representation for signed integers. (i) Determine the range of values representable in a 16-bit two's complement system. Indicate whether the given numbers fall within the range. (ii) Represent each value in binary and hexadecimal. (iii) Demonstrate how the processor uses two's complement to compute (−182) + 487.
You have met this. It is PQ 2025/2026 Q1(c), word for word, spacecraft and all, solved in full in the Past Papers section. Here it is again, as simply as it goes.
Worked exampleRevision A
Given a 16-bit machine, 2's complement · Temperature = −182, Pressure = 487, Altitude = −1023
Find (i) the range and whether each fits, (ii) each in binary and hex, (iii) the sum (−182) + 487 in binary
Formula range = −215 to 215 − 1 · negative in 2's complement = invert the positive and add 1 · group the 16 bits in fours to read the hex
  1. Range. A 16-bit 2's complement register holds −215 to 215 − 1, that is −32768 to 32767. All three of −182, 487 and −1023 sit comfortably inside it.
  2. 487 is positive, so just write it in binary: 0000 0001 1110 0111. Group in fours: 0000=0, 0001=1, 1110=E, 0111=7, so hex = 01E7.
  3. −182. First +182 = 0000 0000 1011 0110. Invert every bit: 1111 1111 0100 1001. Add 1: 1111 1111 0100 1010. Hex: 1111=F, 1111=F, 0100=4, 1010=A, so −182 = FF4A.
  4. −1023. First +1023 = 0000 0011 1111 1111. Invert: 1111 1100 0000 0000. Add 1: 1111 1100 0000 0001. Hex: 1111=F, 1100=C, 0000=0, 0001=1, so −1023 = FC01.
  5. (−182) + 487. Add the two 16-bit patterns and throw away any carry out of the top: 1111 1111 0100 1010 + 0000 0001 1110 0111 = 0000 0001 0011 0001. That pattern is positive and equals 256 + 32 + 16 + 1 = 305, which is exactly −182 + 487. The machine got the right answer with nothing but addition.
Range −32768 to 32767 (all three fit). 487 = 01E7; −182 = FF4A; −1023 = FC01. (−182) + 487 = 0000 0001 0011 0001 = 305.

Use a Zero, One, Two and Three address instruction format to write a Pentium 4 assembly language program segment for the expression: X = ((A * B) + C/D) / (F*G + J*K)
You have met this. Same expression as PQ 2025/2026 Q4(b), solved in full in Module One Unit 4. Worked exampleRevision B
Given X = ((A × B) + C/D) / (F × G + J × K)
Find the program in each of the four formats
Formula 3-address names both sources and the destination · 2-address lets the destination double as a source · 1-address works through one accumulator (LOAD, op, STORE) · 0-address pushes operands on a stack and each operation pops two

Do the numerator (A×B + C/D) and the denominator (F×G + J×K) first, then divide.

3-address (shortest)

MUL  R1, A, B      ; R1 = A*B
DIV  R2, C, D      ; R2 = C/D
ADD  R1, R1, R2    ; R1 = A*B + C/D    (numerator)
MUL  R2, F, G      ; R2 = F*G
MUL  R3, J, K      ; R3 = J*K
ADD  R2, R2, R3    ; R2 = F*G + J*K    (denominator)
DIV  X,  R1, R2    ; X  = numerator / denominator

The revision slide prints the last line as "DIV X, R2, R3", which is a slip: that would divide the denominator by J*K. The correct last line is DIV X, R1, R2, numerator over denominator.

2-address (destination is also a source)

MOV  R1, A         ; R1 = A
MUL  R1, B         ; R1 = A*B
MOV  R2, C
DIV  R2, D         ; R2 = C/D
ADD  R1, R2        ; R1 = numerator
MOV  R3, F
MUL  R3, G         ; R3 = F*G
MOV  R2, J
MUL  R2, K         ; R2 = J*K
ADD  R2, R3        ; R2 = denominator
DIV  R1, R2        ; R1 = X
MOV  X,  R1

1-address (one accumulator, AC)

LOAD  F            ; AC = F
MUL   G            ; AC = F*G
STORE T            ; T  = F*G
LOAD  J
MUL   K            ; AC = J*K
ADD   T            ; AC = F*G + J*K
STORE T            ; T  = denominator
LOAD  A
MUL   B            ; AC = A*B
STORE R            ; R  = A*B
LOAD  C
DIV   D            ; AC = C/D
ADD   R            ; AC = numerator
DIV   T            ; AC = numerator / denominator
STORE X            ; X  = AC

0-address (stack, postfix A B * C D / + F G * J K * + /)

PUSH A   PUSH B   MUL          ; A*B
PUSH C   PUSH D   DIV   ADD    ; + C/D   -> numerator
PUSH F   PUSH G   MUL          ; F*G
PUSH J   PUSH K   MUL   ADD    ; + J*K   -> denominator
DIV      POP  X                ; numerator / denominator, store X
Fewer address fields means shorter instructions but more of them: 3-address is 7 instructions, 0-address is 16. Each program computes the same X.

Pipelining and Hazards

Two pipeline speedup questions and the data-hazard classification. The second pipeline question and the hazard one you have already met; the first is the deck's one new example, so learn it fresh.

From the slidesRevision D

the lecturer's revision deck

A non-pipelined processor requires 60 ns per instruction. The processor is redesigned into a 6-stage pipeline with a cycle time of 12 ns. Calculate: (a) Time required for 50 instructions without pipelining (b) Time required for 50 instructions with pipelining (c) Speedup obtained
This one is new. It is not on any past paper, so it is the only question in the whole revision deck you have not already drilled. It is an easy one, worth learning cold.
Worked exampleRevision D
Given non-pipelined time = 60 ns per instruction · pipeline stages k = 6 · pipeline cycle time = 12 ns · n = 50 instructions
Find (a) non-pipelined time, (b) pipelined time, (c) speedup
Formula non-pipelined = n × time per instruction · pipelined = (k + n − 1) × cycle time · speedup = non-pipelined / pipelined
  1. (a) Without pipelining. Each instruction takes the full 60 ns and they run one after another: 50 × 60 = 3000 ns.
  2. (b) With pipelining. The first instruction must pass through all 6 stages, which takes 6 × 12 = 72 ns to fill the pipe. After that, one instruction finishes every cycle, so the remaining 49 add 49 × 12 = 588 ns. Total = 72 + 588 = 660 ns. Same thing in one line: (k + n − 1) × cycle = (6 + 50 − 1) × 12 = 55 × 12 = 660 ns.
  3. (c) Speedup. = 3000 / 660 = 4.55 (about four and a half times faster).
Without pipelining 3000 ns; with pipelining 660 ns; speedup 3000 / 660 ≈ 4.55.
From the slidesRevision E

the lecturer's revision deck

Consider a pipeline having 4 phases with duration 60, 50, 90 and 80 ns. Given latch delay is 10 ns. Calculate: (i) Pipeline cycle time (ii) Non-pipeline execution time (iii) Speed up ratio (iv) Pipeline time for 500 tasks (v) Sequential time for 500 tasks
You have met this. It is PQ 2025/2026 Q5(b) and PQ 2024/2025 Q5(b), exactly, and it is worked in Module Two Unit 3 and again in the Past Papers section. (The 2024/2025 version adds a sixth part, "Throughput", which this one drops.)
Worked exampleRevision E
Given four phases of 60, 50, 90, 80 ns · latch delay = 10 ns · n = 500 tasks for parts (iv) and (v)
Find cycle time, non-pipeline time for one task, speedup, and the pipelined and sequential times for 500 tasks
Formula cycle = slowest phase + latch · pipelined(n) = (k + n − 1) × cycle · sequential(n) = n × sum of phases · speedup = sum of phases / cycle
  1. (i) Cycle time = slowest phase + latch = max(60, 50, 90, 80) + 10 = 90 + 10 = 100 ns. The slowest phase sets the clock, not the average.
  2. (ii) Non-pipeline time for one task = 60 + 50 + 90 + 80 = 280 ns.
  3. (iii) Speed up ratio = 280 / 100 = 2.8.
  4. (iv) Pipeline time for 500 tasks = (k + n − 1) × cycle = (4 + 499) × 100 = 503 × 100 = 50 300 ns.
  5. (v) Sequential time for 500 tasks = 500 × 280 = 140 000 ns.
Cycle 100 ns; one task 280 ns; speedup 2.8; 500 tasks pipelined 50 300 ns against sequential 140 000 ns.

Worked exampleRevision F
Given three pairs of instructions, each writing and reading registers
Find which data hazard each pair is, with an arrow from the first access to the second
Formula find the one register on both lines, then read its order: write then read is RAW, read then write is WAR, write then write is WAW
PairRegister on both linesOrderHazard
(i)  R3 written, then R3 readR3 write → readRAW (read after write)
(ii)  R1 read, then R1 writtenR1 read → writeWAR (write after read)

Worked exampleRevision cache, the method
Given nine caches, each with a memory size, a cache size and a block size (and a way count for the set-associative three)
Find offset, index or set bits, tag bits, lines, and the tag-directory size for each
Formula address = log2(memory) · offset = log2(block) · lines = cache / block · sets = lines / ways · tag = address − index (or set) − offset · tag directory = lines × tag bits (divide by 8 for bytes)

The method never changes: work the address width from the memory size, the offset from the block, the lines from cache over block, and whatever is left after offset and index (or set) is the tag. Fully associative has no index at all, so its tag is the widest. The three tables below apply exactly this to all nine caches.
