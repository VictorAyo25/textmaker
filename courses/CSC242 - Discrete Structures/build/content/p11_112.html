The Four Examined Programs

Four programs have been set across two papers, worth 19 marks between them. Every one is below, quoted as printed, broken down, then answered with a listing that was compiled at full warnings and run. The output panels are what the machine actually printed, not what it ought to have printed.

By the end of this section you will be able to write the power set program, the bit-string program, the isPerfectSquare function with its main, and the degree-counting snippet, and to explain each line of them.

TeachHow these listings were checked

Every listing in this part was saved to a file, compiled with warnings turned up, and run with the input the question specifies. Nothing was transcribed from memory or from a listing that had merely been read through.

That matters more here than anywhere else in the book. A wrong number in a worked example is visible to anyone who checks the arithmetic; a program that does not compile looks exactly like a program that does, and a manual that prints one has taught the reader to write it.

The output panels below are captured output. Where a prompt and an answer sit on the same line, that is because the program printed the prompt without a newline and the input was supplied from a file rather than typed. It is what the terminal showed.

1. The power set

As printed2024/2025 · Q3(b)

b. Write a C++ program to generate all possible subsets (also known as the power set) of a given set of integers.

For example, if the user enters the set {1, 2, 3}, the output should include:
{ }
{1}
{2}
{1, 2}
{3}
{1, 3}
{2, 3}
{1, 2, 3} 6 marks

Note on the paper
Nothing is printed wrongly here, but the sample output is doing more work than it looks. It is not a random selection of subsets: it is all eight of them, in the exact order a counting loop produces, as the bit table in section 11.1 shows. Reproducing that order is free if you enumerate by counting and awkward if you enumerate any other way, so take the hint.

Note also the empty set prints as { }, with a space between the braces, while every other line has no space inside them. That is one extra line of code and it is the kind of detail a marker checks first.
Break it down
Given
A set of integers, entered by the user. The size is not fixed by the question.
Asked
Write a C++ program that generates all possible subsets. One deliverable: a complete, runnable program, not a fragment.
Marks say
6. Expect roughly: the skeleton and input, the enumeration loop, the membership test, the printing format, and the correct count of subsets. The sample output is printed for you, which means the format itself carries marks.
Teaches
Sections 11.1 (bits, vector, loops) and 2.1 (a set of n elements has 2n subsets).
Trap
Writing the set into the source as {1, 2, 3}. The question says "a given set of integers" and "if the user enters", so the program must read it. Also: forgetting the empty set, which is subset number 0 and the one candidates most often lose.
Worked examplePQ 24/25 Q3(b), compiled and run
Given
n integers read from the keyboard into a vector.
Find
A program printing all 2n subsets in the paper's format and order.
Formula
Count mask from 0 to 2n − 1; element i is in the subset exactly when bit i of mask is 1, that is when mask & (1 << i) is non-zero.
powerset.cpp
// PQ 2024/2025 Question Three (b): the power set of a set of integers.
#include <iostream>
#include <vector>
using namespace std;

// Print the one subset picked out by the bits of `mask`.
void printSubset(const vector<int>& s, int mask) {
    cout << "{";
    bool first = true;
    for (int i = 0; i < (int)s.size(); i++) {
        if (mask & (1 << i)) {          // is element i in this subset?
            if (!first) cout << ", ";
            cout << s[i];
            first = false;
        }
    }
    if (first) cout << " ";             // the empty set prints as { }
    cout << "}" << endl;
}

int main() {
    int n;
    cout << "How many integers are in the set? ";
    cin >> n;

    vector<int> s(n);
    cout << "Enter " << n << " integers: ";
    for (int i = 0; i < n; i++) cin >> s[i];

    int total = 1 << n;                 // 2^n subsets
    cout << "The power set has " << total << " subsets:" << endl;
    for (int mask = 0; mask < total; mask++) printSubset(s, mask);

    return 0;
}
What it printed, for the paper's own example
How many integers are in the set? Enter 3 integers: The power set has 8 subsets:
{ }
{1}
{2}
{1, 2}
{3}
{1, 3}
{2, 3}

Line for line against the question. The eight lines are the paper's eight lines, in the paper's order, including the space inside the empty braces.

  • The enumeration. total = 1 << n is 2n, so the loop runs once per subset. That is section 2.1's count, used rather than restated.
  • The membership test. mask & (1 << i) asks whether bit i is set. It is the bit string of section 2.3 read one position at a time.
  • The comma. first exists so the separator goes between elements and not before the first one. Printing s[i] << ", " instead would leave a trailing comma on every line.
  • The cast. (int)s.size() is there because size() returns an unsigned type, and comparing it with a signed int draws a warning. Not examinable; say one line about it if asked.

2. The bit strings

As printed2023/2024 · Q3(b)

(b) Write a C++ program that dynamically takes these sets in 3(i-iii) above as input and displays the corresponding bit strings for each set. (7 marks)

Note on the paper
"These sets in 3(i-iii) above" points back at part (a) of the same question, which is quoted in full in section 2.3: the universal set is U = {1, 2, ..., 10} and the three sets are {3, 4, 5}, {1, 3, 6, 10} and {2, 3, 4, 7, 8, 9}. Part (a) also fixes the convention the program must follow, that "the ith bit in the string is 1 if i is in the set and 0 otherwise", so the program is not free to choose its own bit order.

The load-bearing word is dynamically. It rules out a program with the three sets typed into the source. Read together with "as input", it is asking for the sets to arrive through cin while the program is running.
Break it down
Given
U = {1, 2, ..., 10}, and three sets to be supplied at run time. The convention that bit i is 1 when i is in the set.
Asked
Write a C++ program that dynamically takes the sets as input and displays the corresponding bit strings.
Marks say
7, the largest of the programming questions. Expect: the skeleton, reading a variable number of sets, reading a variable number of elements per set, the conversion itself, the correct bit order, and the display. The word "dynamically" is worth marks on its own.
Teaches
Sections 11.1 (vector, string, nested loops) and 2.3 (what a bit string is).
Trap
Two of them. Writing the sets as constants, which fails "dynamically"; and putting element m at position m rather than m − 1, which shifts every bit one place and produces a plausible wrong answer.
Worked examplePQ 23/24 Q3(b), compiled and run
Given
A universe of 10 elements, and sets read at run time.
Find
A program printing each set's bit string.
Formula
Start with ten '0' characters; for each member m, set position m − 1 to '1'.
bitstrings.cpp
// PQ 2023/2024 Question Three (b): read sets dynamically, print bit strings.
#include <iostream>
#include <string>
#include <vector>
using namespace std;

const int UNIVERSE = 10;                // U = {1, 2, ..., 10}

// The bit string of one set: position i carries 1 when i is a member.
string bitString(const vector<int>& members) {
    string bits(UNIVERSE, '0');         // start with every position 0
    for (int i = 0; i < (int)members.size(); i++) {
        int m = members[i];
        if (m >= 1 && m <= UNIVERSE) bits[m - 1] = '1';
    }
    return bits;
}

int main() {
    int howMany;
    cout << "How many sets? ";
    cin >> howMany;

    for (int s = 1; s <= howMany; s++) {
        int size;
        cout << "Set " << s << ", how many elements? ";
        cin >> size;

        vector<int> members(size);
        cout << "Enter " << size << " elements from 1 to " << UNIVERSE << ": ";
        for (int i = 0; i < size; i++) cin >> members[i];
        cout << endl;                   // close the line the user typed on

        cout << "Set " << s << " bit string: " << bitString(members) << endl;
    }
    return 0;
}
What it printed, given the three sets of part (a)
How many sets? Set 1, how many elements? Enter 3 elements from 1 to 10:
Set 1 bit string: 0011100000
Set 2, how many elements? Enter 4 elements from 1 to 10:

Check against section 2.3, where the same three sets were converted by hand: {3, 4, 5} gives 0011100000, {1, 3, 6, 10} gives 1010010001, and {2, 3, 4, 7, 8, 9} gives 0111001110. The program agrees with the hand answer in all thirty positions, which is the point of writing both.

  • Two loops, nested. The outer one walks the sets, the inner one walks the elements of one set. Each has its own counter, and reusing i for both would destroy the outer count.
  • The subtraction. bits[m - 1] is where element m lives, because string positions count from 0. Getting this wrong produces 0001110000 for the first set, which looks right at a glance and is not.
  • The guard. m >= 1 && m <= UNIVERSE stops a typed 11 from writing outside the string. A program that crashes on bad input has lost the marks it was about to earn.
  • Why a function. bitString does one job and is called once per set. It also makes the answer readable, which on a 7-mark question is worth doing.

3. isPerfectSquare, by binary search

As printed2024/2025 · Q4(c)

c. Write a C++ function called isPerfectSquare that uses a binary search algorithm to verify if a given integer num is a perfect square. The function should:

i. Narrow down the search range [low,high] by repeatedly dividing it into two parts (midpoint).

ii. Calculate the square of the midpoint value.

iii. Check if the square of the midpoint is equal to num. If so, return the midpoint as the square root of num.

iv. If the square of the midpoint is greater than or less than num, adjust the search range accordingly.

v. If the search range is exhausted and no midpoint satisfies the condition, return -1.

Write a main function to:

i. Prompt the user to enter an integer xx.

ii. Call isPerfectSquare(x).

iii. Display whether xx is a perfect square. If xx is a perfect square, also display its integer square root. 6 marks

Note on the paper
Three names for one value. The function's parameter is called num, the main function is told to prompt for "an integer xx", then to call isPerfectSquare(x) with a single x, then to report on xx again. Only one value is involved. Answer it with one variable, named once, and say in a line which name you adopted; a marker reading three names in a six-mark question is looking to see whether you noticed.

The function name is not yours to change. The question names it isPerfectSquare, so that is its name, spelled and capitalised exactly that way. Renaming it to perfect_square or isSquare is the same defect as paraphrasing a quotation: the question asked for a specific thing and got something else.

Part iv says "greater than or less than". Those are two different adjustments, not one, and the answer must make both moves: too big means search below the midpoint, too small means search above it. A single branch answers half the part.
Break it down
Given
An integer. A five-step specification of the function, and a three-step specification of main.
Asked
Write a function called isPerfectSquare using binary search, plus a main that prompts, calls and reports. Two deliverables.
Marks say
6, split across eight numbered requirements. The cheapest way to secure them is to make the numbering visible in the answer, so that each printed requirement has a line the marker can point at.
Teaches
Sections 11.1 (functions, while, integer division) and 9.4, where T(n) = T(n/2) + 1 is exactly this algorithm's cost.
Trap
Answering with sqrt(num). It is shorter, it works, and it scores nothing, because the question asks for a binary search and that is what the marks are for. Also: returning true or false, when the question says to return the midpoint or −1, so the return type is int despite the name beginning with "is".
Worked examplePQ 24/25 Q4(c), compiled and run
Given
An integer num, and the search range [low, high] starting at [1, num].
Find
The integer square root of num, or −1.
Formula
Halve the range each pass: compare mid2 with num and keep whichever half can still contain the answer.
perfectsquare.cpp
// PQ 2024/2025 Question Four (c): isPerfectSquare by binary search.
#include <iostream>
using namespace std;

// Returns the integer square root of num, or -1 if num is not a perfect square.
int isPerfectSquare(int num) {
    if (num < 0) return -1;             // no real square root
    if (num == 0) return 0;             // 0 = 0 * 0

    int low = 1, high = num;            // the search range [low, high]
    while (low <= high) {
        int mid = low + (high - low) / 2;        // i. the midpoint
        long long square = (long long)mid * mid; // ii. square it

        if (square == num) return mid;           // iii. found it
        if (square < num) low = mid + 1;         // iv. adjust upward
        else high = mid - 1;                    // iv. adjust downward
    }
    return -1;                          // v. range exhausted
}

int main() {
    int x;
    cout << "Enter an integer: ";              // i. prompt
    cin >> x;

    int root = isPerfectSquare(x);            // ii. call it
    if (root == -1) {                          // iii. report
        cout << x << " is not a perfect square." << endl;
    } else {
        cout << x << " is a perfect square." << endl;
        cout << "Its integer square root is " << root << "." << endl;
    }
    return 0;
}
What it printed, run twice
Enter an integer: 49 is a perfect square.
Its integer square root is 7.

Enter an integer: 50 is not a perfect square.

The name is the paper's. isPerfectSquare, spelled and capitalised exactly as printed, and one variable x for the value the question called num, xx and x in three different places. The comments carry the paper's own numbering, i to v and i to iii, so each requirement has a line beside it.

  • Why the range starts at [1, num]. The square root of num is never larger than num for whole numbers, so the answer, if it exists, is inside. Starting at [1, num] is safe and needs no justification; [1, num/2 + 1] is tighter and needs one.
  • Why low + (high - low) / 2. It is the midpoint, written so that low + high is never formed. That sum can exceed what an int holds when num is large, and the overflow would produce a negative midpoint. Worth one line in an answer.
  • Why long long for the square. mid can be close to num, so mid × mid can be far past the int limit. Squaring inside an int is the bug this program is most likely to have, and it is silent.
  • Why the loop ends. Every pass either returns or moves low up or high down by at least one, so the range strictly shrinks and low <= high must eventually fail. That is the termination argument, and it is the sort of thing section 9.2 taught you to state rather than assume.
  • The cost. Each pass halves the range, so the number of passes is the number of halvings needed to reduce num to 1. That is the recurrence T(n) = T(n/2) + 1 of section 9.4, and it is why binary search beats testing 1, 2, 3, ... in turn.

Now redo it: trace the function on num = 49 by hand. Range [1, 49], mid 25, 625 > 49 so high becomes 24; mid 12, 144 > 49 so high becomes 11; mid 6, 36 < 49 so low becomes 7; mid 9, 81 > 49 so high becomes 8; mid 7, 49 = 49, return 7. Five passes to search forty-nine numbers.

4. Counting the remaining degree-3 and degree-4 vertices

TeachWhere this question is quoted

2024/2025 Question Five is printed as a single scenario with seven parts, so it is quoted whole, once, in section 6.3 where the Handshaking theorem is taught. Part (d) is the programming one:

"Write a C++ code snippet to compute the remaining number of vertices that have either degree 3 or 4." 3 marks

Section 6.3 answers the mathematics: 24 vertices and 30 edges force the degree sum to 60; the five of degree 4, seven pendant and seven of degree 2 account for 19 vertices and 41 of that sum, leaving 5 vertices to share 19, which can only be four of degree 4 and one of degree 3. So the graph has 9 vertices of degree 4, not the five the question appears to state. This section turns that reasoning into the snippet the part asks for.

Note the word "snippet". The question does not ask for a complete program, so a fragment would be accepted. The listing below is complete anyway, because a complete program can be run and a fragment cannot, and the wrapper is ours, not the examiner's: if you reproduce this in an exam, the part inside main is the answer and the include line is scaffolding.

Formula

degrees.cpp
// PQ 2024/2025 Question Five (d): the vertices of degree 3 or 4 still to classify.
#include <iostream>
using namespace std;

int main() {
    int vertices = 24, edges = 30;
    int knownDeg4 = 5, pendant = 7, deg2 = 7;

    int accounted = knownDeg4 + pendant + deg2;      // vertices already named
    int remaining = vertices - accounted;            // still to classify

    int degreeSum = 2 * edges;                       // Handshaking theorem
    int usedDegree = 4 * knownDeg4 + 1 * pendant + 2 * deg2;
    int leftDegree = degreeSum - usedDegree;         // degree left to share

    // Solve  four + three = remaining  and  4*four + 3*three = leftDegree.
    int four = leftDegree - 3 * remaining;
    int three = remaining - four;

    cout << "Vertices still to classify: " << remaining << endl;
    cout << "Degree left to share:       " << leftDegree << endl;
    cout << "Of those, degree 4: " << four << ", degree 3: " << three << endl;
    cout << "Degree-4 vertices in the whole graph: " << knownDeg4 + four << endl;
    return 0;
}
What it printed
Vertices still to classify: 5
Degree left to share:       19
Of those, degree 4: 4, degree 3: 1
Degree-4 vertices in the whole graph: 9

Where the two-line solution comes from. Let four and three be the counts. Then four + three = 5 and 4 × four + 3 × three = 19. Substituting three = 5 − four into the second gives 4 × four + 15 − 3 × four = 19, so four = 19 − 15 = 4 and three = 1. The single line four = leftDegree - 3 * remaining is that substitution done once and for all, which is why it deserves the comment above it.

The final line is the answer to part (a), not part (d), and printing it costs nothing. 5 + 4 = 9 vertices of degree 4, which is the trap the whole question is built around.

Recall and check

1. How does the power set program enumerate subsets, and why does that give the paper's order?

2. What does the word "dynamically" require of the bit-string program?

3. Why is element m stored at position m − 1?

4. Why must isPerfectSquare return an int rather than a bool?

5. Give two reasons the binary search uses long long and low + (high - low) / 2.

6. In the degree question, how many vertices of degree 4 does the graph have?

Answers

1. By counting a mask from 0 to 2n − 1 and reading its bits. Counting in that order is exactly the order the paper printed.
2. That the sets arrive through cin at run time rather than being written into the source.
3. Because string and vector positions count from 0, so the ten elements of U occupy positions 0 to 9.
4. Because the question says to return the midpoint as the square root, or −1 if there is none, and neither of those is a truth value.
5. long long because mid × mid can exceed the int range and overflow silently; the midpoint form because low + high can overflow before the division happens.
6. Nine: the five named in the question plus four of the five remaining vertices.
