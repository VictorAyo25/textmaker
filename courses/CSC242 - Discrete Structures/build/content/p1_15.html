Rules of Inference and Valid Arguments

An argument moves from things you accept to something new. The rules below are the moves that are always safe, and the two famous ones that are not.

By the end of this section you will be able to say what makes an argument valid, name and apply the standard rules of inference, spot the two classic fallacies, and construct acceptable logic statements leading to a conclusion, which the 2025/2026 paper asks for directly.

What "valid" means

Must memoriseValidity is about shape, not truth

An argument is a list of propositions called premises, followed by one called the conclusion.

An argument is valid when the conclusion is true in every case where all the premises are true. Equivalently, the conjunction of the premises implies the conclusion, and that implication is a tautology.

Validity says nothing about whether the premises are actually true. A valid argument from false premises can reach a false conclusion. What validity guarantees is that the step is safe.

Memory hook: valid means the wiring is sound. Sound means the wiring is good and the input is true. An exam asks about the wiring.

TeachA valid argument with a false conclusion

Premise 1: If it is a bird, it can fly.
Premise 2: A penguin is a bird.
Conclusion: A penguin can fly.

The conclusion is false, yet the argument is valid: the shape is the safest one there is. The fault lies in premise 1, which is false. That is the distinction the word "valid" exists to make.

The rules of inference

Must memoriseThe standard rules

Each rule reads: given the premises above the line, you may write the conclusion below it.

NamePremisesConclusionIn words
Modus ponensp → q, and pqThe rule fired, so the result follows.
Modus tollensp → q, and ¬q¬pThe result did not happen, so the cause did not.
Hypothetical syllogismp → q, and q → rp → rChain two implications.
Disjunctive syllogismp ∨ q, and ¬pqOne of two, and not the first, so the second.
Additionpp ∨ qIf p is true, "p or anything" is true.
Simplificationp ∧ qpIf both, then certainly one.
Conjunctionp, and qp ∧ qTwo separate facts combine.
Resolutionp ∨ q, and ¬p ∨ rq ∨ rThe rule automated theorem provers run on.

Memory hook: ponens is Latin for affirming and tollens for denying. Modus ponens affirms the hypothesis; modus tollens denies the conclusion. Those two carry most of the marks.

TeachModus tollens is the contrapositive at work

Modus tollens says: from p → q and ¬q, conclude ¬p.

That is nothing more than section 1.2 in action. Since p → q is equivalent to its contrapositive ¬q → ¬p, and you have ¬q, modus ponens on the contrapositive gives ¬p.

So the two rules are the same rule, seen from either end of an implication. Saying that in an answer shows the marker you understand the structure rather than having memorised a table.

The two fallacies

TrapThe two invalid moves that look valid

Affirming the consequent. From p → q and q, concluding p. This is invalid, and it is the converse mistake from 1.2 wearing a different hat.

If it is raining, the ground is wet. The ground is wet. Therefore it is raining.

No: a burst pipe would do it. The wet ground is consistent with rain but does not establish it.

Denying the antecedent. From p → q and ¬p, concluding ¬q. Also invalid, and it is the inverse mistake.

If it is raining, the ground is wet. It is not raining. Therefore the ground is not wet.

No: the pipe again.

Both fallacies come from treating p → q as if it ran both ways. Only the contrapositive runs the other way, which is precisely why 1.2 matters here.

The question the newest paper asks

As printed2025/2026 · Q4(c)

(c) Develop three good examples of acceptable logic statements leading to a conclusion. (3 marks)

Note on the paper
The wording is loose. "Acceptable logic statements leading to a conclusion" means valid arguments: premises followed by a conclusion that genuinely follows. It does not mean three true sentences. Answer it as "give three valid arguments, naming the rule of inference each uses", which is what earns the marks, and say in one line that this is how you are reading it.
Break it down
Given
Nothing but the instruction. You supply the content.
Asked
Develop three examples, each being premises plus a conclusion that follows. Since you choose them, choose ones you can name.
Marks say
3 marks, one per example. Each needs premises, a conclusion, and the name of the rule; a bare pair of sentences is half an answer.
Teaches
This section, 1.5.
Trap
Offering an argument that is not actually valid, most often by affirming the consequent. Stick to modus ponens, modus tollens and hypothetical syllogism, which are impossible to get wrong.
Worked examplePQ 25/26 Q4(c)

Reading the question as asking for three valid arguments, each named.

Example 1, modus ponens.
Premise 1: If a program compiles without errors, then it produces an executable file.
Premise 2: This program compiles without errors.
Conclusion: Therefore it produces an executable file.

Form: p → q, p, therefore q. Valid, because the only row where p → q and p are both true also has q true.

Example 2, modus tollens.
Premise 1: If a set has 5 elements, then it has 32 subsets.
Premise 2: This set does not have 32 subsets.
Conclusion: Therefore this set does not have 5 elements.

Form: p → q, ¬q, therefore ¬p. Valid. (Section 2.1 established the premise: a set of n elements has 2n subsets, and 25 = 32.)

Example 3, hypothetical syllogism.
Premise 1: If a student passes the practical, then the student qualifies for the project.
Premise 2: If a student qualifies for the project, then the student graduates.
Conclusion: Therefore if a student passes the practical, that student graduates.

Form: p → q, q → r, therefore p → r. Valid, by chaining.

Finish with one line that earns the last mark: in each case the conclusion is true in every situation where the premises are both true, which is the definition of a valid argument.

Now redo it: write three more of your own, one of them using disjunctive syllogism, and check each against the rules table.

Logic in computing

As printed2025/2026 · Q4(b)

(b) Discuss the place of Logic in Computer Science highlighting practical areas of relevance? (2 marks)

Note on the paper
Printed with a question mark on a command, which is a habit of this examiner and carries no meaning. Two marks means two or three sentences with named areas, not an essay.
Worked examplePQ 25/26 Q4(b)

Logic is the formal language in which computer science states precise conditions and reasons about them, and it appears at every level of the subject.

Hardware. Every digital circuit is a Boolean expression made physical: AND, OR and NOT gates implement the connectives directly, so simplifying an expression means using fewer components. Part Eight is this.

Programming. Every condition in an if or while is a proposition, and the compiler applies De Morgan's laws and the implication law to optimise them.

Databases. A query is a predicate; the engine uses quantifiers and logical equivalence to rewrite it into a faster but equivalent form.

Verification. Proving that a program meets its specification, and automated theorem proving, both run on the rules of inference, with resolution as the workhorse.

Artificial intelligence. Knowledge representation and rule-based reasoning are predicate logic with an inference engine attached.

For two marks, three of these named with a one-line reason each is a full answer.
