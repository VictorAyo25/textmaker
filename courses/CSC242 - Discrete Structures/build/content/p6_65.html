Part Six · 6.5

Adjacency, Path and Relation Matrices

A graph can be stored as a grid of ones and zeros. Once it is, questions about routes become questions about multiplying the grid by itself, and the newest paper gives 6.5 marks to how a computer holds it.

By the end of this section you will be able to write the adjacency matrix of a graph or digraph, read degrees off it, build the path matrix from powers of the adjacency matrix, tell a logical matrix from a relation matrix, and answer the four matrix questions on the 2025/2026 paper.

The adjacency matrix

Must memoriseAdjacency matrix

Number the vertices 1 to n in a fixed order. The adjacency matrix A of the graph is the n by n grid whose entry in row i, column j is

aij = the number of edges from vertex i to vertex j, which for a simple graph is 1 if they are joined and 0 if they are not.

Where n is the order of the graph, so A is always square and always n by n. the vertex order must be fixed and stated first. Re-number the vertices and you get a different-looking matrix for the same graph. aii, on the leading diagonal, records loops at vertex i.

Three properties to state whenever you are asked to explain one.

  1. For an undirected graph, A is symmetric: aij = aji, because an edge joining i and j joins j and i. For a digraph it usually is not, since an arc has a direction.
  2. The row sum is the degree. Adding across row i gives deg(i) for an undirected simple graph, and deg+(i) for a digraph; the column sum gives deg−(i).
  3. A simple graph has zeros all along the leading diagonal, because a simple graph has no loops.

Memory hook: row to column, tail to head. Read aij as "from i to j". For an undirected graph the direction does not matter and the matrix comes out symmetric, which is itself the proof that the graph is undirected.

The path matrix

Must memoriseWalks, and the path matrix

The key fact. If A is the adjacency matrix, then the entry in row i, column j of Ak is the number of walks of length exactly k from vertex i to vertex j.

The path matrix (also called the reachability matrix) P records only whether a route exists at all:

pij = 1 if there is a path from i to j, and 0 if there is none.

Where a walk of length k is a sequence of k edges followed end to end; vertices and edges may repeat. Ak is A multiplied by itself k times, using ordinary arithmetic. P is built from A + A2 + … + An−1 by replacing every non-zero entry with 1. Nothing longer than n − 1 edges is needed: a path that visits no vertex twice cannot use more.

The difference the exam asks about, in one line: the adjacency matrix answers "can I get there in one step?"; the path matrix answers "can I get there at all?"

Memory hook: adjacency is one hop, path is any number of hops. Powers of A count the routes of each exact length; flattening the sum to ones and zeros forgets how many and remembers only whether.

Logical matrix against relation matrix

Must memoriseLogical and relation matrices

A logical matrix (also called a Boolean or binary matrix) is any matrix whose entries are all 0 or 1, where the entries are read as false and true rather than as numbers.

A relation matrix is the particular logical matrix that records a relation R from a set A to a set B, as defined in section 3.1:

mij = 1 exactly when (ai, bj) is in R, and 0 otherwise.

Where ai is the i-th element of A in a fixed listed order, giving the rows. bj is the j-th element of B, giving the columns. For a relation on one set, A and B are the same and the matrix is square. mij is 1 or 0, and it is a truth value, not a count.

The relationship between the three terms, which is what a "differentiate between" question is really asking for:

  • Every relation matrix is a logical matrix. The reverse does not hold: a logical matrix is only a relation matrix once you say which sets index its rows and columns.
  • An adjacency matrix of a simple graph is also a logical matrix, and it is exactly the relation matrix of the relation "is joined to". A multigraph's adjacency matrix is not logical, because its entries count parallel edges and may exceed 1.

Memory hook: logical says what the entries are, relation says what they mean. The first is a description of the contents; the second is a description of the job.

The question is quoted in full in section 6.1: "v) A logical matrix and relation matrix", printed "(2marks)" with no space.

The distinction. A logical matrix is any matrix all of whose entries are 0 or 1, read as false and true. A relation matrix is a logical matrix whose rows are labelled by the elements of one set and whose columns are labelled by the elements of another, with a 1 marking exactly the pairs that belong to the relation. So every relation matrix is a logical matrix given a job to do; not every logical matrix has been given that job.

Two examples of a logical matrix. (1) The 2 by 2 grid with rows (1, 0) and (0, 1) is logical, and until its rows and columns are labelled it records nothing in particular. (2) The truth table of a two-variable connective, written as a grid of Ts and Fs, is a logical matrix in disguise.

Worked examplePQ 25/26 Q6(a)

i. Clearly explain the adjacency matrix

Definition. Fix an order on the n vertices of a graph. The adjacency matrix A is the n by n matrix whose entry aij is the number of edges from vertex i to vertex j, which is 1 or 0 for a simple graph.

What it is for. It turns a drawing into data. A picture cannot be given to a program; a grid of numbers can, and every graph algorithm in computing starts from a representation of this kind.

Its properties, which is where the half marks live: it is square; it is symmetric exactly when the graph is undirected; its diagonal is zero exactly when there are no loops; its row sums are the degrees; and the entries of Ak count the walks of length k.

An example. Give the four-vertex matrix drawn above, with its vertex order stated, and point at one entry: a34 = 1 because vertices 3 and 4 are joined, while a14 = 0 because they are not.

ii. Memory management in the adjacency matrix

Four points, one per mark.

  1. The cost is n2, whatever the graph. An adjacency matrix stores an entry for every ordered pair of vertices, so a graph of n vertices needs n2 cells regardless of how many edges it actually has. A graph on 1000 vertices needs 1000000 cells even if it has only 5 edges. The storage depends on the order, never on the size.
  2. It is wasteful on sparse graphs, and most real graphs are sparse. A graph is sparse when its edge count is far below the n(n − 1)/2 maximum, and dense when it is near it. Road networks, social graphs and computer networks are all sparse: a city has millions of junctions and each meets three or four roads. For these the matrix is almost entirely zeros, and storing zeros costs exactly as much as storing ones.
  3. Two savings are available without changing structure. First, an undirected graph's matrix is symmetric, so only the upper triangle need be held, roughly halving the space to n(n − 1)/2 cells. Second, a simple graph's entries are single bits, so 64 of them pack into one machine word instead of one integer each; that is a factor of 32 or 64 on the same data.
  4. The alternative is an adjacency list. Store, for each vertex, only the list of its neighbours. That costs about n + 2|E| for an undirected graph rather than n2, which is dramatically less when |E| is small. The trade-off is the point to state: the matrix answers "are i and j adjacent?" in constant time by one lookup, while the list must scan a neighbour list; but the list walks all the neighbours of a vertex in time proportional to their number, while the matrix must scan a whole row of n cells to find them.

The closing sentence that makes it a discussion rather than a list: choose the adjacency matrix for small or dense graphs and for algorithms that ask "is this pair joined?" repeatedly; choose the adjacency list for large sparse graphs and for algorithms that walk neighbours, which is most traversal and shortest-path work.
