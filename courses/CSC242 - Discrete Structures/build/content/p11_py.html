Enough Python to Answer the Question

You are not being examined on Python. You are being examined on whether you can express a discrete structure as a program. That takes far less of the language than a programming course would give you, and this section is the whole of what the four examined questions use. Section 11.2 gives the same tools in C++ for the older papers; read whichever language you will write.

By the end of this section you will be able to write and read a complete Python program: printing and reading, the values this course needs, arithmetic including the two kinds of division and the remainder, conditions, both kinds of loop, lists, functions with a return value, and the bit operations that turn a subset into a number.

Almost nothing in the course text, and none of what the exam asks
The official text carries exactly one worked program: a count of the integers below 100 divisible by 2, 3 or 5, done by inclusion and exclusion and printed in both C++ and Python3, followed by a single exercise that says "write a Python or C++ program" for the same kind of count. That is the whole of its programming content. It explains no syntax, no values, no input, no loop as an idea; it drops the two listings in and moves on. None of the four programs the papers actually set, the power set by bit mask, the bit strings, the binary search, the degree count, resembles it. So this part teaches both languages from the ground up, to exactly the depth those questions need, and every listing in it was run before it went on the page.

The smallest program, and what Python spares you

Must memoriseA whole program is one line

Where C++ needs four lines of scaffolding before it prints anything, Python needs none. This complete program prints one word:

The smallest complete program
# A comment. Everything after a hash is ignored by Python.
print("Hello")            # no #include, no main, no braces, no semicolons
Where print(...) writes what is inside the brackets to the screen and then moves to a new line. It is the whole of output for this course. the round brackets are a function call: print is a function, and the value to print goes between its brackets. "Hello" in double quotes is a string, a piece of text. # starts a comment, which runs to the end of the line. It is Python's //. no semicolon is needed: in Python the end of the line ends the statement.

Memory hook: Python has no boilerplate. The first line of your answer is the first line of the solution, not four lines of ceremony.

Values and variables

Must memoriseFour kinds of value, and no type to declare

Python does not make you announce what kind of value a name holds. You write the name, an =, and the value; the kind is decided by what you put there.

Where n = 24 reads: make a name n and let it stand for 24. No type word in front, unlike C++. = is assignment, not equality. It puts the right side into the name on the left. The test for equality is ==, with two signs. True and False are capitalised in Python, which is the spelling the compiler insists on. int of any size is the difference that matters here. Python integers never overflow: they grow to whatever size the arithmetic needs.

Why "any size" is worth a sentence. The password count of section 5.1 is 2684483063360, far past what a fixed-width integer holds. In C++ that forces a choice of long long, and choosing wrong gives a silent wrong answer; in Python the number simply grows and there is nothing to get wrong. If you write the same count in both languages, this is the one place they differ.

Where / in Python is true division and always produces a decimal: 7 / 2 is 3.5, and even 4 / 2 is 2.0, not 2. This is the opposite of C++, where / between whole numbers throws the fraction away. Getting the two languages the wrong way round here is the single commonest slip. // is floor division, the one that keeps only the whole part: 7 // 2 is 3. When you want the midpoint of a range or an integer count, this is the slash you need, not /. % is read "mod" and gives what is left over. n % 2 is 0 exactly when n is even, the definition from section 9.1 written as a test. and, or, not are conjunction, disjunction and negation from Part One, spelled as English words rather than symbols.

Memory hook: one slash divides for real, two slashes keep the whole part. In C++ it is the single slash that keeps the whole part; do not carry the C++ habit across.

Reading input, and making choices

Must memoriseinput, int(), and the if

input() reads one line from the keyboard and hands it back as a string. To do arithmetic on it you must convert it, with int(...) for a whole number.

Reading a number and testing it
n = int(input("Enter an integer: "))   # read a line, turn it into a number

if n % 2 == 0:
    print(n, "is even")
else:
    print(n, "is odd")
Where input("...") prints its prompt, waits for a line, and returns what was typed as text. Without the int(...) around it, n would be the string "24", and "24" % 2 is meaningless. the colon ends the if line, and every block in Python opens with one: after if, else, for, while and def. the indentation is the block. Python has no braces; the lines belonging to the if are exactly the lines indented under it. Four spaces is the convention, and being consistent is not optional: mixed indentation is an error. print(n, "is even") prints several things separated by a space, so the output reads "24 is even".

Dynamic input is what "dynamically" means in an exam question. The 2023/2024 paper asks for a program that "dynamically takes these sets as input"; that is a request for input(), not for the three sets typed into the source as constants. A program with the answer already written into it has not been asked for.

Loops

Must memorisefor and while

Two loops, and the choice between them is mechanical.

A for loop: use it when you know how many times
for i in range(n):        # i takes 0, 1, ..., n - 1
    print(i, end=" ")
A while loop: use it when you stop on a condition
while low <= high:        # keep going until the range is empty
    pass                 # the real body would shrink the range
Where range(n) produces the numbers 0, 1, ..., n − 1: n of them, starting at 0 and stopping before n. So the loop runs n times, and counting from 0 is the Python convention just as it is the C++ one. for i in ... takes each value in turn and puts it in i. There is no separate start, condition and step as in C++; range holds all three. end=" " tells print to end with a space instead of a new line, so the numbers print along one line. while takes only the condition, so something in the body must eventually make it false. If nothing does, the program never stops. pass is a do-nothing statement, here only because a block may not be empty; the real loop puts work there.

Memory hook: for counts, while waits. A known number of passes is a for; a search that ends when it finds something is a while.

The off-by-one to expect. range(n) stops at n − 1, which is n passes and exactly the length of an n-element list. This is the same one-fewer-than-you-think that section 9.3 met in an = a + (n − 1)d.

Many values at once

Must memoriselist, and reading a whole line of numbers
Declaring, filling and reading a list
s = [0] * n                # n slots, all 0 to begin with
for i in range(n):
    s[i] = int(input())      # fill one slot per line
print(s[0], "and there are", len(s), "of them")
Where [0] * n makes a list of n zeros. A list is Python's array, and it can be any length, which is what "dynamically" needs. s[i] is the slot at position i, counting from 0. A three-element list has slots s[0], s[1], s[2], and s[3] does not exist. len(s) is how many slots there are. s[-1], worth knowing, is the last slot, counting from the end.

Reading a whole line of numbers at once, which the examined programs use, is one idiom worth memorising:

One line of numbers into a list
s = list(map(int, input().split()))   # "1 2 3" becomes [1, 2, 3]
Where input().split() reads the line and breaks it at the spaces into pieces of text: "1 2 3" becomes "1", "2", "3". map(int, ...) applies int to each piece, turning each string into a number. list(...) collects the results into a list. The three steps read left to right: split the line, convert each piece, gather them up.

Position 0 is not a quirk to work around. It is the reason bits[m - 1] appears in the bit-string program: element m of the universe {1, ..., 10} lives at slot m − 1. Write that subtraction down deliberately rather than discovering it by being one out.

Functions

Must memoriseWriting a function and calling it

A function is a named piece of program that takes values in and hands one value back. It is the section 4.1 idea of a function, made executable.

Definition, then use
def larger(a, b):          # takes two values, hands one back
    if a > b:
        return a
    return b

print(larger(3, 9))         # prints 9
Where def larger(a, b): begins a definition: def, the name, the parameters in brackets, then a colon. There is no return type to declare, unlike C++. a, b are the parameters: names for the values passed in. These are the domain of section 4.1. return a hands a value back and stops the function immediately. Everything after it in that path is not run. larger(3, 9) is the call. The whole expression stands for the value returned, so it can be printed, stored or used in arithmetic. the indented block is the body, exactly as with a loop: the function is the lines indented under the def.

Python does not require a function to appear before it is called, as long as the definition has run by the time the call happens. Defining every helper at the top of the file, above the code that uses it, is the safe habit and the one every program in the next section follows.

Bits, and why a subset is a number

TeachThe two operators the power set needs

Section 2.3 encoded a subset as a bit string: one bit per element of the universe, 1 when the element is in. Python can hold that string of bits as a single whole number and test one bit at a time, which turns "list every subset" into "count from 0 upwards". These two operators are spelled exactly as in C++, so this is the one part of the language the two share letter for letter.

WrittenReadDoes
1 << ione shifted left by ia number with a single 1 bit, at position i

Where << is the shift operator: it moves the bits of a number to the left, so 1 << i is 1 followed by i zeros in binary. In Python << has only this meaning, with none of the printing sense it carries in C++. & with one ampersand is bitwise and: it lines two numbers up bit by bit and keeps a 1 only where both have one. The word and is the logical connective of Part One; the symbol & is the bit operator, and they are not interchangeable. mask is the number whose bits name a subset: bit i is 1 when element i is in. position i counts from 0 at the right-hand end, so 1 << 0 is 1, 1 << 1 is 2, 1 << 2 is 4.

TrapYou are writing on paper, not in an editor

There is no interpreter in the hall. Nobody will run what you write, which cuts both ways: a missing colon will not stop you, and a program that only looks plausible will not fool a marker who can read. This advice holds whichever language you answer in.

  • Comment the steps the question numbered. 2024/2025 Q4(c) lists five things the function must do; put those five as comments in the body and the marker can find each one.
  • Indent consistently. In Python the indentation is the program, so ragged indentation is not untidy, it is wrong. Four spaces a level, the same throughout.
  • End every block header with a colon, after if, for, while and def. It is the semicolon of Python for how often it is left out.
  • Prompt before every read. Put the message inside input(...), every time.
  • Name things as the question names them. If it says the function is called isPerfectSquare, that is its name. Renaming it is the same defect as paraphrasing a quotation.
  • If you run out of time, write the logic in ordered comments. A correct method in comments earns more than half a program that stops mid-loop.
