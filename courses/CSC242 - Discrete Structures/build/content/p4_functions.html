Functions, Domain and Range

A function assigns exactly one output to each input. That single word "exactly" is the whole definition, and it is what separates a function from an ordinary relation.

By the end of this section you will be able to say whether a given rule or diagram is a function, name the domain, codomain and range, and explain the difference between the last two.

From relations to functions

Must memoriseDefinition

A function f from A to B, written f : A → B, is a relation from A to B in which every element of A is paired with exactly one element of B.

If f pairs a with b we write f(a) = b, and call b the image of a, and a a pre-image of b.

Two conditions are hiding in "every ... exactly one":

Totality: nothing in A is left unassigned.
Single-valuedness: nothing in A gets two different outputs.

Memory hook: a function is a machine with one slot and one answer. Put the same thing in twice and you must get the same thing out; put anything valid in and something must come out.

Must memoriseDomain, codomain, range

For f : A → B,

domain = A, the set of all allowed inputs.
codomain = B, the set the outputs are declared to live in.
range (or image) = the set of values actually produced, {f(a) | a ∈ A}.

The range is always a subset of the codomain, and it may be smaller.

Memory hook: the codomain is what you promised, the range is what you delivered. When they are equal, the function is onto, which is section 4.2.

TeachWhy range and codomain differ

Take f : ℝ → ℝ with f(x) = x².

The domain is all reals and the codomain is all reals, because that is how the function was declared. But no square is negative, so the range is only the non-negative reals. The function promised to return a real number and delivered only half of them.

In programming terms the codomain is the declared return type and the range is the set of values the routine can actually return. A routine declared to return an integer might in fact only ever return 0 or 1.

TrapTwo ways a relation fails to be a function

An input with no output. On A = {1, 2, 3}, the relation {(1,a), (2,b)} is not a function: 3 has no image. Every element of the domain must be used.

An input with two outputs. {(1,a), (1,b), (2,c), (3,d)} is not a function either: 1 is sent to two places.

An output used twice is fine: {(1,a), (2,a), (3,a)} is a perfectly good function. The restriction is on inputs, never on outputs. Getting that backwards is the commonest error in the diagram question of 4.2.

Worked exampleMethod

Which of these relations on A = {1, 2, 3} to B = {a, b, c} are functions?

RelationFunction?Why
{(1,a), (2,b), (3,c)}yeseach input once, each with one output
{(1,a), (2,a), (3,a)}yesrepeated outputs are allowed
{(1,a), (2,b)}no3 has no image, so it is not total
{(1,a), (1,b), (2,c), (3,c)}no1 has two images

For the second one, the domain is {1,2,3}, the codomain is {a,b,c}, and the range is just {a}.

Now redo it: is {(1,c), (2,c), (3,b)} a function? What is its range? (Yes; range {b, c}.)

TeachThe two-line notation

For a function on a small finite set, the tidiest way to write it is a two-line table with each input directly above its output:

f = ( 1 2 3 )
( 2 3 1 )

meaning f(1) = 2, f(2) = 3, f(3) = 1. It is only notation, and it is not a matrix in the sense of section 3.1: you cannot multiply two of these or row-reduce them. The name is borrowed, the operations are not.

Recall and check

1. What two conditions must a relation satisfy to be a function?

2. For f : ℝ → ℝ, f(x) = x², state the codomain and the range.

3. May two different inputs share an output?

4. May one input have two outputs?

Answers

1. Every element of the domain is used (totality), and none is sent to more than one place (single-valuedness).
2. Codomain ℝ; range the non-negative reals.
3. Yes, always allowed.
4. No. That is exactly what a function forbids.
