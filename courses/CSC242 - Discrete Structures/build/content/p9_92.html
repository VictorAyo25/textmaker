Mathematical Induction

One proof, infinitely many statements. Induction is how you prove something about every natural number without checking them one at a time, and it is the technique behind the tree bound of section 7.2 that the 2024/2025 paper asked for outright.

By the end of this section you will be able to state the principle of mathematical induction, lay out the three steps in the order a marker expects, prove a summation formula, a divisibility claim and an inequality by induction, explain why the base case cannot be skipped, and use strong induction where ordinary induction stalls.

TeachThe ladder and the dominoes

Suppose there is an infinite ladder and you know two things:

  • you can reach the first rung, and
  • from any rung you reach, you can reach the next one.

Can you reach every rung? Yes. And notice you were never told how to reach rung 400 directly. The second fact is a machine that manufactures that answer: reach 1, so reach 2, so reach 3, and the argument runs as far as anyone cares to push it.

The same picture with dominoes standing in a line. Knock the first one over, and space them so that each falling one topples its neighbour. Both conditions are needed. A first domino that never falls leaves the line standing; a gap anywhere in the line stops the chain there and everything past the gap survives.

The principle of mathematical induction

The claim. Let P(n) be a statement about the integer n. If P is true at a starting value, and if the truth of P at any value forces its truth at the next value, then P is true at every value from the start onwards. One check plus one implication buys infinitely many statements.

In symbols.
If P(a) is true, and P(k) → P(k + 1) for every k ≥ a,
then P(n) is true for every n ≥ a.

Conditions. The statement must be indexed by an integer that increases in steps of one; there is no induction over the real numbers, because there is no "next" real number. The starting value a is usually 0 or 1 but may be any integer, and the conclusion then only covers n ≥ a. The inductive step must hold for every k from a onwards, not merely for the small ones you tried.

The limiting case. With no base case the principle says nothing at all, however impeccable the inductive step. "If n = n + 1 then n + 1 = n + 2" is a perfectly valid inductive step for a statement that is false everywhere; nothing ever gets it started. The base case is not a formality, it is half the proof.

Must memoriseThe three steps, in order

Write these three headings on the page before you write any mathematics. Markers award them separately.

StepWhat you write
1. Base caseState P(a) for the smallest a in the claim, and verify it by direct computation. Both sides, evaluated.
2. Inductive hypothesisAssume P(k) holds for some arbitrary k ≥ a. Write out what P(k) actually says.
3. Inductive stepUsing that assumption, prove P(k + 1). Write out what P(k + 1) says as a target, then reach it.

The whole principle on one line, which is what the three steps above amount to:

P(a), together with P(k) → P(k + 1) for every k ≥ a, gives P(n) for every n ≥ a

Where P(n) is the statement being proved, a predicate in the sense of section 1.4: for each n it is either true or false. It is not a number and you never "calculate P(n)". a is the base value, the smallest n the claim covers. k is an arbitrary value at or above a. It is not a specific number, and it is not n; using n for both is the most common way to write a proof that says nothing. P(k) → P(k + 1) is the inductive step, a conditional, so it is proved by assuming the left side, in the manner of section 9.1.

Close with the conclusion. "By the principle of mathematical induction, P(n) holds for all n ≥ a." A proof that stops after the algebra has left its last mark on the table.

Memory hook: check one, assume one, earn the next. And the assumption is the tool, so every inductive step must use it somewhere; if yours does not, you have proved P(k + 1) outright and did not need induction at all.

A summation formula

Worked exampleMethod · 1 + 2 + … + n
Given
The claim P(n): 1 + 2 + 3 + … + n = n(n + 1) / 2, for every natural number n ≥ 1.
Find
A proof by induction on n.
Formula
Base case, inductive hypothesis, inductive step.

Step 1. Base case, n = 1

The left side is the single term 1. The right side is

1 × (1 + 1) / 2 = 2 / 2 = 1

Both sides equal 1, so P(1) holds.

Step 2. Inductive hypothesis

Assume P(k) holds for some k ≥ 1, that is

1 + 2 + … + k = k(k + 1) / 2

Step 3. Inductive step

The target. P(k + 1) says

1 + 2 + … + k + (k + 1) = (k + 1)(k + 2) / 2

Start from the left side and use the hypothesis. The first k terms are exactly what the hypothesis measures, so replace them:

1 + 2 + … + k + (k + 1)
= k(k + 1) / 2 + (k + 1)     [inductive hypothesis]
= k(k + 1) / 2 + 2(k + 1) / 2     [common denominator]
= (k + 1)(k + 2) / 2     [take out the factor (k + 1)]

which is the target, so P(k + 1) holds.

Conclusion. By the principle of mathematical induction, 1 + 2 + … + n = n(n + 1) / 2 for every n ≥ 1. □

A check that costs one line. At n = 100 the formula gives 100 × 101 / 2 = 5050. Adding one more term, 5050 + 101 = 5151, and the formula at n = 101 gives 101 × 102 / 2 = 5151. That agreement is the inductive step happening in front of you at one particular k.

Now redo it: prove 1 + 3 + 5 + … + (2n − 1) = n2. Base case n = 1: left 1, right 1. Step: k2 + (2(k + 1) − 1) = k2 + 2k + 1 = (k + 1)2. Sanity check at n = 4: 1 + 3 + 5 + 7 = 16 = 42.

A divisibility claim

Worked exampleMethod · n cubed plus 2n is divisible by 3
Given
P(n): n3 + 2n is divisible by 3, for every positive integer n.
Find
A proof by induction.
Formula
Divisibility is the definition of section 9.1: 3 divides x when x = 3t for some integer t.

Step 1. Base case, n = 1

13 + 2 × 1 = 1 + 2 = 3

and 3 = 3 × 1, so P(1) holds.

Step 2. Inductive hypothesis

Assume P(k): k3 + 2k is divisible by 3, so by the definition there is an integer t with

k3 + 2k = 3t

Naming t is the step candidates skip, and without it there is nothing to substitute later.

Step 3. Inductive step

The target. (k + 1)3 + 2(k + 1) is divisible by 3.

Expand, using (k + 1)3 = k3 + 3k2 + 3k + 1:

(k + 1)3 + 2(k + 1)
= k3 + 3k2 + 3k + 1 + 2k + 2
= (k3 + 2k) + (3k2 + 3k + 3)

Now use the hypothesis on the first bracket, and take 3 out of the second:

= 3t + 3(k2 + k + 1)
= 3(t + k2 + k + 1)

and t + k2 + k + 1 is an integer, so the total is divisible by 3. P(k + 1) holds.

Conclusion. By induction, n3 + 2n is divisible by 3 for every positive integer n. □

The move to learn here is the regrouping: split the expanded expression so that the hypothesis appears intact as one bracket, and everything left over is visibly a multiple of 3. Every divisibility induction has that shape.

Check three values: n = 2 gives 8 + 4 = 12, n = 3 gives 27 + 6 = 33, n = 4 gives 64 + 8 = 72. All multiples of 3.

Now redo it: prove 6n − 1 is a multiple of 5 for every natural number n. Base n = 0: 1 − 1 = 0, which is 5 × 0. Hypothesis: 6k − 1 = 5j, so 6k = 5j + 1. Then 6k+1 − 1 = 6(5j + 1) − 1 = 30j + 5 = 5(6j + 1). Check: n = 1 gives 5, n = 2 gives 35, n = 3 gives 215.

An inequality, and where the base case really lives

Worked exampleMethod · n squared below 2 to the n
Given
P(n): n2 < 2n, for every integer n ≥ 5.
Find
A proof by induction, and an explanation of why the claim starts at 5.
Formula
Base case at n = 5, then the step.

First, why 5. Test the small values and the reason appears:

nn22nIs n2 < 2n?
112yes
244no, they are equal
398no
41616no, they are equal
52532yes
63664yes

The claim is false at n = 2, 3 and 4, and true from 5 onwards. That is why the question says n ≥ 5, and it is a good illustration that a base case is a genuine check, not a ritual: the same inductive step would run happily from a base of 3 and would then be carrying a false statement.

Step 1. Base case, n = 5

52 = 25 and 25 = 32, and 25 < 32. P(5) holds.

Step 2. Inductive hypothesis

Assume P(k) for some k ≥ 5, that is k2 < 2k.

Step 3. Inductive step

The target. (k + 1)2 < 2k+1.

Work on the left side. (k + 1)2 = k2 + 2k + 1. Since k ≥ 5 we have 2k + 1 ≤ k2, because that inequality holds for every k ≥ 3. So

(k + 1)2 = k2 + 2k + 1 ≤ k2 + k2 = 2k2

Now use the hypothesis: k2 < 2k, so

2k2 < 2 × 2k = 2k+1

Chaining the two, (k + 1)2 < 2k+1, which is P(k + 1).

Conclusion. By induction, n2 < 2n for every integer n ≥ 5. □

The technique in inequality inductions is always this: bound the awkward extra term by something the hypothesis can absorb. Here 2k + 1 was bounded by k2, and the side condition k ≥ 3 that made that legal was stated rather than assumed.

The examined one

Worked examplePQ 24/25 Q6(b) vii, in the induction template

The 2024/2025 paper asked for a proof that an m-ary tree of height h has at most mh leaves. That question is quoted as printed and answered in section 7.2, where the tree vocabulary lives. It is repeated here in the three-step layout so you can see the same proof through this section's frame, because the two are the same argument written for two different markers.

Given
An m-ary tree of height h, that is a rooted tree in which every vertex has at most m children.
Find
A proof that it has at most mh leaves.
Formula
Induction on the height h, not on the number of vertices.

Step 1. Base case, h = 0

A tree of height 0 is a single vertex, which is both the root and a leaf. It has 1 leaf, and m0 = 1, so the bound holds with equality.

Step 2. Inductive hypothesis

Assume every m-ary tree of height k has at most mk leaves.

Step 3. Inductive step

Let T be an m-ary tree of height k + 1. Remove the root. What remains is at most m subtrees, one per child of the root, and each has height at most k. By the hypothesis each has at most mk leaves. Every leaf of T lies in one of them, so

leaves of T ≤ m × mk = mk+1

Conclusion. By induction the bound holds at every height. □

Note what the induction was on. Choosing the right quantity to induct on is most of the skill. Inducting on the number of vertices here would be painful, because removing a vertex from an m-ary tree need not leave an m-ary tree of any convenient height. Height was the quantity that made the step easy.

Strong induction

TeachWhen one step back is not enough

Ordinary induction assumes P(k) and proves P(k + 1): it reaches back exactly one rung. Sometimes the argument needs to reach further, or to reach back to a value it cannot predict.

Strong induction assumes P(a), P(a + 1), …, P(k) all at once, and proves P(k + 1) from any of them it likes. The principle is the same and is itself provable from ordinary induction, so no new permission is needed.

The standard example: every integer n ≥ 2 is a product of prime numbers.

Proof. Base case: 2 is itself prime, so it is a product of one prime. Assume every integer from 2 up to k is a product of primes, and consider k + 1. Either k + 1 is prime, in which case it is a product of one prime and we are done; or it is not, in which case k + 1 = ab for some integers a and b with 2 ≤ a ≤ k and 2 ≤ b ≤ k. Both a and b are covered by the hypothesis, so each is a product of primes, and multiplying those products gives one for k + 1. □

Why ordinary induction fails here. The factors a and b are not k, and there is no telling in advance where they land. Only an assumption covering every smaller value is any use. That is the signal for strong induction: the step goes back an unpredictable distance. The same signal appears in section 9.4, where a second-order recurrence needs two previous terms rather than one.

TrapThree ways an induction proof loses marks

1. Assuming what is to be proved. Writing "1 + 2 + … + (k + 1) = (k + 1)(k + 2) / 2" at the top of step 3 and then manipulating both sides until they agree is circular. Start from one side, use the hypothesis, and arrive at the other. If you do work on both sides, say plainly that you are showing two expressions are equal, and never treat the target as available.

2. Never using the hypothesis. An inductive step that does not cite P(k) anywhere has proved P(k + 1) from nothing, which either means induction was unnecessary or, far more often, that a step is missing. Point at the line where you used it.

3. A base case that is asserted rather than checked. "Clearly true for n = 1" earns nothing. Evaluate both sides and show they agree. The inequality above is the reason: at n = 4 that claim is false, and only an evaluated base case catches it.

Recall and check

1. Name the three steps of an induction proof.

2. What exactly do you assume in step 2, and about which value?

3. Why can the base case not be skipped?

4. State the formula for 1 + 2 + … + n and evaluate it at n = 100.

5. What does strong induction assume that ordinary induction does not?

6. Give the signal that tells you strong induction is needed.

Answers

1. Base case, inductive hypothesis, inductive step.
2. That P(k) is true, for an arbitrary k at or above the base value.
3. The inductive step alone only passes truth along; with nothing true to start from it proves nothing, and it will happily carry a false statement forever.
4. n(n + 1) / 2, which is 100 × 101 / 2 = 5050.
5. Every earlier case, P(a) through P(k), rather than P(k) alone.
6. The step needs a value an unpredictable distance back, as when a number is split into two unknown factors.
