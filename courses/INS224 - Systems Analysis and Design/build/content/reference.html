TrapThe look-alikes

Four pairs are almost identical and each is a lost mark if confused. Fix them now:

  • Hollow vs filled diamond (class): hollow is aggregation (part survives), filled is composition (part dies with the whole).
  • Include vs extend arrow (use case): include points to the step always run; extend points to the base it might add to.
  • Bar vs crow's foot (ERD): bar is one, crow's foot is many; the circle beside either makes it optional.
  • Closed box vs open-ended rectangle: a closed rectangle is an entity or an external entity; the data store is open at the right.

The Must-Memorise List

The lists the examiner asks you to reproduce. Recite each one from memory, then check. If you know these, Section A is done and Section B has no surprises.

Must memoriseThe core lists
  • SDLC phases (PADIS): Planning, Analysis, Design, Implementation, Support.
  • Analyst's skills: technical, business, people (people is the most important).
  • Problem-solving sequence: understand, verify benefit > cost, define requirements, alternatives, recommend, detail, implement, monitor.
  • Feasibility (TEOSL): Technical, Economic, Operational, Schedule, Legal.
  • Elicitation techniques: interview, questionnaire, observation, document review, JAD, prototyping.
  • Requirement types: functional (what it does) vs non-functional (a quality); and business / user / system levels.
  • Use case relationships: association, include, extend, generalization.
  • DFD elements: external entity, process, data store, data flow.
  • DFD mechanical errors: black hole (no output), miracle (no input), grey hole (too little input).
  • Cardinal relationships: one-to-one, one-to-many, many-to-many.
  • Object-oriented concepts: encapsulation, inheritance, polymorphism, composition, aggregation, association.
  • Multiple inheritance drawbacks: the diamond problem, complexity, name clashes.
  • UML categories: structural (class, object) and behavioural (use case, activity, sequence). Inventors: Booch, Rumbaugh, Jacobson.
  • Client-server tiers: single, two, three, n-tier.
  • Hardware non-functional requirements (OPSC): operational, performance, security, cultural/political.
  • Acquisition strategies: build, buy, outsource.
  • Conversion strategies: direct cutover, parallel, phased, pilot.
  • Support activities: maintain, enhance, support the users (help desk).
Must memoriseThe one-line answers
  • Analyst: a business problem solver, the bridge between users and the technical team.
  • Model vs tool vs technique vs methodology: a model represents the system; a tool is software you use; a technique is a way of doing one activity; a methodology is the whole package.
  • Predictive vs adaptive: predictive plans everything upfront; adaptive plans as it goes in short iterations.
  • Cardinality vs ordinality: cardinality is the maximum (one or many); ordinality is the minimum (mandatory or optional).
  • Object vs class: a class is the blueprint; an object is an instance of it.
  • Composition vs aggregation: composition the part dies with the whole; aggregation the part lives on.
  • Data model vs process model: a data model (ERD) shows data at rest; a process model (DFD) shows data in motion.
  • Forward vs backward chaining: read a relationship in the direction of the verb, then the reverse.
