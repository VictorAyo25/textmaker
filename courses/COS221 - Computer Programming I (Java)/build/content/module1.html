UNIT 1.1 · OVERVIEW OF COMPUTER PROGRAMMING

Programming, and why it matters

By the end of this unit you should be able to explain computer programming and its significance, identify the major programming paradigms and the languages associated with each, and identify classes, objects, attributes and methods in a written Java program.

Foundations showed you what a machine does. This unit is about the words: the vocabulary your lecturer, your exam and your future colleagues all use. Most of the marks here are definitions, and definitions are the cheapest marks on any paper.

TEACH · Computer programming

Computer programming is the process of writing instructions that tell a computer how to perform tasks. Those instructions are written as code, in a specialised language such as Java, Python or C++.

Learn that sentence in that form. It is your course's own definition, and "define computer programming" is worth marks in the exam almost every year.

TEACH · Why programming matters

Your course gives four reasons, and an exam question asking for "three major benefits" wants three of these:

BenefitWhat it means
Task automationRepetitive work is done by the machine, saving time and removing human error.
Software developmentWebsites, apps and enterprise systems all exist because someone wrote them.
Problem solvingIt trains logical thinking, which transfers to fields far outside computing.
Career growthDiverse, well-paid work in software engineering, data science and beyond.

Programming is called the backbone of software development because it drives innovation in artificial intelligence, web development, data analysis and automation. That phrasing is the expected answer to a past in-text question.

RECALL AND CHECK

Define computer programming in one sentence, and give three benefits of learning it.

Answer

Computer programming is the process of writing instructions that enable a computer to perform specific tasks. Three benefits: task automation, which saves time and reduces errors; the creation of software such as websites and mobile apps; and the development of logical thinking and problem-solving skills.

UNIT 1.2 · PROGRAMMING PARADIGMS

Five ways to think about a problem

TEACH · A paradigm

A programming paradigm is a fundamental style or approach to writing computer programs. It is not a language. It is a way of thinking about what a program is, and languages are built to support one or more of them.

Your course names five. The whole set turns on one distinction, so learn that distinction and the five arrange themselves.

MUST-MEMORISE · The one distinction underneath all five

Imperative paradigms say HOW: step by step, do this, then this.

Declarative paradigms say WHAT: describe the result you want and let the language work out the steps.

Everything else is detail. Imperative and object-oriented are HOW styles; declarative, logic-based and functional lean WHAT.

MEMORY HOOK: a taxi. Imperative is giving the driver turn-by-turn directions. Declarative is saying "the airport, please".

TEACH · The five, with their languages
ParadigmThe ideaLanguages
ImperativeStep by step: tell the computer how to achieve the task. Built on variables, loops and conditionals.C, and Java's method bodies
FunctionalFocuses on what to compute. Functions are first-class citizens; pure functions; avoid changing variables (immutability).Haskell, Lisp, JavaScript in functional style
DeclarativeExpress the logic of a computation without describing its control flow.SQL
Logic-basedA declarative style built on formal logic: write facts and rules, and the engine infers answers by deduction.Prolog
Object-orientedOrganise code as objects, which are instances of classes, each holding its own data and behaviour.Java, C++, Python in OOP style

Java is object-oriented, and that is the answer if you are asked which paradigm this course sits in. Note that Java is not purely OOP: the inside of any method you write is plain imperative code, step after step. Most real languages blend paradigms.

TEACH · The same task, three ways

To make the difference concrete, here is "give me the total of the amounts over 20", written three ways. You are not expected to write SQL or Prolog in this course; read them only to feel the shift from HOW to WHAT.

imperative (Java)   total = 0;                    for (int i = 0; i < a.length; i++)                        if (a[i] > 20) total += a[i];      <- you write every stepdeclarative (SQL)   SELECT SUM(amount) FROM sales WHERE amount > 20;                                                          <- no loop, no counterlogic (Prolog)      big(X) :- sale(X), X > 20.            <- facts and rules only

The imperative version names a counter, a loop and an order. The other two never mention any of it. That is the whole distinction, and it is what an exam answer should say.

TRAP · A paradigm is not a language

"Java is a paradigm" is wrong, and so is "OOP is a language". Java is a language that supports the object-oriented paradigm. Python supports several. The paradigm is the style of thinking; the language is the grammar you express it in. Examiners notice this one.

UNIT 1.3 · CLASSES, OBJECTS, ATTRIBUTES AND METHODS

The four words the rest of the course is built on

Module 6 teaches object-oriented programming properly. This unit gives you the four words and lets you find them in a program, which is exactly what your learning outcome asks and no more.

TEACH · The main idea of OOP

Object-oriented programming organises code using objects, which represent real-world things. Each object carries both:

  • data, called its attributes or state: what it is;
  • methods, its behaviour: what it can do.

The main idea is to model software as a collection of interacting objects, each responsible for its own data and its own logic.

MUST-MEMORISE · Class versus object

A class is a blueprint. It describes what something will be like. It is written once, and on its own it holds no data.

An object is an instance of a class: one actual thing built from that blueprint, with its own values. One class, many objects.

MEMORY HOOK: the class is the architect's drawing; the objects are the houses built from it. Nobody lives in the drawing, and every house has its own furniture.

CODE · One class, two objectsFROM THE SLIDES
// The CLASS: a blueprint for dogs. No dog exists yet.class Dog {    String name;        // ATTRIBUTE (data / state)    int age;            // ATTRIBUTE    void bark() {        // METHOD (behaviour)        System.out.println(name + " says: Woof!");    }}public class DogDemo {    public static void main(String[] args) {        Dog a = new Dog();   // OBJECT 1: an instance of Dog        a.name = "Rex";        a.age = 3;        Dog b = new Dog();   // OBJECT 2: same blueprint, own values        b.name = "Bella";        b.age = 5;        a.bark();        b.bark();        System.out.println(a.name + " is " + a.age + ", "                         + b.name + " is " + b.age);    }}
OutputRex says: Woof!
Bella says: Woof!
Rex is 3, Bella is 5

One bark() method was written, and it printed a different name each time, because it belongs to whichever object it was called on. That sentence is the whole of OOP in miniature, and Module 6 unpacks it.

TEACH · Finding the four in any program

Your learning outcome is to identify these in written Java. There is a mechanical way to do it:

Look forYou have foundIn the listing above
class Name {a class (blueprint)Dog, DogDemo
a variable declared straight inside the classan attribute (state)name, age
returnType name(...) {a method (behaviour)bark(), main()
new Name()an object being createda, b

The word new is the giveaway: new is the moment an object comes into existence. Before line 15 there were no dogs, only the idea of a dog.

TRAP · The attribute is not inside a method

name and age are declared directly inside the class, not inside bark(). That is what makes them attributes: they belong to the object and live as long as it does.

A variable declared inside a method is a local variable. It is born when the method starts and dies when it ends, and it is not an attribute. Asked to identify attributes, students routinely list local variables and lose the mark.

RECALL AND CHECK

In one sentence each: what is a class, what is an object, what is an attribute, what is a method?

Answer

A class is a blueprint describing what something will be like. An object is an instance of a class: one actual thing built from that blueprint, with its own values. An attribute is a piece of data an object holds, its state. A method is a piece of behaviour, something the object can do.

WORKED EXAMPLE · Reading an unfamiliar classEXAM SKILL

An exam gives you a class you have never seen and asks you to identify its parts. Work outside in, and never read the method bodies first.

  1. Find every class keyword. Those are your blueprints. A file can hold several. Only one may be public, and it names the file (F.6).
  2. Inside each class, list variables declared before any method opens. Those are the attributes. Indentation is a lie: it is not what makes them attributes. Position relative to the braces is.
  3. List everything shaped type name(parameters) {. Those are the methods.
  4. Search for new. Every occurrence is an object being born.

Now redo it: cover the Dog listing and write out its two classes, two attributes, two methods and two objects from memory. Then do the same for the Hello program in F.5. (It has one class, no attributes, one method, and no objects at all: perfectly legal, and worth understanding why.)

KEY POINT

A class is a definition and an object is an instance built from it. The class says what fields and methods every instance will have; each object made with new gets its own copy of the fields and shares the methods.

Blunt version: the class is the biscuit cutter, the object is the biscuit. new is the press.
