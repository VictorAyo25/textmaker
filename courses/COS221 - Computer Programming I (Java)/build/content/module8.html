UNIT 8.1 · ARRAYS, PROPERLY

What F.10 promised to finish

By the end of this unit you should be able to define arrays and explain their uses, declare and manipulate arrays of different dimensions, use array methods for sorting and searching, and carry out array operations.

TEACH · Where you already are

F.10 taught you an array as a fixed row of numbered boxes, indexes 0 to n-1, arr.length with no brackets, and ArrayIndexOutOfBoundsException when you overshoot. All of that still holds and none of it is repeated here.

This module adds what F.10 promised: the formal definition, a second dimension, the built-in toolkit, searching, sorting, and the techniques your exam actually asks for.

MUST-MEMORISE · An array

An array is a data structure used to store multiple values of the same data type in a single variable. Each element is identified by an index.

A 1D array (linear array) is a linear collection of elements of the same type, stored in contiguous memory locations and accessed by index.

Two words earn their place. Same data type: an int[] holds only ints, which is what makes it different from a list of anything. Contiguous: the boxes sit next to each other in memory, which is why reaching arr[9000] is exactly as fast as arr[0]. Java does not walk to it; it computes where it is.

MEMORY HOOK: an array is a street of identical houses, numbered from 0. Same type of house, all in a row, and you find number 40 by arithmetic, not by walking past 39 doors.

SYNTAX · The three ways to make one
// 1. declare, then allocate, then assign  (three steps)int[] numbers;                  <- DECLARATION: a name, no array yetnumbers = new int[3];           <- ALLOCATION: three boxes, all 0numbers[0] = 10;                <- ASSIGNMENT// 2. declare and allocate togetherint[] numbers = new int[3];// 3. declare, allocate and fill in one line  (the usual way)int[] numbers = {10, 45, 30};   <- size taken from the list

The size is fixed at allocation and can never change. That is the defining limitation of an array, and the reason ArrayList exists. Your exam bans ArrayList, so this limitation is permanent for you.

UNIT 8.2 · TWO-DIMENSIONAL ARRAYS

An array of arrays

MUST-MEMORISE · 2D arrays

A 2D array is an array of arrays. Picture a table with rows and columns. Each element needs two indices: one for the row, one for the column.

int[][] matrix = new int[3][2];    3 rows, 2 columns

matrix[r][c]: row first, column second. matrix.length is the number of rows; matrix[0].length is the number of columns.

"What is the syntax to declare and allocate a 2D array of size 3x2?" is a stated in-text question, and the answer is the line in the card.

MEMORY HOOK: RC, like a spreadsheet: Row then Column. And matrix.length counts rows because a 2D array literally is an array of rows: each row is itself an array, so it has its own .length.

CODE · A 2D array, built and walkedFROM THE SLIDES
public class TwoD {    public static void main(String[] args) {        // declare + allocate: 3 rows, 2 columns        int[][] numbers = new int[3][2];        numbers[0][0] = 1;  numbers[0][1] = 2;        numbers[1][0] = 3;  numbers[1][1] = 4;        numbers[2][0] = 5;  numbers[2][1] = 6;        // or all at once        int[][] grid = {{1, 2}, {3, 4}, {5, 6}};        System.out.println("rows    : " + grid.length);        System.out.println("columns : " + grid[0].length);        // a nested loop: outer walks rows, inner walks columns        for (int r = 0; r < grid.length; r++) {            for (int c = 0; c < grid[r].length; c++) {                System.out.print(grid[r][c] + " ");            }            System.out.println();          // end of a row        }    }}

The nested loop is the shape to learn: outer loop for rows, inner loop for columns, and println() at the end of each row to break the line. Note grid[r].length rather than grid[0].length in the inner condition: rows in Java need not all be the same length, so asking each row for its own is the habit that never breaks.

TEACH · Operations and methods

Your course draws a distinction worth keeping: an array operation is a task you want done (sort, search, copy, compare), and an array method is a predefined method that does it for you. The methods live in the Arrays class, in java.util, so they need an import.

TRAP · Printing an array directly prints gibberish

System.out.println(arr) does not print the contents. It prints something like [I@4617c264: the type and a hash code, because an array is an object (Unit 3.3) and nobody taught it how to describe itself.

Always Arrays.toString(arr). "How do you get a string representation of an array?" is a stated in-text question, and the answer is that method.

The same reasoning explains Arrays.equals: arr1 == arr2 compares references, exactly as with Strings, so it is false for two different arrays holding identical contents.

CODE · Linear search, written by handFROM THE SLIDES
public class LinearSearch {    // returns the INDEX, or -1 if not there. -1 is the Java convention.    static int search(int[] arr, int target) {        for (int i = 0; i < arr.length; i++) {            if (arr[i] == target) {                return i;              // found: leave at once (Unit 4.7)            }        }        return -1;                    // checked every one: not here    }    public static void main(String[] args) {        int[] data = {4, 8, 15, 16, 23, 42};        System.out.println("search 15 -> index " + search(data, 15));        System.out.println("search 4  -> index " + search(data, 4));        System.out.println("search 99 -> index " + search(data, 99));    }}
Outputsearch 15 -> index 2
search 4  -> index 0
search 99 -> index -1

A linear search checks each element sequentially until it finds the target. Returning -1 for "absent" is a convention worth adopting: it cannot be confused with a real index, because indexes start at 0. It is the same convention String.indexOf uses (Module 7), and that consistency is not an accident.

UNIT 8.4 · THE EXAM'S ARRAY TECHNIQUES

The four patterns worth real marks

Every array question on both papers is one of these four, or a blend. Learn them as shapes and you are writing from memory rather than inventing.

WORKED EXAMPLE · 1. Accumulate: sum, count, maxPAST PAPER · 24/25 Q2 D, Q5 B

One pass, one running total. The whole family looks the same.

  1. Declare the accumulator before the loop. Inside it, it would be reborn every pass.
  2. Seed it correctly. Sum and count start at 0. Max starts at arr[0], never at 0. Seed max at 0 and an array of negatives returns 0, which is not in the array. This is a real, silent bug.
  3. Update it once per element.
  4. Use it after the loop.
public class Accumulate {    static int countNegatives(int[] arr) {      // 24/25 Q5 B, verbatim        int count = 0;        for (int i = 0; i < arr.length; i++) {            if (arr[i] < 0) count++;        }        return count;    }    static int max(int[] arr) {        int best = arr[0];                     // seed from the data        for (int i = 1; i < arr.length; i++) {  // start at 1: 0 is already in            if (arr[i] > best) best = arr[i];        }        return best;    }    static int sumOdd(int[] arr) {        int sum = 0;        for (int v : arr) {                     // for-each: read only            if (v % 2 != 0) sum += v;        }        return sum;    }    public static void main(String[] args) {        int[] data = {3, -4, 7, -1, 8, 5};        System.out.println("negatives : " + countNegatives(data));        System.out.println("max       : " + max(data));        System.out.println("sum odd   : " + sumOdd(data));        int[] allNeg = {-9, -3, -17};          // the seed trap        System.out.println("max of all-negatives : " + max(allNeg));    }}
Outputnegatives : 2
max       : 8
sum odd   : 14
max of all-negatives : -3

The last line is the point. max seeded from arr[0] returns -3, correctly. Seed it at 0 and it returns 0, a number that is not in the array at all, and nothing warns you.

And check sum odd before you accept it: the odd values are 3, 7, -1 and 5, totalling 14. Forget that -1 is odd and you get 15.

That is not a hypothetical slip. The test v % 2 == 1 looks like the obvious way to ask "is this odd", and it returns 15 on this data, because -1 % 2 is -1, not 1: Unit 3.6's rule that the remainder keeps the sign of the left operand, arriving where nobody was looking for it. So % 2 == 1 silently skips every negative odd number in any array you ever write.

Always test odd with v % 2 != 0. It is right for negatives and positives alike, and it is why the listing above uses it.

Now redo it: write max on paper starting int best = 0; and trace it on {-9, -3, -17} to watch it fail. That is how a trap becomes memorable.

TEACH · The for-each loop

for (int v : arr) reads "for each int v in arr". It hands you every element in turn, with no index and no chance of an off-by-one.

Its limits, which decide when you may use it: no index (so you cannot compare with arr[i-1]), and writing to v changes nothing, because v is a copy, exactly as Unit 5.4 said. Use it to read; use a counted loop to write or to look sideways.

WORKED EXAMPLE · 2. Compare with the neighbourPAST PAPER · 25/26 Q3 A

The paper: "a consecutive duplicate is any position i (i >= 1) where saleAmounts[i] == saleAmounts[i-1]", over {20, 20, 35, 40, 40, 40, 15, 60, 60, 25}, in one pass. The hint says it must not flag 35, 15 or 25.

  1. Start at 1, not 0. Index 0 has no predecessor, so arr[-1] would throw. The question tells you this by writing i >= 1. Read the gift.
  2. Compare arr[i] with arr[i-1].
  3. Count the matches.
public class Duplicates {    static int countConsecutive(int[] a) {        int count = 0;        for (int i = 1; i < a.length; i++) {   // i starts at 1            if (a[i] == a[i - 1]) count++;        }        return count;    }    public static void main(String[] args) {        int[] sales = {20, 20, 35, 40, 40, 40, 15, 60, 60, 25};        System.out.println("consecutive duplicates: " + countConsecutive(sales));    }}
Outputconsecutive duplicates: 4

WORKED EXAMPLE · 3. Look both ways, and the edgesPAST PAPER · 25/26 Q3 A ii

The harder half: flag every amount that equals its predecessor or its successor. The paper is explicit about the edges: "Index 0 checks only its successor; the last index checks only its predecessor."

That sentence is the whole difficulty. Ask a[i-1] at index 0 or a[i+1] at the last index and you throw. The tool is Unit 3.8's short-circuit: guard the index first, and && never evaluates the lookup.

public class Flagged {    static String flagged(int[] a) {        String out = "";                       // plain concatenation only        for (int i = 0; i < a.length; i++) {            boolean prev = (i > 0)            && a[i] == a[i - 1];            boolean next = (i < a.length - 1) && a[i] == a[i + 1];            if (prev || next) {                if (!out.isEmpty()) out = out + ", ";                out = out + a[i];            }        }        return out;    }    public static void main(String[] args) {        int[] sales = {20, 20, 35, 40, 40, 40, 15, 60, 60, 25};        System.out.println("flagged: " + flagged(sales));    }}
Outputflagged: 20, 20, 40, 40, 40, 60, 60

Check it against the paper's own hint: 35, 15 and 25 are absent, exactly as required. And look at the two guards. At i = 0, (i > 0) is false, so && stops and a[-1] is never evaluated. Swap the two sides of that && and the program throws on its first line. That is short-circuiting doing real work, exactly as Unit 3.8 promised.

Now redo it: write the two guard lines from memory, then say what happens if you write a[i] == a[i-1] && i > 0 instead.

WORKED EXAMPLE · 4. Parallel arraysPAST PAPER · 25/26 Q6 B

The paper: fill "two parallel arrays of length V", the hours parked and the permit type, and it bans every collection class. Parallel arrays are the answer to "I need two facts about each thing, and I may not use an object or a list".

The idea: two arrays, same length, where index i means the same thing in both. hours[3] and permits[3] describe the same vehicle.

public class Parallel {    static double fee(int hours, String permit) {        if (permit.equals("Staff")) {          // nested, per the paper            if (hours <= 2) return 0.0;         // first 2 hours free            double f = (hours - 2) * 1.00;            return f > 10.00 ? 10.00 : f;      // capped        } else {                             // anything not Staff = Visitor            double f = (hours <= 3) ? 6.00 : 6.00 + (hours - 3) * 2.50;            return f > 25.00 ? 25.00 : f;        }    }    public static void main(String[] args) {        int[]    hours   = {1, 5, 12, 2, 20};       // parallel:        String[] permits = {"Staff", "Staff", "Staff", "Visitor", "guest"};        double total = 0;        for (int i = 0; i < hours.length; i++) {  // ONE index, BOTH arrays            double f = fee(hours[i], permits[i]);            total += f;            System.out.printf("%-8s %2dh -> %5.2f%n", permits[i], hours[i], f);        }        System.out.printf("total %.2f%n", total);    }}
OutputStaff     1h ->  0.00
Staff     5h ->  3.00
Staff    12h -> 10.00
Visitor   2h ->  6.00
guest    20h -> 25.00
total 44.00

Read the rows against the paper's rules. Staff for 1 hour is free. Staff for 5 pays for 3 of them. Staff for 12 would pay 10.00 and is capped at exactly 10.00. And "guest" is not exactly "Staff", so it was treated as a Visitor and capped at 25.00, which is the rule the paper states and the row a marker checks.

The discipline parallel arrays demand: the two arrays must stay the same length and in the same order forever. Sort one without the other and every vehicle silently gets someone else's permit. That fragility is exactly why objects (Module 6) exist, and why the exam banning them is an artificial constraint you must simply obey.
