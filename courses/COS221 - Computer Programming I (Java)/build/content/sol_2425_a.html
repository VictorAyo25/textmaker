S.8 · 2024/25 · HOW THIS PAPER WORKS

The 2024/25 paper, and why you are reading it

A different shape, the same four skills, and a title that changed while the subject did not.

MUST-MEMORISE · The format changed; the skills did not

2024/25: six questions at 17.5 marks, attempt any four. No sections.
2025/26: three sections, one question from each, 20 + 25 + 25.

Both are 70 marks over 3 hours. Both test exactly four things: define, debug, dry run, write a program.

The course was even retitled between the two: "Object-Oriented Programming (Java)" became "Computer Programming I (Java)". Same code, COS221, same lecturer, same syllabus.

So do not learn a paper. Learn the four skills. A format can change again between the writing of this book and the day you sit down; the four things being tested have not changed in two years and will not.

MEMORY HOOK: define, debug, dry run, write. Every question on both papers is one of those four, or a bundle of all four.

TEACH · The 24/25 template, question by question

S.9 · 2024/25 · QUESTION ONE · 17.5 MARKS

Question One, worked in full

Q1 A · Define method signature, overloading, and void method3 MARKS

Model answer. One mark each, and each is one sentence.

  1. Method signature. A method's name together with its parameter list (the number, types and order of its parameters). The return type is not part of the signature. It is what the compiler uses to tell one method from another.
  2. Method overloading. Declaring more than one method with the same name but different parameter lists in the same class, so the compiler chooses between them at compile time by matching the arguments at the call site against each signature.
  3. Void method. A method declared void, meaning it returns no value. It is called as a statement on its own, cannot be used in an expression, and may use a bare return; to exit early.

Where the marks are: the examiner asked for signature and overloading in the same breath deliberately, because the second is defined by the first. Say "signature = name + parameter list, return type excluded" and the overloading definition writes itself. Units 5.1, 5.2 and 5.6.

Q1 B · Debug SquareCalc3 MARKS

The code as printed:

public class SquareCalcBroken {    public static void main(String[] ) {        int num = 5;        double result = square(num)        System.out.println("Square is: " + result);    }    public static int square(int) {        return n * n;
Compiler outputerror: <identifier> expected

The errors, listed. The question says list and correct, so list them: a correction with no list is half an answer.

  1. Line 2: main(String[] ) has no parameter name. A parameter needs a type and a name. Fix: main(String[] args).
  2. Line 4: no semicolon after double result = square(num).
  3. Line 8: square(int) has no parameter name. Fix: square(int n).
  4. Line 9: n does not exist. It is the symptom of error 3: name the parameter and n exists. Worth saying out loud in your answer, because it shows you understand the cause rather than listing every red squiggle.
  5. The braces are missing for both square and the class.

Three marks, five errors. Do not stop at three: the marker is looking for the set, and errors 3 and 4 are one fault with two faces.

Java widens the int to a double on the way in (Unit 5.7), so what gets printed is a double, and a double always prints its point. Nothing is wrong; but if you wrote "Square is: 25" you have missed a mark that costs nothing to get right.

Q1 C · Dry run sumSeries with 3, 4, 5, 74 MARKS

The paper gives you this and four values to trace:

public static int sumSeries(int i) {    int sum = 0;    for (int j = 1; j <= i; j++) {        sum += j / (j + 1);    }    return sum;}

The answer is 0. For all four values.

MUST-MEMORISE · Four values, one answer, and that is the question

j and j + 1 are both int, so j / (j + 1) is integer division.

j is always smaller than j + 1. A smaller int divided by a larger int is always 0. Every term is 0. The sum is 0.

1/2 is 0. 2/3 is 0. 3/4 is 0. Not 0.5, 0.67, 0.75: 0, because integer division throws the remainder away (Unit 3.6). It does not round; it truncates.

Why the examiner gave you four values. Being handed 3, 4, 5 and 7 shouts "four different answers". It is bait. The four values are there so that you either notice the types once and answer all four in one line, or trace fractions by hand for ten minutes and write four confident wrong numbers.

MEMORY HOOK: int / int is an int. Before you trace any division, look at the two types. One double anywhere on top and the answer changes completely: 1.0 / 2 is 0.5.

Q1 D · Overload area for circle, rectangle and triangle7.5 MARKS

The question. Write a program that overloads a method named area to compute (i) the area of a circle, (ii) the area of a rectangle, (iii) the area of a triangle, and call them from main.

MUST-MEMORISE · The obvious answer to this question does not compile

Circle needs one number. Rectangle needs two. Triangle needs two.

So rectangle is area(double, double), and triangle (base and height) is also area(double, double).

That is the same signature. It will not compile.

Overloading needs different parameter lists, and "base, height" is not different from "length, width": the parameter names are not part of the signature, only the types (Q1 A, which you just answered). Write both and javac says:

error: method area(double,double) is already defined in class

The resolution: give the triangle a three-number formula, so its signature is area(double, double, double) and distinct. Heron's formula takes the three sides:

s = (a + b + c) / 2     and     area = √ s(s-a)(s-b)(s-c) 

MEMORY HOOK: overloads differ by types, not by names. If two of your methods take the same types in the same order, you have one method and a compiler error.

This is the single most valuable thing in Question One, and the examiner may not have noticed it. Say it explicitly in your answer: "base and height would collide with length and width, so the triangle is done by Heron's formula on three sides, giving a distinct signature." That sentence proves you understand overloading, which is what the question is for.

CODE · Q1 D, completeVERIFIED ON THE JVM
public class AreaOverload {    // i. circle: one number, so the signature is area(double)    public static double area(double radius) {        return Math.PI * radius * radius;    }    // ii. rectangle: two numbers, so the signature is area(double, double)    public static double area(double length, double width) {        return length * width;    }    // iii. triangle: base and height would ALSO be area(double, double), which is    // the rectangle's signature and will not compile. Three sides gives a distinct    // signature and a genuine formula: Heron's.    public static double area(double sideA, double sideB, double sideC) {        double s = (sideA + sideB + sideC) / 2;        return Math.sqrt(s * (s - sideA) * (s - sideB) * (s - sideC));    }    public static void main(String[] args) {        System.out.println("Circle, radius 7      : " + area(7.0));        System.out.println("Rectangle, 5 by 3     : " + area(5.0, 3.0));        System.out.println("Triangle, sides 3 4 5 : " + area(3.0, 4.0, 5.0));    }}
OutputCircle, radius 7      : 153.93804002589985
Rectangle, 5 by 3     : 15.0

Check the triangle without trusting Heron. 3, 4, 5 is a right triangle, so its area must be half of 3 × 4, which is 6. Heron gave exactly 6.0. When you use a formula you cannot see through, feed it a case whose answer you already know. Math.PI and Math.sqrt are Unit 3.6.
