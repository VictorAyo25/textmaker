O.1 · OBJECTIVE · HOW TO ATTACK AN OBJECTIVE QUESTION

How to attack an objective question

The paper carries an objective section as well as the long questions, and it is answered under more time pressure than anything else on it. This part is where you practise that half.

TEACH · Where these questions came from

Say this plainly, because it decides how to read them. This course has no computer-based test among its papers, so unlike the forty question parts solved earlier in this book, which are quoted from the examiner word for word, these questions were written for this manual. They are not the examiner's and they do not pretend to be.

What they are grounded in is real. Every one comes from something this book teaches and something the two past papers actually ask about, and the paper's habits are copied on purpose: it asks for the output of a fragment, it asks you to find the error, it asks for a definition with an example, and it asks for the difference between two things that look alike.

Every program below was compiled with javac and run on a real JVM, and the answer is what came back. Two questions claim that a program does NOT compile, and those were checked the same way: the compiler was run and its message read. If your answer differs from the book's, the JVM settled it, not an opinion.

KEY POINT

In a four-option question, three options are wrong for a reason you can state. Finding that reason is faster and safer than recognising the right answer, because recognition is exactly what a well-built distractor attacks.

Blunt version: do not hunt for the right one. Kill the wrong ones.

TEACH · The four moves, in order
  1. Underline the instruction word. NOT, TRUE, BEST, PRIMARILY and EXCEPT each flip or narrow the question. Read a NOT question as an ordinary one and every wrong answer starts to look right.
  2. On a code question, dry run it before you read the options. Variables down the margin, one row per statement. The options are built from the answers you get by tracing it WRONG, so reading them first plants the mistake.
  3. Strike the impossible. Two of the four usually die at once: an option that contradicts a definition, or one that is true but answers a different question.
  4. Split the last two on the exact wording. It is nearly always one word: only, always, all, entirely, every.
TRAP · The six that decide most output questions

Six facts answer a large share of every what-does-this-print question this course can set. Know them cold and the tracing gets much shorter.

  1. int divided by int is an int. 7 / 2 is 3, and the fraction is discarded.
  2. Java truncates towards zero, so -7 / 2 is -3, and % takes the sign of the left operand.
  3. Once a String is involved, every later plus JOINS. "T: " + 1 + 2 is "T: 12".
  4. == on objects compares references. For strings, always use equals.
  5. Strings are immutable. A String method returns a new string and changes nothing.
  6. Java passes by value. Reassigning a parameter never reaches the caller.
RECALL · How to use this part

Sit one group at a time, timed at 45 seconds a question, with the answers covered. Then read the whole answer block for that group, including the questions you got right: on an objective paper a right answer for the wrong reason is a mark you will not get twice.

O.2 · OBJECTIVE · THE LANGUAGE, THE TOOLCHAIN AND OBJECTS

The Language, the Toolchain and Objects

5 questions, from Foundations, Module One and Module Two. Cover the answers, sit the whole set, then read every line of the answer block.

  1. What does javac produce, and what runs it?

    • (a) Machine code for your processor, run directly by the operating system
    • (b) Bytecode in a .class file, run by the Java Virtual Machine
    • (c) A .java file, run by javac itself
    • (d) An executable .exe file, run by double clicking it

  2. Which signature does the JVM look for to start a program?

    • (a) public static void main(String[] args)
    • (b) public void main(String[] args)
    • (c) static void Main(String[] args)
    • (d) public static int main(String args)

  3. Which statement best distinguishes a class from an object?

    • (a) A class is a running instance and an object is its definition
    • (b) A class is a blueprint; an object is an instance of it, with its own values
    • (c) A class and an object are two words for the same thing
    • (d) A class can have only one object at a time

  4. Java is described as an object-oriented language. Which TWO features below are the reason? Choose the single option naming BOTH correctly.

    • (a) Pointers and manual memory management
    • (b) Encapsulation and inheritance
    • (c) Preprocessor directives and macros
    • (d) Goto statements and labels

  5. Which statement is TRUE?

    • (a) The JDK contains the JRE, which contains the JVM
    • (b) The JVM contains the JRE, which contains the JDK
    • (c) The JDK and the JRE are two names for the same thing
    • (d) The JRE is needed to compile, the JDK only to run
ANSWERS · and why every option is what it is

1. The answer is Bytecode in a .class file, run by the Java Virtual Machine. Source to bytecode by javac, bytecode to behaviour by the JVM. Java is compiled AND interpreted, and saying only one of those loses half the mark.

  • Machine code for your processor, run directly by the operating system. Wrong. Compiling straight to machine code is the C model, and it is exactly what Java avoids, because machine code runs on one kind of processor only.
  • Bytecode in a .class file, run by the Java Virtual Machine. Correct. javac turns your .java source into bytecode in a .class file, and the java command starts a JVM that executes that bytecode. The JVM is what makes the same .class file run on any machine that has one.
  • A .java file, run by javac itself. Wrong. The .java file is what you WRITE and what javac consumes. It is the input, not the output.
  • An executable .exe file, run by double clicking it. Wrong. Java deliberately does not produce a platform executable. That is the whole point of write once, run anywhere.

2. The answer is public static void main(String[] args). public static void main(String[] args). Write it out by hand until it is automatic; a paper answer that gets it wrong has failed before the first statement.

  • public static void main(String[] args). Correct. public so the JVM can reach it, static so it runs with no object, void because it returns nothing, and a String array for the command line arguments.
  • public void main(String[] args). Wrong. Without static the JVM would need an object to call it on, and no object exists yet when the program starts.
  • static void Main(String[] args). Wrong on two counts: Java is case sensitive so Main is a different name, and without public the JVM cannot reach it.
  • public static int main(String args). Wrong on two counts: main returns void, and the parameter is an ARRAY of String, not a single String.

3. The answer is A class is a blueprint; an object is an instance of it, with its own values. Class is the blueprint, object is the building. new is what turns one into the other.

  • A class is a running instance and an object is its definition. Wrong, and it is exactly backwards. The definition is the class; the running instance is the object.
  • A class is a blueprint; an object is an instance of it, with its own values. Correct. The class says what every instance will have and be able to do; each object made with new has its own copy of the fields.
  • A class and an object are two words for the same thing. Wrong. If they were the same, new would have nothing to do.
  • A class can have only one object at a time. Wrong. A class exists so that many objects can be created from it.

4. The answer is Encapsulation and inheritance. Encapsulation, inheritance, polymorphism, abstraction. Those four are the answer to any what-makes-it-object-oriented question.

  • Pointers and manual memory management. Wrong. Java deliberately has neither: references replace pointers and the garbage collector replaces manual freeing.
  • Encapsulation and inheritance. Correct. Bundling data with the methods that act on it, and letting one class extend another, are two of the four pillars, alongside abstraction and polymorphism.
  • Preprocessor directives and macros. Wrong. Those are C and C++ features. Java has no preprocessor at all.
  • Goto statements and labels. Wrong. goto is a reserved word in Java that is not usable, kept reserved precisely so nobody writes one.

5. The answer is The JDK contains the JRE, which contains the JVM. JDK contains JRE contains JVM. Compile needs the JDK, run needs only the JRE.

  • The JDK contains the JRE, which contains the JVM. Correct. The JDK is the developer kit and holds the compiler; inside it is the runtime environment, and inside that is the virtual machine that actually executes bytecode.
  • The JVM contains the JRE, which contains the JDK. Wrong, and it inverts the nesting. The smallest of the three is the JVM.
  • The JDK and the JRE are two names for the same thing. Wrong. The JRE can only RUN programs. Only the JDK carries javac.
  • The JRE is needed to compile, the JDK only to run. Wrong, and it swaps them: you compile with the JDK and can run with the JRE alone.

  12. Which assignment compiles WITHOUT a cast?

    • (a) int n = 3.5;
    • (b) double d = 7;
    • (c) int n = 7L;
    • (d) char c = "A";
ANSWERS · and why every option is what it is

1. The answer is 3 then 1 then 3.5. int divided by int gives int, and the fraction is discarded, not rounded. One double operand promotes the whole expression.

  • 3 then 1 then 3.5. Correct. Two ints divide as ints, so the fraction is thrown away and 7 / 2 is 3. The remainder is 1. Making either operand a double promotes the whole expression, so 7.0 / 2 is 3.5.
  • 3.5 then 1 then 3.5. Wrong on the first line. Integer division truncates in Java; it does not produce a decimal. That is the single most common Java arithmetic error.
  • 3 then 1 then 3. Wrong on the last line. 7.0 is a double, so the division is done in doubles.
  • 3.5 then 3.5 then 3.5. Wrong throughout. % is the remainder operator, not a division.

2. The answer is -3 then -1. Java truncates towards zero and % takes the sign of the left operand. Both differ from some other languages, so this is worth knowing exactly rather than by feel.

  • -4 then 1. Wrong. Java truncates towards ZERO, so -7 / 2 is -3, not -4. Flooring to -4 is what Python does, and the difference is a real exam trap.
  • -3 then -1. Correct. Division truncates towards zero giving -3, and the remainder takes the sign of the LEFT operand, giving -1.
  • -4 then -1. Wrong on the division for the same reason: Java truncates towards zero.
  • -3 then 1. Wrong on the remainder. In Java the result of % has the sign of the dividend, so a negative dividend gives a negative remainder.

3. The answer is 66 then B. A char is a number with a costume on. Arithmetic strips the costume; a cast back to char puts it on again.

  • B then B. Wrong on the first line. A char in arithmetic is promoted to int, so the result is a number, not a letter.
  • 66 then B. Correct. c + 1 promotes the char to its code, 65, and adds 1 to give 66. The cast on the second line turns 66 back into a char, which prints as B.
  • A1 then B. Wrong. Plus between a char and an int is ARITHMETIC, not joining. Joining would need one side to be a String.
  • 66 then 66. Wrong on the second line: the cast to char is what makes it print as a letter.

4. The answer is Total: 12 then Total: 3. Plus is left-associative, and once a String is involved every later plus joins. Bracket the arithmetic and this whole class of bug goes away.

  • Total: 12 then Total: 3. Correct. Plus groups left to right. The first plus has a String on its left, so it JOINS, producing "Total: 1", and the next plus joins the 2 onto that. The brackets on the second line force the addition first.
  • Total: 3 then Total: 3. Wrong on the first line. Nothing adds 1 and 2 there: by the time the 2 is reached the left side is already a String.
  • Total: 12 then Total: 12. Wrong on the second line. The brackets change the answer, which is the whole point of the question.
  • Total: 3 then Total: 12. Wrong, and it has the two lines swapped.

5. The answer is 2147483647 then -2147483648. int holds -2147483648 to 2147483647, and overflow wraps silently. Use long when a value might exceed it.

  • 2147483647 then 2147483648. Wrong. An int cannot hold 2147483648. The type does not grow to fit.
  • 2147483647 then -2147483648. Correct. int is 32 bits, so its maximum is 2147483647, and adding 1 wraps round to the most negative value. Java does not report this: it just gives the wrong number quietly.
  • 2147483647 then error at run time. Wrong. There is no exception for integer overflow in Java. That silence is exactly what makes it dangerous.
  • 2147483648 then -2147483648. Wrong on the first line. MAX_VALUE is 2147483647, one less than 2 to the power 31.

6. The answer is 0.30000000000000004 then false. Never compare two doubles with ==. Compare the size of their difference against a small tolerance instead.

  • 0.3 then true. Wrong on both lines. Binary floating point cannot hold 0.1 or 0.2 exactly, so their sum is not exactly 0.3.
  • 0.30000000000000004 then false. Correct. The stored sum is very slightly above 0.3 and prints in full, so the equality test is false.
  • 0.3 then false. Wrong on the first line: println shows the true stored value, tiny error and all.
  • 0.30000000000000004 then true. Wrong on the second line: if the value printed is not 0.3, it cannot equal 0.3.

7. The answer is 5 then 6 then 7. Post says use it then change it; pre says change it then use it. The variable ends up the same either way, and what the EXPRESSION gives back is what differs.

  • 5 then 6 then 7. Correct. i++ yields the OLD value 5 and then makes i 6. The second line shows that 6. ++i increments first, to 7, and yields 7.
  • 6 then 6 then 7. Wrong on the first line. The post-increment gives back the value BEFORE the increment.
  • 5 then 5 then 6. Wrong on the second line. The increment did happen, so i is 6 by then.
  • 6 then 7 then 7. Wrong on the first line, for the same reason as the second option.

8. The answer is 14 then 20 then 5. Multiply and divide before add and subtract, then left to right. When in doubt, write the brackets yourself.

  • 14 then 20 then 5. Correct. Multiply before add gives 14, brackets force 20, and subtraction groups left to right so 10 - 2 is 8 and 8 - 3 is 5.
  • 20 then 20 then 5. Wrong on the first line. Multiplication binds tighter than addition without any brackets.
  • 14 then 20 then 11. Wrong on the last line. Left to right gives 5; grouping the right pair first would give 11, and no operator in Java does that.
  • 14 then 14 then 5. Wrong on the second line: the brackets really do change it.

9. The answer is done. && and || evaluate the right side only when they must. That is what makes if (s != null && s.length() > 0) safe.

  • left then right then done. Wrong. Neither call happens, which is the whole point of short circuiting.
  • done. Correct. && stops as soon as its left side is false, and || stops as soon as its left side is true, so neither shout is ever called.
  • left then done. Wrong. false && anything is already decided, so the right side is skipped.
  • right then done. Wrong. true || anything is already decided, so the right side is skipped.

10. The answer is int n = in.nextInt();. nextInt for an int, nextDouble for a double, nextLine for a whole line of text. Mixing nextInt with nextLine leaves the newline behind, which is the classic Scanner bug.

  • int n = in.nextInt();. Correct. nextInt() reads the next token and returns it as an int, which is what the variable needs.
  • int n = in.next();. Wrong. next() returns a String, and a String cannot be assigned to an int without conversion.
  • int n = in.nextLine();. Wrong for the same reason: nextLine() also returns a String. It would need Integer.parseInt around it.
  • int n = Scanner.nextInt();. Wrong. nextInt is an instance method, called on your Scanner object, not on the class.

11. The answer is 3.14 then 42|. %.2f fixes the decimals, %5d fixes the width and right-aligns, %-5d left-aligns, and %n is the newline that works everywhere.

  • 3.14 then 42|. Correct. %.2f gives two decimal places, and %5d pads the number to five characters on the LEFT, so the spaces come first.
  • 3.142 then 42 |. Wrong on both counts: .2f is two decimals, and %5d right-aligns.
  • 3.14 then 42 |. Wrong on the padding. A width without a minus sign right-aligns; %-5d would pad on the right.
  • 3.1 then 42|. Wrong on the decimals: two were asked for, not one.

12. The answer is double d = 7;. Widening is automatic, narrowing needs a cast. Remember the direction: small into big is safe, big into small is your responsibility.

  • int n = 3.5;. Wrong. A double into an int loses information, so Java requires you to say so with an explicit cast.
  • double d = 7;. Correct. int to double is a WIDENING conversion: nothing can be lost, so Java does it silently.
  • int n = 7L;. Wrong. long to int is narrowing, so it needs a cast.
  • char c = "A";. Wrong. Double quotes make a String, and a String is not a char. A char literal uses single quotes.

    public class Q407 {    public static void main(String[] args) {        int count = 0;        for (int i = 0; i < 10; i += 2) count++;        System.out.println(count);    }}
    • (a) 4
    • (b) 5
    • (c) 6

ANSWERS · and why every option is what it is

1. The answer is Tue then Wed. A switch enters at the matching label and runs on until a break. Missing breaks are the classic switch bug and a favourite exam question.

  • Tue. Wrong. Without a break at the end of case 2, execution falls straight into case 3.
  • Tue then Wed. Correct. It enters at case 2, prints Tue, falls through into case 3 and prints Wed, and the break there stops it.
  • Tue then Wed then Other. Wrong. The break at the end of case 3 stops it before default.
  • Mon then Tue then Wed. Wrong. It ENTERS at the matching case; the cases above it are skipped entirely.

2. The answer is end. An else binds to the nearest if, whatever the indentation says. Braces on every if remove the ambiguity, and they cost nothing.

  • small then end. Wrong, and it is what the INDENTATION suggests, which is why the question is here. The else does not belong to the outer if.
  • end. Correct. An else attaches to the nearest unmatched if, which is the INNER one. Since x is not greater than 10, neither if is entered and nothing but end prints.
  • big then end. Wrong. x is 5, so the outer condition is already false.
  • small. Wrong. The last println is outside every if and always runs.

3. The answer is 15 then 24. The three parts of a for header, initialise, test, update, are exactly the three pieces you place by hand when converting to a while. This conversion is worth 10 marks on the 2024/25 paper.

  • 15 then 24. Correct. 1+2+3+4+5 is 15, and 1x2x3x4 is 24.
  • 10 then 24. Wrong. The loop includes 5, because the test is i <= 5, not i < 5.
  • 15 then 10. Wrong on the second: the while loop multiplies rather than adds.
  • 21 then 24. Wrong. 21 would be summing to 6, and the loop stops at 5.

4. The answer is do 10. while tests first and may run zero times; do-while runs at least once. That difference is the whole reason both exist.

  • nothing is printed. Wrong. The do-while body runs before its condition is ever looked at.
  • do 10. Correct. The while loop tests first, finds 10 is not less than 5, and never runs. The do-while runs its body once, prints do 10, and only then tests.
  • while 10 then do 10. Wrong. The while loop prints nothing at all.
  • do 10 then do 11. Wrong. After the single pass n is 11, the condition fails, and the loop ends.

5. The answer is 1 3 . continue abandons this pass, break abandons the loop. Read the order of the statements carefully: whether the break is before or after the print changes the answer.

  • 1 3 . Correct. 1 prints, 2 is skipped by continue, 3 prints, and at 4 the break leaves the loop before 5 is reached.
  • 1 2 3 . Wrong. The continue skips the print for 2.
  • 1 3 5 . Wrong. The break at 4 stops the loop, so 5 never happens.
  • 1 3 4 . Wrong. The break happens BEFORE the print, so 4 is never printed.

6. The answer is * then ** then ***. Triangle patterns are a standing favourite. Trace the inner limit for each value of the outer variable and write the row out; three rows of tracing settles any pattern question.

  • * then ** then ***. Correct. The inner loop runs i times, so one star, then two, then three.
  • *** then *** then ***. Wrong. The inner limit is i, not 3, so it grows with each outer pass.
  • * then * then *. Wrong. That would need the inner loop to run exactly once each time.
  • *** then ** then *. Wrong, and it is upside down: i grows, so the rows get longer.

7. The answer is 5. When a loop steps by more than one, write the values out rather than dividing in your head. The last value is the one people get wrong.

  • 4. Wrong. Count them out: 0, 2, 4, 6, 8. That is five values, not four.
  • 5. Correct. i takes 0, 2, 4, 6 and 8, then 10 fails the test i < 10, so the body runs five times.
  • 6. Wrong. 10 is not less than 10, so it never enters with i at 10.
  • 10. Wrong. The step is 2, so it runs half as often as a step of 1 would.

Methods

5 questions, from Module Five. Cover the answers, sit the whole set, then read every line of the answer block.

  1. What does this print?

    public class Q501 {    static void change(int n) { n = 99; }    public static void main(String[] args) {        int x = 5;        change(x);        System.out.println(x);    }}

    • (b) 5
    • (c) 0
    • (d) it does not compile

  2. What does this print?

    public class Q502 {    static void fill(int[] a) { a[0] = 99; }    static void replace(int[] a) { a = new int[]{7, 7}; }    public static void main(String[] args) {        int[] nums = {1, 2};        fill(nums);        replace(nums);        System.out.println(nums[0] + " " + nums[1]);    }}
    • (a) 1 2
    • (b) 99 2
    • (c) 7 7
    • (d) 99 7

  3. What does this print?

    public class Q503 {    static String f(int n) { return "int"; }    static String f(double d) { return "double"; }    static String f(String s) { return "String"; }    public static void main(String[] args) {        System.out.println(f(1));        System.out.println(f(1.0));        System.out.println(f("1"));    }}
    • (a) int
      double
      String
    • (b) double
      double
      String
    • (c) int
      int
      String
    • (d) it does not compile, because three methods share a name

  4. Why can a static method not use an instance field directly?

    • (a) Because static methods are private
    • (b) Because a static method may run with no object in existence, so there is no instance whose field it could mean
    • (c) Because instance fields are always final
    • (d) Because static methods run before the class is loaded

  5. What does this print?

    public class Q505 {    static int addUp(int n) {        int total = 0;        for (int i = 1; i <= n; i++) {            total += i;            if (total > 6) return total;        }        return -1;    }    public static void main(String[] args) {        System.out.println(addUp(5));    }}
    • (a) 15
    • (b) 10
    • (c) -1
    • (d) 6
ANSWERS · and why every option is what it is

1. The answer is 5. Java is pass by value, always. For an object the VALUE passed is the reference, which is why an object's contents can be changed by a method while the caller's variable still points at the same object.

  • 99. Wrong. The method changed its own copy of the value, not the caller's variable.
  • 5. Correct. Java passes arguments BY VALUE. The parameter n is a separate variable holding a copy of 5, so assigning to it cannot reach x.
  • 0. Wrong. x was assigned 5 and nothing since has touched it.
  • it does not compile. Wrong. The code is perfectly legal; it simply does not do what it looks like it does.

2. The answer is 99 2. Through the reference you can change the object; assigning to the parameter only changes where that copy points. This one pair of methods is the clearest statement of what pass by value means in Java.

  • 1 2. Wrong. fill really did change the array, because both names refer to the same array object.
  • 99 2. Correct. fill reaches through the reference and changes element 0. replace only rebinds its own copy of the reference, so the caller's array is untouched.
  • 7 7. Wrong. replace cannot change which array the caller's variable points at.
  • 99 7. Wrong for the same reason: nothing from replace escapes the method.

3. The answer is int then double then String. Overloading is same name, different parameter list, resolved at compile time by the argument types. Return type alone cannot distinguish two overloads.

  • int then double then String. Correct. Overload resolution picks by the argument TYPES: 1 is an int, 1.0 is a double, "1" is a String.
  • double then double then String. Wrong. 1 is an int literal and an exact int match exists, so no widening is needed.
  • int then int then String. Wrong. 1.0 is a double literal, so the double version matches exactly.
  • it does not compile, because three methods share a name. Wrong. Sharing a name with different parameter lists is exactly what overloading IS.

4. The answer is Because a static method may run with no object in existence, so there is no instance whose field it could mean. Static belongs to the class, instance belongs to the object. This is exactly why main is static: the JVM calls it before any object of your class exists.

  • Because static methods are private. Wrong. static and private are unrelated: a static method can be public.
  • Because a static method may run with no object in existence, so there is no instance whose field it could mean. Correct. Static belongs to the class, so it can be called with no object at all. An instance field only exists inside an object, so the reference would be to nothing.
  • Because instance fields are always final. Wrong. Instance fields are ordinarily variable; final is a separate choice.
  • Because static methods run before the class is loaded. Wrong. The class is loaded before any of its methods run.

5. The answer is 10. return leaves the method at once, loop and all. Note the strictness of the comparison: greater than 6 excludes 6 itself.

  • 15. Wrong. 15 is the full sum to 5, but the method leaves as soon as the running total passes 6.
  • 10. Correct. The totals are 1, 3, 6, 10. The first that is greater than 6 is 10, and return hands it back immediately.
  • -1. Wrong. The final return is only reached if the loop finishes without the condition ever being true.
  • 6. Wrong. 6 is not GREATER than 6, so the loop continues one more pass.

      Rex

    • (c) unnamed
      unnamed
    • (d) it does not compile

  2. Which pair of choices implements encapsulation?

    • (a) Public fields and no methods
    • (b) Private fields with public getters and setters
    • (c) Static fields with a public constructor
    • (d) Final fields with no constructor

  3. What does this print?

    public class Q603 {    static class Animal {        void speak() { System.out.println("some sound"); }    }    static class Dog extends Animal {        @Override void speak() { System.out.println("woof"); }    }    public static void main(String[] args) {        Animal a = new Dog();        a.speak();    }}
    • (a) some sound
    • (b) woof
    • (c) it does not compile
    • (d) both lines print, superclass first

  4. What does this print?

    public class Q604 {    static class A {        A() { System.out.println("A"); }    }    static class B extends A {        B() { System.out.println("B"); }    }    public static void main(String[] args) { new B(); }}
    • (a) B
    • (b) A
      B
    • (c) B
      A
    • (d) nothing prints

  5. Which statement is TRUE of an abstract class?

    • (a) It can be instantiated directly with new
    • (b) It may contain both abstract methods and fully implemented methods
    • (c) All of its methods must be abstract
    • (d) A class may extend several abstract classes at once

  6. What does this print?

    public class Q606 {    static class Point {        int x = 1, y = 2;        @Override public String toString() { return "(" + x + ", " + y + ")"; }    }    public static void main(String[] args) {        System.out.println(new Point());    }}
    • (a) (1, 2)
    • (b) Point@1b6d3586
    • (c) Point
    • (d) it does not compile
ANSWERS · and why every option is what it is

1. The answer is unnamed then Rex. A constructor has the class name, no return type, and runs on new. this(...) chains to another constructor and must be the first statement in the body.

  • null then Rex. Wrong. The no-argument constructor does not leave name unset: it calls the other constructor with a default.
  • unnamed then Rex. Correct. this("unnamed") chains to the other constructor, so the first object gets unnamed and the second gets Rex.
  • unnamed then unnamed. Wrong. The second call passes Rex explicitly, and that is what is stored.
  • it does not compile. Wrong. Constructor chaining with this(...) is legal, provided it is the first statement.

2. The answer is Private fields with public getters and setters. Private data, public methods. Hiding the data is only half of it: the point of the getter and setter is that they are a place to check.

  • Public fields and no methods. Wrong, and it is the opposite: public fields let anything change the object into an invalid state with no check possible.
  • Private fields with public getters and setters. Correct. The data is hidden and every route to it goes through a method, which is where validation can live.
  • Static fields with a public constructor. Wrong. static concerns whether the field belongs to the class or the object, and has nothing to do with hiding it.
  • Final fields with no constructor. Wrong. final stops reassignment; it does not hide anything, and a class with no constructor still gets the default one.

3. The answer is woof. The variable's type decides what you may CALL; the object's type decides what actually RUNS. That sentence answers most polymorphism questions on this paper.

  • some sound. Wrong. The DECLARED type is Animal, but the method that runs is chosen by the object's ACTUAL type at run time.
  • woof. Correct. The object is a Dog, so Dog's override runs. This is polymorphism, and it is exactly what makes inheritance useful.
  • it does not compile. Wrong. Assigning a subclass object to a superclass variable is always allowed: a Dog IS an Animal.
  • both lines print, superclass first. Wrong. An override replaces the superclass version. Running both would need an explicit super.speak() call.

4. The answer is A then B. Constructors run from the top of the hierarchy down. A subclass object cannot exist until the superclass part of it has been built.

  • B. Wrong. The superclass constructor always runs first, whether or not you wrote super().
  • A then B. Correct. Java inserts an implicit super() at the top of B's constructor, so A's constructor completes before B's body starts.
  • B then A. Wrong, and it is the wrong way round: the base is built before the part built on top of it.
  • nothing prints. Wrong. new B() runs both constructors.

5. The answer is It may contain both abstract methods and fully implemented methods. Abstract class for shared state and partial implementation; interface for a contract that many unrelated classes can sign. One superclass, many interfaces.

  • It can be instantiated directly with new. Wrong. An abstract class is incomplete by definition, so new on it is a compile error. Its subclasses are what get instantiated.
  • It may contain both abstract methods and fully implemented methods. Correct. That is the difference from an interface in the classic form: an abstract class can carry shared state and shared behaviour alongside the methods it leaves to subclasses.
  • All of its methods must be abstract. Wrong. It may have none at all and still be marked abstract.
  • A class may extend several abstract classes at once. Wrong. Java allows single inheritance of classes. Several INTERFACES may be implemented, which is how the restriction is worked around.

6. The answer is (1, 2). println on an object calls toString(). Override it and your objects become printable; forget to, and you get the class name and a hash.

  • (1, 2). Correct. println on an object calls its toString(), and this class overrides it.
  • Point@1b6d3586. Wrong for THIS class. That class-name-and-hash form is what the INHERITED toString gives, and it is what you see when you forget to override it.
  • Point. Wrong. Nothing prints just the class name.
  • it does not compile. Wrong. Overriding toString is ordinary and expected.

  4. Why is StringBuilder preferred to String for building text in a loop?

    • (a) It is shorter to type
    • (b) String is immutable, so each join creates a new object, while StringBuilder changes one buffer in place
    • (c) StringBuilder can hold more characters than String
    • (d) String cannot be used inside a loop
ANSWERS · and why every option is what it is

1. The answer is true then false then true. == asks whether they are the same OBJECT; equals asks whether they read the same. For strings, always use equals. This is the most asked string question there is.

  • true then true then true. Wrong on the second line. new String() deliberately builds a separate object, so the two references differ.
  • true then false then true. Correct. Two identical literals share one pooled object, so a == b is true. new String makes a distinct object, so a == c is false. equals compares the CHARACTERS, so it is true.
  • false then false then true. Wrong on the first line: string literals are interned, so both names point at the same pooled object.
  • true then false then false. Wrong on the last line. equals compares contents, and the contents are the same.

2. The answer is java then JAVA. A String method never changes the string. If you do not catch what it returns, nothing happened. A statement that is only a method call on a String is almost always a bug.

  • JAVA then JAVA. Wrong on the first line. The result of the first call was thrown away, because nothing was assigned.
  • java then JAVA. Correct. Strings are immutable, so toUpperCase returns a NEW string and leaves s alone. The first call changes nothing; the second prints its result directly.
  • java then java. Wrong on the second line: the value returned by the call is what is printed, and it is uppercase.
  • JAVA then java. Wrong, and it has the two lines the wrong way round.

3. The answer is 7 then P then ROG then 3. length() has brackets on a String and none on an array, index from zero, and substring excludes its end index. Those three answer most string questions.

  • 7 then P then ROG then 3. Correct. Seven characters; index 0 is P; substring(1, 4) takes indexes 1, 2 and 3, stopping BEFORE 4; and the first G is at index 3.
  • 7 then P then ROGR then 3. Wrong. substring stops before its second index, so it takes three characters, not four.
  • 7 then R then ROG then 4. Wrong. charAt(0) is the first character, P. Java indexes from zero.
  • 6 then P then ROG then 3. Wrong. PROGRAM has seven letters.

4. The answer is String is immutable, so each join creates a new object, while StringBuilder changes one buffer in place. Immutable means every join allocates. In a loop of n joins that is n objects created and discarded, which is why StringBuilder exists.

  • It is shorter to type. Wrong. It is longer to type, which is why the reason has to be a real one.
  • String is immutable, so each join creates a new object, while StringBuilder changes one buffer in place. Correct. Joining strings in a loop makes a fresh object every pass and throws the previous one away. StringBuilder appends to a single mutable buffer.
  • StringBuilder can hold more characters than String. Wrong. Neither has a practical limit you will meet on this course.
  • String cannot be used inside a loop. Wrong. It can be used, it is just wasteful.

    • (a) -2

ANSWERS · and why every option is what it is

1. The answer is 3 then 0 then 5. a.length with no brackets for an array, s.length() with brackets for a String. Arrays are created filled with the zero of their type: 0, 0.0, false or null.

  • 3 then 0 then 5. Correct. length is a FIELD on an array, with no brackets. An int array is filled with 0 when created, and a[0] was then set to 5.
  • 3 then null then 5. Wrong. null is the default for an OBJECT array. A numeric array defaults to zero.
  • 2 then 0 then 5. Wrong. new int[3] gives three elements, indexed 0, 1 and 2.
  • 3 then 0 then 0. Wrong. a[0] was assigned 5 on the second line.

2. The answer is caught Index 3 out of bounds for length 3. An array of length n has indexes 0 to n minus 1. The last valid index is always length minus one, and this off-by-one is the most common runtime error in the whole course.

  • 3. Wrong. Index 3 is the FOURTH element, and there are only three.
  • caught Index 3 out of bounds for length 3. Correct. Valid indexes are 0, 1 and 2, so a[3] throws, and the catch prints the exception's own message.
  • caught null. Wrong. The exception carries a message describing the index and the length.
  • 0. Wrong. Reading past the end does not return a default; it throws.

3. The answer is 2 then 3 then 6. Outer index is the row, inner index is the column, and both count from zero. m.length is rows; m[i].length is the width of row i.

  • 2 then 3 then 6. Correct. m.length is the number of ROWS, two. m[0].length is the length of the first row, three. m[1][2] is row 1, column 2, which is 6.
  • 3 then 2 then 6. Wrong, and it swaps rows and columns. The outer length is always the number of rows.
  • 2 then 3 then 5. Wrong. m[1][2] is the third element of the second row, which is 6, not 5.
  • 6 then 3 then 6. Wrong. m.length counts rows, not the total number of elements.

4. The answer is 0. Start max at the FIRST ELEMENT, never at zero. This exact fault is a standing exam favourite, and the fix is one line: int max = a[0], then loop from index 1.

  • -2. Wrong, and it is the answer the program was MEANT to give. It does not, because of the way max was initialised.
  • 0. Correct, and it is the bug. Starting max at 0 means no negative value can ever beat it, so 0 survives even though it is not in the array.
  • -9. Wrong. -9 is the smallest, not the largest.
  • -5. Wrong. -2 is larger than -5, so -5 could not win even with a correct start.
O.9 · OBJECTIVE · RECURSION

Recursion

3 questions, from Module Nine. Cover the answers, sit the whole set, then read every line of the answer block.

  1. What does this print?

    public class Q901 {    static int fact(int n) {        if (n <= 1) return 1;        return n * fact(n - 1);    }    public static void main(String[] args) {        System.out.println(fact(5));    }}
    • (a) 15
    • (b) 120
    • (c) 5
    • (d) StackOverflowError

  2. What does this print?

    public class Q902 {    static int fib(int n) {        if (n <= 1) return n;        return fib(n - 1) + fib(n - 2);    }    public static void main(String[] args) {        for (int i = 0; i < 7; i++) System.out.print(fib(i) + " ");    }}
    • (a) 0 1 1 2 3 5 8
    • (b) 1 1 2 3 5 8 13
    • (c) 0 1 2 3 4 5 6
    • (d) 1 2 3 5 8 13 21

  3. Which statement about recursion compared with iteration is TRUE?

    • (a) Recursion is always faster because it uses fewer instructions
    • (b) Recursion uses stack space for every pending call, so a deep recursion can exhaust it
    • (c) Any recursive method is impossible to write as a loop
    • (d) Recursion never needs a stopping condition
ANSWERS · and why every option is what it is

1. The answer is 120. Every recursion needs a base case and a step that moves towards it. Remove either and you get StackOverflowError, which is what the paper asks you to identify.

  • 15. Wrong. 15 is the SUM 1+2+3+4+5. This method multiplies.
  • 120. Correct. 5 x 4 x 3 x 2 x 1 is 120, and the base case at n <= 1 stops the recursion.
  • 5. Wrong. The method does not simply return its argument.
  • StackOverflowError. Wrong. There IS a base case and each call moves towards it, so the recursion terminates.

2. The answer is 0 1 1 2 3 5 8 . Two base cases here, folded into one line: fib(0) is 0 and fib(1) is 1. Trace the first four calls on paper and the pattern becomes obvious.

  • 0 1 1 2 3 5 8 . Correct. The base case returns n itself for 0 and 1, so the sequence starts 0, 1, and each later term is the sum of the two before it.
  • 1 1 2 3 5 8 13 . Wrong. This version starts at 0, because fib(0) returns 0.
  • 0 1 2 3 4 5 6 . Wrong. That is just the counting numbers, not a sum of the two previous terms.
  • 1 2 3 5 8 13 21 . Wrong. Seven terms from index 0 ends at 8, not 21.

3. The answer is Recursion uses stack space for every pending call, so a deep recursion can exhaust it. Recursion buys clarity on naturally recursive problems and pays for it in stack space and call overhead. Both sides of that trade earn marks.

  • Recursion is always faster because it uses fewer instructions. Wrong. Recursion is usually SLOWER: every call costs a stack frame and the work of calling.
  • Recursion uses stack space for every pending call, so a deep recursion can exhaust it. Correct. Each call in progress keeps its frame until it returns, so depth costs memory, and running out of it is StackOverflowError.
  • Any recursive method is impossible to write as a loop. Wrong. Anything recursive can be written iteratively, sometimes with an explicit stack of your own.
  • Recursion never needs a stopping condition. Wrong. Without a base case it never stops, and the program dies.

Exceptions and File Input and Output

5 questions, from Module Ten. Cover the answers, sit the whole set, then read every line of the answer block.

  1. What does this print?

    public class Q1001 {    static int f() {        try {            return 1;        } finally {            System.out.println("finally");        }    }    public static void main(String[] args) {        System.out.println(f());    }}
    • (a) 1
    • (b) finally
      1
    • (c) 1
      finally
    • (d) finally

  2. What happens when this is compiled?

    public class Q1002 {    public static void main(String[] args) {        try {            int x = 1 / 0;        } catch (Exception e) {            System.out.println("general");        } catch (ArithmeticException e) {            System.out.println("arithmetic");        }    }}
    • (a) It prints general
    • (b) It prints arithmetic
    • (c) It does not compile: the second catch can never be reached
    • (d) It prints both lines

  3. Which statement is TRUE?

    • (a) A checked exception must be caught or declared with throws
    • (b) An unchecked exception must always be caught
    • (c) All exceptions in Java are checked
    • (d) A checked exception cannot be caught

  4. Which class does this course use to read a text file line by line, and what must surround it?

    • (a) Scanner or BufferedReader, inside a try block that handles IOException
    • (b) System.out, inside a for loop
    • (c) FileWriter, inside a switch
    • (d) String, with no exception handling needed

  5. What does this print?

    public class Q1005 {    public static void main(String[] args) {        String s = null;        try {            System.out.println(s.length());        } catch (NullPointerException e) {            System.out.println("null pointer");        }    }}
    • (a) 0
    • (b) null pointer
    • (c) null
    • (d) it does not compile
ANSWERS · and why every option is what it is

1. The answer is finally then 1. finally runs on every path out of a try, including a return. That is why it is where cleanup belongs.

  • 1. Wrong. The finally block runs even when the try block returns.
  • finally then 1. Correct. The return value is computed, then finally runs on the way out, and only then does the caller receive the 1 and print it.
  • 1 then finally. Wrong on the order. finally runs BEFORE the method actually returns to its caller, so its output appears first.
  • finally. Wrong. The method does return 1, and main prints it.

2. The answer is It does not compile: the second catch can never be reached. Catch the most specific exception FIRST and the general one last. Reversing them is a compile error, not a subtle bug, which is the helpful part.

  • It prints general. Wrong. It never runs at all, because it does not compile.
  • It prints arithmetic. Wrong for the same reason, and the general catch would win in any case.
  • It does not compile: the second catch can never be reached. Correct. Exception is the superclass of ArithmeticException, so the first catch already covers everything the second could. Java rejects unreachable catch clauses at compile time.
  • It prints both lines. Wrong. At most one catch clause ever runs for a given exception.

3. The answer is A checked exception must be caught or declared with throws. Checked means the compiler makes you deal with it. Unchecked means it is your job to avoid it, and the commonest ones, null pointer and array index, are bugs rather than conditions.

  • A checked exception must be caught or declared with throws. Correct. The compiler insists: handle it, or declare that your method may throw it. IOException is the one this course meets most.
  • An unchecked exception must always be caught. Wrong. Unchecked exceptions, the RuntimeException family, need neither. NullPointerException is the standard example.
  • All exceptions in Java are checked. Wrong. Everything descending from RuntimeException and Error is unchecked.
  • A checked exception cannot be caught. Wrong. It can be caught; it simply may not be ignored.

4. The answer is Scanner or BufferedReader, inside a try block that handles IOException. Reading needs a reader and reading can fail, so it needs a catch. Both halves of that sentence earn marks.

  • Scanner or BufferedReader, inside a try block that handles IOException. Correct. Either class can read lines, and file work throws a CHECKED exception, so it must be caught or declared.
  • System.out, inside a for loop. Wrong. System.out is the output stream, not a way in.
  • FileWriter, inside a switch. Wrong. FileWriter writes. Reading needs a reader.
  • String, with no exception handling needed. Wrong. String is a type, not a file, and the exception handling is not optional for file access.

5. The answer is null pointer. null means the reference points at no object. Reading it is fine; calling a method on it is not. Check for null before you dereference.
