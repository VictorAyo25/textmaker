UNIT 2.1 · INTRODUCTION TO JAVA

What Java is, and what makes it Java

By the end of this unit you should be able to explain the fundamental concepts of Java programming, install and configure the JDK on any operating system, and set up the environment variables needed to run Java applications.

TEACH · Java, in one paragraph

Java is a versatile, object-oriented programming language used to build scalable applications across multiple platforms. It launched in 1995 and has remained a first choice for web, desktop, enterprise and mobile development ever since.

Its defining property is "Write Once, Run Anywhere" (WORA), powered by the Java Virtual Machine, which gives it cross-platform compatibility.

TEACH · You have already met the machinery

F.3 built the compile-and-run story from zero: source becomes bytecode becomes a running program, and the JVM is what makes the same bytecode work everywhere. F.4 got a JDK onto your machine and your first program running.

This unit is not a repeat. It is the same material as your course examines it: the formal definitions, the distinctions between the three J-words, and the question forms that actually appear on the paper. If F.3 and F.4 are hazy, go back now; the rest of this unit assumes them.

MUST-MEMORISE · Java's four headline properties

Platform independent: compiled to bytecode, run by a JVM, so one compilation runs anywhere (WORA).
Object-oriented: code is organised as classes and objects.
Versatile: web, desktop, enterprise and mobile.
Scalable: suits systems that must grow.

MEMORY HOOK: Java is a POVS language: Platform independent, Object-oriented, Versatile, Scalable. Then attach one sentence to each letter, because a bare list earns half the marks a sentence does.

RECALL AND CHECK

What does WORA stand for, what makes it possible, and what is the role of the JVM?

Answer

WORA stands for "Write Once, Run Anywhere": Java's ability to run the same code on multiple platforms. It is possible because Java compiles to bytecode rather than to machine code, and bytecode is identical on every platform. The JVM's role is to read that bytecode and carry it out on its own particular platform, which is what makes the same compiled file run everywhere.

UNIT 2.2 · THE JAVA DEVELOPMENT ENVIRONMENT

JDK, JRE, JVM, and getting them working

TEACH · The JDK

To write Java you download and install the Java Development Kit. The JDK is a software development environment used for developing Java applications: it provides the tools needed to write, compile and run them.

That three-verb phrase is your course's own wording, and it is the shape of the expected answer to "what is the JDK?".

TEACH · Which of the three do you need?

The three J-words nest, as F.4 set out: JDK > JRE > JVM. The exam likes the distinction, so hold it precisely:

NameIsLets youWho needs it
JVMthe virtual machine that executes bytecodeexecute bytecodeeveryone, and it comes inside the others
JREJVM + the standard class libraryrun Java programsa user running someone else's program
JDKJRE + development tools, above all javacwrite, compile and runyou

Install the JDK. A JRE cannot compile, and a language you cannot compile is a language you cannot learn.

TEACH · Installing and configuring

The full procedure, with every step and every trap, is F.4: download the JDK for your operating system, install it, set JAVA_HOME to the JDK folder, add %JAVA_HOME%\bin to PATH, open a new terminal, and verify.

It is in Foundations rather than here for one reason: you needed a working compiler before Module 1, not after it. Nothing about it is different when your course reaches this unit.

The verification command is the one your course gives:

TerminalC:\> java --version
openjdk 17.0.16 2025-07-15
OpenJDK Runtime Environment Temurin-17.0.16+8 (build 17.0.16+8)
OpenJDK 64-Bit Server VM Temurin-17.0.16+8 (build 17.0.16+8, mixed mode, sharing)

Your version numbers will differ, and that is fine: any JDK 17 or later runs everything in this book. What matters is that the command answers at all. Silence or "not recognised" means PATH, and F.4.1 fixes it.

TRAP · java --version is not proof you can compile

Your course's verification step only runs java --version. That command answers happily on a machine with a JRE and no compiler, and then javac Hello.java fails and you cannot see why.

Always check both. If java answers and javac does not, you have a JRE, not a JDK.

TerminalC:\> javac --version
javac 17.0.16
MUST-MEMORISE · The two environment variables

JAVA_HOME = the JDK folder itself.
  C:\Program Files\Java\jdk-17

PATH gets the bin inside it.
  %JAVA_HOME%\bin

PATH is the list of folders your terminal searches when you type a command. That is why the bin goes there: bin is the folder the commands actually live in.

MEMORY HOOK: HOME is the house, PATH is the front door. You address a letter to the house; you walk in through the door.

WORKED EXAMPLE · Diagnosing a broken setupEXAM SKILL

"I installed Java but javac says it is not recognised." Work it in this order, and stop at the first step that fails.

  1. Does java --version answer? If yes, Java is installed and PATH is partly right, so jump to step 3. If no, PATH is wrong or nothing is installed.
  2. Does the JDK folder exist in File Explorer, with a bin holding javac.exe? If there is no javac.exe, you installed a JRE. Reinstall the JDK. This is the single most common cause.
  3. Is this terminal older than the change you made? Close it, open a new one, try again. Second most common cause, and it costs people hours.
  4. Does echo %JAVA_HOME% print the JDK folder, with no \bin on the end and no quotes?
  5. Does echo %PATH% contain that folder plus \bin?

Now redo it: from memory, name the two most common causes in order. Then say why java can work while javac does not, in one sentence.
