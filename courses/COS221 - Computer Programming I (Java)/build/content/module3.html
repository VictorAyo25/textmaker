Variables, data types, operators, control structures

Your course says programming rests on four building blocks. Every program you write for the rest of your life is made of these and nothing else.

MUST-MEMORISE · The four building blocks

Variables hold data. Data types say what kind of data. Operators combine and compare it. Control structures decide what runs, and how often.

MEMORY HOOK: a kitchen. Variables are the containers, data types say what may go in each, operators are the knives and the mixer, control structures are the recipe deciding order and repetition.

UNIT 3.2 · VARIABLES AND THE RULES FOR NAMING THEM

Declaring a variable, and what you may call it

TEACH · Declaration

F.8 introduced a variable as a named box holding one value. Formally: a variable is a container that stores data, and a variable in Java must be declared before it is used. You declare it by writing its data type and then its name.

int number;

int is the data type, number is the name. That line makes the box but puts nothing in it. To make it and fill it in one go:

dataType variableName = value;

which your course calls declaration and initialisation. Learn that one-line syntax exactly: "what is the syntax to declare and initialise a variable" is a stated in-text question, so it is a candidate for the two-mark define slot in Section A.

OutputJohn is 25, active: true, price: 19.99
MUST-MEMORISE · The six naming rules

1. Must start with a letter, an underscore _, or a dollar sign $.
2. Cannot start with a digit.
3. May contain letters, digits, _ and $.
4. Are case-sensitive: age, AGE and Age are three different variables.
5. Cannot contain spaces or special characters like !, @, -.
6. Cannot be a keyword: int, class, float, if, public, else, private are all illegal as names.

MEMORY HOOK: rules 1, 2, 3 and 5 all say the same thing once you see it: a name is letters, digits, _ and $, and it may not start with a digit. Learn that one sentence, then add case-sensitivity and no-keywords. Six rules, two facts.

TRAP · Case-sensitivity is not a formality

Rule 4 sounds like pedantry and is the source of real bugs. Declare int count = 0; and later write Count++ and Java does not correct you; it says cannot find symbol, because Count is a different name that was never declared.

This is a planted error on the 2024/25 paper: a loop body writes Count where the variable is count. Two of that question's three marks are for spotting it.

RECALL AND CHECK

Which of these are illegal variable names, and why? 2fast, _total, grand-total, double, $price, my name

Answer

Illegal: 2fast starts with a digit; grand-total contains a hyphen, a special character; double is a keyword; my name contains a space. Legal: _total and $price, because underscore and dollar are both allowed starters.

UNIT 3.3 · DATA TYPES

Primitive and non-primitive, and the sizes you must know

TEACH · What a data type is for

Data types specify the type of data a variable can hold, and the type determines the operations that can be performed on it. That second half is the part students skip and the exam rewards: the type is not just a label on the box, it decides what you are allowed to do.

+ on two ints adds. + on two Strings joins. Same symbol, different operation, chosen entirely by the types. F.11's "25" + 1 trap is precisely this.

MUST-MEMORISE · Primitive versus non-primitive

Primitive types are the most basic type of data in Java. They represent single values and are built into the language. There are eight: byte, short, int, long, float, double, char, boolean.

Non-primitive types are also called reference types, because they refer to objects in memory. They can store objects and can be user-defined. The four your course names: Classes, Interfaces, Arrays, Strings.

MEMORY HOOK: a primitive variable is the value; a reference variable is a street address where the value lives. The box holds the number itself, or it holds directions to it.

UNIT 3.4 · CONSTANTS

final: a box that will not change

TEACH · Constants

A constant is a data container whose value cannot change once it has been assigned. Constants improve readability and prevent accidental modification. In Java you declare one with the final keyword.

final dataType CONSTANT_NAME = value;

By convention constant names are written in capitals with underscores. That is a convention, not a rule: the compiler accepts final double pi, and every Java programmer alive will read it as a mistake.

CODE · final, and what happens if you fight it
public class FinalDemo {    public static void main(String[] args) {        final double PI = 3.14159;        final int MAX_USERS = 100;        System.out.println(PI + " " + MAX_USERS);        PI = 3.14;      // the compiler refuses this    }}
What the compiler saysFinalDemo.java:7: error: cannot assign a value to final variable PI
        PI = 3.14;
        ^
1 error

Note when this is caught: at compile time, not run time. The program never runs at all. That is the value of final, in the sense of F.7: it converts a possible logic error into a compile-time error, which is the cheapest kind.

WORKED EXAMPLE · Tax-inclusive pricingFROM THE SLIDES

Your course's own example: total price of some items including 15% tax, with the rate as a constant.

public class TaxInclusivePricing {    public static void main(String[] args) {        final double TAX_RATE = 0.15;      // 15%, fixed        int quantity = 3;        double basePrice = 250.0;        double total = quantity * basePrice * (1 + TAX_RATE);        System.out.println("Total: " + total);    }}
OutputTotal: 862.4999999999999

Look at that output. Three items at 250.00 plus 15% is exactly 862.50, and Java printed 862.4999999999999. Nothing is broken and this is not a bug in your code: it is what double is, and Unit 3.6 explains it. It is also why real money is never stored in a double. Your course's slide does not mention this; the machine does.

Now redo it: write the same program with TAX_RATE as an ordinary variable rather than final, and say in one sentence what you have lost.

RECALL AND CHECK

Why declare final double INTEREST_RATE = 0.05; rather than just writing 0.05 wherever it is needed?

Answer

Three reasons. Readability: INTEREST_RATE says what the number means and 0.05 does not. Safety: final makes accidental modification a compile-time error rather than a silent logic error. And change: the rate lives in one place, so a new rate is a one-line edit rather than a hunt for every 0.05 in the file, some of which might mean something else entirely.

MUST-MEMORISE · The three things % buys you

n % 2 == 0   means   n is even
n % k == 0   means   n divides exactly by k
n % 10      gives   the last digit of n, and n / 10 removes it

That last line is an entire exam technique. The Armstrong, palindrome, digit-sum and Harshad questions on your papers are all built from % 10 and / 10 in a loop, and nothing else.

MEMORY HOOK: % peels the last digit off, / pushes it away. Together they walk a number's digits from right to left.

WORKED EXAMPLE · Walking a number's digitsEXAM TECHNIQUE

This tiny loop is the engine of four separate past-paper questions. Learn it as a shape.

public class Digits {    public static void main(String[] args) {        int n = 4821;        int temp = n, sum = 0, reversed = 0;        while (temp > 0) {            int d = temp % 10;          // peel the last digit off            sum += d;                    // use it            reversed = reversed * 10 + d;// build the reverse            temp /= 10;                  // push it away        }        System.out.println("n        = " + n);        System.out.println("digitsum = " + sum);        System.out.println("reversed = " + reversed);    }}

3.6.1 The pitfalls

TEACH · Your course names three

Division by zero, modulus with negative numbers, and string concatenation. Its example program is below, and it is worth more than your course claims.

CODE · The slide's program, exactly as printedFROM THE SLIDES
public class ArithmeticOperatorsPitfalls {    public static void main(String[] args) {        System.out.println(10/0);        System.out.println(10.0/0);        System.out.println(-7%3);        System.out.println(7%-3);    }}

Your course says: line 3 throws an ArithmeticException; line 4 prints Infinity; line 5 prints -1; line 6 prints 1. Every one of those statements about the expressions is true. The claim about the program is not.

TRAP · Lines 4, 5 and 6 never run

An uncaught exception stops the program dead. Line 3 throws, so the JVM abandons main there and lines 4, 5 and 6 are never reached. Run this program exactly as printed and it produces no output at all, only a crash report:

What actually happensException in thread "main" java.lang.ArithmeticException: / by zero
	at ArithmeticOperatorsPitfalls.main(ArithmeticOperatorsPitfalls.java:3)

So if an exam hands you this program and asks "state the output", the answer is not "Infinity, -1, 1". It is: the program throws ArithmeticException: / by zero at line 3 and terminates, printing none of the remaining lines.

This matters beyond one slide. It is the difference between reading code line by line as four independent facts, and dry running it as one program with a flow that can stop.

CODE · The same four expressions, made to surviveVERIFIED ON THE JVM
public class Pitfalls {    public static void main(String[] args) {        try {            System.out.println(10/0);       // int / int  -> throws        } catch (ArithmeticException e) {            System.out.println("line 3 -> " + e.getMessage());        }        System.out.println("line 4 -> " + (10.0/0));   // double -> Infinity        System.out.println("line 5 -> " + (-7%3));    // sign follows the LEFT        System.out.println("line 6 -> " + (7%-3));    // sign follows the LEFT    }}

MUST-MEMORISE · The three arithmetic pitfalls

1. Division by zero depends on the type.
10/0 with ints throws ArithmeticException and stops the program.
10.0/0 with a double gives Infinity and carries on. (And 0.0/0.0 gives NaN, "not a number".)

2. Modulus keeps the sign of the LEFT operand.
-7 % 3 is -1.   7 % -3 is 1.

3. + joins when either side is text.
"25" + 1 is "251", not 26.

MEMORY HOOK: for modulus, the remainder inherits its sign from the number being divided, not the divider. Ask "what is left of -7?" and the answer is negative.

TRAP · Integers throw, doubles do not

This asymmetry catches everyone. There is no int that can represent infinity, so Java has no choice but to throw. double has a genuine Infinity value built into it, so it returns one and the program keeps running with a poisoned number in it, which is arguably worse: a crash is loud, an Infinity quietly contaminates every later calculation.

MUST-MEMORISE · Never compare doubles with ==

0.1 + 0.2 == 0.3 is false, because 0.1 + 0.2 is actually 0.30000000000000004.

A double stores a number in binary, and 0.1 has no exact binary form, exactly as 1/3 has no exact decimal form. The tiny error is real and it survives the addition.

To compare two doubles, ask whether they are close enough:
if (Math.abs(a - b) < 0.0000001) { ... }

MEMORY HOOK: writing 1/3 in decimal you must stop somewhere: 0.3333. Binary has to stop somewhere too, and 0.1 is binary's 1/3. Doubles are approximations wearing a convincing disguise.

TRAP · == compares values, not types

num == decimal, comparing int 10 with double 10.0, is true. Java widens the int to a double and compares the values. The types differ; the values do not; == only cares about the values.

And letter > num, comparing 'A' with 10, is true, because a char is a number: 'A' is 65. This is why char sits in the integer family of primitives rather than off on its own.

UNIT 3.8 · LOGICAL OPERATORS

Combining conditions, and the shortcut Java takes

TEACH · The four

MUST-MEMORISE · Short-circuit evaluation

&& stops as soon as it meets a false: if the left side is false the whole thing is false, so the right side is never evaluated.

|| stops as soon as it meets a true, for the mirror reason.

This is not an optimisation you can ignore. It is a tool: it is what lets you write if (i < a.length && a[i] > 0) safely. The left guard runs first, and when it is false the array is never touched, so no exception. Swap the two around and the same line crashes.

MEMORY HOOK: && is a pessimist and || is an optimist. The pessimist stops at the first bad news; the optimist stops at the first good news. Neither reads any further.
