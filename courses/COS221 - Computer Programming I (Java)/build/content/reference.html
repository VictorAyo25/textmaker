R.1 · REFERENCE · THE EXAM API CARD

The API card: what you must have cold

Every call below has appeared on a real COS221 paper. This is the short list. If you know only one page of this reference, know this one.

MUST-MEMORISE · Input and output, the lecturer's way

Every write-a-program question on both papers says JOptionPane. It is two calls and one import.

CallWhat it does, and what to watch
import javax.swing.JOptionPane; The import. javax, not java: the single commonest typo in the hall.
JOptionPane.showInputDialog(null, "Enter age:") Asks, and returns what was typed as a String, always. Returns null if the user presses Cancel.
JOptionPane.showMessageDialog(null, "Total: " + t) Shows a message. Returns nothing. The null is the parent window: there isn't one.
System.exit(0) Ends the program. 0 means "ended normally". See F.11: it is insurance, not a rescue.

MEMORY HOOK: showInput asks, showMessage tells. Input comes back as text, so it always needs converting.

MUST-MEMORISE · Text to number, because a dialog only ever gives you text
CallWhat it does, and what to watch
Integer.parseInt(s) String to int. Throws NumberFormatException if s is not a whole number.
Double.parseDouble(s) String to double. Same exception on nonsense.

The full shape, which you will write a dozen times on one paper:

int age = Integer.parseInt(JOptionPane.showInputDialog(null, "Age:"));

MEMORY HOOK: the dialog hands you a String even when you asked for a number. Every input is two steps: ask, then convert.

MUST-MEMORISE · The file I/O the paper allows

The 2025/26 Question Three names five classes and permits nothing else: FileWriter, FileReader, BufferedReader, BufferedWriter, IOException.

CallWhat it does, and what to watch
new FileWriter("f.txt") Opens for writing. Creates the file if absent, and truncates it if present.
new FileWriter("f.txt", true) The same, but appends. This second argument is the only way to append, and it belongs here, on the writer that touches the disk.
new BufferedWriter(new FileWriter("f.txt")) Wraps a writer and writes in blocks. Gives you newLine().
new PrintWriter(new FileWriter("f.txt", true)) Wraps a writer and gives you printf() and println() on a file. Note new PrintWriter("f.txt") on its own truncates and cannot append.
new BufferedReader(new FileReader("f.txt")) Opens for reading, in blocks. Gives you readLine().
readLine() The next line, or null at the end of the file. That null is the loop's stopping condition.
try (BufferedReader in = ...) { } try-with-resources. Closes it whether the block ends normally or by throwing. Nothing to forget.
catch (IOException e) Checked: catch it or declare throws, or it will not compile.

MEMORY HOOK: Reader in, Writer out; Buffered wraps; Print formats. The one that touches the disk carries the append flag.

MUST-MEMORISE · printf, and the four formats that cover every paper
FormatMeans
%da whole number
%fa decimal. %.2f means two decimal places.
%sa string. %-8s means left-aligned in 8 columns.
%nend the line. Use this, not \n.

printf rounds the digits you wrote, half up, so your paper arithmetic is trustworthy: %.2f of 1.005 really is 1.01. See MS.4, where that was measured against 99,999 values.

MEMORY HOOK: width before the point, precision after. %-8.2f is "left-aligned, eight wide, two decimals".

TEACH · String: the text type, and it never changes

Every method here returns a new String. None of them alters the one you called it on, because a String cannot be altered (Unit 7.1). If you do not keep the answer, nothing happened.

CallWhat it does

TEACH · Exceptions, and the wrappers that throw them
NameWhat it is
ExceptionThe parent of nearly all of them. catch (Exception e) catches everything below it, which is why it must come last, and why catching it instead of the specific one is a way of not saying what you expected to go wrong.
IOExceptionChecked. Anything went wrong with a file. Catch it or declare it.
FileNotFoundExceptionChecked. A subclass of IOException, so catch it first or it is unreachable.
NumberFormatExceptionUnchecked. parseInt met something that is not a number.
ArithmeticExceptionUnchecked. Integer division by zero. Decimal division by zero gives Infinity instead.
ArrayIndexOutOfBoundsExceptionUnchecked. An index below 0 or at length or above.
NullPointerExceptionUnchecked. A method was called on null.
new IllegalArgumentException("why")Unchecked. Throw it yourself when an argument makes no sense.
new ArithmeticException("why")Throwing one yourself, to show throw against throws.
getMessage()The text carried by the exception.
getClass()The object's class, at run time.
getSimpleName()On a class: its name without the package, so IOException rather than java.io.IOException.

MEMORY HOOK: throw does, throws warns. The s is a signature, not an action.

TRAP · The keywords this course does not use are still reserved

Java has fifty reserved words. This book uses the forty-two above, because they are the ones your course teaches and your papers examine. The rest are real and you may not use them as names either:

assert, const, enum, goto, instanceof, native, package, strictfp, synchronized, transient, volatile.

Two of those are curiosities worth ten seconds: const and goto are reserved and do nothing at all. They exist only so that the compiler can give you a proper error instead of a confusing one if you arrive from a language that has them. Java's constant is final.

They are listed here rather than tabled above for one reason: this book documents what it uses. An entry claiming to teach you synchronized would be a promise no page of this manual keeps.

R.4 · REFERENCE · THE GLOSSARY

The glossary

The vocabulary, defined once. Both papers open with "define" and "describe" questions, and those are the cheapest marks on either paper: they are the only ones you can be certain of before you walk in.

TEACH · The machine and the language
TermDefinition
Source codeThe Java you type, in a .java file. Text, readable by people.
Compiler (javac)Translates source into bytecode, and refuses if the source is not legal Java.
BytecodeThe .class file. Not machine code, and not tied to any one processor.
JVMThe Java Virtual Machine: the program that runs bytecode. The reason Java runs anywhere.
JDKThe kit: compiler, JVM, and libraries. You need it to write Java, not merely to run it.
Compile-time errorThe code is not legal Java. Nothing runs. The compiler tells you the line.
Run-time errorLegal code that hits something impossible while running. Java throws an exception.
Logic errorIt compiles, it runs, it finishes, and the answer is wrong. Nothing warns you. Only a dry run finds it.
Dry runExecuting a program by hand, one row per step, writing down every variable as it changes. Your lecturer's own term, and an exam skill.
TEACH · Data
TermDefinition
VariableA named box holding one value of a declared type.
Primitive typeOne of the eight built-in types. The variable holds the value itself.
Reference typeEverything else. The variable holds a reference to an object stored elsewhere.
LiteralA value written directly in the code: 42, 3.14, "hi". Its type is fixed when you type it, before anything is assigned.
ConstantA final variable: set once, never changed.
CastingTelling the compiler to convert a type, taking responsibility for the loss: (int) 3.9 is 3.
WideningA smaller type flowing into a bigger one automatically, losing nothing: an int into a double.
NarrowingThe reverse, which loses data, so Java never does it silently.
Integer division/ between two whole numbers, which chops the remainder away. 7 / 2 is 3. It does not round.
ArrayA fixed-length run of values of one type, reached by index from 0.
IndexAn element's position. The last is always length - 1.
Parallel arraysTwo or more arrays of equal length where the same index means the same subject. This course's substitute for a collection.
TEACH · Methods
TermDefinition
MethodA named, reusable block that may take values in and may give one back.
Formal parameterThe variable named in the method's declaration. A name waiting for a value.
Actual argumentThe value written at the call, which is copied into the parameter.
Method signatureThe name plus the parameter list. The return type is not part of it.
Return typeThe type of what comes back, or void for nothing.
OverloadingSeveral methods, same name, different parameter lists. Resolved at compile time. Compile-time polymorphism.
OverridingA subclass replacing an inherited method with the same signature. Resolved at run time.
Pass by valueJava's only mechanism. The value is copied. For a reference type, the reference is copied, so the method can change the object but cannot make your variable point elsewhere.
RecursionA method that calls itself, with a base case that stops it.
TEACH · Objects
TermDefinition
ClassThe blueprint: what an object of this kind knows and can do.
ObjectOne thing made from that blueprint, with its own copy of the state.
Attribute (field)A variable belonging to an object: what it knows.
ConstructorRuns once, at new, to put a new object into a valid state. Named exactly like the class, and declares no return type at all.
Instance methodBelongs to an object. Called on one: account.deposit(500).
Static methodBelongs to the class. Called on it: Math.abs(-3).
EncapsulationKeeping state private and exposing it through methods, so an object controls its own data.
InheritanceA subclass acquiring the superclass's members with extends. An is-a relationship.
PolymorphismOne name, several behaviours. Compile-time is overloading; run-time is overriding.
Dynamic method dispatchThe run-time half: the object decides which override runs, not the reference's declared type.
AbstractionExposing what a thing does and hiding how. In Java: abstract classes and interfaces.
TEACH · Exceptions and files
TermDefinition
ExceptionAn object describing something that went wrong, thrown at the point of failure.
Checked exceptionThe compiler insists you catch it or declare it. IOException. A fact about the world, not a bug.
Unchecked exceptionNot policed. NullPointerException. Usually a bug, so the fix is to correct the code, not to catch it.
try-with-resourcestry (Reader r = ...): closes what it opened, on every path, including the throwing one.
StreamA one-way flow of data. A reader reads one; a writer writes one.
BufferingCollecting data and moving it in blocks rather than one character at a time.
SentinelA value that means "stop", chosen so it cannot be real data: readLine() gives null, read() gives -1.
MUST-MEMORISE · The five definitions both papers keep asking for

Across 2024/25 and 2025/26, these came up again and again. If you learn five definitions, learn these, in these words:

1. Method signature: the method's name plus its parameter list. The return type is not part of it.
2. Overloading against overriding: same name different parameters, settled at compile time; against same signature in a subclass, settled at run time.
3. Checked against unchecked: the compiler forces you to handle a checked one, or it will not compile.
4. Encapsulation: private state, public methods, so the object owns its own data.
5. Dry run: hand-execute the code, one row per step.

MEMORY HOOK: every one of these is a distinction, not a fact. The mark is in the contrast, so answer in two halves and say which is which.
