How to use this book

Read this page. It is two minutes long and it is the difference between finishing this book able to write Java and finishing it able to recognise Java.

What this book promises

You may never have written a line of code in your life. That is the reader this book is written for. It starts from what a computer actually does when it runs a program, and it ends with you sitting a three hour paper and writing correct Java on paper, by hand, under time pressure.

Two promises follow from that, and they shape every page:

  • Nothing is used before it is explained. No keyword, no symbol, no method appears in this book before the page that introduces it. If you meet something you do not recognise, that is a defect in the book, not a gap in you.
  • You will not need anything else. No other textbook, no website, no official documentation, no lecturer. Every library method this course uses is documented in here, in full, at the point you need it, and again in the reference at the back.
TEACH · Reading is not studying

Reading code feels productive and teaches you almost nothing. You will read a worked example, think "yes, obviously", turn the page, and be unable to reproduce a line of it. This is the single most common way people fail a programming exam: they have seen everything and can write nothing.

The cure is retrieval: closing the book and producing the answer from your own head. Every device in this book exists to force that. It will feel slower and less pleasant than reading. It is roughly three times more effective per hour, and it is the only thing the exam actually measures.

MUST-MEMORISE · The colour that means "learn this"

This cyan is reserved. It appears in this book only on MUST-MEMORISE boxes and nowhere else, ever. If you are short of time, flick through and read only the cyan.

MEMORY HOOK: cyan is the colour of a cursor blinking at you, waiting. It is the book asking you a question.

How the book is arranged

The Foundations part comes first and owes nothing to the module order. It builds the machine underneath everything else: what a program is, what the compiler does, what a variable really is, and how to get a program running on your own laptop. Do not skip it, even if you have programmed before, because the modules assume it.

Then Modules 1 to 10, numbered exactly as your lecturer numbers them, so that this book and your course are always talking about the same Module 4. Then the back matter: every past exam question solved in full, mock papers in both formats, and a reference section you can revise from the night before.

TRAP · The module order is not a learning order

Your course teaches arrays in Module 8, near the end. But both Section A questions on the most recent paper are array problems, and arrays are the natural way to understand loops back in Module 4. The course also demands JOptionPane for input and output long before it explains what an object is.

This book fixes that without renumbering anything. Foundations teaches you, honestly and from zero, the few things the early modules need early, and tells you plainly where each one is developed in full. So when Module 8 arrives you are deepening something you already understand, not meeting it for the first time with three weeks to go.

If you have two weeks

  1. Foundations, properly, doing every RECALL AND CHECK. One day.
  2. Modules 3, 4, 5 and 8 (types, control, methods, arrays). These four carry most of the marks on every paper we have. Four days, and write out every worked example by hand.
  3. Every solved past question in the back, with the solution covered. Three days.
  4. Modules 6, 7, 9, 10. Three days.
  5. The mock papers, timed, on paper, with the book shut. Three days.

Step 5 is not optional. You do not find out whether you can write Java under time pressure by reading about writing Java under time pressure.
