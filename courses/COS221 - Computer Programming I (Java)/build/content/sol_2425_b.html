Q2 A · Define dynamic array initialisation, length, and the out-of-bounds exception3 MARKS

Model answer.

  1. Dynamic array initialisation. Creating the array with new and a size decided while the program runs, rather than from a literal list written in the source: int[] a = new int[n]; where n is only known at run time. Every element starts at its default (0 for int, null for objects), and the values are filled in afterwards. Contrast static initialisation, int[] a = {2, 4, 6, 8};, where the size and the values are both fixed in the source.
  2. The length property. a.length gives the number of elements. It is a field, not a method, so there are no brackets: writing a.length() is a compile error. It is final: an array's length is fixed the moment it is created and can never change. A String's length IS a method, s.length(). The examiner knows that catches people; Unit 7.2.
  3. The out-of-bounds exception. ArrayIndexOutOfBoundsException, thrown at run time when you use an index below 0 or at or above length. Valid indexes are 0 to length - 1, so a[a.length] always throws. It is unchecked, so the compiler will not warn you about it.

Where the marks are: "length is a field, not a method" and "indexes are 0 to length-1" are the two facts every other part of this question depends on. F.10 and Unit 8.1.

import java.util.Scanner;public class ArrayStats {    // ii a. find, count and display the even numbers    public static void evens(int[] values) {        int count = 0;        String found = "";        for (int i = 0; i < values.length; i++) {            if (values[i] % 2 == 0) {                count++;                found = found.equals("") ? MUST-MEMORISE · Test for odd with != 0, never == 1

if (v % 2 != 0)   is odd. Always.

if (v % 2 == 1)   is odd only for positives, and silently wrong for negatives.

In Java, % keeps the sign of the left operand, so -3 % 2 is -1, not 1. So -3 % 2 == 1 is false and the == 1 test declares -3 even.

The test data above proves it. The odd numbers are 7, -3, 9, 15 and 11, and they sum to 39. Had the method used == 1, it would have skipped -3 and printed 42: a wrong answer, from a program that runs cleanly and looks right. That is why the ten values include a negative odd number, and why yours should too. Unit 3.6 and Unit 8.4.

MEMORY HOOK: "not even" is safe; "equals one" is not.

TEACH · Priming the maximum: why not start at 0

The maximum loop starts int max = values[0]; and then runs from i = 1. The tempting alternative is int max = 0;, and it is a bug waiting for the right data.

If every value is negative, max = 0 never gets replaced and the program reports a maximum of 0, a number that is not in the array. Priming with values[0] cannot do that: the answer starts as a real element and only ever moves to another real element.

The same reasoning as Unit 8.4's minimum, and the same reasoning that makes Integer.MIN_VALUE the other correct prime. Starting at 0 is correct only if you know the data contains a non-negative number, and "I know my data" is how bugs are born.

Q3 A · Define PrintWriter, Files.write(), and try-with-resources3 MARKS

Model answer.

  1. PrintWriter. A character-output class that writes formatted text to a file or stream, giving you the same familiar methods as System.out: print, println and printf. It is a wrapper: you hand it a destination (a file name, or another Writer) and it adds the formatting.
  2. Files.write(). A static method on java.nio.file.Files that writes an entire byte array or collection of lines to a file in a single call, creating the file if needed and closing it for you. It is the one-line alternative to opening a writer, looping, and closing.
  3. try-with-resources. A try with the resource declared in brackets, try (PrintWriter out = ...) { ... }, which automatically closes that resource when the block ends, whether it ends normally or by an exception. It removes the need for a finally block whose only job is closing. Unit 10.2.

Where the marks are: for each, say what it is and what it saves you. "PrintWriter writes formatted text" earns the mark; "PrintWriter is for files" does not distinguish it from FileWriter.

The errors, listed.

  2. FileWriter("note.txt") is missing new. Creating an object requires new: without it Java looks for a method called FileWriter and finds none. Fix: new FileWriter("note.txt").

Error 4 is the one that separates answers. Anyone can see a missing bracket; the examiner wants to know whether you understand that a checked exception is a compile-time obligation.

MUST-MEMORISE · print, println, printf: the three differences

print("Age: ")   writes the text, no line break. So the 25 lands on the same line.

println(25)   writes it and a line break. That break is what ends line 1.

printf("Score: %.2f", 89.456)   formats, and adds no line break unless you write %n.

1. %.2f rounds, it does not truncate. 89.456 to two places is 89.46, not 89.45. Unit 3.11.

2. The file has no trailing newline. printf did not add one, so the file ends immediately after the 6 of 89.46. The file is 21 bytes and its last character is not a line break.

3. Nothing appears on screen. Every call is on pw, not on System.out. A common wrong answer is to write the two lines as program output.

MEMORY HOOK: only println breaks the line. print and printf leave the cursor exactly where it stopped.

Q3 D · Write students.txt as a formatted, appended table7.5 MARKS
MUST-MEMORISE · PrintWriter cannot append. The FileWriter under it can

new PrintWriter("students.txt")   truncates the file to empty. Every time. There is no append constructor.

new PrintWriter(new FileWriter("students.txt", true))   appends.

The true is the append flag, and it belongs to FileWriter, not to PrintWriter. So the answer to "append with PrintWriter" is to wrap one around a FileWriter opened in append mode, exactly as Unit 10.3 wraps a BufferedReader around a FileReader to get readLine(). Each wrapper adds what the other lacks.

And it satisfies part i for free. FileWriter creates the file if it does not exist, in either mode. So "create students.txt if it does not exist" needs no if, no File.exists(), no check at all: opening it in append mode does both jobs.

MEMORY HOOK: the flag is on the writer that touches the disk. PrintWriter only formats; FileWriter opens the file, so the mode is its business.

The dots are the marks. %-8s means: a String, left aligned, padded to 8 columns, and you can count the padding: "Name" plus four dots, "Lilian" plus two. The minus sign is what makes it left aligned; drop it and every column is pushed right and the table goes ragged. %-6.2f is the same idea for a double, fixed at 2 decimal places, which is why 3.75 prints as 3.75 and not 3.8. Unit 3.11.

Those trailing dots are real spaces, sitting at the end of every line. printf pads the last column just as faithfully as the others, because it cannot know it is last. Harmless in a text file, and worth knowing before you go looking for why two files that "look identical" are not.
