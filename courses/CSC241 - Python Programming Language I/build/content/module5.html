Module Five · Unit 1

Python and Databases

A file holds data. A database organises it, so you can ask questions of it.

By the end of this unit you can: say what a database is and why it is used, explain what sqlite3 does, name the three SQL commands this course wants, and write the contact program it sets.

What a database is

Must memoriseAsked in these words

A database is an organised collection of data, stored so that it can be searched, changed and retrieved efficiently. Data lives in tables: a table has named columns, and each row is one record.

Why it is used in programming, which is the second half of the question:

  • It lasts. Like a file, the data outlives the program.
  • It can be searched. Ask for one record out of a million without reading the other 999,999. A text file makes you read the lot.
  • It has structure. Columns have types, so a score cannot quietly become text.
  • It handles many users at once without them overwriting each other.
  • It keeps data consistent, through rules such as a primary key that forbid nonsense.

Compare with Module Four's students.txt: to find one student there you read every line and split every one. In a database you ask for that student.

Must memoriseWhat sqlite3 is

SQL (say "sequel", or spell it out) is the language you ask a database questions in. It is not Python. You write it as a string inside your Python and hand it over to be run.

SQLite is a small database that keeps everything in a single ordinary file on your disk. There is no server to install and no password.

sqlite3 is the Python module that lets your program talk to an SQLite database. It ships with Python, so there is nothing to install: it is part of the standard library from Module Four, Unit 2.

That is the answer to "what role does the sqlite3 module play in Python": it is the built in interface between your Python code and an SQLite database file, letting you create tables, insert rows, and query them from Python.

The three SQL commands

Must memoriseName these three
CommandFunctionExample
CREATE TABLEMakes a new table and names its columnsCREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT)
INSERT INTOAdds a row of dataINSERT INTO students (name) VALUES ('Ada')
SELECTFetches rows back outSELECT * FROM students

Two more are worth a sentence each, in case the question asks for more than three: UPDATE changes rows that already exist, and DELETE removes rows.

SQL keywords are conventionally written in capitals. It is not required, but it is what a marker expects. The * in SELECT * means "every column".

TeachColumn types and the primary key

In CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT), each column is a name then a type:

  • INTEGER whole numbers, TEXT for text, REAL for decimals.
  • PRIMARY KEY marks the column that identifies a row uniquely. Declared as INTEGER PRIMARY KEY, SQLite fills it in for you, counting up, so you never supply an id yourself.

That is why the example inserts only the name: INSERT INTO students (name) VALUES ('Ada') names the one column it is supplying, and id appears by itself.

The five steps

Must memoriseEvery database program

Every program in this unit is the same five steps:

import sqlite3

conn = sqlite3.connect("school.db")   # 1 connect (creates the file if absent)
cursor = conn.cursor()                # 2 get a cursor
cursor.execute("...")               # 3 run SQL
conn.commit()                         # 4 save the changes
conn.close()                          # 5 disconnect

What each one is, since the question may ask:

  • connect opens the database file, and creates it if it does not exist. It never fails for a missing file, unlike open in read mode.
  • A cursor is the object you actually run SQL through and read results back from. Think of it as the hand that reaches into the database.
  • execute runs one SQL statement, given as a string.
  • commit makes your changes permanent. Without it, your inserts are thrown away when the program ends. No error, no warning, no data.
  • close ends the connection.
TrapThis exact code has been set

Meant to create a table named students. Find the errors:

import sqlite3
conn = sqlite3.connect("school.db")
cursor = conn.cursor
cursor.execute("CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT)")
conn.commit
conn.close()

Two errors, and both are missing brackets. Exactly the file.close bug from Module Four, wearing a different hat.

  • conn.cursor without () does not call the method. It hands you the method itself, so cursor is not a cursor at all. The next line then fails.
  • conn.commit without () does nothing at all, silently. The table is never saved.

Only the first one speaks up:

Traceback (most recent call last):
  File "C:\Users\you\db.py", line 4, in <module>
    cursor.execute("CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT)")
AttributeError: 'builtin_function_or_method' object has no attribute 'execute'

Read that message closely, because it names the bug precisely: the thing you called cursor is a method, not a cursor, and methods have no execute. Corrected:

import sqlite3
conn = sqlite3.connect("school.db")
cursor = conn.cursor()
cursor.execute("CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT)")
conn.commit()
conn.close()

Watch out: run that corrected version twice and the second run fails, because the table already exists. See the next box.

Must memoriseIF NOT EXISTS

Creating a table that is already there is an error:

sqlite3.OperationalError: table students already exists

Since connect keeps the file between runs, this bites the second time you run any program that creates a table. The fix is to say so in the SQL:

cursor.execute("CREATE TABLE IF NOT EXISTS students (id INTEGER PRIMARY KEY, name TEXT)")

Now it creates the table the first time and quietly does nothing afterwards. The examination asks for a table "if it doesn't already exist" in as many words, so IF NOT EXISTS is the phrase that earns the mark.

TeachWhat this code does, and its assumptions

A question shows this and asks three things: explain it, say what happens when it runs, and state what must be true for it to succeed.

import sqlite3
conn = sqlite3.connect("school.db")
cursor = conn.cursor()
cursor.execute("INSERT INTO students (name) VALUES ('Ada')")
conn.commit()
conn.close()

What it does: connects to school.db, creating the file if absent; gets a cursor; adds one row to the students table with the name Ada, letting id fill itself; saves the change; closes.

What happens when it runs: nothing appears on screen. It is not a SELECT, so there is nothing to display. If it works you see no output at all, which is the correct answer and an easy mark to miss.

What must be true for it to succeed:

  • The students table must already exist, with a name column. This code never creates it, so if the table is absent you get sqlite3.OperationalError: no such table: students.
  • id must fill itself, i.e. be an INTEGER PRIMARY KEY, since no id is supplied.
  • The file must be writable.

The single quotes around 'Ada' are SQL's quotes, inside Python's double quotes. Two languages, one line.

Reading rows back

Must memoriseSELECT and fetchall

execute runs the SELECT, but it does not hand you the rows. You fetch them from the cursor:

cursor.execute("SELECT * FROM students")
rows = cursor.fetchall()
for row in rows:
    print(row)
(1, 'Ada')
(2, 'Bola')

Each row comes back as a tuple, in the column order of the table. So row[0] is the id and row[1] is the name, and the round brackets in that output are Python showing you tuples, from Module Three, Unit 3.

fetchall() gives every row as a list of tuples. fetchone() gives just the next row, or None when there are none left.

A SELECT needs no commit, because it changes nothing.

Must memoriseThe ? placeholder

Everything so far put fixed text in the SQL. Real data comes from variables, and there is a right way and a wrong way.

Right: a question mark for each value, and a tuple of the values.

cursor.execute("INSERT INTO contacts (name, phone) VALUES (?, ?)", (name, phone))

Wrong: building the SQL by joining strings.

sql = "INSERT INTO contacts (name, phone) VALUES ('" + name + "', '" + phone + "')"
cursor.execute(sql)

The joined version breaks the moment a name contains an apostrophe, which ends the SQL string early and leaves nonsense behind. A name like O'Brien is enough to do it. It is also how databases get attacked, by typing SQL into a name box.

The placeholder is a question mark, not a format specifier. Do not use an f-string here. And note the comma inside (name,) if you have only one value: without it, it is not a tuple.

WorkedThe question this course sets

A contact manager. Create contacts.db with a table contacts (id, name, phone), read three contacts from the user, insert each, then commit and close.

  1. Connect and get a cursor. connect creates contacts.db if it is absent
  2. Create the table if it does not already exist. The question says those words, so use IF NOT EXISTS.
  3. Loop three times with range(3), reading name and phone. phone stays TEXT: numbers can start with 0
  4. Insert with placeholders, then commit once at the end and close.
contacts.py
import sqlite3

conn = sqlite3.connect("contacts.db")
cursor = conn.cursor()

cursor.execute("""CREATE TABLE IF NOT EXISTS contacts
                  (id INTEGER PRIMARY KEY, name TEXT, phone TEXT)""")

for i in range(3):
    name = input("Name: ")
    phone = input("Phone: ")
    cursor.execute("INSERT INTO contacts (name, phone) VALUES (?, ?)", (name, phone))

conn.commit()
conn.close()
print("Contacts saved.")

Entering Ada 08011112222, Bola 08033334444, John 08055556666:

Contacts saved.

The triple quoted string """...""" lets a long piece of SQL run across two lines without fuss. It is an ordinary string, just one that may contain newlines.

Why phone is TEXT and not INTEGER: a phone number starting with 0 would lose that 0 as a number, and nobody ever adds two phone numbers together. Storing it as text is the correct choice, and saying so earns the mark.

WorkedPart (e): any number, then show them

The extension: accept contacts until the user types 'done' as the name, then fetch and display everything in the table. Sentinel loop from Module Three, plus SELECT.

contacts_any.py
import sqlite3

conn = sqlite3.connect("contacts.db")
cursor = conn.cursor()
cursor.execute("""CREATE TABLE IF NOT EXISTS contacts
                  (id INTEGER PRIMARY KEY, name TEXT, phone TEXT)""")

while True:
    name = input("Name (or 'done'): ")
    if name == "done":
        break
    phone = input("Phone: ")
    cursor.execute("INSERT INTO contacts (name, phone) VALUES (?, ?)", (name, phone))

conn.commit()

cursor.execute("SELECT * FROM contacts")
for row in cursor.fetchall():
    print(f"{row[0]} | {row[1]} | {row[2]}")

conn.close()

Entering Ada 08011112222, then Bola 08033334444, then done:

1 | Ada | 08011112222
2 | Bola | 08033334444

Commit before you select. It happens to work without it here, but the habit is what keeps the marks, and the question asks for the changes to be saved.

Now you try: run it a second time and add John. What ids do you see? (1, 2 and 3. The file persists, so the old rows are still there and the new one continues the count. If you expected to see only John, you have just learned what "it lasts" means.)

Module Five · Unit 2

Python GUI Programming

Putting a window, a box and a button on the front of a program.

By the end of this unit you can: say what a GUI is, build a window with a label, an entry and a button, and wire the button to a function.

Teach

A GUI is a Graphical User Interface: windows, buttons and boxes, rather than typing at a prompt. The opposite is the command line interface, which is everything you have written so far.

tkinter is Python's built in GUI module. Like sqlite3, it ships with Python.

A GUI program is inside out compared with everything so far. A normal program runs top to bottom and ends. A GUI program builds its window, then waits, and things happen only when the user does something. That waiting is a loop, and you start it yourself.

Must memoriseThe four widgets
WidgetIsMade with
WindowThe window itselftk.Tk()
LabelText the user readstk.Label(window, text="...")
EntryA box the user types intk.Entry(window)
ButtonSomething to clicktk.Button(window, text="...", command=fn)

Every widget must be placed before it appears. .pack() is the simplest way: it stacks widgets down the window in the order you pack them. Create it and forget to pack it, and it simply is not there.

Must memorisecommand takes the name, not the call

A button is told which function to run when clicked:

tk.Button(window, text="Go", command=convert)

command=convert, not command=convert(). With brackets you would call it now, at the moment the button is built, and hand its return value to command. The button would then do nothing when clicked, and the work would have happened once, before the window even appeared.

Same rule as file.close against file.close() in Module Four, and conn.cursor against conn.cursor() in this module. Brackets mean "do it now". No brackets means "the thing itself". Here you want the thing itself, because the button will do it later.

WorkedThe question this course sets

A window that converts Celsius to Fahrenheit. The formula is F = C × 9/5 + 32.

  1. Import tkinter, conventionally shortened to tk, and make the window.
  2. Define what the button will do. It reads the entry with .get(), which hands back a string, exactly like input. Convert it. float(entry.get())
  3. Show the answer by changing the label's text with .config(text=...).
  4. Pack every widget, then start the wait with mainloop().
converter.py
import tkinter as tk

window = tk.Tk()
window.title("Celsius to Fahrenheit")

label = tk.Label(window, text="Celsius:")
entry = tk.Entry(window)
result = tk.Label(window, text="")

def convert():
    celsius = float(entry.get())
    fahrenheit = celsius * 9 / 5 + 32
    result.config(text=f"{fahrenheit:.1f} F")

button = tk.Button(window, text="Convert", command=convert)

label.pack()
entry.pack()
button.pack()
result.pack()

window.mainloop()

Type 100 and click Convert, and the bottom label reads:

212.0 F

mainloop() is the line people forget. Without it the program builds the window, reaches the end, and exits. The window flashes up and vanishes, or never appears at all. It must be the last line.

Now you try: what does 37 give? (98.6 F. Worth knowing: it is body temperature, so it is an easy check that your formula is the right way round.)

Trapget() gives a string

entry.get() hands back a string, always, exactly like input() in Module Two. Forget to convert and

celsius = entry.get()
fahrenheit = celsius * 9 / 5 + 32

fails with

TypeError: unsupported operand type(s) for /: 'str' and 'int'

Read where that error actually lands, because it is instructive. celsius * 9 does not fail: "100" * 9 is a perfectly legal string repeated nine times, giving "100100100100100100100100100". It is the / 5 on the next step that has nowhere to go, because you cannot divide text.

So the error names the division, several characters after the mistake. The line Python blames is not always the line you got wrong, and here the real fault is the missing float() one line earlier.

It is the 53 trap from Module Two wearing a window.
