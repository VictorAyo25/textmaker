Module Four · Unit 1

Functions in Python

Giving a piece of work a name, so you can ask for it by name.

By the end of this unit you can: define and call a function, explain parameters against arguments, use return, name the two types of user defined function, use default parameters, and say why functions matter.

What a function is

Teach

A function is a block of code with a name, which runs only when you ask for it. You have been using functions since page one: print, len, int and input are all functions.

Now you write your own.

def greet():
    print("Hello!")

greet()
Hello!

Two separate things happened, and keeping them apart matters:

  • Defining the function, with def. This only tells Python the name and the recipe. Nothing runs.
  • Calling the function, by writing its name with brackets. Now the block runs.

Define it once, call it as many times as you like. Delete the last line above and the program prints nothing at all, because a definition on its own does nothing.

Must memoriseWhy functions matter

Asked two ways in those words: "why are functions important in programming", and "list five benefits of modularizing a program with functions". Modularizing just means building the program out of functions, so these are the same list. Five reasons:

  • Reuse. Write it once, call it anywhere. No copying.
  • Readability. A name says what a block does, so the program reads as steps rather than detail.
  • Maintenance. Fix a bug in one place and every caller is fixed.
  • Decomposition. A large problem splits into small named pieces, each testable on its own.
  • Abstraction. A caller uses a function by knowing what it does, not how it does it, so the detail stays hidden and out of the way.

A sixth, if you need one: collaboration, since a team can split the functions between them and work in parallel.

Parameters and arguments

Must memoriseThe two words

A function can be handed values to work on.

def greet(name):        # name is a PARAMETER
    print("Hello,", name)

greet("Ada")            # "Ada" is an ARGUMENT
Hello, Ada

A parameter is the name in the definition. An argument is the value you pass in at the call. Same slot, two words, depending on which side you are standing on.

Several parameters are separated by commas, and the arguments line up with them by position:

>>> def add(a, b):
...     print(a + b)
...
>>> add(2, 3)
5

return

Must memoriseThe two types of function

This is asked in those words: explain the two types of user defined function.

1. A void function does something and hands nothing back. It has no return.

def greet(name):
    print("Hello,", name)

2. A value returning function works something out and hands it back with return.

def square(x):
    return x * x

The difference is what you can do with the call. A value returning function's call is a value, so it can go anywhere a value can:

>>> def square(x):
...     return x * x
...
>>> square(4)
16
>>> y = square(4) + 1
>>> y
17
Trapprint is not return

These look alike and are not alike at all.

>>> def shout(x):
...     print(x * 2)
...
>>> result = shout(5)
10
>>> print(result)
None

shout displayed 10, then handed back nothing. So result is None.

A function with no return returns None. Always. print shows a value to a human; return gives a value back to the program. If a question says "returns Healthy", it means return, and print will not earn the mark.

Also: return ends the function at once. Anything written after it in the same block never runs.

Meant to define a function that squares a number and call it. Find the errors:

def square(x)
    return x * x

Two errors, and you only ever hear about the first:

  • No colon after def square(x). This is a SyntaxError, caught while reading the file, so nothing runs.
  • Square with a capital S does not exist. The function is square. Names are case sensitive.

Fix the colon and run again, and only then do you meet the second:

Traceback (most recent call last):
  File "C:\Users\you\sq.py", line 3, in <module>
    print(Square(4))
          ^^^^^^
NameError: name 'Square' is not defined. Did you mean: 'square'?

That is the syntax before runtime rule from Module Two doing exactly what it promised. The corrected program:

def square(x):
    return x * x

print(square(4))
16

Default parameters

Must memoriseThis exact code has been set

A parameter may be given a value to fall back on, used when the caller does not supply one.

>>> def greet(name="Guest"):
...     print("Hello,", name)
...
>>> greet()
Hello, Guest
>>> greet("Ada")
Hello, Ada

Called empty, name takes its default. Called with an argument, the argument wins. Note the comma and space in the output: that is print putting one space between its two items, not part of the string.

The rule: parameters with defaults must come after those without. Writing def f(a=1, b) is a SyntaxError, because Python could not tell what a single argument was meant to fill.

WorkedThe question this course sets

Define is_healthy(bmi) returning "Healthy" if the BMI is between 18.5 and 24.9, and "Unhealthy" otherwise. Read three patients and display each result as Patient: John | BMI: 22.4 | Status: Healthy.

  1. Return, do not print. The question says "returns", so the function hands the word back and the caller displays it. return "Healthy"
  2. The range test is a chained comparison, from Module Two, Unit 3. 18.5 <= bmi <= 24.9
  3. Loop three times with range(3), reading a name and a BMI each pass. BMI is a decimal, so convert with float, not int.
  4. Display with an f-string. The vertical bars are literal text.

Now you try: what does is_healthy(24.95) return, and why is that worth thinking about? ("Unhealthy", because 24.95 is above 24.9. The question's own boundary is 24.9, so anything between 24.9 and 25 is Unhealthy. Say the boundary you used and you cannot be marked wrong.)

Must memoriseExtending to any number: part (e)

The follow up asks for any number of patients, stopping at 'done'. That is the sentinel loop from Module Three, wrapped around the same function:

def is_healthy(bmi):
    if 18.5 <= bmi <= 24.9:
        return "Healthy"
    else:
        return "Unhealthy"

healthy = 0
total = 0
while True:
    name = input("Patient name (or 'done'): ")
    if name == "done":
        break
    bmi = float(input("BMI: "))
    status = is_healthy(bmi)
    total += 1
    if status == "Healthy":
        healthy += 1
    print(f"Patient: {name} | BMI: {bmi} | Status: {status}")

print(f"Total: {total}, Healthy: {healthy}, Unhealthy: {total - healthy}")

The function did not change at all. Only the loop around it did. That is the point of a function, and it is the point of part (e).

Module Four · Unit 2

Modules and Packages

Using code somebody else already wrote.

By the end of this unit you can: import a module, use the two import forms, and name the modules this course uses.

Must memoriseModule, package, library
  • A module is a single file of Python code you can use from your own.
  • A package is a folder of modules grouped together.
  • The standard library is the large set of modules that ships with Python. Nothing to install; it is already there.

You use a module by importing it, and there are two forms:

>>> import math
>>> math.sqrt(16)
4.0
>>> from math import sqrt
>>> sqrt(16)
4.0

import math brings in the whole module, and you reach into it with a dot. from math import sqrt brings in that one name, which you then use bare. Both give 4.0, a float, because sqrt always returns a float.

Module Four · Unit 3

File Handling in Python

Making data survive the program. Everything you have stored so far vanished the moment the program ended.

By the end of this unit you can: name the four access modes, open, write, read and close a file, explain reading against appending, use with, and write the record keeping programs this course sets.

The three steps

Must memoriseAsked in these words

Using a file is always three steps, and the question "state the three steps of file use" wants exactly these:

  1. Open the file, which connects your program to it and says what you intend to do.
  2. Process it: read from it, or write to it.
  3. Close it, which finishes the job and makes sure everything you wrote is actually saved.
Must memoriseThe four access modes

open takes the file name and the mode, a short string saying what you intend.

ModeNameIf the file existsIf it does not
"r"ReadReads it. Cannot write.FileNotFoundError
"w"WriteErases it completely, then writesCreates it
"a"AppendAdds to the end, keeps what is thereCreates it
"x"Exclusive createFileExistsErrorCreates it

"r" is the default, so open("f.txt") means read.

Must memoriseReading against appending

Asked directly. Give the pair:

  • Reading ("r") takes data out of the file and changes nothing. The file must already exist.
  • Appending ("a") puts data into the file, at the end, keeping everything already there. It creates the file if needed.

And the distinction that actually loses data: "w" erases the whole file the moment you open it, before you write a single character. If you meant to add to a file and opened it with "w", everything in it is already gone. "a" is the one that adds.

Writing

Teach
f = open("note.txt", "w")
f.write("This is a note.")
f.close()

Two things surprise people about write:

  • It adds no newline. print does; write does not. Two writes in a row land on the same line unless you put \n in yourself.
  • It only writes strings. Passing a number is a TypeError, so convert with str() first.
f = open("names.txt", "w")
f.write("Ada\n")
f.write("Bola\n")
f.close()

gives a file holding two lines. Without the \n it would hold AdaBola on one line.

TrapThis exact code has been set

Meant to write a message to note.txt. Find the errors:

file = open("note.txt", "w")
file.write("This is a note."
file.close

Two errors, and the first hides the second:

  • The write line is missing its closing bracket. That is a SyntaxError, so the file never runs.
  • file.close has no brackets, so it is not a call. It names the method and throws it away, doing nothing. The file is never closed.

The second is the nastier one, because it is silent: no error, no message, and possibly no data in the file. Fixed:

file = open("note.txt", "w")
file.write("This is a note.")
file.close()

Brackets mean "do it". No brackets means "the thing itself". The same rule catches conn.cursor against conn.cursor() in Module Five.

with

Must memoriseThe safe way

Forgetting close() is easy, and a crash between opening and closing skips it entirely. with closes the file for you, whatever happens.

with open("example.txt", "a") as f:
    f.write("New line added.\n")

print("Done writing.")
Done writing.

Read it as: open the file, call it f, and when the indented block ends close it automatically. There is no close() to write and none to forget.

What this code does, if asked: it opens example.txt in append mode, creating it if absent; adds one line to the end without disturbing what is already there; closes it; then prints Done writing. to the screen. Note that only "Done writing." appears on screen. The written line went into the file, not to the display.

Reading

Must memoriseThree ways to read

Given a names.txt holding Ada and Bola on two lines:

MethodGivesResult here
f.read()The whole file as one string'Ada\nBola\n'
f.readline()The next line only, as a string'Ada\n'
f.readlines()A list of all lines['Ada\n', 'Bola\n']

The usual way is to loop over the file directly, which gives one line at a time and does not load a large file into memory at once:

with open("names.txt") as f:
    for line in f:
        print(line.strip())
Ada
Bola

Every line you read keeps its \n on the end. That is why strip() is there: without it you would print a blank line after each name, because the line's own newline and print's newline both land.

WorkedThe question this course sets

Store student records (name and score) until 'done' is entered, in students.txt, one per line as Name, Score. Then read it back, print each record, and count passes and fails. The pass mark is 45 and above.

  1. Sentinel loop to collect, writing as you go. Mode "w" because we are creating the file fresh. Test for 'done' before asking for the score
  2. write needs a string and adds no newline, so build the line with an f-string and put \n on the end yourself.
  3. Close, then reopen in "r". The question asks for this explicitly.
  4. Split each line at the comma, convert the score, count. 45 and above passes
students.py
with open("students.txt", "w") as f:
    while True:
        name = input("Name (or 'done'): ")
        if name == "done":
            break
        score = int(input("Score: "))
        f.write(f"{name}, {score}\n")

passes = 0
fails = 0
with open("students.txt", "r") as f:
    for line in f:
        name, score = line.strip().split(", ")
        score = int(score)
        print(f"{name} scored {score}")
        if score >= 45:
            passes += 1
        else:
            fails += 1

print(f"Passes: {passes}, Fails: {fails}")

Entering John 76, Ada 45, Bola 30, then done:

John scored 76
Ada scored 45
Bola scored 30
Passes: 2, Fails: 1

Ada passes. The mark is 45 and above, so the test is >=, not >. Getting that boundary wrong is the difference between 2 passes and 1.

Module Four · Unit 4

Exception Handling

Catching a runtime error instead of letting it kill the program.

By the end of this unit you can: explain what an exception is, use try and except, catch the right error, and use finally.

Teach

An exception is a runtime error, in the Module Two sense: the line was grammatically fine, but doing it turned out to be impossible. Unhandled, it prints a traceback and the program stops dead.

You met this one already:

>>> int("xyz")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'xyz'

In a program that asks the user for a number, that is not a bug in your code. It is a user typing badly. The program should say so and carry on, not crash.

Must memorisetry and except
try:
    age = int(input("Your age: "))
    print("Next year you are", age + 1)
except ValueError:
    print("That is not a whole number.")

Run it and type xyz:

Your age: xyz
That is not a whole number.

No traceback, no crash. How it works:

  • Python runs the try block.
  • If nothing goes wrong, the except block is skipped entirely.
  • If a ValueError happens, Python abandons the rest of the try block at once and runs the except block instead.

Note the second line inside the try never ran. That is why the block should hold only the risky work and what depends on it.

Every one of these has appeared in this manual before this page. That is the point of the table: you have met them all as accidents, and now you can catch them on purpose.

TrapDo not catch everything

A bare except: catches every error there is, including the ones caused by your own bugs, and hides them:

try:
    age = int(input("Age: "))
except:
    print("Something went wrong.")

Misspell a name inside that try and you get "Something went wrong" instead of a NameError telling you exactly which line and which name. You have thrown away the most useful message on the screen.

Name the exception you expect. except ValueError: catches bad input and leaves your own mistakes visible.

WorkedInput that will not crash

The exam's programs all begin by reading a number. Combining this unit with the loops from Module Three gives input that cannot be broken:

while True:
    try:
        n = int(input("Enter a whole number: "))
        break
    except ValueError:
        print("Not a whole number. Try again.")

print("You entered", n)

Typing xyz, then 3.5, then 7:

Enter a whole number: xyz
Not a whole number. Try again.
Enter a whole number: 3.5
Not a whole number. Try again.
Enter a whole number: 7
You entered 7

The break is inside the try, after the conversion. So it is only reached when the conversion worked. Put it after the try block and the loop would exit even on bad input.

Note 3.5 is rejected: int() only accepts a whole number written out, as Module Two, Unit 2 showed.

Must memoriseelse and finally

Two optional extras complete the shape:

  • else runs only if no exception happened. Same idea as the loop else from Module Three: "if nothing interrupted".
  • finally runs always, exception or not. It is for cleaning up.
try:
    f = open("data.txt")
except FileNotFoundError:
    print("No such file.")
else:
    print("Opened it.")
    f.close()
finally:
    print("Finished trying.")

With no data.txt present:

No such file.
Finished trying.

finally is what with does for you automatically, which is why with is preferred for files.
