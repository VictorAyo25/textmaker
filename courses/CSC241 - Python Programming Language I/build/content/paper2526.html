Question One

AnswerQ1 (a) the and operator, 2.5 marks

and is a boolean operator. It joins two conditions and is true only when both are true. If either side is false, the whole thing is false.

LeftRightleft and right
TrueTrueTrue
TrueFalseFalse
FalseTrueFalse
FalseFalseFalse

The example the marker wants is a range check:

>>> score = 72
>>> score >= 0 and score <= 100
True

Both sides hold, so the score is valid. Change score to 150 and the right side fails, so the whole test is False. and also short-circuits: if the left is false, Python never even looks at the right, because the answer is already settled.

AnswerQ1 (b) strings and four methods, 5 marks

A string is an ordered sequence of characters, written in quotes. It is immutable: its characters cannot be changed in place. Four common methods, one example each:

MethodDoesExampleGives
upper()Capitals"hi".upper()'HI'
lower()Lower case"Hi".lower()'hi'

Each returns a new string, because the original cannot change. Others you know and could name instead: split(), count(), find(), title(). See Module Two, Unit Four for all of them.

AnswerQ1 (c) the dictionary errors, 3 marks

The dictionary defines its keys as 'name', 'age', 'city' and 'Email'. Every access then uses the wrong case, and a dictionary key is case sensitive, so each is a KeyError. Python stops at the first one it reaches:

Traceback (most recent call last):
  File "person.py", line 4, in <module>
    print("Name:", person['Name'])
KeyError: 'Name'

The full list of faults, so you earn every mark:

  • person['Name'], person['Age'], person['City']: the keys are lower case. Three KeyErrors.
  • person['email'] on line 7 and del person['email'] on line 11: the key is 'Email' with a capital E.
  • person['Age'] = "35" does not raise, but it creates a new key 'Age' beside the real 'age', rather than updating the age. A silent logic error.

Corrected so the case matches throughout, this is what it prints:

AnswerQ1 (d) BMI, 3.5 marks

H^2 in the question is H ** 2 in Python: ** is the power operator from Module Two, not ^, which is something else entirely. Read the two values, compute, then classify with if/elif.

bmi.py
weight = float(input("Weight (kg): "))
height = float(input("Height (m): "))

bmi = weight / height ** 2

if bmi < 18.5:
    category = "Underweight"
elif bmi < 25:
    category = "Normal weight"
elif bmi < 30:
    category = "Overweight"
else:
    category = "Obese"

print(f"BMI = {bmi:.2f}")
print("Class:", category)

For a 72 kg person 1.75 m tall:

BMI = 23.51
Class: Normal weight

The elif ladder needs no upper bound on each rung: by the time you reach elif bmi < 25, the first if has already ruled out everything below 18.5, so < 25 alone means the 18.5 to 25 band. That is the whole economy of elif.

AnswerQ1 (e) compound interest, 3.5 marks

The formula A = P(1 + r/n)^(nt) is one line once you use ** for the power and brackets for the exponent, so the whole n*t is the power:

interest.py
P = float(input("Principal: "))
r = float(input("Annual rate (decimal): "))
n = int(input("Times compounded per year: "))
t = int(input("Years: "))

A = P * (1 + r / n) ** (n * t)

print(f"Future value (A): {A:.2f}")
print(f"Interest earned: {A - P:.2f}")

For 100000 at 0.05, compounded 4 times a year for 3 years:

Future value (A): 116075.45
Interest earned: 16075.45

The :.2f rounds to two decimal places for display only. The mark hinges on the brackets: ** (n * t), not ** n * t, which would raise to the power n and only then multiply by t, a different and wrong number.

Question Two

AnswerQ2 (a) count-controlled loop, 3.5 marks

A count-controlled loop runs a known, fixed number of times, once per item in a sequence. In Python it is the for loop with range. You use it when you know how many passes you need before the loop starts.

for i in range(5):
    print(i)

It contrasts with a condition-controlled loop (while), which runs an unknown number of times, until a condition turns false. Count-controlled: "do this five times". Condition-controlled: "do this until the user types done".

AnswerQ2 (b) control structures, 4.5 marks

There are three kinds of control structure, and the answer names all three with an example each:

  • Sequence: statements run top to bottom, in order. The default. a = 2; b = 3; print(a + b)
  • Selection: a choice, with if/elif/else. if score >= 50: print("Pass")
  • Repetition: doing something many times, with for or while. for i in range(3): print(i)

The difference is what decides the flow: sequence has no decision, selection runs a block or skips it once, repetition runs a block again and again.

Question Three

AnswerQ3 (a) five benefits, 2.5 marks

Five benefits of modularizing a program with functions, which is building it out of named pieces:

  1. Reuse: write it once, call it anywhere, no copying.
  2. Readability: a name says what a block does.
  3. Maintenance: fix a bug in one place and every caller is fixed.
  4. Decomposition: a large problem splits into small, testable pieces.
  5. Abstraction: a caller uses a function knowing what it does, not how.

Module Four, Unit One carries the same list under "why functions matter".

AnswerQ3 (b) functions, built-in vs user-defined, 6 marks

A function is a named block of code that runs only when you call it. They matter for the five reasons above. The two kinds:

Who wrote itComes with PythonYou did, with def

Examplesprint, len, inputcube, grade_of

print("hi") calls a built-in; after def cube(n): return n*n*n you call your own with cube(4).

AnswerQ3 (c) list1 and list2, 3 marks
list1 = [1, 2] * 2
list2 = [3]
list2 += list1
  • [1, 2] * 2 repeats the list, so list1 is [1, 2, 1, 2], not [2, 4].
  • list2 += list1 extends list2 in place, tacking on every item of list1.
list1 = [1, 2, 1, 2]
list2 = [3, 1, 2, 1, 2]

The trap is reading * as multiply-the-numbers. On a list it repeats. See Module Three, Unit Three.

Question Four

AnswerQ4 (a) strings are immutable

Immutable means a string cannot be changed after it is made. Trying to change one character is an error:

>>> s = "cat"
>>> s[0] = "b"
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: 'str' object does not support item assignment

The reason: every method that "changes" a string, like upper() or replace(), actually returns a new string and leaves the original untouched. To "edit" a string you build a new one and reassign it: s = s.replace("c", "b"). A list, by contrast, is mutable and does allow list[0] = "b".

AnswerQ4 (b) the cube function, 1 + 1 marks

(i) A statement that passes 4 and stores the result:

result = cube(4)

(ii) cube(4) returns 4 * 4 * 4, so:

result = 64

The call cube(4) is a value, because cube returns one, so it can sit on the right of an =. That is a value-returning function from Module Four.

AnswerQ4 (c) the SQLite program, 10.5 marks

The biggest single part on the paper, and it walks through the whole of Module Five, Unit One plus the new WHERE, UPDATE, DELETE and summary functions. Take the seven requirements in order.

school.py
import sqlite3

conn = sqlite3.connect("school.db")
cursor = conn.cursor()

# i. create the table if it is not there
cursor.execute("""CREATE TABLE IF NOT EXISTS student
                  (StudentID INTEGER PRIMARY KEY, StudentName TEXT,
                   Class TEXT, Score REAL)""")

# ii. insert the given records
records = [(101, "David James", "SS1", 78),
           (102, "Mary Johnson", "SS2", 85),
           (103, "Peter Okoro", "SS1", 67),
           (104, "Grace Bello", "SS3", 92),
           (105, "Esther Ade", "SS2", 74)]
cursor.executemany("INSERT INTO student VALUES (?, ?, ?, ?)", records)
conn.commit()

# iii. all records
print("All students:")
cursor.execute("SELECT * FROM student")
for row in cursor.fetchall():
    print(row)

# iv. SS2 only
print("SS2 students:")
cursor.execute("SELECT * FROM student WHERE Class = ?", ("SS2",))
for row in cursor.fetchall():
    print(row)

# v. statistics in one query
cursor.execute("SELECT COUNT(*), MAX(Score), AVG(Score) FROM student")
total, highest, average = cursor.fetchone()
print("Total:", total, " Highest:", highest, " Average:", average)

# vi. update Peter's score
cursor.execute("UPDATE student SET Score = ? WHERE StudentName = ?",
               (75, "Peter Okoro"))
conn.commit()

# vii. delete student 105
cursor.execute("DELETE FROM student WHERE StudentID = ?", (105,))
conn.commit()

conn.close()

Five marks are in the details a rushed answer drops:

  • Scores print as 78.0, with a decimal, because the column is REAL.
  • Placeholders, not glued strings, for every value. ("SS2",) keeps its comma.
  • UPDATE and DELETE each commit. Forget the commit and the change is thrown away silently.
  • The statistics are one query. COUNT, MAX and AVG come back as a single row, unpacked into three names.

Question Five

AnswerQ5 (a) file handling, 2 marks

File handling is reading data from, and writing data to, a file on disk, so the data lasts after the program ends. Python does it with open(), the read and write methods, and close() (or a with block that closes for you). See Module Four, Unit Three.

AnswerQ5 (b) four file modes, 6 marks
ModeMeansIf the file existsIf it does not
"r"ReadReads itFileNotFoundError
"w"WriteErased firstCreated
"a"AppendAdds at the endCreated
"r+"Read and writeBoth, no eraseFileNotFoundError

The two that catch people: "w" destroys the existing contents the moment you open it, and "r" is the only common one that fails on a missing file.

AnswerQ5 (c) reading vs appending, 2 marks

Reading ("r") takes data out of a file and changes nothing. Appending ("a") adds new data to the end, keeping what is already there. Reading needs the file to exist; appending creates it if it does not. In short: one looks, the other adds without erasing.

AnswerQ5 (d) the CA records file, 7.5 marks

Write the first records with "w", add more with "a" so the first are kept, then read the whole file and just the first five. The same file name throughout, as the question insists.

ca_records.py
filename = "23CG012345_CSC241.txt"

with open(filename, "w") as f:
    for i in range(10):
        name = input("Name: ")
        matric = input("Matric No: ")
        dept = input("Department: ")
        score = input("Score: ")

# ii. 5 more, "a" keeps the first ten
with open(filename, "a") as f:
    for i in range(5):
        name = input("Name: ")
        matric = input("Matric No: ")
        dept = input("Department: ")
        score = input("Score: ")
        f.write(f"Name: {name}, Matric No: {matric}, "
                f"Department: {dept}, Score: {score}\n")

# iii. read and show all
print("All records:")
with open(filename, "r") as f:
    for line in f:
        print(line.strip())

with open(filename, "r") as f:
    for i, line in enumerate(f):

The marks live in the modes: "w" once at the start, then "a" so the append does not wipe the ten already written. If both used "w", the second open would erase the first ten before adding five, and you would end with five records, not fifteen. Reading the first five uses enumerate and break to stop early, from Module Three.

AnswerQ6 (b) the void function, 7 marks

A void function does the displaying and returns nothing. Read the inputs, sum the daily steps, work out the target, then hand three values to the function.

steps.py
def display_achievement_summary(user_name, actual_total, target_total):
    print(f"--- Progress Report for {user_name} ---")
    print("Total Steps:", actual_total)
    if actual_total >= target_total:
        print("Milestone Achieved!!")
    else:
        print("Milestone Not Achieved.")

name = input("Enter your name: ")
days = int(input("Enter the number of days to track: "))
goal = int(input("Enter your daily step goal: "))

total_steps = 0
for day in range(1, days + 1):
    steps = int(input(f"Enter steps for day {day}: "))
    total_steps += steps

target = goal * days
display_achievement_summary(name, total_steps, target)

For Alice, 3 days, a 10000 goal, and steps 12000, 9000, 11000:

--- Progress Report for Alice ---
Total Steps: 32000
Milestone Achieved!!

The target is 10000 * 3 = 30000, and 32000 clears it, so the milestone is achieved. The function prints and returns nothing, which is exactly what "void" means: it is called for its effect, not for a value.

AnswerQ6 (c) value-returning functions and math.pi, 7 marks

Three value-returning functions, each handing a value back, and math.pi for the area of the circle. This is the modular style the question demands.

flooring.py
import math

def get_data():
    radius = float(input("Enter room radius (meters): "))
    price = float(input("Enter flooring price per square meter: "))
    labor = float(input("Enter labor fee: "))
    return radius, price, labor

def calculate_area(radius):
    return math.pi * radius ** 2

def calculate_total(area, material_price, labor_fee):
    return area * material_price + labor_fee

radius, price, labor = get_data()
area = calculate_area(radius)
total_cost = calculate_total(area, price, labor)

print("--- Project Estimate ---")
print(f"Total Calculated Cost: {total_cost:.2f}")
if total_cost > 10000:
    print("Status: Requires Senior Management Approval.")
else:
    print("Status: Approval not required.")

For radius 12, price 20, labor 1500:

--- Project Estimate ---
Total Calculated Cost: 10547.79
Status: Requires Senior Management Approval.
TrapThe paper's own answer is wrong

The question sheet prints the sample cost as 10546.90. Run the arithmetic it asks for and you get 10547.79. The paper is wrong by 0.89, and it is worth seeing why, because the method is sound and only the printed figure is off.

>>> import math
>>> area = math.pi * 12 ** 2
>>> area
452.3893421169302
>>> area * 20 + 1500
10547.786842338604

Rounded to two places that is 10547.79. There is no radius, price or fee near the sheet's own sample that reaches 10546.90 with math.pi. Write the working, show the run, and state your figure. A marker who has run it will credit the correct number; one who has not still sees a fully justified method. This is the same discipline the whole book is built on: trust the run, not the printout, even when the printout is the examiner's.
