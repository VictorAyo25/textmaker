Before you start

How to use this manual

Read this page once. It is short, and it decides whether the rest of the manual works for you.

TeachThe bargain

This manual assumes you have never written a line of code, and it carries you from there to a full mark in the examination. It is also meant to be enough on its own. You should never need a lecturer, a website or the official documentation to follow it. Anything it uses, it teaches first.

In exchange it asks one thing: type the code. Reading code creates a feeling of understanding that disappears in the examination hall. Typing it, getting it wrong, and fixing it is the thing that actually teaches. Every code block here was run on a real interpreter before it was printed, so if yours does something different, the difference is information.

The boxes

Every page is built from a small set of boxes. Each has one job, and the colour tells you which before you read a word.

Teach

New ideas, explained from nothing. Read these properly.

Must memorise

Python yellow means learn this by heart. It is the only thing this colour is ever used for in this manual. Nothing decorative is yellow. If a page has yellow on it, there is something on that page you are expected to know cold.

Worked

A problem solved in numbered steps, then a now you try at the end. Do the "now you try" before moving on.

Dry run

A program traced by hand, one line at a time, with a table of what every variable holds. This examination asks you to state what code displays, and this is how you work it out without a computer. Dry run is the term used in this course.

Trap

A mistake that is easy to make and costly. Most of these are taken from the errors the examination itself plants in its code.

Recall

Questions with the answers printed underneath, below a dashed line. Cover the answers. Say your answer out loud, or write it, and only then look. Checking whether you knew something is not the same as knowing it, and the difference is the whole point of this box.

Reading the code

Must memoriseThree kinds of block

Code appears in three kinds of block, and confusing them is the most common early mistake. Each has a different coloured left edge.

1. The interactive prompt. Lines starting >>> are what you type. Lines without it are what Python printed back. You never type the >>> itself.

>>> 2 + 2
4

2. A script. The contents of a file, to be saved and run as a whole. No >>> anywhere.

print("saved in a file")

3. Output. What appeared on screen. You never type this.

saved in a file

Where a keystroke is meant rather than something to type, it is shown as a key: press Enter.

TeachOne promise about output

Every output shown in this manual was captured from a real Python 3.13 interpreter at the moment this page was built. None was typed by hand from memory. This matters more than it sounds: a printed output that was never actually run is just a confident guess, and where Python's real answer is surprising, a guess is exactly where it will be wrong. You will meet one such surprise in Module Two, Unit 2, and it is the reason for this promise.
