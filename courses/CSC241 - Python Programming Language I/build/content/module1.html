Overview of Python

Start here even if you have never written a line of code. This unit assumes nothing.

What a program is

TeachFrom zero

A computer does nothing on its own. It waits to be told, in exact terms, what to do. A program is that telling: an ordered list of instructions, written down, that the computer carries out one after another.

Think of a recipe. A recipe is not the cooking; it is the written instructions that produce the cooking when somebody follows them. A program is not the work; it is the written instructions that produce the work when the computer follows them.

Two words that follow from this, and that you will use constantly:

  • Code is the text you write. The instructions themselves.
  • Running (or executing) a program means telling the computer to carry out those instructions now, from the top, in order.
Anchor

A recipe written down is a program. It lists ingredients, which are the data, and steps in an order that matters, which are the instructions. Anyone who follows it exactly gets the same cake, and that is the whole idea: the cook does no thinking, and every decision was made by whoever wrote the recipe. A computer is a cook that follows a recipe perfectly and understands nothing.

Why we need a language

Teach

The computer's own vocabulary is numbers. Nothing else. Instructions inside the machine are patterns of the digits 0 and 1, called machine code. Writing anything useful directly in 0s and 1s is possible and unbearable.

So we write in a programming language instead: a fixed, small, precisely defined set of words and symbols that a human can read and that can be turned into machine code automatically. Python is one such language.

A programming language is deliberately far stricter than English. In English, "print hello" and "hello, print it" and "could you print hello" all land. A programming language accepts exactly one form and rejects the rest. That strictness is not the language being difficult. It is the reason the translation to machine code can be done without a human guessing at your intention.

Interpreter and compiler

Something must sit between your text and the machine's numbers. There are two ways to build that something, and the difference is examinable.

TeachExaminable

A compiler reads your whole program, translates all of it into machine code, and writes that machine code out as a new file. Nothing runs during translation. You run the produced file afterwards, and it runs on its own.

An interpreter reads your program one instruction at a time, and carries out each instruction as soon as it has read it. Nothing is written out. There is no separate file to run afterwards. Translation and running are the same activity.

Python is interpreted. The program that reads your Python and does what it says is called the Python interpreter, and installing Python (Unit 2) means installing it.

Marks are lost here by naming only one difference. The question asks you to differentiate, so give the pair each time: what it reads, and what it produces.

Trap

"Interpreted means Python has no errors until it runs" is half true and the half that is false costs marks. Python still checks that each line is grammatically possible before running anything in that file. A missing colon is caught immediately, before the first line executes. What waits until the line is reached is a meaning error, such as dividing by zero.

You will meet this split again as SyntaxError versus runtime error in Module Two, and it is worth marks on its own.

Key point

A compiler translates the whole program before any of it runs, so it finds faults up front. An interpreter translates and runs one statement at a time, so a fault on line 40 is only found when line 40 runs, and lines 1 to 39 have already had their effect.

Blunt version: a compiler reads the whole recipe first. An interpreter starts cooking, and it runs until it hits the mistake.

Why Python

Teach
  • It reads close to English. Fewer symbols stand between your intention and the page, so there is less to get wrong.
  • It is short. Work that takes many lines elsewhere often takes one here.
  • It comes with a large standard library: a big collection of ready made code that ships with Python, so common jobs are already solved. You will use one of these, sqlite3, in Module Five.
  • It is portable. The same Python file runs on Windows, macOS and Linux.
  • It is free and its interpreter is open source.

Module One · Unit 2

Setting Up Python

Do this once, on your own machine, before you read Module Two. Everything after here is meant to be typed, not watched.

By the end of this unit you can: install Python, confirm it installed, use the interactive prompt, write and run a script file, and say which of the two you are looking at.

Installing

TeachWindows
  1. Open python.org and choose Downloads. The site offers you the installer for the system you are on.
  2. Run the installer.
  3. Tick "Add Python to PATH" on the first screen. This is the one step that people skip and then cannot proceed. It is explained directly below.
  4. Choose "Install Now" and wait for it to finish.
Must memorisePATH

PATH is a list your operating system keeps of the folders it will search when you type a command. If Python's folder is not on that list, then typing python gets you "command not found", even though Python is installed perfectly well. The program is there; the system just does not know where to look.

If you have already installed without ticking it, run the installer again, choose Modify, and add it. You do not need to uninstall anything.

TeachmacOS and Linux

Both usually ship with a Python already, but often an old one. Install the current version from python.org in the same way. On Linux you may instead use your system's package manager, for example sudo apt install python3 on Ubuntu.

On macOS and Linux the command is often python3 rather than python. If python gives you an error or a version starting with 2, use python3 everywhere in this manual.

Confirming it worked

Teach

Open a terminal, the window where you type commands to your operating system rather than clicking. On Windows it is called Command Prompt or PowerShell; on macOS and Linux it is called Terminal. Type this and press Enter:

In the terminal, not in Python
python --version

It should answer with a version number:

Python 3.13.5

Your exact numbers will differ, and that is fine. Any version starting with 3 is fine. If it starts with 2, or you get "command not found", see the PATH box above, and try python3 --version.

TrapPython 2

If your version starts with 2, stop and fix it. Python 2 is a different language in small, silent ways. In Python 2, 5 / 2 is 2. In Python 3 it is 2.5. Nothing warns you; you simply get wrong answers. Every page of this manual is Python 3.

Key point

The interactive prompt evaluates what you type and DISPLAYS the result, which is why 2 + 3 shows 5 there. A script does not: an expression on its own line is computed and thrown away, so a script must call print() to show anything.

Blunt version: the prompt talks back, a script does not. If your file prints nothing, that is usually why.

The two ways to run Python

This is the distinction that confuses beginners more than any other, so it gets its own box. From here on, every code block in this manual is labelled as one or the other.

Must memorisePrompt vs script

1. The interactive prompt (also called the REPL, or interactive mode). You type one line, press Enter, and Python answers immediately. You recognise it by the three symbols >>> at the left, which Python prints to mean "your turn". It forgets everything when you close it.

2. A script. You type many lines into a file, save it with a name ending in .py, and run the whole file at once. It keeps everything, because it is a file.

The prompt is for asking. A script is for building. Your exam answers are scripts.

TeachThe prompt

Type python on its own in the terminal and press Enter. The prompt appears:

>>>

Now type an instruction and press Enter. Python answers on the next line, then offers you the prompt again:

>>> print("Hello, World!")
Hello, World!
>>>

To leave the prompt and return to the terminal, type exit() and press Enter.

Must memoriseReading transcripts

In every prompt transcript in this manual:

  • Lines beginning >>> are what you type. Do not type the >>> itself; Python prints that.
  • Lines with no >>> are what Python printed back.

So in the transcript above, you typed 21 characters and Python printed Hello, World!. Getting this backwards is the single most common early confusion, which is why the two are given different coloured edges throughout.

TeachA script

Open any plain text editor. Notepad works. So does IDLE, which was installed alongside Python: find it in your programs, then choose File, then New File.

Type these two lines:

hello.py
print("Hello, World!")
print("I am running from a file.")

Save it as hello.py. The .py ending is what marks a file as Python. Then, in the terminal, move to the folder you saved it in and type:

In the terminal
python hello.py

Python reads the file from the top, carries out each line in order, prints:

Hello, World!
I am running from a file.

and then exits. Notice there is no >>> anywhere: you are not having a conversation, you are handing over a finished list of instructions.

TrapCosts marks and hours

Typing python hello.py while already at the >>> prompt gives you a SyntaxError. Those are terminal commands, not Python instructions. They live in different places:

>>> python hello.py
  File "<stdin>", line 1
    python hello.py
           ^^^^^
SyntaxError: invalid syntax

If you see this, you are at the Python prompt when you meant to be at the terminal. Type exit() first.
