Three control structures, one example each

  • Sequence. Statements run one after another, top to bottom, with no choices. Example: a = 2 then b = a + 1.

AnswerQuestion Three (a)

What a function is: a named block of code that runs only when it is called. It may take values in and may hand a value back.

Why they matter: reuse (write once, call anywhere); readability (a name says what a block does); maintenance (fix a bug in one place); decomposition (a large problem splits into small testable pieces).

Built in against user defined: a built in function comes with Python and is always available (print, len, int, max). A user defined function is one you write with def, and it must be defined before it is called.

The two types of user defined function:

  • Void: does something and returns nothing. It has no return, so calling it gives None. Example: a function that only prints.
  • Value returning: works something out and hands it back with return, so the call can be used as a value.

Four things are asked here and each is worth roughly a quarter. Answer all four explicitly, with a heading for each if it helps you not to forget one.

Explanation

The one that catches everybody

ch.isalpha() is not optional. A consonant is a letter that is not a vowel. Without that test the spaces get counted, since a space is certainly not in "aeiou", and the answer comes out as 10 instead of 8.

Question Five

AnswerQuestion Five (a)

File handling is working with files on disk from a program, so that data survives after the program ends. It is always three steps: open, process, close.

ModeNameBehaviour
"r"ReadOpens for reading. Error if the file does not exist.
"w"WriteErases the file completely, then writes. Creates it if absent.
"a"AppendAdds to the end, keeping what is there. Creates it if absent.
"x"Exclusive createCreates it. Error if it already exists.

Reading against appending: reading takes data out of the file and changes nothing, and the file must already exist. Appending puts data into the file at the end, keeps everything already there, and creates the file if needed.

Worth adding, and it shows real understanding: the dangerous distinction is "w" against "a". Opening with "w" destroys the contents immediately, before you write anything.

AnswerQuestion Five (b)

The errors

  • The write line is missing its closing bracket. This is a SyntaxError, so nothing in the file runs.
  • f.close has no brackets, so it is not a call. It names the method and discards it. The file is never closed.

The first hides the second, and the second is the more dangerous, because it reports nothing at all: no error, no message, and possibly an empty file.

The fix

f = open("report.txt", "w")
f.write("Weekly Report")
f.close()

Better still, and worth saying:

with open("report.txt", "w") as f:
    f.write("Weekly Report")

with closes the file for you, so the second bug becomes impossible.

AnswerQuestion Six (b)

The issues

Both are missing brackets, and they behave very differently.

  • conn.cursor does not call the method, so cursor holds the method itself rather than a cursor. The next line then fails with AttributeError: 'builtin_function_or_method' object has no attribute 'execute'.
  • conn.commit does nothing at all, silently. The table would never be saved.

The fix

import sqlite3
conn = sqlite3.connect("library.db")
cursor = conn.cursor()
cursor.execute("CREATE TABLE IF NOT EXISTS books (id INTEGER PRIMARY KEY, title TEXT)")
conn.commit()
conn.close()

Worth the extra mark: add IF NOT EXISTS. Without it the fixed program works once and then fails on every later run with sqlite3.OperationalError: table books already exists, because connect keeps the file between runs.

AnswerQuestion Six (c)

i. What it does: connects to library.db, creating the file if it does not exist; gets a cursor; runs an INSERT adding one row to the books table with the title 'Things Fall Apart', letting id fill itself; commits, making the change permanent; and closes the connection.

ii. What happens when it runs: nothing is displayed at all. There is no print and no SELECT, so a successful run produces no output. One row is silently added to the table.

iii. The assumptions:

  • The books table must already exist, with a title column. This code never creates it, so without it you get sqlite3.OperationalError: no such table: books.
  • id must fill itself, that is, be declared INTEGER PRIMARY KEY, since no id is supplied.
  • The file must be writable, and the disk must have room.

Part ii is the easy mark most candidates miss. "No output" is the answer, and it is worth saying in those words.
