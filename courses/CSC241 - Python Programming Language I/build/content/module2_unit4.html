Working with Strings

Text, in depth. An entire question on your paper is nothing but this unit, so it earns the space.

By the end of this unit you can: index and slice a string, explain why a string cannot be changed, use every string method this course examines, and write the text analysis programs it sets.

A string is a sequence

Must memoriseIndexing and slicing

A string is a sequence of characters, and everything you learned about indexing a list in Module Three applies here unchanged. The first character is number 0.

>>> name = "Python"
>>> name[0]
'P'
>>> name[-1]
'n'
>>> name[0:3]
'Pyt'
>>> len(name)
6

Negative indexes count from the right. Slices exclude the stop. Same rules, same traps, and name[6] is an IndexError just as a list's would be.

Must memoriseStrings are immutable

A list can be changed in place. A string cannot. This property is called being immutable, and it is asked directly.

>>> name = "Python"
>>> name[0] = "J"
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: 'str' object does not support item assignment

Compare that message with the tuple's in Module Three: they are the same sentence with a different type name, because they are the same idea.

The consequence, and this is the important part: every string method that looks like it changes a string actually returns a new string and leaves the original untouched.

>>> name = "Python"
>>> name.upper()
'PYTHON'
>>> name
'Python'

name is unchanged. To keep the result you must catch it:

>>> name = name.upper()
>>> name
'PYTHON'

Calling name.upper() on its own line and expecting name to change is one of the most common errors in this course. It is the mirror image of the sort() trap from Module Three: a list method changes the list and returns None, a string method changes nothing and returns the answer.

Must memoriseindex vs find

They do the same job and fail differently, which is the whole reason both exist.

>>> "Ada".find("z")
-1
>>> "Ada".index("z")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: substring not found

find returns -1 when it is not there. index raises a ValueError. Use find when absence is normal, index when absence means something has gone wrong.

Must memorisesplit, with and without an argument

split() behaves differently depending on whether you give it a separator, and both forms are examined.

>>> "70 55 90".split()
['70', '55', '90']
>>> "ada@mail.com".split("@")
['ada', 'mail.com']
  • No argument: cuts at every run of whitespace, and ignores extra spaces. This is the one used for "values separated by spaces".
  • With an argument: cuts at exactly that text, which is then thrown away.

It always returns a list of strings, never numbers. That is the split-and-convert pattern from Module Three: split then int.

Note what happens when the separator is not there at all. You get a list of one:

>>> "nothing here".split("@")
['nothing here']

No error. So parts[1] on that would be an IndexError, which is worth remembering when a question asks you to split an email at the @.

TrapThis exact code has been set

Meant to extract the first name and put it in capitals. Find the errors:

full_name = "Ada Lovelace"
first_name = full_name[0:full_name.index()]
print("First name:", first_name.uppercase())

Two errors, and both are invented method calls:

  • index() is called with nothing to look for. It needs the text you want the position of. Here that is the space.
  • uppercase() does not exist in Python. The method is upper(). Nothing in the language is called uppercase.

Only the first speaks, because the program stops there:

TypeError: index expected at least 1 argument, got 0

Fix that, run again, and only then do you meet the second:

AttributeError: 'str' object has no attribute 'uppercase'

Note what you do not get here: a suggestion. Python offers "Did you mean" only when your typo is close enough to a real name. Write uppe() and it says Did you mean: 'upper'?; write uppercase() and it just says no. The help arrives when you least need it. Do not rely on it.

The corrected program:

full_name = "Ada Lovelace"
first_name = full_name[0:full_name.index(" ")]
print("First name:", first_name.upper())
First name: ADA

full_name.index(" ") is 3, the position of the space, so the slice takes characters 0 to 2. The space itself is excluded, because a slice stops before its stop.

A neater answer, worth mentioning to a marker: full_name.split()[0] does the same job in fewer characters and does not break when there is no space.

Must memoriseThis exact code has been set

A "what is the output, explain each line" question. It looks gentle and has a trap in the middle.

text = "  Hello, Python!  "
print(text.strip())
print(text.lower().replace("python", "world"))
print(len(text))
Hello, Python!
  hello, world!
18

Line by line, which is what "explain the result of each line" wants:

  • text.strip() removes the two spaces at each end, giving Hello, Python!. text itself is unchanged, which the next line proves.
  • text.lower() gives " hello, python! ". Now replace("python", "world") matches, because the text is lowercase by the time replace sees it. The result keeps its spaces, because strip on the line before returned a new string and changed nothing.
  • len(text) is 18, counting the original with all four spaces: 2 at the front, 14 for Hello, Python!, 2 at the back.

The trap is the middle line. Answer it without noticing the lower() and you will say replace finds nothing and the text is unchanged. It does match, and the answer is hello, world!. Chained methods run left to right, and each one works on what the one before it returned.

WorkedPart (e): analysing a paragraph

The extension: read a paragraph, split it into sentences at ".", and for each one strip it, skip it if empty, count the words, put it in capitals, and count the vowels.

  1. Split at ".". This is where the empty pieces come from: a paragraph ending in a full stop leaves an empty string after the last one. "A. B.".split(".") gives ['A', ' B', '']
  2. strip() each piece, then skip the empties. That is what the requirement is protecting you from.
  3. split() with no argument to count words.
  4. Count vowels by walking the characters and testing membership with in.
analyse.py
paragraph = input("Enter a paragraph: ")

for sentence in paragraph.split("."):
    sentence = sentence.strip()
    if sentence == "":
        continue

    words = len(sentence.split())

    vowels = 0
    for ch in sentence.lower():
        if ch in "aeiou":
            vowels += 1

    print(f"Sentence: {sentence.upper()}")
    print(f"  Words: {words}, Vowels: {vowels}")

Entering Python is fun. I like code.

Enter a paragraph: Python is fun. I like code.
Sentence: PYTHON IS FUN
  Words: 3, Vowels: 3
Sentence: I LIKE CODE
  Words: 3, Vowels: 5

Three details that decide whether this works:

  • ch in "aeiou" asks whether that character appears in the string "aeiou". It is a neat way to test membership without five comparisons joined by or.
  • Count vowels on sentence.lower(), not on the sentence. The I in "I like" is a vowel, and testing it against lowercase "aeiou" would miss it. Count first, then display in capitals.
  • "Python is fun" has three vowels, not four. They are the o, the i and the u. The y in Python is not counted, because the question defines the vowels as (a, e, i, o, u) and y is not in that list. Follow the question's definition, not your instinct about English.

Now you try: why is the continue needed at all? (The paragraph ends with a full stop, so splitting leaves an empty final piece. Without the skip you would print a blank sentence with 0 words.)
