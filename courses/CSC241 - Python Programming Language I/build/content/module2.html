Module Two · Unit 1

Python Language Syntax

Syntax means the grammar: the rules that decide whether a line is Python at all, before anyone asks whether it is correct.

By the end of this unit you can: write and run statements, use comments, explain why indentation is not decoration in Python, print with sep and end, use escape characters, format with f-strings, and read a traceback.

Statements

Teach

A statement is one complete instruction. In Python, one statement occupies one line, and the end of the line ends the statement. There is no symbol to mark the end.

print("first")
print("second")

Two lines, two statements, carried out top to bottom. If you know a language that ends statements with a semicolon, note that Python does not want one. It is not an error, but it marks your code as written by somebody thinking in another language, and the marks in this course go to Python style.

Comments

Teach

A comment is a note to a human. Python ignores it completely. Everything from a # to the end of that line is a comment.

# Work out the area of the room.
area = length * width      # in square metres

Comments do not run, do not print, and do not affect anything. They exist so that you, in three weeks, can tell what you meant.

Must memoriseRead this once, carefully

A comment is never output. If you see

>>> 10 % 2
0          # Even

then the output is 0. The words # Even are a human annotation sitting beside it, not something Python said. Python never answers you in comments.

This matters because printed material sometimes puts the annotation where the output should be, and a reader new to the language cannot tell which is which. In this manual the rule is absolute: output is shown on its own line, in an output block, exactly as a real interpreter printed it. Every output in this manual was captured from a run, not typed by hand.

Indentation

TeachPython's one big idea

In most languages, spaces at the start of a line are decoration, and blocks of code are marked with braces. In Python the spaces are the structure. There are no braces. Indentation is how Python knows which lines belong to what.

You have not met if yet, and it arrives properly in Module Three. Read this only for the shape:

if raining:
    print("take a coat")      # indented: belongs to the if
print("leave the house")      # not indented: always runs

The indented line runs only when it is raining. The unindented line always runs. Move that one line four spaces to the left or right and you have changed what the program does. Nothing else changed.

The rule: a colon at the end of a line means "a block follows", and that block is the lines indented beneath it. Use four spaces per level. Be consistent: Python accepts any consistent width, and rejects a mixture.

TrapExam favourite

Indentation errors are a standing question in this course. Two distinct failures, and the wording of the error tells you which:

IndentationError: expected an indented block after 'if' statement on line 1

means you wrote the colon and then did not indent anything beneath it.

IndentationError: unexpected indent

means you indented a line that had no colon above it to belong to.

Printing

Teach

print() displays things. Give it several items separated by commas and it prints them all, putting one space between each:

>>> print("Ada", 25, "Lagos")
Ada 25 Lagos

It then moves to a new line. Both of those behaviours can be changed, and each has a name you must know.

Must memorisesep and end

sep sets what goes between the items. Default: one space.

end sets what goes after the last item. Default: a newline, written \n.

>>> print("2026", "07", "17", sep="-")
2026-07-17
>>> print("Ada", "Bob", sep="")
AdaBob

Setting end to the empty string stops the newline, so the next print continues on the same line:

>>> print("Hello", end="")
>>> print("World")
HelloWorld

Read that transcript carefully. The first print displayed Hello and stayed put; the second added World and ended the line. The output HelloWorld is the work of both statements together.

Quotes and escape characters

Teach

Text in Python is written inside quotes, and is called a string. Single and double quotes are equally valid and mean exactly the same thing:

'Ada'
"Ada"

Having both is useful, because a string in double quotes may freely contain a single quote:

>>> print("It's fine")
It's fine

The problem arrives when the string must contain the same quote that ends it. Python reads the second quote as the end of the string and the rest becomes nonsense. The fix is an escape character: a backslash \ before the quote, which tells Python "this next character is data, not punctuation".

>>> print("She said, \"Python is cool!\"")
She said, "Python is cool!"
Must memoriseEscape characters
EscapeMeans
\nNewline: move to the next line
\tTab: jump to the next tab stop
\"A double quote, as data
\'A single quote, as data
\\One backslash, as data

A question asking you to "list three escape characters and their effects" has appeared in this course. The three safest to give are \n, \t and \\.

TeachOne string, two lines

\n inside a string breaks it across lines when printed. It is one string, not two:

>>> print("Name: Ada\nCity: Lagos")
Name: Ada
City: Lagos

f-strings

Teach

You will constantly want to put a value inside a sentence. The direct way is an f-string: put the letter f immediately before the opening quote, then write { } wherever a value belongs.

>>> name = "Ada"
>>> age = 25
>>> print(f"{name} is {age}")
Ada is 25

The f is not optional and not decoration. Without it you get the braces themselves:

>>> print("{name} is {age}")
{name} is {age}
Must memoriseFormat specifiers

After a colon inside the braces you may say how to display the value. These are the ones this course uses:

WrittenMeansExample inExample out

:,Comma between thousands12500001,250,000

In the last two rows each dot stands for one space, so that you can count them. Python prints spaces, not dots.

WorkedAlignment you can actually see

Field widths exist to build columns, and columns only work in a font where every character takes the same width. Every code block in this manual is set in such a font. Give three rows the same format string and they line up:

>>> print(f"{'Item':<10}{'Price':>10}")
Item           Price
>>> print(f"{'Apple':<10}{1.5:>10.2f}")
Apple           1.50
>>> print(f"{'Banana':<10}{12.75:>10.2f}")
Banana         12.75

The words start in the same column because :<10 pins them to the left. The prices end in the same column because :>10 pins them to the right, and that is true even though 1.50 and 12.75 have different lengths. That is what a field width buys you.

Spaces cannot be counted by eye, so here are those same three lines with every space drawn as a dot. Each dot is one space, and nothing else has changed:

Item···········Price
Apple···········1.50
Banana·········12.75

Count the first line. Item takes 4 of its 10 columns, so 6 spaces pad it on the right. Price is 5 characters pushed to the right hand edge of its own 10 columns, so 5 spaces come first. That is 6 + 5 = 11 dots, which is what you counted. Every line is 20 characters wide.

Now you try: work out the dots for a row holding 'Fig' and 3.5 in the same format, before you run it. (3 + 7 pad, then 6 + '3.50': Fig then 13 dots then 3.50.)

Reading a traceback

TeachWorth many marks

When Python cannot do what you asked, it prints a traceback. Beginners see a wall of red and look away. It is the most useful text on the screen, and half of this course's code marks come from finding errors, so learn to read it.

Traceback (most recent call last):
  File "C:\Users\you\hello.py", line 3, in <module>
    print(10 / 0)
          ~~~^~~
ZeroDivisionError: division by zero

Read it from the bottom up:

  • Last line is what went wrong: ZeroDivisionError, and in plain words, division by zero. This is the line that tells you the problem.
  • Above it is the offending code, with the marks ~~~^~~ pointing at the exact part that failed. The ^ sits under /, the operation that could not be done.
  • Above that is where: the full path of the file, and line 3.

Error type, then message, then place. Three facts, always in that order.

Python prints the file's whole location, so your first line will be longer than the one above and will show wherever you saved it. Only the file name and the line number matter to you.

Must memoriseSyntax before runtime

Errors come in two kinds and they happen at different times:

A SyntaxError is a grammar failure. Python finds it while reading the file, before running a single line. Nothing in the file executes. There is no traceback of the kind above, because nothing ran.

A runtime error is a meaning failure in a line that is grammatically fine. Python only finds it when it reaches that line, so everything before it has already run and printed.

The consequence, which is examinable: a SyntaxError anywhere in a file hides every other error in it. If a file has a missing bracket on line 2 and a misspelled name on line 9, you are told about line 2 only. Fix it, run again, and only then hear about line 9.

RecallCover the answers

2. What are sep and end?

3. Which end of a traceback do you read first?

4. A file has a SyntaxError on line 2 and a NameError on line 9. What does Python report?

Answers

  1. That a block follows, made of the lines indented beneath it.
  2. sep is what print puts between items (default one space); end is what it puts after the last one (default a newline).
  3. The bottom. The last line names the error and states it in words.
  4. The SyntaxError on line 2, and nothing else. The file never runs, so line 9 is never reached.
Module Two · Unit 2

Variables and Data Types

Where values are kept, what kinds of value exist, and the one thing about numbers that surprises everybody exactly once.

By the end of this unit you can: create and reassign variables, name them legally, list the four basic types, check a type, read input, convert between types, and explain why 0.1 + 0.2 is not 0.3.

Variables

Teach

A variable is a name that refers to a value. You make one by writing the name, then =, then the value:

>>> age = 25
>>> age
25

The = here does not mean equals. It means assign: work out the value on the right, then make the name on the left refer to it. It is an instruction, not a statement of fact. This is why

count = count + 1

is perfectly sensible, though as mathematics it would be nonsense. It reads: take what count is now, add 1, and make count refer to that.

TeachReassignment

A variable can be given a new value at any time, including a value of a different kind. The old value is simply forgotten:

>>> x = 99
>>> print(x)
99
>>> x = "Take me to your leader."
>>> print(x)
Take me to your leader.

Python does not object. The name is a label, not a box of a fixed size.

Must memoriseNaming rules

Must:

  • Start with a letter or an underscore. Never a digit.
  • Contain only letters, digits and underscores. No spaces, no hyphens.
  • Not be a Python keyword (if, for, class, and the rest).

Should: be lowercase with underscores between words (total_score), and say what it holds. A name like x tells the reader nothing.

Case matters. age, Age and AGE are three different variables. This is a standing source of exam errors: a program that defines square and calls Square is broken.

The four basic types

Trap2.0 is not an int

2 and 2.0 are equal in value but are different types. The decimal point makes it a float, even when there is nothing after it. This decides what division gives you back, as Unit 3 shows.

Teachtype()

type() tells you what something is. When in doubt, ask:

>>> type(25)
<class 'int'>
>>> type(3.14)
<class 'float'>
>>> type("Ada")
<class 'str'>
>>> type(True)
<class 'bool'>

Read <class 'int'> as "this is an int". The word class is Python's internal vocabulary for a type.

Input

Must memoriseinput always gives a string

input() stops the program, waits for the user to type something and press Enter, and hands back what they typed. The text you pass to it is shown as the prompt.

What it hands back is always a string. Always. Even when the user types digits.

age = input("How old are you? ")
print(type(age))
How old are you? 25
<class 'str'>

The user typed 25 and Python is holding the two characters "25", not the number. This single fact causes more broken exam answers than anything else in the course.

TrapThe classic

Forget to convert, and arithmetic does something silently absurd rather than failing:

a = input("First number: ")   # user types 5
b = input("Second number: ")  # user types 3
print(a + b)
First number: 5
Second number: 3
53

53, not 8. Because + on two strings joins them end to end. The program did exactly what you asked and nothing reported an error. The fix is to convert.

Converting between types

Must memoriseCasting

int()an integerint("25")25
float()a floatfloat("3.5")3.5

So the fix for the trap above, and the pattern you will write hundreds of times:

age = int(input("How old are you? "))

Read it from the inside out: input collects text, int turns that text into a number, = stores the number.

Teachint() truncates

int() on a float throws the decimal part away. It does not round:

>>> int(3.9)
3
>>> int(-3.9)
-3

It cuts towards zero. Use round() if you want rounding.

Trapint() is fussy about strings

int() can only convert a string that is entirely a whole number. Give it anything else and you get a runtime error, and the program stops:

>>> int("xyz")
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
ValueError: invalid literal for int() with base 10: 'xyz'

Note that int("3.5") fails too, for the same reason: 3.5 is not a whole number written out. Use float("3.5"), or int(float("3.5")) if you truly want 3.

Floats are not exact

Must memoriseEverybody meets this once

Type this at the prompt. It is not a trick:

>>> 0.1 + 0.2
0.30000000000000004

Python is not broken and you did not make a mistake. A computer stores numbers in binary, in a fixed amount of space. Some numbers that are short and exact in decimal, such as 0.1, cannot be written exactly in binary at all, in the same way that 1/3 cannot be written exactly in decimal: 0.333... never finishes. Python stores the closest value it can fit, and the tiny difference shows up when you add.

This is not a Python quirk. It is how nearly every language on nearly every machine stores decimals.

WorkedWhere it will bite you

It hides until it does not. Watch an ordinary looking interest calculation:

>>> INTEREST_RATE = 0.069
>>> balance = 10000
>>> amount = balance * INTEREST_RATE
>>> amount
690.0000000000001

Not 690.0. And yet change the rate to 0.072 and it comes out perfectly clean:

>>> INTEREST_RATE = 0.072
>>> amount = balance * INTEREST_RATE
>>> amount
720.0

Same code, same shape, one is ugly and one is clean. That is exactly what makes this dangerous: you cannot predict which by looking, so you must handle it always rather than when it looks likely.

The rule: never show a raw float to a user, and never compare two floats with ==. Format it on the way out.

Must memoriseThe fix

Format the float when you display it, and the problem disappears at the only point where it mattered:

>>> amount = 10000 * 0.069
>>> print(f"Interest: {amount:.2f}")
Interest: 690.00

Any exam program that reports an average, a percentage or an amount of money should print it through :.2f. It is one keystroke's worth of effort and it is the difference between a professional answer and a puzzling one.

RecallCover the answers

1. What type does input() return?

2. The user types 5 and 3 into two input() calls and you print a + b. What appears, and why?

3. What is int(3.9)?

4. Why is 0.1 + 0.2 not 0.3?

Answers

  1. A string, always, even if the user typed digits.
  2. 53. Both are strings, and + on strings joins them. No error is reported.
  3. 3. int() truncates towards zero, it does not round.
  4. Floats are stored in binary in fixed space. 0.1 has no exact binary form, so Python stores the nearest value it can, and the small error becomes visible when adding. Format with :.2f on output.

Python Operators

The symbols that combine values. Two of them, // and %, carry more exam marks than the rest put together.

By the end of this unit you can: use every arithmetic operator, predict what division returns, use % to test divisibility, apply precedence correctly, and use comparison and logical operators.

Arithmetic

Must memorise/ always gives a float

/ gives a float every time, even when the division is exact:

>>> 10 / 2
5.0
>>> 5 / 2
2.5

10 / 2 is 5.0, not 5. If you need a whole number, use // or wrap it in int().

// divides and throws away the fractional part, giving the whole number of times the divisor fits:

>>> 7 // 5
1
>>> 17 // 3
5
Must memorise% is the workhorse

% gives the remainder after division. 17 % 3 is 2, because 3 fits into 17 five times with 2 left over.

// and % are the two halves of one division:

>>> 17 // 3
5
>>> 17 % 3
2

17 divided by 3 is 5 remainder 2. The first gives the 5, the second the 2.

The use that appears in this exam every year: a number is divisible by n exactly when number % n == 0.

>>> 10 % 2
0
>>> 7 % 2
1

A remainder of 0 on division by 2 means even. A remainder of 1 means odd. Read those two transcripts again: the outputs are 0 and 1. That is what Python printed.

WorkedSeconds into hours, minutes, seconds

This is // and % working together, and it is the standard demonstration of both. Turn 11730 seconds into hours, minutes and seconds.

  1. An hour is 3600 seconds. How many whole hours fit? That is floor division. 11730 // 3600 gives 3
  2. What is left over after those hours? Take the remainder on 3600, then ask how many whole minutes fit in it. Both steps at once: take the remainder on 60 of the total whole minutes. (11730 // 60) % 60 gives 15
  3. Seconds left over is the remainder on 60. 11730 % 60 gives 30
time_converter.py
total_seconds = 11730
hours   = total_seconds // 3600
minutes = (total_seconds // 60) % 60
seconds = total_seconds % 60
print("Hours:", hours)
print("Minutes:", minutes)
print("Seconds:", seconds)
Hours: 3
Minutes: 15
Seconds: 30

Now you try: change 11730 to 7325 and predict the three numbers before running it. (2 hours, 2 minutes, 5 seconds.)

Must memorise** is right associative

Nearly every operator groups from the left. ** groups from the right:

>>> 2 ** 3 ** 2
512

This is 2 ** (3 ** 2), which is 2 ** 9, which is 512. It is not (2 ** 3) ** 2, which would be 64.

** also does roots, because a square root is the power one half:

>>> 9 ** 0.5
3.0

Precedence

Must memoriseOrder of operations

When several operators appear in one expression, Python applies them in this order, highest first:

OrderOperators

Within one row, work left to right (except **, which goes right to left).

>>> 2 + 3 * 4

>>> (2 + 3) * 4

When in doubt, add brackets. They cost nothing and they make your intention unmistakable to a marker.

Trap= against ==

= assigns. == asks. They are unrelated, and confusing them is the most common single error in this course's error-spotting questions.

age = 18      # assigns 18 to age
age == 18     # asks: is age 18? Gives True.

Write if age = 18: and Python stops you with a SyntaxError, because a question was expected and you gave it an instruction.

TeachChaining

Python lets you write a range check the way mathematics does, and it means what it looks like:

>>> bmi = 22.4
>>> 18.5 <= bmi <= 24.9
True

This is worth remembering: a question in this course asks for exactly this test on a BMI value, and the chained form is shorter and clearer than joining two comparisons with and.
