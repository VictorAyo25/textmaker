The Python Reference Card

Every keyword, built-in function and method this manual uses, in one place, with the thing people actually get wrong about each one: what it hands back.

By the end of this section you can say, for any name in this course, what it does, what it returns, and whether it changes the thing it was called on.

Must memorisethe question to ask of every call

Three questions, and they answer most of the paper's tracing questions before you trace anything.

  1. What does it RETURN? A call that returns None cannot be assigned to anything useful.
  2. Does it CHANGE the thing it was called on? A list method usually does. A string method never does.
  3. What TYPE comes back? input() gives a string. A single slash gives a float. A slice of a list gives a list.

Trapthe two that look alike

sorted(xs) returns a new sorted list and leaves xs alone. xs.sort() sorts xs itself and returns None. Writing ys = xs.sort() puts None in ys, silently, and the bug shows up several lines later.

Recall and check

Name every call in this course that returns None, and say why that matters.

Answer

print(), .append(), .remove(), .sort(), .write() to a degree, .close(), .commit(), and any function with no return statement. It matters because assigning one of them to a variable stores None, which then fails much later and a long way from the mistake.

Must memorisethe sentences, as sentences
  • Python is an interpreted, high-level, general-purpose programming language, known for readable syntax and dynamic typing.
  • Dynamically typed means the type belongs to the value, not to the name, so a variable may be rebound to a value of a different type and no declaration is needed.
  • Lists are ordered means every item has a position, that position is fixed until you change it, and items can be reached and sliced by that position.
  • Strings are immutable means a string object cannot be altered after it is created. Every string operation returns a NEW string, and s[0] = "X" raises TypeError. To change a string you rebind the name.
  • Sets are unique means a set holds at most one copy of any value, so adding a value already present changes nothing and len() does not grow.
  • A KeyError is raised when a dictionary is asked for a key it does not hold. d.get(key) returns None instead of raising.
  • A function is a named block of code that runs when it is called, takes parameters and may return a value. It is the unit of reuse.
  • Modularising a program gives reuse, independent testing, readability, easier maintenance, and division of work across a team. It does not make the program run faster.
  • An exception is an error detected while the program runs. try and except let the program handle it instead of stopping.
  • A module is a file of Python code that can be imported; a package is a directory of modules.

Must memorisethe SQL this course needs
CREATE TABLE students (id INTEGER PRIMARY KEY, name TEXT, score REAL)
INSERT INTO students VALUES (?, ?, ?)
SELECT * FROM students WHERE score > 50 ORDER BY score DESC
UPDATE students SET score = 60 WHERE name = 'Ada'
DELETE FROM students WHERE score < 30
SELECT COUNT(*), MAX(score), MIN(score), AVG(score) FROM students

Six lines. WHERE is optional on UPDATE and DELETE, and leaving it out applies the statement to every row in the table.

Exam Day Strategy

Three hours, one paper carrying an objective section and long questions, and no computer. How to spend the time, and how to write code that earns marks on paper.

Teachthe plan for the three hours
  1. First five minutes: read the whole paper. Mark every question you can already do. That is not wasted time, it is the difference between answering the questions you know and running out of time before you reach them.
  2. Do the objective section first, at pace. Roughly 45 seconds a question. Any one you cannot settle in that time gets a mark in the margin and your best guess now, because there is no negative marking and a blank scores nothing.
  3. Then the long question you marked as easiest. Confidence is worth real marks, and an early complete answer stops you spending the whole paper on your worst topic.
  4. Watch the marks, not the question numbers. A part worth 2 marks wants two sentences. A part worth 8.5 wants a whole program. Writing an essay for 2 marks is how people run out of time.
  5. Leave ten minutes. Go back to the marked objective questions and to any part you left blank. Something written is always worth more than nothing.
Teachwriting code by hand

The examiner cannot run your program, so what earns the marks is that it is readable and obviously correct. Five habits do most of that work.

  • Indent visibly. Four clear spaces, or a ruled line down the block. An examiner who cannot see which lines are inside the loop cannot give you the loop mark.
  • Write the colons. Every if, for, while, def and except ends its header with a colon, and it is the most commonly dropped character under time pressure.
  • Name things properly. total, count, student_name. A program full of a, b and c reads as a guess even when it is right.
  • Convert your input. Any number read with input() gets int() or float() around it. This single line appears in almost every program this paper asks for.
  • Trace your own answer once with a small value before you move on. Three lines of a trace table in the margin catch an off-by-one that would otherwise cost the whole part.
Teachhow to answer the four question shapes
ShapeWhat earns the marks
Explain a property (lists are ordered, strings are immutable) Define it in one sentence, then give a two-line example that SHOWS it, then say what it means in practice. The example is usually worth as much as the sentence.
What is the outputTrace it line by line in the margin with a small table of variables. Write the output exactly as Python would print it, including quotes and brackets on a list.
Identify and correct the errorsSay WHERE (the line number), WHAT (the fault), and WHY it is wrong, then write the corrected line. Three parts, and most people give only the correction.
Write a programInput, then process, then output, in that order, with a comment above each stage. Handle the obvious bad input if the marks are generous enough to imply it.
Key point

Marks are awarded for demonstrated understanding, not for a program that would compile. A partly written answer with correct structure and clear naming scores; a blank scores nothing at all.

Blunt version: never leave a part empty. Write the input line and the loop header even if you cannot finish.

Recall and check

Without looking: what does each of these return, and does it change what it was called on? sorted(xs), xs.sort(), s.upper(), xs.append(3), d.get("k"), cur.fetchone().

Answer

sorted(xs) returns a new list, xs unchanged. xs.sort() returns None, xs sorted. s.upper() returns a new string, s unchanged, because strings are immutable. xs.append(3) returns None, xs one item longer. d.get("k") returns the value or None, d unchanged. cur.fetchone() returns the next row as a tuple, or None when they run out.
